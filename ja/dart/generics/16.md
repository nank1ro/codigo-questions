# --description--

`typedef` は型に名前を付けます。そしてtypedefはそれ自体の型パラメータを持てます。通常の目的は、使うたびにいちいち書き連ねる代わりに、関数型の族に一度名前を付けることです：

```dart
typedef Transform<I, O> = O Function(I input);

final Transform<String, int> length = (word) => word.length;
print(length('kiwi')); // 4
```

`Transform<String, int>` は `int Function(String)` の別の書き方にすぎないので、2つは互いに交換できます。得られるのは読みやすさです。`Transform<I, O> transform` と宣言されたパラメータは関数が何のためのものかを語りますが、`O Function(I)` は見た目しか語りません。

ジェネリックなtypedefとジェネリックな関数は自然に組み合わさります。関数自身の型パラメータがtypedefの型パラメータを埋めます。

# --instructions--

2つの型パラメータ `I` と `O` を持ち、`I` を受け取って `O` を返す関数に名前を付けるジェネリックなtypedef `Transform` を宣言してください。

次に、型パラメータ `I` と `O` を持ち、`List<I>` の `items` と `Transform<I, O>` の `transform` を受け取り、変換されたすべてのアイテムを順番に保持する `List<O>` を返すジェネリック関数 `convertAll` を書いてください。

例：
```dart
print(convertAll<String, int>(['fig', 'kiwi'], (w) => w.length)); // [3, 4]
```

`convertAll<String, int>(['fig', 'kiwi'], (w) => w.length)` は `[3, 4]` を返すはずです

```dart
  test('test1', () {
    expect(
      convertAll<String, int>(['fig', 'kiwi'], (w) => w.length),
      [3, 4],
      reason: '--err-t1--',
    );
  });
```

`convertAll` は `List<O>` を返すはずです。intを文字列に変換すると `List<String>` になるはずです

```dart
  test('test2', () {
    final result = convertAll<int, String>([1, 2], (n) => 'n$n');
    expect(result, ['n1', 'n2'], reason: '--err-t2--');
    expect(result, isA<List<String>>(), reason: '--err-t2--');
  });
```

typedef `Transform` は関数型に名前を付けるはずです。空のリストは空のリストになるはずです

```dart
  test('test3', () {
    final Transform<int, int> twice = (n) => n * 2;
    expect(convertAll<int, int>([1, 2, 3], twice), [2, 4, 6], reason: '--err-t3--');
    expect(convertAll<String, int>(<String>[], (w) => w.length), <int>[], reason: '--err-t3--');
  });
```

# --solutions--

```dart
typedef Transform<I, O> = O Function(I input);

List<O> convertAll<I, O>(List<I> items, Transform<I, O> transform) {
  return items.map(transform).toList();
}
```
