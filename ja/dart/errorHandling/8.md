# --description--

ハンドラーが回復するのにふさわしい場所ではないこともあります：失敗に*気づく*だけにして、実際に対処できる呼び出し元へ伝播させ続けたい場合です。`rethrow` キーワードは `catch` や `on ... catch` ブロックの中でそれを行います：

```dart
try {
  return int.parse(text);
} on FormatException {
  log.add('bad input: $text');
  rethrow;
}
```

`rethrow` は**同じ**オブジェクトを先へ送るので、呼び出し元は元の失敗を見ます。代わりに `throw e` と書いても動きますが、旅をやり直すことになり、失敗が最初に起きた場所が失われます。

同じ文の `finally` ブロックは、外へ出ていく途中でも実行されます。

# --instructions--

`String` の `text` と `List<String>` の `log` を受け取り、`int.parse(text)` を返す関数 `parseOrLog` を書いてください。

テキストが整数でないときは、`'bad input: '` にテキストを続けた文字列を `log` に追加し、それから `FormatException` を rethrow して、呼び出し元にもそれが見えるようにしてください。

例：
```dart
final log = <String>[];
print(parseOrLog('42', log)); // 42
```

# --asserts--

`parseOrLog('42', log)` は `42` を返し、ログを空のままにするべきです

```dart
  test('test1', () {
    final log = <String>[];
    expect(parseOrLog('42', log), 42, reason: '--err-t1--');
    expect(log, isEmpty, reason: '--err-t1--');
  });
```

`parseOrLog('oops', log)` は `FormatException` を投げるべきです

```dart
  test('test2', () {
    expect(() => parseOrLog('oops', <String>[]), throwsFormatException, reason: '--err-t2--');
  });
```

ログは失敗1件につき1行を集め、正しい値は記録されないべきです

```dart
  test('test3', () {
    final log = <String>[];
    expect(() => parseOrLog('oops', log), throwsFormatException, reason: '--err-t3--');
    expect(log, ['bad input: oops'], reason: '--err-t3--');
    expect(parseOrLog('7', log), 7, reason: '--err-t3--');
    expect(() => parseOrLog('x', log), throwsFormatException, reason: '--err-t3--');
    expect(log, ['bad input: oops', 'bad input: x'], reason: '--err-t3--');
  });
```
