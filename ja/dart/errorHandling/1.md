# --description--

実行できない文というものがあります：数字ではないテキストの読み取り、リストの末尾を越えた要素の取り出し、空のリストの最初の項目を要求すること。そのようなとき、Dart は失敗を記述するオブジェクトを**投げます**。

`throw` キーワードを使えば、自分でも1つ投げられます。`Exception('message')` は短い説明を運んだ、できあいのオブジェクトを作ります：

```dart
throw Exception('no fuel');
```

throw は `return` ではありません。投げられると、その文、その関数、そしてその上にあるすべての呼び出し元を放棄し、それを処理するものを探します。どこにも見つからなければ、プログラムは停止して失敗を出力します：

```
Unhandled exception:
Exception: no fuel
```

throw の後のすべてはスキップされるので、本来なら実行されるはずだった行は決して実行されません。このトピックの要点はまさにそこにあります：プログラムを終わらせてしまう代わりに、失敗をどこで処理するかを決めることです。

# --instructions--

このプログラムは何を出力しますか？

```dart
void main() {
  print('start');
  throw Exception('no fuel');
  print('end');
}
```

# --answers--

- `start`、続いて未処理の例外のレポート、そして `end` は決して出力されない
- `start` と `end`。`throw` は自分の行だけをスキップするため
- `end` のみ。throw がその前の print をキャンセルするため
- `start`、`Exception: no fuel`、`end`。Dart はレポートの後にも処理を続けるため
