# --description--

この章のすべては、1つの問いに答えています。失敗に対処するのは誰か、という問いです。

スローする関数はそれに答えることを拒みます。何が間違っていたかを名指しし——`Error`列挙型のケースとして、ハンドラーが必要とするものすべてを載せて——判断を上へと引き渡します。呼び出し元はそこで道具を選びます。ケースごとに反応するなら`do`/`catch`、デフォルト値に頼るなら`try?`と`??`、どちらに転んでも出口でクリーンアップするなら`defer`です。

この分担こそがすべてです。問題を検出する関数は、次に何が起きるべきかをほとんど知りません。そして、それを知っているコードは、そのチェックを繰り返したいとはほとんど思いません。

# --instructions--

この章のすべてを使ってバリデータを書いてください:
- `FormError`に`Int`型の`maximum`を持つ2番目のケース`tooLong`を付ける
- `validate`は名前が空のとき`FormError.empty`をスローし、10文字より長いとき`FormError.tooLong(maximum: 10)`をスローし、そうでなければ名前を返す
- `safeName`は検証済みの名前を返し、`validate`がスローしたときは`"guest"`を返す

関数呼び出しの例:
```swift
print(safeName(""))
// guest を出力
```

func _kind(_ name: String) -> String {

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
