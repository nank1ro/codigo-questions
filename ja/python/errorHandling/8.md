# --description--

後ろに型を書かない `except:` は**裸のexcept（bare except）**です。これはすべてに一致するため、守ろうとしていた操作とは無関係な例外まで捕捉されます。ルールは単純です：実際に回復できる型だけを必ず指定しましょう。

# --instructions--

このコードは、裸の `except:` を使う代わりに、具体的な例外の型を指定するべきなのはなぜですか？
```python
try:
    total = int(amout)
except:
    total = 0
```

# --answers--

- 裸の `except:` は無関係な失敗も捕捉するためです。スペルミスの `amout` が引き起こす `NameError` も捕捉され、本物のバグが黙って `total = 0` になってしまいます
- 裸の `except:` は遅くなるためです。Pythonは例外をすべての組み込みクラスと比較しなければなりません
- 裸の `except:` はモジュールレベルでしか機能せず、関数の中では `SyntaxError` を発生させるためです
- 裸の `except:` は何も捕捉せず、ブロックが終わるとすぐに例外が再度発生するためです
