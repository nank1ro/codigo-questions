**コメント**は、ソースコードの中に書かれる、コードを読む人のためのメモです。Pythonはコメントを完全に無視するので、プログラムの動作が変わることはありません。

Pythonにあるコメントは**1行コメント**だけです。`#`で始まり、行の終わりまで続きます。
```python
# ユーザーに挨拶する
print("Hello")
```
コメントは、コードが何のためのものか、なぜそのように書かれたのかを説明するために使います。

---

コメントは独立した行である必要はありません。コードと同じ行に続けることができます。これは**行内コメント**と呼ばれ、その行の処理についての短いメモを書くのに適した場所です：
```python
retries = 3  # 3回試したら諦める
```
`#`から行の終わりまではすべて無視されますが、その前のコードは通常どおり実行されます。

Pythonのスタイルガイド**PEP 8**は、ここで少しスペースを入れることを求めています。コードと `#` の間には**2つ以上のスペース**、`#` の後には**1つのスペース**を入れます。独立した行にあるコメントは、`#` の後のスペースだけで構いません。

---

Pythonはコメントを完全に取り除くので、コメントを追加したり削除したりしても、プログラムの動作は決して変わりません。実行されるのは、コメントされて**いない**コードだけです。

そのため、`#` はコードの行を削除せずに無効にする手軽な方法になります。これは**コメントアウト**と呼ばれます：
```python
total = 10
# total = total + 5
print(total)  # 10を出力する
```
2行目は今やコメントなので、`total` は `10` のままです。`#` を取り除けば、その行は再び有効になります。

コメントアウトは実験している間は便利ですが、後片付けを忘れないでください。長い間コメントアウトされたままのコードは、次に読む人を混乱させるだけです。

---

多くの言語には、`/* ... */` のように複数行にまたがる2つ目のコメント形式である**ブロックコメント**があります。Pythonにはそのような構文はなく、`#` だけです。

説明が複数行にわたるときは、すべての行の先頭に `#` を付けます：
```python
# ウェルカムバナーを出力する。
# アプリの起動時に一度だけ呼び出される。
print("Welcome!")
```
同じやり方で、複数行のコードを一度にコメントアウトできます。1行に1つの `#` です。どのエディタでも、選択した範囲全体に `#` を付けたり外したりするショートカットが1つあるので、見た目ほど手間ではありません。

---

**トリプルクォート文字列**が、まるでブロックコメントであるかのように使われているのをよく見かけます：
```python
"""
This looks like a comment,
but it is a string.
"""
print("done")
```
`"""` から `"""` までの文字列は複数行にまたがることができ、それ単体で書かれた文字列は有効な文です。Pythonはその文字列を組み立てますが、何もせずに捨てます。何も出力されないので、結果はコメントのように見えます。

しかし、コメントではありません。文字列リテラルなので、引用符のルールがそのまま適用されます。対応の取れていない引用符や、文字列の中に紛れ込んだ余分な `"""` はプログラムを壊します。一方、`#` コメントの中では何を書いても構いません。また、ファイル、クラス、関数の最初の文になってしまうと、うっかりdocstringになってしまいます。それ以外の場所では、単にどこにも残りません。CPythonはコンパイル中に文全体を捨てます。

ですから、コードを無効にするときは `#` を使ってください。トリプルクォート文字列にはそれ自身の役割があり、それは次の演習で始まります。

---

文字列が関数の中の**最初の文**であるとき、Pythonはそれをその関数のドキュメントとして扱います。これは**docstring**と呼ばれます：
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"
```
慣例として、docstringは1行に収まる場合でも、トリプルダブルクォート `"""` の間に書きます。後で内容が増えても引用符を変更せずに済むようにするためです。

要約は、関数を説明するかのように三人称で書きます。「Returns...」「Adds...」「Checks...」のようにです。docstringは本体の中で他のどの文よりも前に来なければなりません。そうでなければ、それは単なる普通の文字列です。

---

docstringは捨てられてしまうわけではありません。Pythonはそれを関数の `__doc__` 属性に格納するので、プログラムは実行中に自分自身のドキュメントを読むことができます：
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"

print(greet.__doc__)  # name への挨拶を返す。
```
関数にdocstringがないとき、`__doc__` は `None` です。`help(greet)` が表示するもの、そして名前の上にカーソルを合わせたときにエディタが表示するものは、これです。

---

ファイルもドキュメント化できます。どのimportや定義よりも前に、**ファイルの最初の文**として書かれた文字列は**モジュールdocstring**です。ファイル全体が何のためのものかを示します。
```python
"""Tools for working with rectangles."""

def area(width, height):
    """Returns the area of a rectangle."""
    return width * height
```
最初の文だけが対象になります。コメントはその上に置いても構いませんが、間に実際のコードがあると、文字列は役に立たない普通の文字列に戻ってしまいます。

---

クラスも同じやり方で動作します。クラス本体の最初の文として置かれた文字列は、そのクラスのdocstringであり、`__doc__` に格納されます：
```python
class Point:
    """A point on a grid."""

    def __init__(self, x, y):
        self.x = x
        self.y = y

print(Point.__doc__)  # A point on a grid.
```
クラスの中の各メソッドも、`Point.__init__.__doc__` のようにして読める独自のdocstringを持てます。つまり、docstringを受け入れる3つの場所とは、モジュールの先頭、クラスの先頭、関数の先頭です。

---

docstringと `#` コメントは似ていますが、答える疑問が異なります。

**docstring**は、コードを**使う**人のためのものです。関数が何をするのか、何を受け取り、何を返すのか。`__doc__` の中に残り、`help()` がそれを読み、エディタがそれを表示し、ドキュメントツールがそれを収集します。

**コメント**は、コードを**読む**人のためのものです。なぜこの行がこのように書かれているのか、奇妙な数字が何を意味するのか、どのバグを回避するためのものなのか。ソースファイルの中にだけ存在し、プログラムが実行されると消えてしまいます。

```python
def timeout():
    """Returns the number of seconds to wait for the server."""
    # サーバーは35秒アイドルだと接続を切る
    return 30
```
つまり、関数のドキュメントはdocstringに、実装に関するメモはコメントに書きます。

---

1行では足りないとき、docstringは**PEP 257**で説明されている決まったレイアウトへと成長します。1行の要約、空行、その後に詳細、そして閉じる `"""` はそれだけで1行に置きます。
```python
def to_seconds(minutes):
    """Returns the number of seconds in the given minutes.

    minutes is a whole number and is never negative.
    """
    return minutes * 60
```
空行には意味があります。ツールは1行目を短い説明として単独で表示し、残りはもっと読みたい人のために取っておくからです。

---

docstringは本体の**最初の行**でなければならず、他のどの文よりも上に置きます。`return` の後や本体の他の場所に書かれた文字列は、単なる文字列にすぎません。`__doc__` は `None` のままになり、どのツールもそれを表示することはありません。

---

エディタが理解できる慣習に従うコメントもあります。最も一般的な**マーカー**は次のとおりです：
- `# TODO: ...` は、まだ書く必要があるものを示します
- `# FIXME: ...` は、間違っていると分かっていて修正されなければならないコードを示します

```python
limit = 10
# TODO: 設定から上限を読み込む
```
Pythonにとってこれらは普通のコメントですが、エディタは専用のパネルにそれらを集めるので、残されている作業を見つけやすくなります。`TODO` は通常、実際のコードが書かれるまでプログラムを動かし続けるプレースホルダーのそばに置かれます。

作業を終えたら、同じ変更の中でプレースホルダーを置き換え、マーカーを削除してください。そうすれば、コメントがコードの状態について嘘をつくことはありません。

---

関数が何をするかを説明するために関数の上に置かれたコメントは、間違った場所にあります。そのための場所はdocstringです。docstringは関数に紐付けられ、`help()` はそれを見つけ、エディタはそれを表示します。一方、`def` の上にある `#` コメントは、そのどれからも見えません。

```python
# a と b を足す
def add(a, b):
    return a + b
```
同じ文を1行下へ、トリプルクォートの間に移動させると、本物のドキュメントになります：
```python
def add(a, b):
    """Returns the sum of a and b."""
    return a + b
```

---

Pythonは `#` をコードの中でだけ探し、**文字列**の中では決して探しません。引用符の間では、`#` は普通の文字です：
```python
print("black is #000000")  # a hex colour
```
最初の `#` はテキストの一部であり、2つ目の `#` が本物のコメントを始めます。`#` コメントの中の `"""` についても同じです。そこでは単なる3つの引用符文字であり、何も始めません。

---

良いコメントは、コードが**何を**するかではなく、**なぜ**それをするのかを説明します。コードはすでに何が起こるかを示しています。それを言葉で繰り返すのはノイズを加えるだけで、コードが変わるとすぐに古くなってしまいます：
```python
# timeout を30に設定
timeout = 30
```
その数字の裏にある理由こそ、読む人には推測できないものです：
```python
# サーバーは35秒アイドルだと接続を切るので、早めに止める
timeout = 30
```
コメントが下の行を言い換えているだけなら、削除するか理由に置き換えてください。最良のコメントは、コードでは語れないことを語るものです。
