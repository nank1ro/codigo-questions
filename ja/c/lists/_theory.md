**リンクリスト**は、メモリ上に散らばった個別の**ノード**に値を格納します。各ノードは値と次のノードへのポインタを保持し、最後のノードは`NULL`を指します。内部のポインタは宣言中の型自身を参照するため、構造体には自分自身に名前を付けるための**タグ**が必要です。波括弧の中ではまだ`typedef`の名前は存在しません:
```c
typedef struct Node {
    int value;
    struct Node *next;
} Node;
```
ノード同士は、あるノードのアドレスを別のノードの`next`に格納することでつながり、指されたノードのメンバにはアロー演算子でアクセスします:
```c
Node second = {2, NULL};
Node first = {1, &second};
printf("%d\n", first.next->value); // prints "2"
```

---

ローカル変数として宣言されたノードは、その関数が返ると消えてしまいます。そのため、リストは`stdlib.h`の`malloc`を使って**ヒープ**上に構築します。`malloc`は要求されたバイト数を確保してそのアドレスを返し、メモリが足りなければ`NULL`を返します。1つのノードに必要な量は`sizeof(Node)`です:
```c
Node *node = malloc(sizeof(Node));
node->value = 5;
node->next = NULL;
```
ヒープのメモリは自動的には解放されません。`malloc`で取得したノードは、不要になった時点で必ず`free(node)`で返さなければなりません。これらの演習では`stdlib.h`がインクルードされ、`Node`はあなたのコードより上で宣言されています。

---

リストは、その最初のノードである**先頭**（head）への1本のポインタによって保持されます。他のノードはすべて、先頭から`next`をたどって到達します。アローは連ねて書けます: `head->next`は2番目のノード、`head->next->next`は3番目のノードです。空のリストとは`NULL`と等しい先頭のことであり、最後のノードの`next`も`NULL`です。そのため、アローを1つ余分にたどると`NULL`の参照外しが起き、プログラムがクラッシュします。

---

リストをたどること、いわゆる**走査**は、先頭から始めて`NULL`に達するまで`next`をたどるループです。`for`ループを使えば、ループ変数としてポインタを置いて1行で書けます:
```c
for (Node *n = head; n != NULL; n = n->next) {
    printf("%d\n", n->value);
}
```
インデックスは存在しません。ノードに到達する唯一の方法は、その前のノードに格納されたポインタを通ることです。

---

ノードを**先頭**に追加するには、ノードを作成し、現在の先頭を指すようにして、新しい先頭として返します。呼び出し側はその結果を先頭を保持する変数に格納し直します:
```c
Node *head = NULL;
head = push_front(head, 7);
head = push_front(head, 8); // the list is now 8, 7
```
空のリストへの追加も同じように動作します。新しいノードは`NULL`を指し、それがリスト全体になります。

---

リストの解放とは、すべてのノードを走査の1ステップずつで解放していくことです。`next`ポインタは、ノードを解放する**前に**保存しなければなりません。解放済みのノードは、その`next`であっても、もう読んではいけないからです:
```c
while (head != NULL) {
    Node *next = head->next;
    free(head);
    head = next;
}
```
`free(head)`の後に`head = head->next`と書くと、直前に解放されたメモリを読むことになり、これは未定義動作です。`free(NULL)`は許されており何もしません。そのため、空のリストに特別な対応は必要ありません。

---

リストはその長さを格納していません。走査で数えるしかありません。`while`形式のループはポインタを外側に置くため、ループ本体で他の変数を更新する場合に便利です:
```c
int count = 0;
Node *n = head;
while (n != NULL) {
    count++;
    n = n->next;
}
```
空のリストではループ本体は一度も実行されず、カウントは`0`のままです。

---

ノードを**末尾**に追加するには、`next`が`NULL`である最後のノードが必要です。関数はそれを見つけるまでたどり、そこに新しいノードを付け加え、変更されていない先頭を返します:
```c
Node *last = head;
while (last->next != NULL) {
    last = last->next;
}
last->next = node;
```
リストが空のときは、たどるべき最後のノードが存在しません。新しいノードがそのまま先頭として返されます。

---

リストの探索は、各値を比較して最初に一致したところで止まる走査です。関数は見つけたノードへのポインタを返し、一致のないままリストの終わりに達したときは`NULL`を返します:
```c
Node *found = find(head, 5);
if (found != NULL) {
    printf("%d\n", found->value);
}
```
値ではなくノードを返すことで、呼び出し側はそれを変更したり、別の操作の起点として使ったりできます。

---

`free(p)`の後も変数`p`は古いアドレスを保持し続けますが、それが指すメモリはもうあなたのものではありません。`p`は今や**ダングリングポインタ**です。それを通じた読み書きや、2回目の解放は未定義動作です。プログラムは古い値を出力したり、ゴミを出力したり、クラッシュしたりするかもしれませんが、コンパイラは警告しません。ポインタが`free`より後まで生き残る必要がある場合は、直後に`NULL`を設定してください。そうすれば、その後の使用は`NULL`チェックに引っかかります。

---

指定したノードの**後ろ**への挿入には走査は不要です。新しいノードが`node`の後続を引き継ぎ、次に`node`が新しいノードを指します:
```c
new_node->next = node->next;
node->next = new_node;
```
2つの代入の順序が重要です。先に`node->next`を設定すると、リストの残りへの唯一のポインタが上書きされ、それらのノードは失われてしまいます。最後のノードの後ろへの挿入も、その`next`が`NULL`なので機能します。

---

最初のノードの削除は`push_front`の鏡像です。2番目のノードのアドレスを保存し、最初のノードを解放し、保存したアドレスを新しい先頭として返します。呼び出し側はその結果を先頭を保持する変数に格納し直します:
```c
Node *next = head->next;
free(head);
return next;
```
先頭が`NULL`になるまで取り除くと、1回の呼び出しで1ノードずつ、リスト全体が解放されます。

---

リストの中間のノードの削除には、その**前**のノードが必要です。そのため走査は2つのポインタを保持します。すでに訪れたノードの`prev`と、調べているノードの`cur`です。`cur`が一致したら、`prev->next`にそのノードをスキップさせ、`cur`を解放します。一致が先頭そのものである場合、`prev`はまだ`NULL`であり、新しい先頭は`cur->next`です:
```c
if (prev == NULL) {
    head = cur->next;
} else {
    prev->next = cur->next;
}
free(cur);
```
一致するノードがないときは、リストは変更されずに返されます。

---

リストの反転は、3つのポインタですべての`next`ポインタをその場で逆向きにします。`prev`はすでに反転済みの部分、`head`は処理中のノード、`next`はリンクを変更する前に保存しておいたリストの残りのコピーです。各ステップで現在のノードを`prev`へ逆向きに指し、次に`prev`と`head`の両方を前へ進めます:
```c
Node *next = head->next;
head->next = prev;
prev = head;
head = next;
```
`head`が`NULL`に達したとき、すべてのリンクは逆向きになっており、`prev`が新しい先頭です。

---

リンクリストは、配列が苦手なところで安価であり、その逆もまた然りです。**先頭**への追加や削除は、長さが何であれ数回のポインタ代入で済みますが、配列ではすべての要素をずらさなければなりません。一方でノードは連続して配置されていないため、`list[i]`のようなものはありません。n番目のノード、最後のノード、全体の長さに到達するには、先頭から間にあるすべてのノードをたどる必要があります。追加を頻繁に行うプログラムは、そのたどりを避けるために、最後のノードを指す2つ目のポインタである**末尾**（tail）を保持することがよくあります。

---

まとめると、リストは配列から構築されることがよくあります。先頭への追加は順序を逆にするため、配列は最後の要素から最初の要素へと**後ろ向き**にたどられ、最初の要素が最終的に先頭に来ます。プログラムはその後、走査でリストを出力し、ノードごとに解放します。そうすることで、すべての`malloc`に対応する`free`が存在します。
