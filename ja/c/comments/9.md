# --description--

良いコメントは、コードが**何を**しているかではなく、**なぜ**そうしているかを説明します。コードは何が起きるかをすでに示しているので、それを言葉で繰り返すとノイズが増えるだけで、コードが変わった途端に古くなってしまいます:
```c
// price に 90 を掛けて 100 で割る
return price * 90 / 100;
```
読んだ人に推測できないのは、その数字の背後にある理由です:
```c
// 先行割引: 会員は6月末まで10%オフ
return price * 90 / 100;
```
コメントが下の行を言い換えているだけなら、削除するか、理由に置き換えましょう。
