**コメント**とは、コンパイラではなく人間のためにソースコード内に書かれるテキストです。コンパイラはプログラムをビルドする前にコメントを捨ててしまうので、コメントを使ってコードの目的を説明したり、メモを残したり、決定を記録したりできます。

最も一般的な種類は**1行コメント**です: `//`からその行の終わりまですべて無視されます。
```c
// Greet the user
printf("Hello\n");
```
プログラムを実行しても最初の行は何もしません。出力を生成するのは`printf`だけです。

---

コンパイラはコメントを完全に取り除くため、コメントを追加したり削除したりしてもプログラムの動作は変わりません。実行されるのはコメントされて**いない**コードだけです。

このため、`//`はコードを削除せずにその行を無効化する手軽な方法になります。これは**コメントアウト**と呼ばれます:
```c
int total = 10;
// total = total + 5;
printf("%d\n", total); // prints "10"
```
2行目は今やコメントなので、`total`は`10`のままです。`//`を取り除けば、その行は再び有効になります。

コメントアウトは実験している間は便利ですが、後片付けを忘れないでください: 長くコメントアウトされたままのコードは、次に読む人を混乱させるだけです。

---

コメントが複数行にわたるときは、Cの**複数行コメント**（ブロックコメントとも呼ばれます）が使えます: `/*`で始まり`*/`で終わり、改行を含む間のすべてが無視されます。
```c
/*
  Prints the welcome banner.
  Called once when the program starts.
*/
printf("Welcome!\n");
```
ブロックコメントは短くして1行に収めることもできます: `/* like this */`。

`//`が行の終わりで止まるのに対し、`/*`コメントは`*/`に到達するまで止まりません。閉じるのを忘れると、その後のすべてのコードがコメントの一部として扱われます。

---

ブロックコメントは**ネストしません**。コンパイラは、前にいくつ`/*`があっても、最初に見つけた`*/`で`/*`コメントを終了します:
```c
/* outer /* inner */ still code */
```
この例ではコメントは`inner`の直後に終わるので、`still code */`がコードとしてコンパイルされ、エラーになります。

これは、すでに`/* */`コメントを含むブロックをコメントアウトしたいときに問題になります: 内側の`*/`が外側のコメントを早く閉じてしまうからです。その場合は、代わりに各行の先頭に`//`を付けてください。

---

コメントは独立した行である必要はなく、同じ行のコードに続けて書くことができます。これは**行末コメント**と呼ばれ、その行の文についての短いメモを書くのに適した場所です:
```c
int retries = 3; // give up after three attempts
```
`//`も`/* */`も行末コメントとして使えますが、`/*`には注意してください: `*/`に到達するまで止まらないため、行末で閉じられていない`/*`はそれに続く行を飲み込み、プログラムはコンパイルできなくなります。

---

ブロックコメントの一般的な使い方の1つが**ヘッダーコメント**です: 関数の真上に置かれる短いブロックで、その関数が何をするか、パラメータが何を意味するか、何を返すかを説明します。
```c
/*
 * Returns the number of seconds in the given minutes.
 * minutes: a whole number of minutes, never negative
 */
int to_seconds(int minutes) {
    return minutes * 60;
}
```
`to_seconds`を呼び出す人は、本体を読む代わりにヘッダーを読めばよいことになります。一緒に更新されるよう、ヘッダーは関数のそばに置いておきましょう。

---

コンパイラはすべてのコメントを1つのスペースに置き換えます。つまり、`/* */`コメントはスペースを書ける場所ならどこにでも現れ、文や式の途中にあってもよいということです:
```c
int area = width /* cm */ * height /* cm */;
```
これは、オペランドや呼び出しの引数にラベルを付けるのにたまに役立ちます。`//`コメントにはこれができません。その後のコードを含む行の残り全部がコメントアウトされてしまうからです。

---

プログラマーは、終わっていない作業を示すために、コメントの先頭によく使われるキーワードをいくつか決めて使います:

- `TODO`は、まだ書く必要があるものを示します
- `FIXME`は、間違っていることが分かっていて修正が必要なコードを示します

```c
// TODO: validate the input before using it
// FIXME: crashes when the list is empty
```
エディタやツールはこれらのマーカーを一覧できるので、残っている作業を見つけやすくなります。作業が終わったらマーカーは削除しましょう: 古くなった`TODO`は誤解を招きます。

---

良いコメントは、コードが**何を**しているかではなく、**なぜ**そうしているかを説明します。コードは何が起きるかをすでに示しているので、それを言葉で繰り返すとノイズが増えるだけで、コードが変わった途端に古くなってしまいます:
```c
// multiply price by 90 and divide by 100
return price * 90 / 100;
```
読んだ人に推測できないのは、その数字の背後にある理由です:
```c
// launch discount: members get 10% off until the end of June
return price * 90 / 100;
```
コメントが下の行を言い換えているだけなら、削除するか、理由に置き換えましょう。

---

まとめましょう: 短いメモや行末コメントには`//`を、長いブロックやヘッダーコメントには`/* */`を使い、終わっていない作業には`TODO`や`FIXME`を付け、不要になったらコメントアウトされたコードや古いマーカーは取り除きます。
