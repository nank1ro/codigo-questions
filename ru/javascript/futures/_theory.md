Некоторые операции не заканчиваются мгновенно: скачивание файла, чтение из базы данных, ожидание таймера. JavaScript не замирает, пока они выполняются. Вместо этого он выдаёт вам **`Promise`**: объект, который представляет значение, которое станет доступным **позже**.

Функция, помеченная **`async`**, всегда возвращает промис. Всё, что возвращает такая функция, становится значением внутри этого промиса:
```javascript
async function fetchNumber() {
  return 42;
}
```
Чтобы извлечь значение из промиса, используют **`await`**. Он приостанавливает функцию, пока у промиса не появится значение, а затем отдаёт само значение. `await` разрешён только внутри `async` функции:
```javascript
async function main() {
  const n = await fetchNumber();
  console.log(n);
  // prints 42
}

main();
```
Без `await` переменная `n` была бы самим промисом, и `console.log(n)` вывел бы `Promise { 42 }` вместо числа.

---

Добавление `async` перед функцией меняет то, что она отдаёт: тело по-прежнему вычисляет обычное значение, но вызывающий код получает промис, обёрнутый вокруг него.
```javascript
function shout(text) {
  return text.toUpperCase();
}
async function shoutLater(text) {
  return text.toUpperCase();
}

console.log(shout("hi"));
// prints HI
console.log(shoutLater("hi"));
// prints Promise { 'HI' }
```
Обе функции содержат одинаковый код; отличается только способ чтения результата. Чтобы `shoutLater("hi")` отдала `"HI"`, её нужно подождать через `await` внутри другой `async` функции.

Пометка функции `async` ничего не стоит, когда ждать нечего, и именно она позволяет использовать `await` внутри неё позже.

---

Когда значение действительно приходит позже, вы создаёте промис сами с помощью **`new Promise`**. Он принимает одну функцию, которая получает колбэк **`resolve`**: вызовите `resolve(value)`, когда значение готово, и промис будет выполнен с ним.
```javascript
const soon = new Promise((resolve) => {
  setTimeout(() => resolve("done"), 1000);
});
```
`setTimeout(callback, ms)` планирует запуск `callback` через `ms` миллисекунд и возвращается сразу, так что в это время ничего не блокируется.

Функция, переданная в `new Promise`, выполняется сразу, но промис остаётся **в ожидании** (pending), пока не вызван `resolve`. Ожидание через `await` даёт значение:
```javascript
async function main() {
  console.log(await soon);
  // prints done, about one second later
}

main();
```

---

Промис всегда находится в одном из трёх состояний:

- **ожидание** (pending): работа ещё продолжается;
- **выполнен** (fulfilled): работа завершилась успешно, и промис содержит значение;
- **отклонён** (rejected): работа завершилась ошибкой, и промис содержит ошибку.

Промис начинается в ожидании и меняет состояние не более одного раза. После выполнения или отклонения он **завершён** (settled) и больше никогда не меняется.

Вызов `async` функции никогда не ждёт: она запускает работу и сразу выдаёт вам ожидающий промис, поэтому строка после вызова выполняется раньше, чем работа закончится. Этот промис — обычный объект, а не значение внутри него, поэтому забыть `await` — такая частая ошибка.

---

`await` — не единственный способ прочитать промис. У каждого промиса есть метод **`.then(callback)`**: колбэк получает значение, как только промис выполнен.
```javascript
Promise.resolve(21).then((n) => {
  console.log(n);
  // prints 21
});
```
**`Promise.resolve(value)`** создаёт промис, который уже выполнен со значением `value`; это удобно, когда значение уже есть под рукой, но вернуть нужно промис.

`.then` возвращает **новый** промис, выполненный с тем, что вернул колбэк, поэтому вызовы можно **объединять в цепочку**, где каждый шаг работает с результатом предыдущего:
```javascript
Promise.resolve(21)
  .then((n) => n * 2)
  .then((n) => console.log(n));
// prints 42
```

---

`async` функция читается сверху вниз, как любая другая функция: `await` просто приостанавливает её, пока ожидаемый промис не выполнится, а затем выполнение продолжается со следующей строки.
```javascript
async function main() {
  console.log("start");
  const value = await Promise.resolve("data");
  console.log(value);
  console.log("done");
}

main();
// prints start, then data, then done
```
Обратите внимание на последнюю строку: `async` функцию всё ещё нужно **вызвать**. Запись `main` без скобок определяет работу, но никогда её не запускает, и ничего не выводится.

---

Асинхронная работа тоже может завершиться неудачей. Функция, переданная в `new Promise`, получает второй колбэк, **`reject`**: вызовите `reject(error)`, и промис станет отклонённым вместо выполненного.
```javascript
function readAge(age) {
  return new Promise((resolve, reject) => {
    if (age >= 0) {
      resolve(age);
    } else {
      reject(new Error("negative age"));
    }
  });
}
```
Всегда отклоняйте промис объектом `Error`: он несёт `message` и стек вызовов, чего нет у простой строки.

Отклонение читается с помощью **`.catch(callback)`**, зеркального отражения `.then`. **`Promise.reject(error)`** создаёт уже отклонённый промис, так же как `Promise.resolve` создаёт выполненный:
```javascript
readAge(-1).catch((error) => {
  console.log(error.message);
  // prints negative age
});
```
Вызов и `resolve`, и `reject`, или вызов одного из них дважды, ничего не меняет: учитывается только первый вызов.

---

`.then`, `.catch` и `.finally` — звенья одной цепочки. Отклонение перескакивает каждый `.then`, пока не встретит `.catch`; как только колбэк `.catch` возвращает значение, цепочка снова становится выполненной и продолжает работать как обычно.

**`.finally(callback)`** выполняется, когда цепочка завершается, независимо от того, была ли она выполнена или отклонена. Его колбэк не принимает аргументов, и его возвращаемое значение игнорируется, поэтому значение продолжает течь к следующему `.then`. Это место для очистки, например для скрытия спиннера:
```javascript
Promise.reject(new Error("no network"))
  .then((value) => `ok: ${value}`)
  .catch((error) => `error: ${error.message}`)
  .finally(() => console.log("cleanup"))
  .then((message) => console.log(message));
// prints cleanup, then error: no network
```

---

Внутри `async` функции `.catch` не нужен. Ожидание отклонённого промиса через `await` **выбрасывает** ошибку, поэтому с ней справляется обычный оператор `try` / `catch` / `finally`:
```javascript
async function main() {
  try {
    const data = await load();
    console.log(data);
  } catch (error) {
    console.log(`failed: ${error.message}`);
  } finally {
    console.log("end");
  }
}
```
Работает и обратное направление: `throw` внутри `async` функции не ломает вызывающий код, а отклоняет промис, который вернула функция.
```javascript
async function risky() {
  throw new Error("boom");
}
// risky() returns a promise rejected with Error("boom")
```
Как и в любом блоке `try`, строки после неудачного `await` пропускаются, блок `catch` выполняется, а блок `finally` выполняется в обоих случаях.

---

Частое применение `try` / `catch` вокруг `await` — заменить сбой разумным значением по умолчанию, чтобы вызывающему коду никогда не пришлось иметь дело с ошибкой:
```javascript
async function sizeOf(path) {
  try {
    return await measure(path);
  } catch (error) {
    return 0;
  }
}
```
Сохраняйте `await` перед `measure(path)`, даже если значение возвращается сразу. Без него промис покинет функцию, так и не пройдя через блок `try`, и отклонение минует `catch`.

---

Когда нужны несколько результатов, ожидание их одного за другим тратит время впустую: каждый начинается только тогда, когда закончился предыдущий. **`Promise.all(promises)`** принимает массив уже запущенных промисов и возвращает один промис, выполненный с массивом всех их значений:
```javascript
const results = await Promise.all([fetchUser(), fetchOrders()]);
```
Два правила стоит запомнить:

- значения приходят **в порядке массива**, а не в порядке их завершения;
- если любой промис отклонён, промис, возвращённый `Promise.all`, немедленно отклоняется с этой первой ошибкой, а остальные значения теряются.

---

`Promise.all` работает с массивом любой длины, включая пустой: ожидание `Promise.all([])` сразу возвращает пустой массив. Это позволяет безопасно передавать список, построенный во время выполнения, без особого случая для «нечего ждать».
```javascript
const values = await Promise.all(items);
console.log(values.length === items.length);
// prints true
```
Возвращаемый массив всегда содержит ровно столько же элементов, сколько было в полученном массиве, на тех же позициях, поэтому его можно перебирать, как любой другой массив.

---

Разница между **последовательным** и **параллельным** ожиданием решается тем, *где* вы поставите `await`:
```javascript
// sequential: about 300 + 300 = 600 ms
const a = await load("a");
const b = await load("b");

// parallel: about 300 ms
const [a, b] = await Promise.all([load("a"), load("b")]);
```
В первой версии вторая загрузка начинается только после завершения первой, потому что `await` приостанавливает функцию на этой строке. Во второй оба вызова сделаны до того, как что-либо ожидается, поэтому обе загрузки уже идут, пока `Promise.all` ждёт.

Используйте последовательные `await`, только когда вторая задача действительно нуждается в результате первой. Иначе запускайте всё сразу, а ожидайте вместе.

---

`Promise.all` сдаётся, как только один из промисов отклонён. Когда вам всё равно нужны все результаты, используйте **`Promise.allSettled(promises)`**: он никогда не отклоняется, а выполняется с одним небольшим объектом на каждый промис, в том же порядке:

- `{ status: "fulfilled", value: ... }` для тех, что завершились успешно;
- `{ status: "rejected", reason: ... }` для тех, что завершились ошибкой.

```javascript
const results = await Promise.allSettled([
  Promise.resolve(1),
  Promise.reject(new Error("nope")),
]);
console.log(results[0].status);
// prints fulfilled
console.log(results[1].reason.message);
// prints nope
```
Читайте `value`, только когда `status` равен `"fulfilled"`, и `reason`, только когда он равен `"rejected"`: другое свойство просто отсутствует.

---

**`Promise.race(promises)`** завершается, как только завершится **первый** из промисов, и копирует его исход: выполнен с первым значением или отклонён с первой ошибкой. Остальные не отменяются, они продолжают работать, но всё, что они произведут, игнорируется.
```javascript
const winner = await Promise.race([slowServer(), fastServer()]);
```
Типичное применение — дедлайн: соревнуйте реальную работу с промисом, который падает через некоторое время, и вы получите либо результат, либо ошибку таймаута.

Будьте осторожны с пустым массивом: `Promise.race([])` навсегда остаётся в ожидании, потому что нечему его завершить.

---

Соединив последние кусочки вместе, получаем небольшой инструмент, который используется почти в каждом реальном приложении: дедлайн. Создайте промис, который отклоняется через `ms` миллисекунд, соревнуйте его с реальной работой, и тот, кто завершится первым, решает исход:
```javascript
const timer = new Promise((resolve, reject) => {
  setTimeout(() => reject(new Error("timeout")), ms);
});
return Promise.race([work, timer]);
```
Возвращать промис из `async` функции можно: промис, который отдаёт функция, следует за ним, поэтому вызывающий код ожидает итоговое значение, а не промис промиса.
