**Регулярное выражение** (или **regex**) — это небольшой шаблон, который описывает форму текста. С его помощью вы отвечаете на вопросы вроде «содержит ли эта строка число?» или «где встречается слово `cat`?».

В JavaScript самый короткий способ записать его — **regex-литерал**: шаблон между двумя косыми чертами.
```javascript
const pattern = /cat/;
```
Обычные символы в шаблоне соответствуют самим себе, поэтому `/cat/` соответствует трём буквам `c`, `a`, `t` в любом месте строки.

Самое простое, что можно сделать с шаблоном, — спросить, встречается ли он в строке. Метод **`test`** принимает текст и возвращает `true` или `false`:
```javascript
console.log(/cat/.test("the cat sleeps"));
// prints true
console.log(/cat/.test("the dog sleeps"));
// prints false
```
Обратите внимание: `test` ищет шаблон *где-то* в строке; вся строка целиком не обязана соответствовать.

---

Шаблоны становятся полезными, когда описывают *тип* символа, а не один конкретный символ. Несколько **escape-последовательностей** покрывают большинство потребностей:
- `\d` любая цифра, от `0` до `9`
- `\w` любой словесный символ: буква, цифра или `_`
- `\s` любой пробельный символ: пробел, табуляция, перевод строки

```javascript
console.log(/\d/.test("room 12"));
// prints true
console.log(/\d/.test("lobby"));
// prints false
```
**Квантификатор** говорит, сколько раз может повториться предыдущая часть. Самый распространённый — `+`, означающий «один или больше»:
```javascript
console.log(/\d+/.test("42"));
// prints true
```
Поэтому `/\d/` соответствует одной цифре, а `/\d+/` — последовательности цифр. Для обычного `test` оба ведут себя одинаково, потому что обоим достаточно наличия одной цифры.

---

Литерал вроде `/\d+/` зафиксирован в момент написания. Когда шаблон должен быть **построен во время выполнения**, используйте **конструктор `RegExp`**, который принимает шаблон в виде строки:
```javascript
const word = "cat";
const pattern = new RegExp(word);
console.log(pattern.test("the cat sleeps"));
// prints true
```
Есть одна ловушка. Внутри строки обратная косая черта начинает escape-последовательность для *строки*, поэтому она исчезает до того, как regex её увидит. Чтобы поместить настоящую обратную косую черту в шаблон, её нужно удвоить:
```javascript
const digits = new RegExp("\\d+");
// the same pattern as /\d+/
```
Запись `new RegExp("\d+")` вместо этого даёт шаблон `/d+/`, который соответствует букве `d`, а не цифре.

Предпочитайте литерал, когда шаблон известен уже при написании кода; он короче и не требует удвоенных обратных косых черт.

---

Ещё два строительных блока позволяют описать почти любую форму текста.

**Символьный класс** — это набор символов в квадратных скобках; он соответствует ровно одному из них. Дефис записывает диапазон, а `^` в начале инвертирует набор:
```javascript
/[aeiou]/   // one vowel
/[a-z]/     // one lowercase letter
/[A-Z0-9]/  // one uppercase letter or one digit
/[^0-9]/    // one character that is not a digit
```
**Квантификаторы** говорят, сколько раз повторяется предыдущая часть: `+` — один или больше, `*` — ноль или больше, `?` — ноль или один, а `{n}` — ровно `n` раз.

Наконец, **якоря** привязывают шаблон к краям текста: `^` означает «начинай здесь», а `$` — «заканчивай здесь». Без них шаблон может совпасть в любом месте строки, поэтому `/\d{2}/.test("abc12def")` — это `true`. С обоими якорями совпасть должна вся строка целиком:
```javascript
console.log(/^\d{2}$/.test("abc12def"));
// prints false
console.log(/^\d{2}$/.test("12"));
// prints true
```

---

`test` отвечает только «да» или «нет». Чтобы получить сам совпавший текст, вызовите **`match`** на строке:
```javascript
const match = "order 42 shipped".match(/\d+/);
```
Когда ничего не совпадает, `match` возвращает `null`. Когда что-то совпадает, он возвращает результат, похожий на массив:
- `match[0]` — совпавший текст
- `match.index` — позиция, с которой начинается совпадение
- `match.input` — вся строка, в которой выполнялся поиск

```javascript
console.log(match[0]);
// prints 42
console.log(match.index);
// prints 6
```
Поскольку результат может быть `null`, проверьте его, прежде чем читать `match[0]`.

---

Поскольку `match` возвращает `null`, когда шаблона нет, чтение `match[0]` сразу же выбрасывает `TypeError: Cannot read properties of null`. Защититесь от этого:
```javascript
function firstWord(text) {
  const match = text.match(/[a-z]+/);
  if (match === null) {
    return "";
  }
  return match[0];
}
```
Оператор нулевого слияния записывает ту же защиту в одну строку, потому что `match?.[0]` — это `undefined`, когда `match` равен `null`:
```javascript
return text.match(/[a-z]+/)?.[0] ?? "";
```

---

Круглые скобки вокруг части шаблона создают **группу захвата**: текст, которому эта часть соответствовала, откладывается в сторону, чтобы вы могли прочитать его обратно.

Группы появляются после `match[0]` и нумеруются слева направо по их открывающей скобке:
```javascript
const match = "2026-09-12".match(/(\d{4})-(\d{2})-(\d{2})/);
console.log(match[0]);
// prints 2026-09-12
console.log(match[1]);
// prints 2026
console.log(match[3]);
// prints 12
```
Поэтому `match[0]` — это всегда всё совпадение, а `match[1]`, `match[2]`, ... — группы. Группа, входящая в часть шаблона, которая вообще не совпадает, заставляет весь `match` вернуть `null`.

---

Захватывайте только то, что нужно. Группа — это не просто способ прочитать кусок обратно; она также подсказывает читателю, какая часть шаблона важна. В шаблоне времени, где вам нужны только минуты, сгруппируйте одни минуты и оставьте остальное без группировки:
```javascript
const minutes = "at 14:35:02".match(/\d{2}:(\d{2}):\d{2}/)?.[1];
console.log(minutes);
// prints 35
```
Весь шаблон всё равно должен совпасть, поэтому часы и секунды по-прежнему обязательны; они просто не захватываются. Меньше групп — меньше чисел, которые нужно держать в голове, когда вы читаете `match[1]`, `match[2]` и так далее.

---

Подсчитывать круглые скобки утомительно, а добавление группы в середину шаблона перенумеровывает всё, что после неё. **Именованная группа** избавляет от обеих проблем: напишите `?<name>` сразу после открывающей скобки и читайте кусок обратно из `match.groups`:
```javascript
const match = "2026-09-12".match(/(?<year>\d{4})-(?<month>\d{2})-\d{2}/);
console.log(match.groups.year);
// prints 2026
console.log(match.groups.month);
// prints 09
```
Именованные группы всё же нумеруются, поэтому `match[1]` продолжает работать, но `match.groups.year` говорит, что означает значение. Когда в шаблоне совсем нет именованных групп, `match.groups` — это `undefined`.

---

Всё, что было до сих пор, останавливалось на первом совпадении. **Флаги**, записываемые после закрывающей косой черты литерала, меняют это и другие детали поиска:
- `g` глобальный: находить каждое совпадение, а не только первое
- `i` игнорировать регистр, поэтому `/cat/i` соответствует также `Cat` и `CAT`

С флагом `g` `match` ведёт себя иначе: он возвращает простой массив совпавших **строк**, без `index` и без групп, или `null`, когда совпадений нет:
```javascript
const numbers = "a1 b22 c333".match(/\d+/g);
console.log(numbers);
// prints [ '1', '22', '333' ]
console.log(numbers.length);
// prints 3
```
Флаги можно комбинировать в любом порядке, как в `/cat/gi`. С конструктором `RegExp` они идут во втором аргументе: `new RegExp("\\d+", "g")`.

---

Флаг `g` даёт вам каждую совпавшую строку, но выбрасывает группы. Когда вам нужны группы *каждого* совпадения, используйте **`matchAll`**. Он возвращает итератор полных объектов совпадений, каждый из которых в точности похож на результат обычного `match`:
```javascript
const text = "a=1;b=2";
for (const match of text.matchAll(/(?<key>\w+)=(?<value>\w+)/g)) {
  console.log(`${match.groups.key} -> ${match.groups.value}`);
}
// prints a -> 1
// prints b -> 2
```
`matchAll` требует флаг `g`; без него он выбрасывает `TypeError`. Поскольку он возвращает итератор, разверните его через `[...text.matchAll(pattern)]`, когда вам нужен настоящий массив, и учтите, что он не выдаёт ничего вовсе, когда шаблон ни разу не совпадает.

---

**`replace`** возвращает новую строку, в которой совпадение заменено на что-то другое. Исходная строка никогда не меняется.
```javascript
console.log("the cat sleeps".replace(/cat/, "dog"));
// prints the dog sleeps
```
Внутри строки замены несколько последовательностей имеют особое значение:
- `$1`, `$2`, ... текст, захваченный группой 1, группой 2, ...
- `$<name>` текст, захваченный именованной группой
- `$&` всё совпадение

Именно это делает `replace` инструментом для переписывания, а не только замены:
```javascript
console.log("2026-09-12".replace(/(\d{4})-(\d{2})-(\d{2})/, "$3/$2/$1"));
// prints 12/09/2026
```
Без флага `g` заменяется только **первое** совпадение.

---

Чтобы переписать **каждое** совпадение вместо первого, у вас есть два варианта:
```javascript
console.log("a1 b2".replace(/\d/g, "#"));
// prints a# b#
console.log("a1 b2".replaceAll(/\d/g, "#"));
// prints a# b#
```
**`replaceAll`** — понятнее из двух, и он также принимает обычную строку в качестве шаблона. Когда вы даёте ему regex, этот regex **обязан** нести флаг `g`, иначе он выбрасывает `TypeError`; именно это останавливает тихую ошибку — написать `replace` и починить только первое совпадение.

---

Замена не обязана быть строкой. Когда вы передаёте **функцию**, она вызывается один раз для каждого совпадения, и всё, что она возвращает, вставляется на место этого совпадения.

Функция получает всё совпадение первым, а затем каждую группу захвата:
```javascript
console.log("hello world".replace(/\w+/g, (word) => word.length));
// prints 5 5

console.log("ann lee".replace(/(\w)(\w*)/g, (whole, first, rest) => first.toUpperCase() + rest));
// prints Ann Lee
```
Это единственный способ вычислить замену из совпавшего текста, чего одна `$1` сделать не может.

---

**`split`** разрезает строку в массив. Получив обычную строку, он режет по этому точному тексту, но получив regex, режет при каждом совпадении с шаблоном, что позволяет одному вызову обрабатывать различающиеся разделители:
```javascript
console.log("a, b;c".split(", "));
// prints [ 'a', 'b;c' ]
console.log("a, b;c".split(/[,;]\s*/));
// prints [ 'a', 'b', 'c' ]
```
Сами разделители не входят в результат. Остерегайтесь разделителя в начале или в конце строки: он даёт пустую строку в массиве, потому что с этой стороны находится пустое поле.

---

Последний флаг завершает набор. По умолчанию `^` и `$` означают начало и конец **всей строки**, поэтому шаблон, заякоренный через `^`, может совпасть только в самом начале, даже когда текст состоит из нескольких строк.

Флаг **`m`** (multiline) меняет это: `^` и `$` тогда также совпадают сразу после и прямо перед каждым переводом строки, поэтому каждая строка заякорена сама по себе:
```javascript
const text = "note a\nb\nnote c";
console.log(text.match(/^note.*/g));
// prints [ 'note a' ]
console.log(text.match(/^note.*/gm));
// prints [ 'note a', 'note c' ]
```
Здесь важны две детали. По умолчанию `.` не совпадает с переводом строки (это меняет только флаг `s`), поэтому `.*` сам останавливается в конце строки. А `match` с флагом `g` возвращает `null`, а не пустой массив, когда ничего не совпадает, так что объединяйте его с `?? []`, когда вы обещаете вернуть массив.
