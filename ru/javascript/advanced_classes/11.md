# --description--

Настоящая ценность сеттера в том, что он может отказать. Между присваиванием и сохранённым значением у вас есть возможность проверить, ограничить или отклонить поступившее значение:
```javascript
class Volume {
    constructor(level) {
        this._level = level;
    }
    get level() {
        return this._level;
    }
    set level(value) {
        if (value <= 10) {
            this._level = value;
        }
    }
}
const v = new Volume(3);
v.level = 50;
console.log(v.level);
// выводит 3, сеттер отклонил 50
```
Геттер и сеттер с одинаковым именем образуют одно свойство, поэтому оно не может быть ещё и обычным полем: сохранённое значение живёт под другим именем, по соглашению — под тем же именем с ведущим подчёркиванием.

# --asserts--

Геттер должен возвращать значение, переданное в конструктор.

```javascript
tryCatch(new Thermostat(20).temperature === 20);
```

Сеттер должен принимать допустимое значение.

```javascript
const t1 = new Thermostat(20);
t1.temperature = 25;
tryCatch(t1.temperature === 25);
```

Сеттер должен игнорировать отрицательное значение.

```javascript
const t2 = new Thermostat(20);
t2.temperature = -5;
tryCatch(t2.temperature === 20);
```

Сеттер должен принимать `0`.

```javascript
const t3 = new Thermostat(20);
t3.temperature = 0;
tryCatch(t3.temperature === 0);
```

Значение должно храниться в `_temperature`.

```javascript
tryCatch(new Thermostat(20)._temperature === 20);
```

class Thermostat {
  constructor(temperature) {
    this._temperature = temperature;
  }
  get temperature() {
    return this._temperature;
  }
  set temperature(value) {
    if (value >= 0) {
      this._temperature = value;
    }
  }
}
