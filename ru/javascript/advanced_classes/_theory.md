Вы уже знаете, что `extends` делает один класс дочерним по отношению к другому. То, что по-настоящему даёт это ключевое слово, — **наследование**: дочерний класс бесплатно получает каждое свойство и метод родителя и может добавлять поверх них свои собственные.

То, что делает наследование полезным, — это **`super`**. Внутри конструктора дочернего класса вызов `super(...)` вызывает родительский конструктор, чтобы родитель мог настроить ту часть объекта, которой владеет сам:
```javascript
class Animal {
    constructor(name) {
        this.name = name;
    }
}
class Dog extends Animal {
    constructor(name, breed) {
        super(name);
        this.breed = breed;
    }
}
```
Здесь `super(name)` передаёт `name` классу `Animal`, который его сохраняет, а `Dog` остаётся заботиться только о `breed`.

---

Дочернему классу не нужно заново определять то, что родитель уже предоставляет. Методы тоже наследуются, поэтому экземпляр дочернего класса может вызывать их, как будто это его собственные:
```javascript
class Animal {
    constructor(name) {
        this.name = name;
    }
    speak() {
        return `${this.name} makes a sound`;
    }
}
class Dog extends Animal {}
console.log(new Dog("Max").speak());
// выводит Max makes a sound
```
Когда дочерний класс объявляет собственный конструктор, вызвать в нём `super(...)` — **обязательно**: без этого объект никогда не будет инициализирован, и JavaScript выбросит `ReferenceError`. Дочерний класс вовсе без конструктора — это нормально, потому что JavaScript сам создаёт конструктор, который пересылает каждый аргумент родителю.

---

Правило насчёт `super()` строже, чем «вызови его где-нибудь». В конструкторе дочернего класса слово `this` не существует, пока не выполнится `super()`, потому что именно родительский конструктор создаёт объект. Обращение к `this` до этой строки приводит к ошибке:
```javascript
class Child extends Base {
    constructor() {
        this.x = 1; // ReferenceError
        super();
    }
}
```
Значит, `super(...)` должен быть **первой инструкцией** любого конструктора дочернего класса, который использует `this`.

---

Когда дочерний класс объявляет метод, который уже есть у родителя, побеждает версия дочернего класса. Это называется **переопределением**:
```javascript
class Animal {
    speak() {
        return "some sound";
    }
}
class Dog extends Animal {
    speak() {
        return "Woof";
    }
}
console.log(new Dog().speak());
// выводит Woof
```
Переопределение не удаляет родительскую версию, а лишь скрывает её. Внутри дочернего метода до неё по-прежнему можно добраться через `super.methodName(...)`, что позволяет расширить поведение родителя, а не заменить его:
```javascript
class Puppy extends Dog {
    speak() {
        return super.speak() + "!";
    }
}
console.log(new Puppy().speak());
// выводит Woof!
```
Обратите внимание на разницу: `super(...)` вызывает **конструктор** родителя, а `super.name(...)` — родительский **метод**.

---

До сих пор каждое свойство создавалось внутри конструктора. **Поле класса** позволяет объявить его прямо в теле класса, с необязательным начальным значением:
```javascript
class Counter {
    count = 0;
    step = 1;
}
console.log(new Counter().count);
// выводит 0
```
Поля присваиваются каждому новому экземпляру до выполнения тела конструктора, поэтому конструктор уже может на них рассчитывать. Поле без значения всё равно объявлено, просто начинается со значения `undefined`:
```javascript
class Task {
    done = false;
    title;
}
```
Обратите внимание на синтаксис: никаких `let`, `const` и `this` в объявлении, а строка заканчивается точкой с запятой.

---

Когда классы наследуют друг от друга, порядок имеет значение. Объявление `class` **не** поднимается вверх так, как это происходит с `function`: имя существует только начиная со строки, где класс написан. Поэтому дочерний класс должен идти *после* родителя, который он расширяет, иначе выражение `extends` завершится ошибкой `ReferenceError`.

---

Некоторое поведение принадлежит самому классу, а не отдельному экземпляру. Например, перевод из одних единиц в другие не нуждается в объекте. Пометка метода словом **`static`** помещает его на класс:
```javascript
class MathUtils {
    static double(n) {
        return n * 2;
    }
}
console.log(MathUtils.double(4));
// выводит 8
```
Статический метод вызывается по имени класса, но никогда на экземпляре: `new MathUtils().double(4)` выбрасывает `TypeError`, потому что экземпляры не получают статические члены. Внутри статического метода `this` указывает на класс, поэтому один статический метод может вызвать другой через `this.otherStatic(...)`.

---

`static` работает и с полями. **Статическое свойство** хранится один раз на классе, а не по одному на каждый экземпляр, что делает его естественным местом для общего счётчика или константы:
```javascript
class Circle {
    static PI = 3.14;
}
console.log(Circle.PI);
// выводит 3.14
```
Так как копия всего одна, каждый экземпляр, который её обновляет, изменяет одно и то же значение. Внутри конструктора до него добираются через имя класса, `Circle.PI`, а не через `this`: `this.PI` стал бы искать свойство на экземпляре, ничего не нашёл бы и вернул `undefined`.

---

Очень частое применение статического метода — **фабрика**: метод, который строит экземпляр из данных другой формы и возвращает его. Он держит `new` в одном месте и даёт созданию имя, которое говорит, что именно происходит:
```javascript
class Duration {
    constructor(seconds) {
        this.seconds = seconds;
    }
    static fromMinutes(minutes) {
        return new Duration(minutes * 60);
    }
}
console.log(Duration.fromMinutes(2).seconds);
// выводит 120
```
Фабрику можно вызвать ещё до того, как появится хоть один экземпляр, чего обычный метод не позволил бы.

---

**Геттер** — это метод, который читается как свойство. Напишите перед ним `get` и уберите круглые скобки в месте обращения:
```javascript
class Rectangle {
    constructor(width, height) {
        this.width = width;
        this.height = height;
    }
    get area() {
        return this.width * this.height;
    }
}
const r = new Rectangle(3, 4);
console.log(r.area);
// выводит 12
```
`r.area` выполняет метод и возвращает его результат, то есть число. Добавленные скобки попытались бы вызвать это число, что приведёт к ошибке.

Зеркальное отражение — **сеттер**, объявляемый через `set`, который выполняется при присваивании свойства. Он принимает ровно один параметр:
```javascript
set area(value) {
    this.width = value / this.height;
}
```

---

Настоящая ценность сеттера в том, что он может отказать. Между присваиванием и сохранённым значением у вас есть возможность проверить, ограничить или отклонить поступившее значение:
```javascript
class Volume {
    constructor(level) {
        this._level = level;
    }
    get level() {
        return this._level;
    }
    set level(value) {
        if (value <= 10) {
            this._level = value;
        }
    }
}
const v = new Volume(3);
v.level = 50;
console.log(v.level);
// выводит 3, сеттер отклонил 50
```
Геттер и сеттер с одинаковым именем образуют одно свойство, поэтому оно не может быть ещё и обычным полем: сохранённое значение живёт под другим именем, по соглашению — под тем же именем с ведущим подчёркиванием.

---

Ведущее подчёркивание в `_temperature` — всего лишь соглашение: ничто не мешает внешнему коду написать `v._level = 999` и пройти мимо вашего сеттера. **Приватное поле** обеспечивается самим языком. Его имя начинается с `#`, оно должно быть объявлено в теле класса, и читать или записывать его можно только изнутри этого класса:
```javascript
class Secret {
    #code = 1234;
    reveal() {
        return this.#code;
    }
}
const s = new Secret();
console.log(s.reveal());
// выводит 1234
console.log(s.#code);
// SyntaxError: the field is not accessible here
```
На двух деталях легко споткнуться. Символ `#` является частью имени, поэтому всегда пишут `this.#code`, но никогда `this.code`. И приватное поле не появляется ни в `Object.keys`, ни в выводе `console.log` для экземпляра.

---

Методы тоже могут быть приватными. Поставьте перед именем `#`, и метод исчезнет с публичной поверхности класса, оставаясь вызываемым из любого другого метода через `this.#name(...)`:
```javascript
class Receipt {
    #format(n) {
        return `$${n}`;
    }
    print(n) {
        return this.#format(n);
    }
}
console.log(new Receipt().print(7));
// выводит $7
```
Именно так вспомогательные шаги держат вне API: вызывающий код видит `print`, а не деталь форматирования за ним. Приватные поля и приватные методы вместе дают классу чёткое разделение на внутреннее и внешнее.

---

Вывод объекта обычно даёт что-то бесполезное. Всякий раз, когда JavaScript нужна строка, а получает он объект, вызывается метод объекта **`toString`**, и стандартный возвращает `[object Object]`. Собственное определение заменяет его:
```javascript
class Money {
    constructor(amount) {
        this.amount = amount;
    }
    toString() {
        return `$${this.amount}`;
    }
}
console.log(`${new Money(7)}`);
// выводит $7
```
Тот же метод используется при конкатенации строк и в `String(value)`. Если вам нужно ещё и осмысленное **число**, определите `[Symbol.toPrimitive](hint)`, который получает `"string"`, `"number"` или `"default"` и решает, что вернуть; если он есть, он побеждает `toString`.

---

Оператор **`instanceof`** спрашивает, был ли объект создан из класса или из любого класса, который от него наследует:
```javascript
class Animal {}
class Dog extends Animal {}
const max = new Dog();
console.log(max instanceof Dog);    // true
console.log(max instanceof Animal); // true, Dog extends Animal
```
В JavaScript нет ключевого слова `abstract`, но ту же идею пишут вручную: базовый класс задаёт форму, а каждый метод, который дочерний класс *обязан* предоставить, просто выбрасывает ошибку:
```javascript
class Shape {
    area() {
        throw new Error("area() must be implemented");
    }
}
```
Дочерний класс, забывший переопределить `area`, громко падает при первом же использовании, вместо того чтобы молча вернуть `undefined`.

---

`for...of` и оператор расширения `...` работают не с любым объектом: они работают с **итерируемыми** объектами, которые предоставляют метод, хранящийся под особым ключом `Symbol.iterator`. Дайте своему классу этот метод, и он вступит в клуб:
```javascript
class Playlist {
    constructor(songs) {
        this.songs = songs;
    }
    *[Symbol.iterator]() {
        for (const song of this.songs) {
            yield song;
        }
    }
}
const list = new Playlist(["a", "b"]);
console.log([...list]);
// выводит [ 'a', 'b' ]
```
Звёздочка `*` перед именем делает его **генератором**: функцией, которая выдаёт значения по одному через `yield` и приостанавливается между ними. Это самый короткий способ выполнить протокол итерации, и он работает для значений, которые вычисляются, а не хранятся.
