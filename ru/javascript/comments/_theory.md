**Комментарий** — это заметка внутри исходного кода для тех, кто его читает. JavaScript полностью игнорирует комментарии, поэтому они никогда не меняют то, что делает программа.

Самый простой комментарий — **однострочный**: он начинается с `//` и идёт до конца строки.
```javascript
// Greets the user
console.log("Hello");
```
Используйте комментарии, чтобы объяснить, для чего нужен фрагмент кода или почему он написан именно так. Обратите внимание: в отличие от некоторых других языков, `#` в JavaScript **не** начинает комментарий.

---

Комментарию не нужна отдельная строка: он может идти после кода в той же строке. Это **строчный комментарий** (или завершающий комментарий), и он хорошо подходит для короткой заметки об этой конкретной инструкции:
```javascript
const retries = 3; // give up after three attempts
```
Всё от `//` до конца строки игнорируется, а код перед ним выполняется как обычно.

---

Поскольку комментарии игнорируются, добавление или удаление комментария никогда не меняет то, что делает программа. Выполняется только тот код, который **не** закомментирован.

Благодаря этому `//` — быстрый способ отключить строку кода, не удаляя её. Это называется **закомментировать** код:
```javascript
let total = 10;
// total = total + 5;
console.log(total); // prints 10
```
Вторая строка теперь комментарий, поэтому `total` остаётся `10`. Если убрать `//`, строка снова оживёт.

Закомментировать код удобно, пока вы экспериментируете, но не забывайте убирать за собой: код, который надолго остаётся закомментированным, только сбивает с толку того, кто прочитает его следующим.

---

Когда комментарию нужно больше одной строки, JavaScript предлагает **многострочный комментарий** (его также называют блочным): он начинается с `/*` и заканчивается `*/`, а всё между ними игнорируется, включая переносы строк.
```javascript
/*
  Prints the welcome banner.
  Called once when the app starts.
*/
console.log("Welcome!");
```
Блочный комментарий может быть и коротким и умещаться в одну строку: `/* like this */`.

---

Каким бы ни был комментарий, правило одно: текст внутри него — **не код**. `console.log` внутри комментария никогда ничего не выводит, а код, написанный после `//` в той же строке, никогда не выполняется, даже если строка начинается с настоящего кода:
```javascript
console.log("a"); // console.log("b");
/* console.log("c"); */
// prints only a
```
Если вы не уверены, что выведет программа, мысленно удалите все комментарии и прочитайте то, что осталось.

---

В отличие от `//`, который заканчивается в конце строки, комментарий `/*` заканчивается только на `*/`. Если забыть его закрыть, JavaScript посчитает весь последующий код частью комментария и сообщит о синтаксической ошибке:
```javascript
const width = 10; /* in centimetres
console.log(width); // still inside the comment: SyntaxError, the comment is never closed
```
И `//`, и `/* */` работают как строчные комментарии, но с `/*` всегда убеждайтесь, что `*/` на месте.

---

Блочные комментарии в JavaScript **не могут быть вложенными**: комментарий заканчивается на **первом** встреченном `*/`, сколько бы `/*` ни было до него.
```javascript
/* outer /* inner */ still a comment */
console.log("done");
```
Здесь комментарий заканчивается сразу после `inner`, поэтому `still a comment */` читается как код и вызывает синтаксическую ошибку. Помните об этом, когда закомментируете блок, в котором уже есть комментарий `/* */`: используйте `//` в каждой строке или сначала уберите внутренний комментарий.

---

Чтобы закомментировать сразу несколько строк, оберните их в один блочный комментарий вместо того, чтобы добавлять `//` к каждой строке:
```javascript
let total = 100;
/*
total = total - 30;
total = total - 20;
*/
console.log(total); // prints 100
```
Так как строки внутри блока игнорируются, `total` никогда не меняется. Помните, что это работает только тогда, когда ни в одной из этих строк нет `*/`.

---

В JavaScript есть третий вид комментария — **документирующий комментарий**, написанный в формате **JSDoc**: блочный комментарий, который начинается с `/**` (две звёздочки) и располагается прямо над функцией. Внутри строки обычно начинаются с ` * `, а специальные **теги**, начинающиеся с `@`, описывают функцию:
- `@param {type} name description` для каждого параметра
- `@returns {type} description` для возвращаемого значения

```javascript
/**
 * Returns the greeting for a person.
 * @param {string} name the name of the person
 * @returns {string} the greeting, ending with an exclamation mark
 */
function greet(name) {
  return `Hi, ${name}!`;
}
```
Для JavaScript это просто комментарий, но редакторы читают его и показывают как подсказку для `greet`, вместе с типом в фигурных скобках (`{number}`, `{string}`, `{boolean}`, `{number[]}`...).

---

Первая строка комментария JSDoc — это **краткое описание**: короткое предложение о том, что делает функция. Пишите его в третьем лице, как будто описываете функцию: "Returns...", "Adds...", "Checks...". Затем перечислите теги, по одному в строке:
```javascript
/**
 * Returns true when n is divisible by two.
 * @param {number} n the number to check
 * @returns {boolean} true for even numbers, false otherwise
 */
function isEven(n) {
  return n % 2 === 0;
}
```
Комментарий должен стоять прямо над объявлением, без пустой строки между ними, иначе редакторы не свяжут его с функцией.

---

Комментарий JSDoc — это ещё и **контракт**: он сообщает тому, кто вызывает функцию, что передать и чего ожидать в ответ, ещё до того, как написано тело. Часто достаточно прочитать комментарий, чтобы реализовать функцию:
```javascript
/**
 * Returns the larger of two numbers.
 * @param {number} a the first number
 * @param {number} b the second number
 * @returns {number} a if it is greater than b, otherwise b
 */
function larger(a, b) {
  return a > b ? a : b;
}
```
Каждый `@param` соответствует одному параметру в том же порядке, а `@returns` описывает любой возможный результат.

---

Порядок внутри комментария JSDoc всегда один и тот же: сначала краткое описание, затем по одному `@param` на каждый параметр в порядке их объявления, и в конце `@returns`. Открывающее `/**` и закрывающее ` */` обрамляют всё это, а сам комментарий стоит прямо над функцией, которую описывает:
```javascript
/**
 * Returns the number of seconds in the given minutes.
 * @param {number} minutes a whole number of minutes
 * @returns {number} minutes multiplied by sixty
 */
function toSeconds(minutes) {
  return minutes * 60;
}
```

---

Файл JavaScript может начинаться со специальной строки, которая называется **шебанг** (или хешбанг): `#!` и затем путь к программе, которая должна запускать этот файл. В Unix-подобных системах это позволяет запускать скрипт прямо из терминала, например `./hello.js`, не набирая сначала `node`:
```javascript
#!/usr/bin/env node
console.log("Hello from Node");
```
JavaScript игнорирует эту строку точно так же, как комментарий, но только когда она — **самая первая строка** файла: в любом другом месте `#!` вызовет синтаксическую ошибку. `/usr/bin/env node` означает "найди `node` в этой системе и используй его".

---

Хороший комментарий объясняет, **почему** код что-то делает, а не **что** он делает. Код и так показывает, что происходит; повторение этого словами добавляет шум и устаревает, как только код меняется:
```javascript
// set timeout to 30
const timeout = 30;
```
Причина, стоящая за этим числом, — как раз то, о чём читатель не догадается:
```javascript
// the server drops idle connections after 35 seconds, so stop earlier
const timeout = 30;
```
Если комментарий лишь пересказывает строку под ним, удалите его или замените причиной.

---

Некоторые комментарии следуют соглашению, которое понимают редакторы. Самые распространённые **маркеры**:
- `// TODO: ...` отмечает то, что ещё предстоит написать
- `// FIXME: ...` отмечает код, о котором известно, что он неверен и должен быть исправлен

```javascript
const limit = 10;
// TODO: read the limit from the settings
// FIXME: crashes when the list is empty
```
Для JavaScript это обычные комментарии; редакторы собирают их в список, чтобы незавершённую работу было легко найти. `TODO` обычно стоит рядом с заглушкой, которая поддерживает работоспособность кода, пока не написана настоящая реализация. Когда вы завершите работу, замените заглушку и уберите маркер тем же изменением: устаревший `TODO` вводит в заблуждение.

---

`FIXME` отличается от `TODO`: код уже существует, но известно, что он неверен. Хороший `FIXME` говорит, в чём ошибка, и по возможности приводит пример, который её показывает, чтобы следующий человек мог быстро её исправить. Как и с `TODO`, удалите маркер, когда ошибка исправлена, но сохраните комментарий JSDoc, который по-прежнему верен.
