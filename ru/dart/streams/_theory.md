`Future` представляет **одно** значение, которое приходит позже. **Stream** представляет **последовательность** значений, приходящих со временем: нажатия клавиш, части файла, сообщения от сервера. Каждое значение называется **событием**, и после последнего события поток **завершён**.

Самый простой способ создать поток — `Stream.fromIterable`, который выдаёт каждый элемент списка, один за другим:

```dart
final numbers = Stream.fromIterable([1, 2, 3]);
```

Чтобы потреблять события по одному, используется цикл **`await for`**. Как и `await`, он разрешён только внутри функции, помеченной `async`, поэтому `main` становится `Future<void> main() async`. Тело цикла выполняется один раз на событие, и цикл заканчивается, когда поток завершён:

```dart
Future<void> main() async {
  final names = Stream.fromIterable(['Ada', 'Linus']);
  await for (final name in names) {
    print(name);
  }
  // Ada
  // Linus
}
```

Обычный цикл `for` здесь не работает: `Stream` — не `Iterable`, его значения недоступны все сразу.

---

`Stream.fromIterable` требует все значения заранее. Чтобы **производить** значения по одному, напиши **асинхронный генератор**: функцию, тело которой помечено `async*`, а возвращаемый тип — `Stream<T>`. Внутри неё `yield` отправляет одно событие в поток:

```dart
Stream<int> countTo(int n) async* {
  for (var i = 1; i <= n; i++) {
    yield i;
  }
}
```

Тело не выполняется, когда ты вызываешь `countTo(3)`: оно выполняется лениво, по мере того как слушатель запрашивает значения, и поток завершается, когда тело заканчивается.

Чтобы собрать все события в `List`, вызови `toList()`. Он возвращает `Future<List<T>>`, поэтому его нужно ждать через `await`:

```dart
final values = await countTo(3).toList();
print(values); // [1, 2, 3]
```

---

Цикл `await for` может не только выводить: он может обновлять переменную, объявленную до цикла. Функция, которая потребляет поток и вычисляет результат, должна быть помечена `async` и возвращает `Future` этого результата:

```dart
Future<int> count(Stream<String> words) async {
  var total = 0;
  await for (final word in words) {
    total += word.length;
  }
  return total;
}
```

Функция доходит до `return` только после того, как поток завершён, поэтому вызывающий получает итоговое значение, когда дожидается future:

```dart
print(await count(Stream.fromIterable(['hi', 'dart']))); // 6
```

---

Любой поток рано или поздно заканчивается. Для генератора `async*` поток **завершён**, как только заканчивается тело функции, независимо от того, дошло ли оно до конца или встретило `return`. Цикл `await for` по завершённому потоку выходит, а любой future от `toList()` выполняется.

Поток не начинается заново и не повторяет свои значения: раз завершившись, он остаётся завершённым.

---

`await for` приостанавливает текущую функцию, пока поток не завершён. Когда ты хочешь реагировать на события **не дожидаясь**, вызови `listen` и передай колбэк: он вызывается один раз на событие, а код после `listen` выполняется сразу же.

```dart
final ticks = Stream.fromIterable([1, 2]);
ticks.listen((tick) => print('tick $tick'));
print('not waiting');
// not waiting
// tick 1
// tick 2
```

`listen` также принимает именованный параметр `onDone` — функцию без аргументов, вызываемую, когда поток заканчивается:

```dart
final ticks2 = Stream.fromIterable([1, 2]);
ticks2.listen((tick) => print(tick), onDone: () => print('no more ticks'));
```

---

Генератор `async*` может передать дальше **каждое событие другого потока** с помощью `yield*` (yield-star). Это как цикл `await for`, который выдаёт каждое значение, но в одну строку:

```dart
Stream<int> ones() async* {
  yield 1;
  yield 1;
}

Stream<int> sequence() async* {
  yield 0;
  yield* ones();
  yield 2;
}
// sequence() emits 0, 1, 1, 2
```

Внешний поток продолжает своими `yield`, как только внутренний поток завершён.

---

Как и у `Iterable`, у `Stream` есть методы, которые строят **новый поток** из существующего:

- `map` преобразует каждое событие
- `where` оставляет только события, удовлетворяющие условию
- `take` останавливается после заданного числа событий

```dart
final numbers = Stream.fromIterable([1, 2, 3, 4, 5, 6]);
final firstOdds = numbers.where((n) => n.isOdd).take(2);
print(await firstOdds.toList()); // [1, 3]
```

Эти методы **ленивые**: ничего не выполняется, пока кто-нибудь не начнёт слушать получившийся поток. Их можно объединять в цепочку, а исходный поток никогда не изменяется.

---

Так как `where`, `map` и `take` каждый возвращают поток, их можно объединить в цепочку и закончить `toList()`, чтобы получить результат списком. Только финальный `toList()` требует `await`, потому что это единственный вызов, возвращающий `Future`:

```dart
final numbers = Stream.fromIterable([5, 12, 8, 20, 3]);
final big = await numbers.where((n) => n > 6).take(2).toList();
print(big); // [12, 8]
```

---

Кроме `toList()`, у потока есть и другие методы, которые **потребляют** все его события и возвращают один `Future`:

- `first` и `last` завершаются первым или последним событием
- `length` завершается количеством событий
- `join(separator)` завершается всеми событиями, соединёнными в одну `String`
- `reduce(combine)` объединяет события по два в одно значение

```dart
final numbers = Stream.fromIterable([3, 9, 2]);
print(await numbers.reduce((a, b) => a + b)); // 14
```

`reduce` вызывает `combine` с накопленным результатом и следующим событием. Он бросает исключение, если поток пуст, поэтому используй его только тогда, когда хотя бы одно событие гарантировано.

---

Методы `Stream` делятся на две группы:

- **преобразующие** методы, такие как `map`, `where`, `take` и `skip`, возвращают **новый `Stream`** и ленивы: ни одно событие не обрабатывается, пока новый поток не начнут слушать
- **потребляющие** методы, такие как `toList`, `reduce`, `join`, `first`, `last` и `length`, слушают поток и возвращают **`Future`** с итоговым результатом

Поэтому цепочка выглядит как ноль или больше преобразующих вызовов, за которыми следует не более одного потребляющего вызова.

---

Генераторы производят события внутри одной функции. Когда события приходят **откуда-то ещё** (от кнопки, из сетевого колбэка, от другого объекта), тебе нужен **`StreamController`**. Он живёт в библиотеке `dart:async`, поэтому файл должен начинаться с `import 'dart:async';`.

Контроллер владеет потоком и позволяет проталкивать в него события:

```dart
import 'dart:async';

Stream<int> dice() {
  final controller = StreamController<int>();
  controller.add(4);
  controller.add(2);
  controller.close();
  return controller.stream;
}
```

- `add(value)` отправляет одно событие
- `close()` завершает поток; забыть о нём — значит оставить слушателей ждать вечно
- `stream` — это `Stream`, который потребляют слушатели

События, добавленные до того, как кто-либо начал слушать, хранятся в буфере, поэтому код выше безопасен: слушатель, который придёт позже, всё равно получит `4` и `2`.

---

`StreamController` часто создаётся и потребляется в одном и том же месте: подписываешься на `controller.stream` через `listen`, затем добавляешь события через `add` и закрываешь контроллер через `close`. Так как `listen` не ждёт, события доставляются после того, как текущий код закончится, но всегда в том порядке, в котором были добавлены:

```dart
import 'dart:async';

void main() {
  final controller = StreamController<int>();
  controller.stream.listen((n) => print('got $n'));
  controller.add(1);
  controller.add(2);
  controller.close();
}
// got 1
// got 2
```

---

Все потоки, которые мы видели до сих пор, **односубскрипционные**: они допускают ровно одного слушателя. Второй вызов `listen`, `await for` или любого потребляющего метода бросает `StateError` ("Stream has already been listened to").

Чтобы разделить поток между несколькими слушателями, преобразуй его в **широковещательный** (broadcast) поток с помощью `asBroadcastStream()`:

```dart
final shared = Stream.fromIterable([1, 2, 3]).asBroadcastStream();
final total = shared.reduce((a, b) => a + b);
final count = shared.length;
print(await total); // 6
print(await count); // 3
```

Широковещательный поток не буферизует: слушатель получает только события, выданные **после** его подписки. В примере оба слушателя подписываются до первого `await`, поэтому оба получают каждое событие.

---

Контроллер может создать широковещательный поток напрямую, с помощью именованного конструктора `StreamController<T>.broadcast()`. Его `stream` принимает любое число слушателей, и каждое событие доставляется им всем, в порядке их подписки:

```dart
import 'dart:async';

void main() {
  final controller = StreamController<String>.broadcast();
  controller.stream.listen((msg) => print('first: $msg'));
  controller.stream.listen((msg) => print('second: $msg'));
  controller.add('hi');
  controller.close();
}
// first: hi
// second: hi
```

Как и любой широковещательный поток, он не буферизует: события, добавленные до того, как слушатель подписался, для него потеряны.

---

Поток может нести не только значения, но и **ошибки**. Внутри генератора `async*` `throw` отправляет событие ошибки и завершает поток; `StreamController` может отправить такое событие через `addError`.

На стороне потребителя цикл `await for` перебрасывает ошибку там, где находится цикл, поэтому её обрабатывают обычным `try`/`catch` вокруг цикла:

```dart
Stream<int> risky() async* {
  yield 1;
  throw StateError('sensor offline');
}

Future<void> main() async {
  try {
    await for (final n in risky()) {
      print(n);
    }
  } catch (e) {
    print('caught: $e');
  }
}
// 1
// caught: Bad state: sensor offline
```

С `listen` вместо этого передай колбэк `onError`: `stream.listen(print, onError: (e) => print('caught: $e'));`
