Вы уже умеете добавлять методы в класс, который написали сами. Но что насчёт `String`, `int` или `List`, чей код находится в Dart SDK? Изменить их нельзя, однако нередко хочется, чтобы у них был ещё один метод.

**Расширение** решает эту задачу: оно добавляет новые члены в **существующий** тип, не затрагивая его исходный код и не создавая подкласс. Синтаксис такой:

```dart
extension ExtensionName on Type {
  // new methods and getters
}
```

Внутри расширения `this` ссылается на значение, у которого вызван член. Как только расширение объявлено, его члены вызываются точно так же, как собственные члены типа:

```dart
extension Greeting on String {
  String greet() => 'Hello, $this!';
}

void main() {
  var name = 'Ada';
  print(name.greet()); // Hello, Ada!
}
```

Расширения объявляются на **верхнем уровне** файла, рядом с классами и функциями, но никогда внутри `main`.

---

Расширения работают с любыми типами, включая числа. Это расширение даёт каждому `int` метод, удваивающий его:

```dart
extension Doubling on int {
  int doubled() => this * 2;
}
```

Поскольку расширение применяется к **типу**, метод можно вызвать и на переменной, и непосредственно на **литерале**. Отрицательным литералам нужны скобки, иначе точка читается раньше знака минус:

```dart
var n = 21;
print(n.doubled());    // 42
print(4.doubled());    // 8
print((-3).doubled()); // -6
```

---

Расширение может также объявлять **геттеры**, которые читаются как свойства, без скобок. Внутри расширения можно вызывать собственные члены типа напрямую: `this.` необязателен, точно как внутри класса.

```dart
extension Sizes on String {
  bool get isLong => length > 10;      // same as this.length
  String get firstChar => this[0];
}

void main() {
  print('Dart'.isLong);           // false
  print('extension'.firstChar);   // e
}
```

Выбирайте геттер, когда член только **читает** значение и не принимает параметров; выбирайте метод, когда он выполняет работу или требует аргументов.

---

Тип после `on` может быть **параметризованным** типом, например `List<int>`. Такое расширение применяется только к спискам этого типа элементов: `[1, 2].total()` работает, а `['a', 'b'].total()` не компилируется.

```dart
extension Totals on List<int> {
  int total() {
    var sum = 0;
    for (final n in this) {
      sum += n;
    }
    return sum;
  }
}
```

Внутри расширения `this` — это список, поэтому можно перебирать его элементы, обращаться по индексу или вызывать `length` как обычно.

---

Расширение на `List<int>` нельзя применить к `List<String>`. Чтобы написать одно расширение, работающее с **любым** типом элементов, задайте расширению **параметр типа**, записываемый в угловых скобках после его имени, и используйте его в типе после `on`:

```dart
extension Firsts<T> on List<T> {
  T get firstOrLast => length > 1 ? this[0] : this[length - 1];
}
```

`T` — это заполнитель для «какого бы ни был тип элементов»: на `List<int>` он становится `int`, на `List<String>` — `String`, поэтому геттер выше возвращает `int` или `String` в зависимости от ситуации. Компилятор подставляет `T` за вас при каждом вызове.

```dart
print([7, 8, 9].firstOrLast); // 7
print(['a', 'b'].firstOrLast); // a
```

---

Расширение на `String` нельзя вызвать у `String?`: значение может быть `null`, и компилятор отклонит вызов. Если же объявить расширение на **nullable**-типе, метод можно вызвать у `String?` напрямую, а внутри него `this` имеет тип `String?`, поэтому случай `null` нужно обработать самостоятельно, например с помощью `??`:

```dart
extension Defaults on int? {
  int orZero() => this ?? 0;
}

void main() {
  int? count = null;
  print(count.orZero()); // 0
  print(5.orZero());     // 5
}
```

Non-nullable `int` можно передать туда, где ожидается `int?`, поэтому расширение работает с обоими.

---

Расширение может добавлять методы, геттеры, сеттеры и операторы, но оно **не может добавлять поля экземпляра**. Значение `int` имеет фиксированное расположение в памяти, а расширение — это лишь набор функций, которые компилятор позволяет вызывать с помощью точки: места для хранения дополнительных данных у каждого значения нет.

```dart
extension Counter on int {
  int count = 0; // error: extensions can't declare instance fields
}
```

Геттеры и сеттеры в расширении могут только вычислять значения из `this` или переадресовывать вызовы существующим членам: они не могут ничего запоминать между вызовами.

---

Расширение может объявлять **статические** члены. Как и в классе, они принадлежат самому расширению, а не какому-либо значению, и доступ к ним осуществляется через **имя расширения**, а не через расширяемый тип:

```dart
extension Temperatures on double {
  static const double boiling = 100.0;

  static bool isBoiling(double celsius) => celsius >= boiling;
}

void main() {
  print(Temperatures.boiling);         // 100.0
  print(Temperatures.isBoiling(37.5)); // false
  print(double.boiling);               // error: 'boiling' isn't defined for 'double'
}
```

Статические члены — удобное место для констант и вспомогательных функций, связанных с расширяемым типом.

---

Расширения нужны не только для типов SDK: можно расширять и **собственные классы**. Это полезно, когда класс приходит из пакета, который вы не контролируете, или когда вы хотите оставить класс небольшим и добавить необязательные помощники рядом с кодом, которому они нужны.

```dart
class Circle {
  final double radius;
  Circle(this.radius);
}

extension CircleMath on Circle {
  double get diameter => radius * 2;
}

void main() {
  print(Circle(3).diameter); // 6.0
}
```

Расширение видит публичные поля и методы класса, точно как код, написанный вне класса.

---

В Dart тип может определить, что означают операторы вроде `+`, `*` или `==` для своих значений, с помощью метода, имя которого — ключевое слово `operator`, за которым следует символ. Правый операнд оператора — это параметр метода:

```dart
extension Scaling on List<int> {
  List<int> operator *(int factor) => map((n) => n * factor).toList();
}

void main() {
  print([1, 2, 3] * 10); // [10, 20, 30]
}
```

Поскольку расширения могут объявлять операторы, вы можете дать существующему типу новый оператор, которого у него ещё нет. У `String` есть `+` и `*`, но нет `-`, поэтому расширение может определить, что означает `'hello world' - 'o'`.

---

Что если расширение объявляет член, который у типа **уже есть**? Собственный член типа всегда побеждает: члены расширения рассматриваются только тогда, когда у самого типа нет члена с таким именем. Член расширения молча игнорируется — ни ошибки, ни переопределения.

```dart
extension Shorter on String {
  int get length => 0;
}

void main() {
  print('four'.length); // 4, String's own length is used
}
```

Поэтому расширение может добавлять члены и заполнять пробелы, но оно никогда не сможет **изменить** поведение существующих членов.

---

Имя расширения необязательно. **Безымянное** расширение работает так же, но оно видно только в файле, который его объявляет:

```dart
extension on int {
  bool get isTriple => this % 3 == 0;
}
```

**Имя** становится важным, как только два расширения предлагают один и тот же член для одного и того же типа: вызов становится **неоднозначным** и не компилируется. Имя позволяет разрешить конфликт двумя способами. Когда расширения приходят из разных файлов, одно из них можно `show` или `hide` в импорте:

```dart
import 'package:loud/loud.dart';
import 'package:quiet/quiet.dart' hide Quiet;
```

Или, в любом месте, можно применить расширение **явно**, обернув значение в имя расширения, как будто это конструктор:

```dart
print(Loud('hi').describe());
```

Безымянные расширения нельзя скрыть или применить явно, поэтому в коде, который будут импортировать другие, предпочитайте именованные расширения.

---

Обобщённое расширение может принимать **функции** в качестве параметров, точно как это делают `where` и `map`. Тип функции записывается с типом элементов `T`, поэтому колбэк получает элементы правильного типа:

```dart
extension Checks<T> on List<T> {
  bool all(bool Function(T) test) {
    for (final item in this) {
      if (!test(item)) return false;
    }
    return true;
  }
}

void main() {
  print([2, 4, 6].all((n) => n.isEven)); // true
}
```
