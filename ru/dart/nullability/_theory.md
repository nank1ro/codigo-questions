Вы уже знаете, как объявить переменную с типом, например `String name = 'Ada';`. Но иногда значение просто **отсутствует**: пользователь без псевдонима, поиск, который ничего не нашёл, текст, который нельзя превратить в число. Dart представляет отсутствующее значение с помощью `null`.

Начиная с Dart 2.12 в языке есть **строгая null-безопасность**: обычный тип вроде `String` **никогда** не может содержать `null`. Попытка присвоить его — ошибка компиляции, поэтому программа даже не запустится:

```dart
String name = null; // error: a value of type 'Null' can't be assigned to 'String'
```

Чтобы разрешить отсутствующее значение, добавьте знак вопроса `?` после типа. `String?` содержит либо `String`, либо `null`, а вывод `null` показывает слово `null`:

```dart
String? nickname = null;
print(nickname); // null

nickname = 'Ada';
print(nickname); // Ada
```

Типы без `?` называются **non-nullable**, типы с `?` — **nullable**.

---

Nullable-переменная, объявленная **без значения**, начинается с `null`, поэтому `= null` можно опустить:

```dart
int? age;
print(age); // null
```

У non-nullable переменной такого значения по умолчанию нет: Dart отказывается компилировать любой код, который читает её до присваивания значения.

```dart
int count;
print(count); // error: 'count' must be assigned before it can be used
```

---

Вызов метода или чтение свойства у `null` привело бы к аварийному завершению, поэтому Dart не позволяет делать это у nullable-значения через обычную точку:

```dart
String? text;
print(text.length); // error: the property 'length' can't be unconditionally accessed
```

Оператор **null-безопасного доступа** `?.` решает эту проблему: если значение равно `null`, всё выражение равно `null` и больше ничего не вычисляется, иначе он работает как обычная `.`:

```dart
String? text = 'Dart';
print(text?.length); // 4

text = null;
print(text?.length); // null
```

Поскольку результат может быть `null`, его тип nullable: `text?.length` — это `int?`, а не `int`.

---

Часто отсутствующее значение нужно заменить **значением по умолчанию**. Оператор **if-null** `??` возвращает левый операнд, когда он не `null`, и правый в противном случае:

```dart
String? nickname;
print(nickname ?? 'anonymous'); // anonymous

nickname = 'Ada';
print(nickname ?? 'anonymous'); // Ada
```

`??` реагирует только на `null`: пустая строка `''` или число `0` — настоящие значения, поэтому они сохраняются.

`??` хорошо сочетается с `?.`, потому что `?.` даёт nullable-результат:

```dart
String? text;
print(text?.length ?? 0); // 0
```

---

Главное преимущество null-безопасности в том, что большинство ошибок с `null` находит **компилятор**, а не ваши пользователи. Правила, изученные до сих пор:

- non-nullable тип (`String`, `int`, `List<int>`...) никогда не может быть `null`
- nullable тип (`String?`, `int?`, `List<int>?`...) может и начинается с `null`, если объявлен без значения
- `.` у nullable-значения не компилируется: используйте `?.` или задайте значение по умолчанию через `??`

---

Оператор **присваивания if-null** `??=` присваивает переменной значение **только если** эта переменная сейчас равна `null`; иначе он оставляет её нетронутой:

```dart
int? retries;
retries ??= 3;
print(retries); // 3

retries ??= 10;
print(retries); // 3, it already had a value
```

Он также работает с элементами map, которые являются nullable, потому что ключа может не быть:

```dart
var stock = {'apple': 4};
stock['pear'] ??= 1;  // added
stock['apple'] ??= 9; // ignored
print(stock); // {apple: 4, pear: 1}
```

---

Иногда **вы** знаете, что nullable-значение в определённой точке не равно `null`, даже если компилятор этого понять не может. Оператор **null assertion** `!` превращает `String?` в `String`, обещая, что значение присутствует:

```dart
String? text = 'Dart';
String sure = text!;
print(sure.length); // 4
```

Будьте осторожны: `!` переносит проверку с времени компиляции на время выполнения. Если значение **всё же** равно `null`, программа выбрасывает ошибку и останавливается:

```dart
String? text;
print(text!.length); // Null check operator used on a null value
```

Используйте `!` умеренно и только тогда, когда `null` в этом месте в любом случае был бы ошибкой.

---

Запомните разницу между тремя операторами, которые вы видели для nullable-значения:

- `?.` возвращает `null`, когда значение равно `null`, и никогда не выбрасывает ошибку
- `??` заменяет `null` значением по умолчанию
- `!` предполагает, что значение присутствует, и **выбрасывает ошибку во время выполнения**, когда его нет

Ни один из них не является ошибкой компиляции: компилятор доверяет вашему `!`, и только работающая программа может обнаружить, что обещание нарушено.

---

Проверять nullable-значение через `if` безопаснее, чем через `!`, и Dart вас за это вознаграждает. После проверки вида `if (x != null)` компилятор знает, что внутри блока `x` не может быть `null`, поэтому считает `x` там non-nullable. Это называется **продвижением типа**:

```dart
int twice(int? n) {
  if (n != null) {
    return n * 2; // here n is an int, no ! needed
  }
  return 0;
}
```

Продвижение работает и после раннего возврата:

```dart
int twice(int? n) {
  if (n == null) return 0;
  return n * 2; // n is an int from here on
}
```

Продвижение применяется к **локальным переменным и параметрам**, значение которых не может измениться за вашей спиной между проверкой и использованием.

---

Продвижение типа **не** работает для **поля** класса, которое может быть изменено извне, потому что между проверкой и использованием другой участок кода (геттер, переопределённый в подклассе, другой метод) может снова установить его в `null`:

```dart
class Box {
  int? value;

  int doubled() {
    if (value != null) {
      return value * 2; // error: 'value' can't be unconditionally accessed
    }
    return 0;
  }
}
```

Стандартное решение — скопировать поле в **локальную переменную**, которая продвигается:

```dart
int doubled() {
  final v = value;
  if (v != null) {
    return v * 2;
  }
  return 0;
}
```

---

Non-nullable поле обычно должно получить значение в конструкторе. Когда значение становится известно только **позже** (после чтения файла, открытия соединения...), можно пометить поле как `late`: компилятор примет отсутствие инициализатора и поверит, что вы присвоите полю значение до его чтения.

```dart
class Connection {
  late String host;

  void open() {
    host = 'example.com';
  }
}
```

Чтение поля `late`, которому ещё не присвоено значение, выбрасывает `LateInitializationError` во время выполнения. Как и `!`, `late` меняет гарантию времени компиляции на проверку во время выполнения, так что это обещание, которое нужно сдержать.

`late` можно также сочетать с инициализатором, который тогда выполняется **лениво**, при первом чтении переменной:

```dart
late String report = buildReport(); // buildReport() runs only when report is used
```

---

Nullability влияет на то, как вы объявляете **именованные параметры**. Именованный параметр с nullable-типом является необязательным: если вызывающий его опустит, он просто будет `null`.

```dart
String label({String? title}) => title ?? 'untitled';

print(label());               // untitled
print(label(title: 'Notes')); // Notes
```

Именованный параметр с non-nullable типом и без значения по умолчанию не имел бы значения при пропуске, поэтому Dart требует пометить его как `required`; тогда вызывающий обязан всегда его передавать:

```dart
String label({required String name, String? title}) { ... }

label(name: 'Ada');               // ok
label(name: 'Ada', title: 'Dr.'); // ok
label(title: 'Dr.');              // error: the named parameter 'name' is required
```

---

Nullability относится и к **элементам** коллекции. `List<int>` никогда не содержит `null`, а `List<int?>` может:

```dart
List<int?> scores = [7, null, 9];
```

Обратите внимание на отличие от `List<int>?` — это список, который сам может отсутствовать, но, когда он есть, содержит только настоящие числа.

Чтобы избавиться от элементов `null`, `nonNulls` возвращает `Iterable` только с присутствующими значениями, типизированный без `?`:

```dart
var present = scores.nonNulls.toList(); // List<int>
print(present); // [7, 9]
```

`whereType<int>()` делает то же самое и работает также, когда список смешивает несколько типов.

---

Многие библиотечные функции используют `null`, чтобы сообщить, что что-то **не удалось сделать**. Преобразование строки в число — классический пример: `int.parse` выбрасывает `FormatException`, когда текст не является числом, а `int.tryParse` вместо этого возвращает `null` и позволяет вам решить, что делать:

```dart
print(int.tryParse('42'));  // 42
print(int.tryParse('4x2')); // null
print(int.tryParse(''));    // null
```

Возвращаемый тип `int.tryParse` — `int?`, поэтому всё изученное применимо: `??` для значения по умолчанию, `?.` для цепочки вызовов и проверка `if` для продвижения. `double.tryParse` работает так же.

---

Ещё у двух операторов есть null-безопасный вариант.

**Null-безопасный каскад** `?..` выполняет цепочку каскадных операций только тогда, когда объект не равен `null`, и пропускает их все в противном случае:

```dart
List<int>? numbers;
numbers?..add(1)..add(2); // nothing happens, numbers is still null
```

**Null-безопасный спред** `...?` вставляет элементы nullable-коллекции в литерал, не добавляя ничего, когда коллекция равна `null`:

```dart
List<int>? extra;
print([0, ...?extra]); // [0]

extra = [1, 2];
print([0, ...?extra]); // [0, 1, 2]
```

Без `?` запись `...extra` для `List<int>?` была бы ошибкой компиляции.

---

Реальные данные полны пробелов: незаполненное поле формы, отсутствующий столбец в файле, строка, которая не совсем число. Инструменты этой главы естественно сочетаются для работы с ними: `nonNulls`, чтобы отбросить отсутствующие элементы, `int.tryParse`, чтобы безопасно преобразовать, и `??` или проверка `if`, чтобы разобраться с тем, что преобразовать не удалось.
