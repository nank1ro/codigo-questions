# --description--

Исключение, брошенное внутри изолята, не может перепрыгнуть в другой: у них отдельные стеки. `Isolate.run` перекрывает этот разрыв за тебя, перехватывая ошибку, копируя её обратно и заставляя возвращённый future завершиться этой ошибкой. Поэтому на твоей стороне это обычная асинхронная ошибка, которую ловят `try`/`catch` вокруг `await`:

```dart
Future<int> parseInIsolate(String text) async {
  try {
    return await Isolate.run(() => int.parse(text));
  } catch (e) {
    return -1;
  }
}
```

`await` внутри `try` важен, точно так же, как с любым другим future: без него future покинул бы блок `try` незавершённым, и `catch` никогда бы не выполнился.

С `Isolate.spawn` такого моста нет. Неперехваченная ошибка молча убивает запущенный изолят, а родитель продолжает ждать сообщение, которое никогда не придёт, — это ещё одна причина сначала обращаться к `Isolate.run`.

# --instructions--

Напиши функцию `safeDivide`, которая принимает два `int` `a` и `b` и возвращает `Future<int>`: она вычисляет `a ~/ b` на другом изоляте с помощью `Isolate.run` и завершается значением `-1`, если вычисление бросает исключение.

Пример:
```dart
print(await safeDivide(10, 2)); // 5
print(await safeDivide(7, 0));  // -1
```
