Каждая написанная тобой строка Dart выполняется внутри **изолята**: потока со своей памятью и своим циклом событий. Программа стартует с одного изолята — *главного* — и может запустить ещё.

Особенность изолятов в том, что они не разделяют **ничего**. Два изолята никогда не видят один и тот же объект, поэтому нет ни блокировок, ни гонок данных, ни наполовину обновлённых значений. Они общаются друг с другом только передавая **копии** сообщений.

Самый короткий способ задействовать второй изолят — **`Isolate.run`**. Он принимает функцию, запускает её на совершенно новом изоляте и возвращает `Future` с её результатом:

```dart
import 'dart:isolate';

Future<void> main() async {
  final total = await Isolate.run(() => 21 * 2);
  print(total); // 42
}
```

`Isolate` живёт в библиотеке `dart:isolate`, поэтому файл должен начинаться с `import 'dart:isolate';`. Пока новый изолят вычисляет, главный изолят остаётся свободным: это настоящий **параллелизм**, работа выполняется на другом процессорном ядре.

---

Функция, которую ты передаёшь в `Isolate.run`, может **захватывать** переменные из окружения. Эти значения копируются в новый изолят вместе с функцией, поэтому вычисление может зависеть от вызывающего кода:

```dart
Future<int> triple(int n) {
  return Isolate.run(() => n * 3);
}
```

`Isolate.run` возвращает `Future` с тем, что возвращает функция, поэтому `triple` может просто вернуть его: ни `async`, ни `await` не нужны, когда ты просто пробрасываешь future дальше.

Смысл переноса работы в другой изолят в том, что долгие вычисления больше не замораживают главный. Цикл, работающий секунду, блокирует всё, пока он выполняется на главном изоляте; внутри `Isolate.run` он выполняется в другом месте, а главный изолят продолжает обрабатывать свои события.

---

Между изолятами копируются только **данные**; **код** — нет. Каждый изолят программы и так видит все функции верхнего уровня и классы этой программы, поэтому вычисление, переданное в `Isolate.run`, может свободно вызывать их:

```dart
int slowLength(String text) => text.length;

Future<int> lengthInIsolate(String text) {
  return Isolate.run(() => slowLength(text));
}
```

В пути находятся захваченный `text` на входе и результирующий `int` на выходе, каждый — копия. Схема всегда одна и та же: оставь тяжёлую функцию там, где она есть, и оберни **вызов** в `Isolate.run`.

---

`await` и `Isolate.run` решают две разные задачи, и их стоит различать.

`await` даёт **конкурентность** на одном изоляте: пока одна функция ждёт таймер или сервер, изолят выполняет другой ожидающий код. Ничего не выполняется в один и тот же момент, изолят просто перестаёт простаивать. Это правильный инструмент для ожидания.

`Isolate.run` даёт **параллелизм**: второй изолят на втором процессорном ядре, выполняющий свой код в тот же момент, что и первый. Это правильный инструмент для вычислений.

```dart
await Future.delayed(const Duration(seconds: 1)); // waiting: no core is busy
await Isolate.run(() => hugeCalculation());       // computing: another core is busy
```

Ожидание медленного вычисления через `await` совсем не помогает: `await bigSum()` всё равно выполняет `bigSum` на текущем изоляте и блокирует его до последней строки. Только второй изолят уносит эту работу прочь.

---

`Isolate.run` — это короткий путь для получения одного результата. Когда тебе нужен изолят, который продолжает работать и сообщает о себе больше одного раза, запусти его сам с помощью **`Isolate.spawn`** и дай ему способ ответить.

Этот способ — пара портов. **`ReceivePort`** — это почтовый ящик: ты создаёшь его на своей стороне и читаешь приходящие сообщения. Его **`sendPort`** — адрес этого ящика, и это единственное, что нужно другому изоляту, чтобы ответить.

```dart
import 'dart:isolate';

void sayHello(SendPort port) {
  port.send('hi');
}

Future<void> main() async {
  final receivePort = ReceivePort();
  await Isolate.spawn(sayHello, receivePort.sendPort);
  final message = await receivePort.first;
  print(message); // hi
}
```

`Isolate.spawn` принимает функцию для запуска и единственное сообщение, которое ей передаётся, — здесь это `SendPort`. На той стороне `send` кладёт значение в почтовый ящик, а `await receivePort.first` ждёт первое сообщение и закрывает порт.

---

Функция, передаваемая в `Isolate.spawn`, называется **точкой входа**. Это должна быть функция верхнего уровня (или статическая), принимающая ровно один параметр: сообщение, которое ей передаёт `Isolate.spawn`.

```dart
void reportAnswer(SendPort port) {
  port.send(42);
}
```

Сообщения, приходящие в `ReceivePort`, имеют статический тип `dynamic`, потому что отправить могли любое значение. Когда ты знаешь, что отправляет другой изолят, приведи тип:

```dart
final receivePort = ReceivePort();
await Isolate.spawn(reportAnswer, receivePort.sendPort);
final answer = await receivePort.first as int;
```

---

Запущенный изолят всегда проходит одни и те же четыре шага: открыть почтовый ящик, запустить работника с его адресом, дождаться ответа, использовать его.

```dart
import 'dart:isolate';

void worker(SendPort port) {
  port.send('done');
}

Future<void> main() async {
  final receivePort = ReceivePort();
  await Isolate.spawn(worker, receivePort.sendPort);
  print(await receivePort.first);
}
```

`await` перед `Isolate.spawn` ждёт *запуска* изолята, а не завершения его работы: результат приходит позже, через порт.

---

`Isolate.spawn` передаёт ровно **одно** сообщение в точку входа, а работнику обычно нужны и `SendPort` для ответа, и какие-то данные для работы. Обычный приём — упаковать всё в один `List` и распаковать на той стороне:

```dart
void multiply(List<Object> message) {
  final port = message[0] as SendPort;
  final value = message[1] as int;
  port.send(value * 2);
}

Future<void> main() async {
  final receivePort = ReceivePort();
  await Isolate.spawn(multiply, <Object>[receivePort.sendPort, 21]);
  print(await receivePort.first); // 42
}
```

Список копируется на входе, поэтому работник читает свои собственные значения. `SendPort` — одна из немногих вещей, которые не копируются, а разделяются: он продолжает указывать на почтовый ящик изолята, который его создал, и именно поэтому его можно использовать как обратный адрес.

---

`first` читает одно сообщение и закрывает почтовый ящик. `ReceivePort` — это ещё и **`Stream`**, поэтому чтобы прочитать много сообщений, перебирай его циклом `await for`.

Цикл сам по себе никогда не заканчивается: порт остаётся открытым в ожидании сообщения, которое может никогда не прийти. Поэтому работник отправляет последнее значение как сигнал, часто `null`, а слушатель реагирует вызовом **`close()`**, который завершает поток и цикл:

```dart
import 'dart:isolate';

void countdown(SendPort port) {
  port.send(3);
  port.send(2);
  port.send(1);
  port.send(null);
}

Future<void> main() async {
  final receivePort = ReceivePort();
  await Isolate.spawn(countdown, receivePort.sendPort);
  await for (final message in receivePort) {
    if (message == null) {
      receivePort.close();
    } else {
      print(message);
    }
  }
  print('done');
}
```

---

Сбор целой серии сообщений следует одному рецепту: пустой список перед циклом, один `add` на каждое настоящее сообщение и `close()` на сигнале, завершающем поток. Когда порт закрыт, `await for` заканчивается, и функция может вернуть значение:

```dart
Future<List<int>> collect(ReceivePort port) async {
  final values = <int>[];
  await for (final message in port) {
    if (message == null) {
      port.close();
    } else {
      values.add(message as int);
    }
  }
  return values;
}
```

Сообщения сохраняют порядок, в котором были отправлены, поэтому собранный список шаг за шагом повторяет работу другого изолята.

---

Открытый `ReceivePort` считается незавершённой работой: пока он существует, изолят-владелец имеет повод оставаться живым, и его цикл событий продолжает ждать сообщение. В консольной программе главный изолят с открытым портом просто **никогда не завершается**, и остановить его нужно вручную.

Поэтому закрытие порта — часть работы, а не оптимизация:

- `await port.first` закрывает его сам после одного сообщения
- `port.close()` закрывает его явно, что и нужно после цикла `await for`

У `Isolate.run` нет всей этой бухгалтерии: он создаёт порты, закрывает их и выключает изолят за тебя. Предпочитай его, когда нужен всего один результат.

---

Исключение, брошенное внутри изолята, не может перепрыгнуть в другой: у них отдельные стеки. `Isolate.run` перекрывает этот разрыв за тебя, перехватывая ошибку, копируя её обратно и заставляя возвращённый future завершиться этой ошибкой. Поэтому на твоей стороне это обычная асинхронная ошибка, которую ловят `try`/`catch` вокруг `await`:

```dart
Future<int> parseInIsolate(String text) async {
  try {
    return await Isolate.run(() => int.parse(text));
  } catch (e) {
    return -1;
  }
}
```

`await` внутри `try` важен, точно так же, как с любым другим future: без него future покинул бы блок `try` незавершённым, и `catch` никогда бы не выполнился.

С `Isolate.spawn` такого моста нет. Неперехваченная ошибка молча убивает запущенный изолят, а родитель продолжает ждать сообщение, которое никогда не придёт, — это ещё одна причина сначала обращаться к `Isolate.run`.

---

Ошибка, приходящая обратно от `Isolate.run`, — это **копия** той, что брошена на той стороне, поэтому обычные проверки по-прежнему работают: `catch (e)` даёт объект, а `e is FormatException` говорит, какого рода это был сбой.

```dart
try {
  await Isolate.run(() => int.parse('abc'));
} on FormatException {
  print('not a number');
}
```

Полагаться нельзя на трассировку стека, указывающую в твой собственный изолят: ошибка путешествовала, стек — нет.

---

Если собрать всё вместе, программа с `Isolate.run` читается как обычный последовательный код: строка перед вызовом выполняется на главном изоляте, вычисление выполняется в другом месте, а строка после `await` снова выполняется на главном изоляте, уже с результатом на руках.

```dart
import 'dart:isolate';

int twice(int n) => n * 2;

Future<void> main() async {
  print('start');
  final result = await Isolate.run(() => twice(4));
  print(result);
}
// start
// 8
```

---

Поскольку изоляты не разделяют память, каждое сообщение **копируется** при переходе. Числа, булевы значения, строки, `null`, списки, отображения и большинство простых объектов могут совершить это путешествие; некоторые вещи вообще нельзя скопировать, например открытый сокет, и попытка отправить такой объект бросает `ArgumentError`.

Следствие — правило, которое делает изоляты безопасными: после отправки обе стороны держат **два независимых объекта**. Что бы один изолят ни делал со своей копией, для другого это невидимо.

```dart
final numbers = [1, 2, 3];
await Isolate.run(() => numbers..add(4)); // the copy grows
print(numbers);                           // [1, 2, 3]
```

`SendPort` — исключение, подтверждающее правило: он разделяется, а не копируется, именно чтобы продолжать указывать на исходный почтовый ящик.

---

Каждый `Isolate.run` запускает свой собственный изолят, поэтому несколько из них действительно выполняются в один и тот же момент, на стольких ядрах, сколько есть у машины. Схема та, которую ты уже знаешь по future: сначала запусти каждое вычисление, затем дождись их всех с помощью `Future.wait`, который сохраняет результаты в порядке входных данных.

```dart
Future<List<int>> doubleAll(List<int> numbers) {
  return Future.wait(numbers.map((n) => Isolate.run(() => n * 2)));
}
```

Запуск изолята не бесплатен: он стоит памяти и нескольких миллисекунд. Разделение одного долгого вычисления между горсткой изолятов окупается, а отправка тысячи тривиальных сложений тысяче изолятов — нет.
