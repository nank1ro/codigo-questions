# --description--

Разница проявляется, как только вы используете значение. У `Box<int?>` вы обращаетесь к полю как обычно, а затем разбираетесь с `null` внутри него, а у `Box<int>?` сначала нужно преодолеть отсутствие самой коробки:

```dart
Box<int?> a = Box(null);
print(a.value ?? 0); // 0, коробка есть, её содержимое — null

Box<int>? b = null;
print(b?.value ?? 0); // 0, самой коробки нет
```

Запись `b.value` у `Box<int>?` вообще не компилируется: Dart отказывается читать поле того, чего может не существовать.

# --instructions--

Дано `Box<int?> a = Box(null);` и `Box<int>? b = null;`. Какое утверждение верно?

# --answers--

- `a` — настоящая коробка, чей `value` равен `null`, а `b` — вовсе не коробка
- Оба объявления означают одно и то же, `?` можно писать с любой стороны
- `a` не компилируется, потому что аргумент типа никогда не может допускать null
- `b` — коробка, хранящая `null`, а `a` — вовсе не коробка
