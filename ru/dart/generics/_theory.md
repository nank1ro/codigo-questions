`List` хранит не просто значения, а значения **одного типа**. Тип указывается в угловых скобках сразу после имени коллекции:

```dart
List<String> names = ['Ada', 'Grace'];
List<int> scores = [10, 20];
```

`String` и `int` здесь — это **аргументы типа**, а тип, который их принимает, называется **обобщённым**. Класс списка написан один раз, а `List<String>` и `List<int>` — два разных типа, полученных из него.

Преимущество в том, что компилятор знает, что находится внутри:

```dart
names.add(42);          // error: 42 is not a String
print(names.first.toUpperCase()); // fine: first is a String
```

---

`List` — не единственная обобщённая коллекция. `Set` принимает один аргумент типа, а `Map` — **два**: один для ключей и один для значений, именно в таком порядке.

```dart
Set<String> tags = {'new', 'sale'};
Map<String, int> ages = {'Ada': 36, 'Grace': 45};
```

Тип пустого литерала коллекции нельзя вывести из его содержимого, поэтому аргументы типа указывают на самом литерале:

```dart
final counts = <String, int>{};
final seen = <String>{};
counts['fig'] = 3;
```

Когда типы известны, всё, что вы извлекаете из коллекции, уже имеет нужный тип: `ages['Ada']` — это `int?`, а не загадочное значение.

---

В Dart есть ещё тип `dynamic`, который означает «можно всё что угодно». `List<dynamic>` принимает любые значения, поэтому выглядит удобнее, чем `List<String>`:

```dart
List<dynamic> things = ['Ada', 'Grace'];
things.add(42);                    // accepted
print(things.first.toUpperCase()); // accepted
```

Загвоздка в том, что ничего не проверяется, пока вы пишете код. Каждый вызов на значении `dynamic` разрешается во время работы программы, поэтому опечатка вроде `things.first.toUpperCse()` спокойно компилируется и приводит к падению перед глазами пользователя.

Дженерики — альтернатива этому: один фрагмент кода работает с **любым** типом, при этом каждое его использование всё равно проверяется на соответствие **одному** типу. В этом и есть суть всей темы.

---

Вы не ограничены обобщёнными классами, которые поставляются вместе с Dart: можно объявлять свои. **Параметр типа** записывается в угловых скобках после имени класса, а дальше внутри тела это обычный тип:

```dart
class Box<T> {
  final T value;

  Box(this.value);

  T unwrap() => value;
}
```

`T` — это лишь заполнитель. Он подставляется при создании `Box` — явно или с помощью выведения типов:

```dart
final a = Box<int>(7);   // Box<int>
final b = Box('fig');    // Box<String>, inferred from the argument
print(a.value + 1);      // 8, the compiler knows value is an int
```

Конкретная буква не важна: `T` — лишь соглашение для «type», и не более того.

---

Функция может быть обобщённой сама по себе, не находясь в обобщённом классе. Параметр типа указывается между именем и списком параметров:

```dart
T firstOf<T>(List<T> items) => items.first;

print(firstOf(['fig', 'kiwi'])); // fig, T is String here
print(firstOf([10, 20]));        // 10, T is int here
```

Одно тело функции, проверенное один раз, переиспользуется для каждого типа. Аргумент типа обычно выводится из аргументов, но его можно указать явно, когда выведению не на что опереться:

```dart
final empty = firstOf<String>(<String>[]); // throws, but the type is clear
```

Методы внутри класса следуют ровно тому же правилу.

---

Внутри обобщённого класса параметр типа виден везде: в полях, параметрах конструктора, сигнатурах методов и телах методов. Он объявляется один раз рядом с именем класса, и каждый член может его использовать.

```dart
class Holder<T> {
  final T item;

  Holder(this.item);

  String describe() => 'holding $item';
}
```

Тип определяет момент создания объекта: `Holder<String>('fig')` делает `item` строкой `String`, а `Holder<int>(3)` — числом `int`.

---

Класс может объявлять более одного параметра типа, разделяя их запятыми. `Map<K, V>` — встроенный пример: один тип для ключей, один для значений.

```dart
class Entry<K, V> {
  final K key;
  final V value;

  Entry(this.key, this.value);
}

final e = Entry<String, int>('age', 30);
```

**Порядок** является частью типа: `Entry<String, int>` и `Entry<int, String>` — никак не связанные типы, и значение одного нельзя присвоить другому. Параметры типа можно также переставлять в возвращаемом типе, благодаря чему метод может вернуть перевёрнутую версию объекта:

```dart
Entry<V, K> get flipped => Entry(value, key);
```

---

При надёжной null safety вопросительный знак может стоять в двух разных местах, и означают они разное:

```dart
Box<int?> a = Box(null); // a box that exists and holds a nullable int
Box<int>? b = null;      // no box at all, but if there is one it holds an int
```

В `Box<int?>` допускает null **аргумент типа**, поэтому `a.value` имеет тип `int?` и может быть `null`, тогда как сама `a` всегда существует. В `Box<int>?` допускает null **переменная**, поэтому `b` может быть `null`, и чтобы добраться до её содержимого, нужны `b?.value` или `b!.value`.

Простой `T` означает `T extends Object?`, поэтому допускающий null аргумент типа, такой как в `Box<int?>`, совершенно допустим.

---

Разница проявляется, как только вы используете значение. У `Box<int?>` вы обращаетесь к полю как обычно, а затем разбираетесь с `null` внутри него, а у `Box<int>?` сначала нужно преодолеть отсутствие самой коробки:

```dart
Box<int?> a = Box(null);
print(a.value ?? 0); // 0, the box is there, its content is null

Box<int>? b = null;
print(b?.value ?? 0); // 0, the box itself is missing
```

Запись `b.value` у `Box<int>?` вообще не компилируется: Dart отказывается читать поле того, чего может не существовать.

---

Неограниченный `T` может быть чем угодно, поэтому внутри тела разрешено использовать только то, что есть у каждого объекта. Такой код не компилируется:

```dart
T twice<T>(T value) => value + value; // error: + is not defined for T
```

Это исправляет **ограничение** (bound). Запись `T extends num` говорит: «`T` может быть только числом», а взамен тело может использовать всё, что предлагает `num`:

```dart
T twice<T extends num>(T value) => (value + value) as T;

num half<T extends num>(T value) => value / 2;
```

Ограничение проверяется в месте вызова: `half(4)` и `half(2.5)` допустимы, а `half('fig')` — ошибка компиляции. Ограничение — это обещание в обе стороны: более узкие аргументы в обмен на больше возможностей внутри.

---

Ключевым словом для ограничения всегда служит `extends`, даже когда ограничение — интерфейс, а не суперкласс. В списке параметров типа нет `implements`.

```dart
num biggerOf<T extends num>(T a, T b) => a > b ? a : b;
```

Без ограничения `a > b` не скомпилировалось бы: оператор сравнения принадлежит `num`, а не каждому объекту.

---

Ограничение может упоминать сам параметр типа. `Comparable<T>` — интерфейс всего, что умеет сравнивать себя с себе подобными с помощью `compareTo`:

```dart
print('fig'.compareTo('kiwi')); // negative: fig comes first
print('kiwi'.compareTo('fig')); // positive
print('fig'.compareTo('fig'));  // zero
```

Поэтому `T extends Comparable<T>` читается как «любой тип, который можно сравнить с самим собой» — именно это нужно функции сортировки или поиска максимума:

```dart
T maxOf<T extends Comparable<T>>(T a, T b) => a.compareTo(b) >= 0 ? a : b;

print(maxOf('fig', 'kiwi')); // kiwi
```

`String` и `DateTime` удовлетворяют ему напрямую. `int` и `double` реализуют `Comparable<num>`, поэтому список чисел просто сравнивается как `num`.

---

То же ограничение отлично работает и для наименьшего элемента: меняется только знак сравнения. `compareTo` возвращает отрицательное число, когда получатель идёт первым, поэтому `item.compareTo(best) < 0` означает «этот элемент меньше».

---

Обобщённый класс может иметь именованные и **фабричные** конструкторы, как любой другой класс, и параметр типа доступен внутри них. Фабричный конструктор сам не создаёт объект: он выполняет тело и возвращает объект, что позволяет выбирать, переиспользовать или собирать экземпляр любым способом.

```dart
class Box<T> {
  final T value;

  Box(this.value);

  factory Box.first(List<T> items) => Box(items.first);
}

final b = Box<int>.first([5, 6]);
print(b.value); // 5
```

Аргумент типа указывается у класса, а не у имени конструктора: `Box<int>.first(...)`. Внутри фабрики `<T>[]` — это настоящий пустой `List<T>`, поэтому фабрика — естественное место для создания значения по умолчанию для ещё неизвестного вам типа.

---

Параметр типа, записанный без ограничения, вовсе не является неограниченным: `class Box<T>` — это сокращение для `class Box<T extends Object?>`. Именно поэтому принимается `Box<int?>`, и именно поэтому внутри класса нельзя никогда полагаться на то, что `value` не null.

Чтобы запретить допускающие null аргументы типа, ограничьте параметр через `Object`:

```dart
class Strict<T extends Object> {
  final T value;
  Strict(this.value);
}

final ok = Strict<int>(7);
final bad = Strict<int?>(null);
// error: Type argument 'int?' doesn't conform to the bound 'Object'
```

`Object` — тип всего, кроме `null`, поэтому `T extends Object` читается как «что угодно, лишь бы это действительно было там».

---

`typedef` даёт имя типу и может иметь собственные параметры типа. Обычно это нужно, чтобы один раз назвать семейство функциональных типов, а не выписывать его при каждом использовании:

```dart
typedef Transform<I, O> = O Function(I input);

final Transform<String, int> length = (word) => word.length;
print(length('kiwi')); // 4
```

`Transform<String, int>` — просто другой способ записи `int Function(String)`, поэтому они взаимозаменяемы. Выигрыш — читаемость: параметр, объявленный как `Transform<I, O> transform`, говорит, для чего функция, а `O Function(I)` — только то, как она выглядит.

Обобщённый typedef и обобщённая функция естественно сочетаются: собственные параметры типа функции заполняют параметры typedef.
