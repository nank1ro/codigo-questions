# --description--

`map` и `where` **ленивы**: их вызов ничего не вычисляет. Они возвращают `Iterable`, который запоминает источник и функцию, а сама функция вызывается только когда кто-то проходит по результату, элемент за элементом.

```dart
final numbers = [1, 2, 3];
final doubled = numbers.map((n) => n * 2); // пока ничего не вычислено
print(doubled.first);                      // вычисляет только 2
```

`toList()` — то, что **материализует** последовательность: она проходит её от начала до конца и сохраняет каждый результат в настоящий `List`.

У ленивости есть два следствия, которые стоит запомнить. Ленивый `Iterable` вычисляется заново при каждом проходе по нему, поэтому однократная материализация с помощью `toList()` выгоднее, когда значения нужны больше одного раза. И он продолжает смотреть на исходную коллекцию, поэтому изменение этой коллекции меняет то, что выдаёт `Iterable`:

```dart
final numbers = [1, 2, 3];
final lazy = numbers.map((n) => n * 2);
final eager = numbers.map((n) => n * 2).toList();
numbers.add(4);
print(lazy.toList()); // [2, 4, 6, 8]
print(eager);         // [2, 4, 6]
```

# --instructions--

Что выводит `print([1, 2, 3].map((n) => n * 2));` и почему?

# --answers--

- `(2, 4, 6)`, потому что `map` возвращает `Iterable`, а `Iterable` выводится в круглых скобках
- `[2, 4, 6]`, потому что `map` возвращает новый `List`
- `[1, 2, 3]`, потому что `map` никогда не изменяет исходные элементы
- Ничего не выводится, потому что ленивый `Iterable` выдаёт значения только после вызова `toList()`
