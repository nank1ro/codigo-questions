**Метод высшего порядка** — это метод, принимающий функцию в качестве аргумента. Коллекции Dart предлагают множество таких методов, а передаваемая функция обычно является анонимной функцией, записанной со стрелочным синтаксисом `(x) => ...`.

`map` — самый распространённый из них: он вызывает функцию для каждого элемента и выдаёт результаты, по одному на каждый элемент, не изменяя исходную коллекцию:

```dart
final numbers = [1, 2, 3];
print(numbers.map((n) => n * 2)); // (2, 4, 6)
print(numbers);                   // [1, 2, 3]
```

Обратите внимание на **круглые скобки** в выводе. `map` не возвращает `List`: он возвращает `Iterable` — последовательность, которую можно пройти. Чтобы получить настоящий список, вызовите на нём **`toList()`**:

```dart
final doubled = numbers.map((n) => n * 2).toList();
print(doubled); // [2, 4, 6]
```

Квадратные скобки в выводе — признак того, что перед вами `List`, круглые — что перед вами обычный `Iterable`.

---

`where` принимает функцию, возвращающую `bool` — она называется **предикатом**, — и оставляет только те элементы, для которых она отвечает `true`. Порядок оставшихся элементов никогда не меняется:

```dart
final numbers = [4, -2, 7, 0];
print(numbers.where((n) => n > 0).toList()); // [4, 7]
```

Как и `map`, `where` возвращает `Iterable` и никогда не изменяет исходную коллекцию, поэтому `toList()` снова превращает результат в `List`.

В других языках этот метод называется `filter`; в Dart это `where`.

---

Функция, передаваемая в `map`, не обязана возвращать тот же тип, что и получаемые элементы. Преобразование списка строк в их длины превращает `List<String>` в `Iterable<int>`, который `toList()` затем делает `List<int>`:

```dart
final words = ['fig', 'kiwi'];
print(words.map((w) => w.length).toList()); // [3, 4]
```

Результат всегда содержит **ровно столько же элементов, сколько в исходном**, в том же порядке: `map` преобразует элементы, но никогда не добавляет и не удаляет их.

---

Некоторые методы высшего порядка отвечают на вопрос о коллекции, а не строят новую. Они принимают предикат и возвращают `bool`:

- `any` равен `true`, когда **хотя бы один** элемент удовлетворяет предикату
- `every` равен `true`, когда **все** элементы удовлетворяют ему

```dart
final numbers = [1, 2, 3];
print(numbers.any((n) => n > 2));   // true
print(numbers.every((n) => n > 2)); // false
```

Оба останавливаются, как только ответ становится известен: `any` — на первом подходящем элементе, `every` — на первом неподходящем.

На пустой коллекции `any` равен `false`, а `every` равен `true`: нет элемента, который доказал бы первое, и нет элемента, который нарушил бы второе.

---

`map` и `where` **ленивы**: их вызов ничего не вычисляет. Они возвращают `Iterable`, который запоминает источник и функцию, а сама функция вызывается только когда кто-то проходит по результату, элемент за элементом.

```dart
final numbers = [1, 2, 3];
final doubled = numbers.map((n) => n * 2); // пока ничего не вычислено
print(doubled.first);                      // вычисляет только 2
```

`toList()` — то, что **материализует** последовательность: она проходит её от начала до конца и сохраняет каждый результат в настоящий `List`.

У ленивости есть два следствия, которые стоит запомнить. Ленивый `Iterable` вычисляется заново при каждом проходе по нему, поэтому однократная материализация с помощью `toList()` выгоднее, когда значения нужны больше одного раза. И он продолжает смотреть на исходную коллекцию, поэтому изменение этой коллекции меняет то, что выдаёт `Iterable`:

```dart
final numbers = [1, 2, 3];
final lazy = numbers.map((n) => n * 2);
final eager = numbers.map((n) => n * 2).toList();
numbers.add(4);
print(lazy.toList()); // [2, 4, 6, 8]
print(eager);         // [2, 4, 6]
```

---

`fold` сворачивает целую коллекцию в **одно значение**. Он принимает два аргумента: начальное значение **аккумулятора** и функцию, которая получает текущий аккумулятор и следующий элемент, а возвращает новый аккумулятор:

```dart
final numbers = [1, 2, 3, 4];
final total = numbers.fold(0, (acc, n) => acc + n);
print(total); // 10
```

Здесь `acc` начинается с `0`, затем становится `1`, `3`, `6` и наконец `10`.

Аккумулятор не обязан быть числом или иметь тот же тип, что и элементы: начав с `''` и добавляя текст, можно построить `String` из списка чего угодно.

Одна деталь, о которой стоит помнить: Dart выводит тип аккумулятора из начального значения **и** из того, где используется результат. Внутри `print(...)` ожидаемый тип неизвестен, поэтому сначала сохраните результат в переменную (или напишите `fold<int>(...)`), иначе компилятор пожалуется, что не может применить `+` к аккумулятору.

---

`reduce` — это укороченный родственник `fold`. Он не принимает начального значения: **первый элемент** становится стартовым аккумулятором, а функция выполняется для каждого оставшегося элемента:

```dart
final numbers = [1, 2, 3, 4];
print(numbers.reduce((a, b) => a + b)); // 10
```

Поскольку начального значения нет, результат всегда имеет **тот же тип, что и элементы**, а вызов `reduce` на пустой коллекции выбрасывает `StateError`: нет первого элемента, с которого можно начать. У `fold` такой проблемы нет, поэтому он является более безопасным выбором по умолчанию.

`reduce` лучше всего подходит, когда вы ищете один элемент среди многих, например наибольший:

```dart
print(numbers.reduce((a, b) => a > b ? a : b)); // 4
```

---

`firstWhere` возвращает **первый** элемент, удовлетворяющий предикату, а не все такие элементы:

```dart
final words = ['fig', 'kiwi', 'banana'];
print(words.firstWhere((w) => w.length > 3)); // kiwi
```

Когда ничего не подходит, возвращать нечего, поэтому `firstWhere` выбрасывает `StateError`. Чтобы получить ответ вместо ошибки, передайте именованный аргумент **`orElse`**: функцию без параметров, которая выдаёт запасное значение.

```dart
print(words.firstWhere((w) => w.length > 10, orElse: () => 'none')); // none
```

`orElse` — это функция, а не обычное значение, поэтому она вызывается только тогда, когда поиск не удался. Запись `orElse: 'none'` не компилируется.

---

Когда функция, передаваемая в `map`, возвращает коллекцию для каждого элемента, на выходе получается последовательность коллекций. **`expand`** делает то же самое, но затем объединяет их все в одну плоскую последовательность:

```dart
final numbers = [1, 2];
print(numbers.map((n) => [n, -n]).toList());    // [[1, -1], [2, -2]]
print(numbers.expand((n) => [n, -n]).toList()); // [1, -1, 2, -2]
```

Порядок сохраняется: сначала идёт всё, что создано первым элементом, затем всё, что создано вторым, и так далее.

Поскольку возвращаемая коллекция может иметь любой размер, `expand` — это также способ получить **больше или меньше** элементов, чем было изначально: пустой список для элемента просто отбрасывает его.

```dart
print(['a b', 'c'].expand((s) => s.split(' ')).toList()); // [a, b, c]
```

---

`take(n)` оставляет **первые** `n` элементов, а `skip(n)` отбрасывает их. Ни один из них не принимает функцию, но оба возвращают ленивый `Iterable`, поэтому они естественно вписываются в ряд других методов высшего порядка:

```dart
final scores = [10, 20, 30, 40, 50];
print(scores.take(2).toList()); // [10, 20]
print(scores.skip(3).toList()); // [40, 50]
```

Запрос большего числа элементов, чем есть, не является ошибкой: вы просто получаете то, что существует, или пустой результат.

`takeWhile` и `skipWhile` — версии с предикатом. Они берут или отбрасывают элементы с начала, **пока** предикат выполняется, и останавливаются на первом элементе, для которого он не выполняется, даже если последующие элементы снова могли бы подойти:

```dart
print(scores.takeWhile((s) => s < 35).toList()); // [10, 20, 30]
```

---

В Dart нет метода `sorted`. `sort` принадлежит `List`: он меняет порядок элементов списка **на месте** и ничего не возвращает:

```dart
final numbers = [3, 1, 2];
numbers.sort();
print(numbers); // [1, 2, 3]
```

Поскольку он возвращает `void`, результатом нельзя воспользоваться вовсе: `final sorted = numbers.sort();` даёт значение, которое компилятор не позволит прочитать. Идиома для упорядоченной **копии** — `toList()` с последующим каскадом `..sort()`: `toList()` создаёт копию, а `..` вызывает на ней `sort`, при этом возвращая саму копию.

```dart
final numbers = [3, 1, 2];
final sorted = numbers.toList()..sort();
print(sorted);  // [1, 2, 3]
print(numbers); // [3, 1, 2], без изменений
```

`sort` также принимает **компаратор**: функцию от двух элементов, возвращающую отрицательное число, когда первый должен идти перед вторым, `0`, когда они равны, и положительное число в противном случае. `compareTo` возвращает именно это, поэтому упорядочивание по любому ключу умещается в одну строку:

```dart
final words = ['kiwi', 'fig', 'banana'];
print(words.toList()..sort((a, b) => a.length.compareTo(b.length)));
// [fig, kiwi, banana]
```

---

`fold` и `reduce` похожи, и выбор между ними сводится к двум вопросам: может ли коллекция быть пустой и имеет ли результат тот же тип, что и элементы?

```dart
final words = ['fig', 'kiwi'];
final joined = words.reduce((a, b) => '$a, $b'); // String из Strings
final letters = words.fold(0, (acc, w) => acc + w.length); // int из Strings
print(joined);  // fig, kiwi
print(letters); // 7
```

`reduce` может вернуть только тип элемента, потому что начинает с элемента. `fold` начинает со значения, которое вы выбрали, поэтому аккумулятором может быть `int`-счётчик, растущий `String` или даже собираемый `List`. А поскольку начальное значение уже существует, пустая коллекция — это просто ответ, который `fold` возвращает без изменений, тогда как `reduce` возвращать нечего, и он выбрасывает ошибку.

---

Каждый из этих методов возвращает `Iterable`, и у каждого `Iterable` снова есть те же методы. Именно это позволяет выстраивать их в **цепочки**: всё вычисление читается как конвейер слева направо, где каждый шаг работает с тем, что создал предыдущий.

```dart
final words = ['kiwi', 'fig', 'banana', 'date'];
print(words.where((w) => w.length == 4).map((w) => w.toUpperCase()).toList());
// [KIWI, DATE]
```

`toList()` нужен только на последнем шаге: вызов в середине построил бы список, который никто не сохранит.

Тип меняется вдоль цепочки, а вместе с ним и то, что получает следующая функция: после `where` на `List<String>` у вас всё ещё строки, но после `map((w) => w.length)` следующий шаг видит числа.

Поскольку каждый шаг ленив, порядок важен для объёма выполненной работы, а не только для результата: сначала отфильтровать с помощью `where` означает, что `map` будет вызван для меньшего числа элементов.

---

В этих методах нет ничего особенного: они просто принимают **функцию в качестве параметра**, и ваши собственные функции могут делать то же самое. Тип параметра-функции записывается как тип возвращаемого значения, затем `Function`, затем типы параметров в скобках:

```dart
List<int> applyAll(List<int> numbers, int Function(int) operation) {
  return numbers.map(operation).toList();
}
```

Вызывающий код решает **что** происходит, а функция решает **над чем**. Обратите внимание, как `operation` передаётся прямо в `map`: значение-функцию можно передавать дальше, как любое другое значение.

Аргументом может быть анонимная функция или **имя** существующей, записанное без скобок. Добавление скобок вызвало бы её вместо передачи:

```dart
int square(int n) => n * n;

print(applyAll([1, 2, 3], square));       // [1, 4, 9]
print(applyAll([1, 2, 3], (n) => n + 1)); // [2, 3, 4]
```

---

Функция также может **возвращать** функцию. Тип возвращаемого значения записывается точно так же, как тип параметра-функции, а возвращаемое значение обычно является анонимной функцией:

```dart
int Function(int) multiplier(int factor) {
  return (n) => n * factor;
}
```

`multiplier(3)` ничего не умножает: она создаёт и возвращает новую функцию, которая умножает на `3`. Затем эта функция сохраняется, вызывается или передаётся в `map`, как любая другая:

```dart
final triple = multiplier(3);
print(triple(5));                       // 15
print([1, 2, 3].map(triple).toList());  // [3, 6, 9]
```

Возвращённая функция по-прежнему помнит `factor` после того, как `multiplier` завершилась. Функция, сохраняющая переменные области видимости, в которой она была создана, называется **замыканием**, и именно она делает возможными такие фабрики функций.

---

Вместе эти методы заменяют большинство циклов, написанных вручную. Конвейер обычно читается в три этапа: **выбрать** элементы с помощью `where`, **преобразовать** их с помощью `map`, затем **объединить** их с помощью `fold`:

```dart
final prices = [12, 40, 7];
final cheapTotal = prices.where((p) => p < 20).fold(0, (acc, p) => acc + p);
print(cheapTotal); // 19
```

Поскольку `fold` сам выбирает начальное значение, он может также завершить цепочку типом, не связанным с элементами, например `String`, собираемым по одному кусочку за раз:

```dart
final words = ['fig', 'kiwi'];
final firstLetters = words.fold('', (acc, w) => acc + w[0]);
print(firstLetters); // fk
```

Каждый этап остаётся коротким и говорит, что он делает, — вот настоящая причина предпочитать их циклу, который делает все три вещи сразу.
