# --description--

Голый `catch` перехватывает всё, а заодно скрывает и те сбои, которые вы не планировали. Чтобы обработать ровно один вид, укажите его тип в предложении `on`:

```dart
try {
  return int.parse(text);
} on FormatException catch (e) {
  return -1;
}
```

`int.parse` выбрасывает **`FormatException`**, когда текст не является целым числом, поэтому именно этот тип нужно указывать при чтении ввода. Предложение `on` соответствует этому типу и его подтипам — и ничему больше: любой другой сбой продолжает распространяться наружу и всё равно проявится, вместо того чтобы быть поглощённым восстановлением, которое для него не предназначалось.
