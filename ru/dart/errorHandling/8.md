# --description--

Иногда обработчик — не то место, где стоит восстанавливаться: вы хотите лишь *заметить* сбой и позволить ему дойти до вызывающего кода, который действительно может с ним разобраться. Ключевое слово `rethrow` делает именно это — внутри блока `catch` или `on ... catch`:

```dart
try {
  return int.parse(text);
} on FormatException {
  log.add('bad input: $text');
  rethrow;
}
```

`rethrow` отправляет дальше **тот же** объект, поэтому вызывающий код видит исходный сбой. Запись `throw e` вместо него тоже сработала бы, но она начинает путь заново и теряет место, где сбой произошёл впервые.

Блок `finally` в той же инструкции всё равно выполняется, даже когда исключение уходит наружу.

# --instructions--

Напишите функцию `parseOrLog`, которая принимает `String` `text` и `List<String>` `log` и возвращает `int.parse(text)`.

Когда текст не является целым числом, добавьте строку `'bad input: '` с текстом в `log`, а затем выполните `rethrow` для `FormatException`, чтобы вызывающий код всё равно его увидел.

Пример:
```dart
final log = <String>[];
print(parseOrLog('42', log)); // 42
```
