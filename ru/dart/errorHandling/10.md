# --description--

`Exception` — это интерфейс, поэтому вашим классом тоже может стать исключение. Собственное исключение даёт сбою имя, которое предложение `on` может выбрать, и поля, которые обработчик может прочитать:

```dart
class EmptyCartException implements Exception {
  final String message;

  EmptyCartException(this.message);

  @override
  String toString() => 'EmptyCartException: $message';
}

throw EmptyCartException('nothing to pay for');
```

Три части стоит сохранить: `implements Exception`, чтобы класс принадлежал к остальным сбоям, поле `final` с подробностью и переопределённый `toString()`, чтобы отчёт о необработанном исключении был читаемым. Без этого переопределения Dart печатает только имя класса, и подробность теряется.

# --instructions--

Определите класс `InvalidEmailException`, который реализует `Exception`, с полем `final String` `message`, задаваемым конструктором, и с `toString()`, возвращающим `'InvalidEmailException: '` с сообщением.

Затем напишите функцию `checkEmail`, которая принимает `String` `email` и возвращает его, но выбрасывает `InvalidEmailException('missing @')`, когда в адресе нет `'@'`.

Пример:
```dart
print(checkEmail('ada@dart.dev')); // ada@dart.dev
```

# --solutions--

```dart
class InvalidEmailException implements Exception {
  final String message;

  InvalidEmailException(this.message);

  @override
  String toString() => 'InvalidEmailException: $message';
}

String checkEmail(String email) {
  if (!email.contains('@')) {
    throw InvalidEmailException('missing @');
  }
  return email;
}
```
