**Метод высшего порядка** — это метод, который принимает функцию в качестве аргумента. Коллекции Kotlin предлагают их множество, и передаваемая функция обычно является **лямбдой**: маленькой анонимной функцией, записанной в фигурных скобках.
`map` — самый распространённый из них: он вызывает лямбду для каждого элемента и возвращает **новый список** с результатами, оставляя исходный нетронутым:
```kotlin
val numbers = listOf(1, 2, 3)
val doubled = numbers.map { it * 2 }
println(doubled) // [2, 4, 6]
println(numbers) // [1, 2, 3]
```
Когда у лямбды один параметр, объявлять его не нужно: Kotlin называет его `it`. Лямбда записывается после имени метода, за круглыми скобками, которые можно опустить, если лямбда — единственный аргумент. Это синтаксис **trailing lambda**, и он используется в каждом упражнении этой темы.

---

`filter` принимает лямбду, возвращающую `Boolean`, которую называют **предикатом**, и возвращает новый список только с теми элементами, для которых предикат равен `true`:
```kotlin
val numbers = listOf(4, -2, 7, 0)
println(numbers.filter { it > 0 }) // [4, 7]
```
Вместо `it` вы можете дать параметру имя, за которым следует стрелка `->`. Именованный параметр делает длинные лямбды понятнее, и он обязателен, когда одна лямбда вложена в другую, потому что внутренний `it` скрывает внешний элемент:
```kotlin
val minLength = 4
val words = listOf("fig", "banana", "kiwi")
println(words.filter { word -> word.length >= minLength }) // [banana, kiwi]
```

---

`forEach` выполняет лямбду по одному разу для каждого элемента и ничего не возвращает. Это альтернатива циклу `for` в стиле высшего порядка, и она используется для побочных эффектов, например для вывода:
```kotlin
listOf("a", "b").forEach { println(it) }
```
`forEachIndexed` даёт также позицию каждого элемента. У его лямбды **два** параметра, поэтому их нужно именовать: `it` существует только для лямбд ровно с одним параметром.
```kotlin
listOf("a", "b").forEachIndexed { index, letter ->
    println("$index: $letter") // 0: a, затем 1: b
}
```

---

`reduce` объединяет все элементы в одно значение. Его лямбда принимает два параметра: **аккумулятор** (результат на текущий момент) и следующий элемент. Он начинает с первого элемента в качестве аккумулятора и выполняет лямбду для каждого оставшегося элемента:
```kotlin
val numbers = listOf(1, 2, 3, 4)
println(numbers.reduce { acc, n -> acc + n }) // 10
```
`reduce` бросает исключение на пустом списке, потому что нет первого элемента, с которого можно начать. `fold` решает эту проблему: вы передаёте **начальное значение** аккумулятора аргументом, и лямбда выполняется для каждого элемента, включая первый:
```kotlin
println(numbers.fold(0) { acc, n -> acc + n })   // 10
println(listOf<Int>().fold(0) { acc, n -> acc + n }) // 0
```
С `fold` аккумулятор может даже иметь тип, отличный от типа элементов, например при построении `String` из списка чисел.

---

Некоторые методы высшего порядка отвечают на вопрос о коллекции, вместо того чтобы строить новую. Все они принимают предикат:
- `any` возвращает `true`, если ему удовлетворяет **хотя бы один** элемент
- `all` возвращает `true`, если ему удовлетворяет **каждый** элемент
- `none` возвращает `true`, если ему не удовлетворяет **ни один** элемент
- `count` возвращает, **сколько** элементов ему удовлетворяют
```kotlin
val numbers = listOf(1, 2, 3)
println(numbers.any { it > 2 })   // true
println(numbers.all { it > 2 })   // false
println(numbers.none { it > 2 })  // false
println(numbers.count { it > 1 }) // 2
```
На пустом списке `any` возвращает `false`, а `all` и `none` возвращают `true`: нет ни одного элемента, который нарушал бы правило.

---

Методы агрегации превращают всю коллекцию в одно значение:
- `sum()` складывает список чисел, а `sumOf` складывает значение, которое лямбда вычисляет для каждого элемента
- `maxByOrNull` и `minByOrNull` возвращают **элемент**, для которого лямбда даёт наибольшее или наименьшее значение, или `null` на пустом списке
```kotlin
val words = listOf("fig", "banana", "kiwi")
println(words.sumOf { it.length })      // 13
println(words.minByOrNull { it.length }) // fig
println(listOf(1, 2, 3).sum())           // 6
```
Обратите внимание на отличие от `maxOf { it.length }`, который возвращает наибольшее **значение** (`6`), а не элемент, который его дал.

---

`sortedBy` возвращает новый список, упорядоченный по значению, которое лямбда вычисляет для каждого элемента, от меньшего к большему. `sortedByDescending` упорядочивает от большего к меньшему. Когда сравнивать нужно сами элементы, `sorted()` и `sortedDescending()` обходятся без лямбды:
```kotlin
val words = listOf("kiwi", "fig", "banana")
println(words.sortedBy { it.length })            // [fig, kiwi, banana]
println(words.sortedByDescending { it.length })  // [banana, kiwi, fig]
println(words.sorted())                          // [banana, fig, kiwi]
```
Сортировка **устойчивая**: элементы с одинаковым ключом сохраняют исходный относительный порядок. Исходный список никогда не изменяется.

---

`take(n)` возвращает новый список с первыми `n` элементами, а `drop(n)` возвращает новый список **без** первых `n` элементов. Ни один из них не принимает лямбду, но их часто ставят в цепочку после метода, который её принимает:
```kotlin
val numbers = listOf(5, 3, 8, 1)
println(numbers.take(2))                    // [5, 3]
println(numbers.drop(2))                    // [8, 1]
println(numbers.sortedDescending().take(2)) // [8, 5]
```
`takeWhile` и `dropWhile` — это версии с предикатом: они берут или отбрасывают элементы с начала **до тех пор, пока** предикат равен `true`, и останавливаются на первом элементе, который его не удовлетворяет:
```kotlin
println(numbers.takeWhile { it > 2 }) // [5, 3, 8]
```

---

`groupBy` разбивает коллекцию в `Map`: лямбда вычисляет **ключ** каждого элемента, и каждому ключу сопоставляется список элементов, которые его дали, в их исходном порядке:
```kotlin
val words = listOf("fig", "kiwi", "pear")
val byLength = words.groupBy { it.length }
println(byLength)    // {3=[fig], 4=[kiwi, pear]}
println(byLength[4]) // [kiwi, pear]
```
Результат имеет тип `Map<K, List<T>>`, где `K` — тип, возвращаемый лямбдой, а `T` — тип элементов. Ключи идут в том порядке, в котором встретились впервые.

---

Когда лямбда возвращает **список** для каждого элемента, `map` даёт список списков. `flatMap` делает то же самое, но затем объединяет все эти списки в один плоский:
```kotlin
val numbers = listOf(1, 2)
println(numbers.map { listOf(it, -it) })     // [[1, -1], [2, -2]]
println(numbers.flatMap { listOf(it, -it) }) // [1, -1, 2, -2]
```
Порядок сохраняется: сначала идут все значения, полученные из первого элемента, затем из второго и так далее. Если у вас уже есть список списков, `flatten()` объединит их без лямбды.

---

`zip` соединяет элементы двух списков позиция за позицией. Без лямбды он возвращает список значений `Pair`, половины которых читаются через `.first` и `.second`; с лямбдой ей передаются два элемента каждой позиции, а результаты собираются в список:
```kotlin
val names = listOf("Ann", "Bob")
val ages = listOf(31, 25)
println(names.zip(ages))                            // [(Ann, 31), (Bob, 25)]
println(names.zip(ages) { name, age -> "$name:$age" }) // [Ann:31, Bob:25]
```
Результат по длине равен **более короткому** из двух списков: лишние элементы более длинного игнорируются.

---

Форма лямбды должна соответствовать тому, что ожидает метод:
- методы, работающие с одним элементом за раз (`map`, `filter`, `sortedBy`, `groupBy`...), принимают лямбду с **одним параметром**, где доступен `it`
- `reduce`, `fold`, `forEachIndexed` и `zip` с лямбдой передают **два** значения, поэтому параметры нужно явно именовать через `a, b ->`
```kotlin
val numbers = listOf(1, 2, 3)
numbers.map { it * 2 }                  // ок: один параметр, it доступен
numbers.reduce { acc, n -> acc + n }    // ок: два параметра, именованные
numbers.reduce { it + 1 }               // ошибка: it не существует при двух параметрах
```
Именовать параметры разрешено всегда, даже когда он один: `numbers.map { n -> n * 2 }`.

---

Методы высшего порядка можно **соединять в цепочку**: каждый возвращает новую коллекцию, с которой работает следующий, поэтому целое вычисление читается как конвейер слева направо:
```kotlin
val words = listOf("kiwi", "fig", "banana", "date")
println(words.filter { it.length == 4 }.map { it.uppercase() }.sorted()) // [DATE, KIWI]
```
У map тоже есть методы высшего порядка. `mapValues` сохраняет ключи и заменяет каждое значение результатом лямбды, которая получает **запись** с `.key` и `.value`:
```kotlin
val byLength = words.groupBy { it.length }      // {4=[kiwi, date], 3=[fig], 6=[banana]}
println(byLength.mapValues { it.value.size })   // {4=2, 3=1, 6=1}
```

---

В цепочке тип `it` меняется на каждом шаге: после `filter` на `List<String>` у вас по-прежнему строки, но после `map { it.length }` у вас `List<Int>`, поэтому следующая лямбда видит числа.
```kotlin
val words = listOf("kiwi", "fig")
println(words.map { it.length }.filter { it > 3 }) // [4]
```
Каждый шаг возвращает **новый** список и никогда не трогает предыдущий, поэтому цепочку можно разбить на именованные промежуточные значения, не меняя результат.

---

Лямбда может содержать другой вызов высшего порядка. Внутри внутренней лямбды `it` относится к **внутреннему** элементу и скрывает внешний, поэтому дайте внешнему параметру явное имя, чтобы оба оставались доступны:
```kotlin
val sales = listOf("north" to 120, "south" to 80, "north" to 30)
val byRegion = sales.groupBy { it.first }
val totals = byRegion.mapValues { entry -> entry.value.sumOf { it.second } }
println(totals) // {north=150, south=80}
```
`"north" to 120` создаёт `Pair`. Здесь внешняя лямбда работает с записью map, а внутренняя — с парами из списка этой записи.

---

`Map` можно обрабатывать как список записей: `filter` и `map` работают прямо с map и получают каждую запись с `.key` и `.value`. `filter` на map возвращает map, а `map` возвращает список. Методы сортировки, такие как `sortedBy`, для map не определены: сначала перейдите к `scores.entries`, коллекции записей:
```kotlin
val scores = mapOf("Ann" to 90, "Bob" to 72)
println(scores.filter { it.value > 80 })              // {Ann=90}
println(scores.entries.sortedBy { it.value }.map { it.key }) // [Bob, Ann]
```
`scores.entries` — это множество всех записей; `scores.keys` и `scores.values` дают только одну из сторон.
