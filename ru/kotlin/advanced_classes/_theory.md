`data class` — это класс, задача которого — **хранить данные**. Из свойств, объявленных в первичном конструкторе, компилятор генерирует за вас четыре члена:

- `toString()`, читаемый текст вида `ClassName(prop=value, ...)`
- `equals()` и `hashCode()`, чтобы два экземпляра с одинаковыми данными считались равными
- `copy()`, который создаёт новый экземпляр, переиспользуя текущие значения

```kotlin
data class Book(val title: String, val pages: Int)

val book = Book("Dune", 412)
println(book)          // Book(title=Dune, pages=412)
println(book.copy())   // Book(title=Dune, pages=412)
```

`copy()` по-настоящему раскрывается вместе с **именованными аргументами**: вы указываете только те свойства, которые хотите изменить, а все остальные значения переносятся как есть.

```kotlin
println(book.copy(pages = 500)) // Book(title=Dune, pages=500)
```

Исходный объект никогда не изменяется: `copy()` возвращает совершенно новый объект.

---

Для каждого свойства первичного конструктора data class также генерирует функцию `componentN()`: `component1()` для первого свойства, `component2()` для второго и так далее.

Эти функции лежат в основе **деструктурирующих объявлений**, где вы распаковываете объект в несколько переменных одной строкой:

```kotlin
data class Point(val x: Int, val y: Int)

val point = Point(3, 7)
val (x, y) = point
println(x)               // 3
println(point.component2()) // 7
```

Порядок переменных следует порядку свойств, а не их именам. Используйте `_`, чтобы пропустить ненужное:

```kotlin
val (_, onlyY) = point
```

---

Сгенерированный `equals()` делает `==` **структурным** сравнением: два экземпляра равны, когда каждое свойство первичного конструктора равно. Оператор `===` работает иначе: он проверяет, указывают ли оба имени на **один и тот же объект** в памяти.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, одинаковые данные
println(a === b) // false, два разных объекта
println(a === a) // true
```

Поскольку `hashCode()` генерируется вместе с `equals()`, экземпляры data class также корректно ведут себя внутри `Set` или в качестве ключей `Map`: дубликаты схлопываются.

```kotlin
println(setOf(a, b).size) // 1
```

Обычный класс не генерирует ничего из этого, поэтому для него `==` сводится к сравнению идентичности.

---

Сгенерированные члены учитывают только свойства, объявленные в **первичном конструкторе**. Свойство, объявленное в **теле** класса, является обычным свойством: оно не входит в `toString()`, `equals()`, `hashCode()` или `copy()`.

```kotlin
data class Item(val name: String) {
    var quantity: Int = 0
}

val a = Item("nail")
a.quantity = 5
println(a) // Item(name=nail)
```

Об этом легко забыть, поэтому помещайте в первичный конструктор всё, что идентифицирует объект, а производное или временное состояние оставляйте в теле.

---

Класс `sealed` описывает **закрытый** набор вариантов: разрешены только подклассы, написанные в том же пакете и модуле, поэтому компилятор знает их все.

```kotlin
sealed class Shape
data class Circle(val radius: Int) : Shape()
data class Square(val side: Int) : Shape()
```

Выигрыш — **исчерпывающий `when`**: когда вы ветвитесь по sealed-типу и покрываете каждый подкласс, ветку `else` можно не писать. Добавьте позже новый подкласс, и компилятор укажет на каждый `when`, который вы забыли обновить, вместо того чтобы молча уйти в `else`.

```kotlin
fun name(shape: Shape): String = when (shape) {
    is Circle -> "circle"
    is Square -> "square"
}
```

После `is Circle` значение подвергается умному приведению, поэтому `shape.radius` доступно внутри этой ветки без ручного приведения типа.

---

Иногда нужен ровно **один** экземпляр чего-либо: логгер, реестр, конфигурация приложения. Замена `class` на `object` объявляет этот синглтон за вас:

```kotlin
object Registry {
    var size = 0
    fun add() {
        size++
    }
}

Registry.add()
println(Registry.size) // 1
```

Экземпляр создаётся при первом обращении, и вы используете само имя: нет ни вызова `Registry()`, ни конструктора. `object` может содержать свойства, методы, блоки `init`, а также реализовывать интерфейсы или наследовать класс.

---

`companion object` — это синглтон, принадлежащий классу. Помимо констант его естественная задача — хранить **фабричные функции**: функции, которые проверяют или преобразуют входные данные перед созданием экземпляра и могут вернуть `null`, когда входные данные бессмысленны.

Пометка конструктора как `private` заставляет каждого вызывающего идти через фабрику:

```kotlin
class Age private constructor(val years: Int) {
    companion object {
        fun of(years: Int): Age? = if (years >= 0) Age(years) else null
    }
}

println(Age.of(30)?.years) // 30
println(Age.of(-1))        // null
```

Companion вызывается по имени класса, `Age.of(...)`, и может обратиться к приватному конструктору, потому что находится внутри класса.

---

`interface` перечисляет, что умеет тип. Его члены по умолчанию абстрактны, но интерфейс может также предоставить **реализацию по умолчанию** — тело, которое каждый реализующий класс наследует бесплатно и может переопределить:

```kotlin
interface Greeter {
    val name: String              // abstract, класс должен предоставить его
    fun greet(): String = "Hi, $name"  // реализация по умолчанию
}

class Person(override val name: String) : Greeter

class Robot(override val name: String) : Greeter {
    override fun greet(): String = "BEEP $name"
}

println(Person("Ann").greet()) // Hi, Ann
println(Robot("R2").greet())   // BEEP R2
```

Интерфейс не может хранить состояние (у него нет backing field), поэтому абстрактное свойство должно быть реализовано классом, обычно через `override val` в конструкторе. В отличие от класса, тип может реализовывать сколько угодно интерфейсов.

---

Класс `abstract` находится между интерфейсом и обычным классом: его нельзя инстанцировать, и он сочетает **абстрактные** члены, у которых нет тела и которые обязательно переопределяются, с конкретными, которые подклассы наследуют как есть.

```kotlin
abstract class Vehicle(val name: String) {
    abstract fun wheels(): Int
    fun describe(): String = "$name has ${wheels()} wheels"
}

class Bike(name: String) : Vehicle(name) {
    override fun wheels(): Int = 2
}

println(Bike("BMX").describe()) // BMX has 2 wheels
```

В отличие от интерфейса, у абстрактного класса есть конструктор и он может хранить состояние в свойствах, поэтому подкласс передаёт `name` наверх через `: Vehicle(name)`. Класс может наследовать только один класс, поэтому берите абстрактный класс, когда подклассы разделяют данные, и интерфейс, когда они разделяют только поведение. Абстрактные члены переопределяются без добавления `open`.

---

Класс, объявленный внутри другого класса, по умолчанию является **вложенным** (nested). Он ничего не знает о внешнем экземпляре, и вы создаёте его от имени внешнего класса:

```kotlin
class Outer {
    class Nested {
        fun hello() = "hi"
    }
}

println(Outer.Nested().hello()) // hi
```

Добавьте ключевое слово `inner`, и ситуация изменится: класс `inner` несёт ссылку на внешний экземпляр, поэтому может читать его свойства, и вы создаёте его **от экземпляра**:

```kotlin
class Counter(val step: Int) {
    inner class Doubler {
        fun value() = step * 2
    }
}

println(Counter(5).Doubler().value()) // 10
```

Внутри класса `inner` `this` — это внутренний объект; используйте `this@Counter`, когда вам явно нужен внешний.

Части этой темы обычно комбинируются: `enum class`, константы которого несут собственные свойства, моделирует фиксированный набор меток, а `data class` переносит сопутствующие данные.

```kotlin
enum class Speed(val surcharge: Int) {
    STANDARD(0),
    EXPRESS(15)
}

data class Order(val total: Int, val speed: Speed)

val order = Order(100, Speed.EXPRESS)
println(order.total + order.speed.surcharge) // 115
```
