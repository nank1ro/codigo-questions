`data class` — это класс, задача которого — **хранить данные**. Из свойств, объявленных в первичном конструкторе, компилятор генерирует за вас четыре члена:

- `toString()`, читаемый текст вида `ClassName(prop=value, ...)`
- `equals()` и `hashCode()`, чтобы два экземпляра с одинаковыми данными считались равными
- `copy()`, который создаёт новый экземпляр, переиспользуя текущие значения

```kotlin
data class Book(val title: String, val pages: Int)

val book = Book("Dune", 412)
println(book)          // Book(title=Dune, pages=412)
println(book.copy())   // Book(title=Dune, pages=412)
```

`copy()` по-настоящему раскрывается вместе с **именованными аргументами**: вы указываете только те свойства, которые хотите изменить, а все остальные значения переносятся как есть.

```kotlin
println(book.copy(pages = 500)) // Book(title=Dune, pages=500)
```

Исходный объект никогда не изменяется: `copy()` возвращает совершенно новый объект.

---

Для каждого свойства первичного конструктора data class также генерирует функцию `componentN()`: `component1()` для первого свойства, `component2()` для второго и так далее.

Эти функции лежат в основе **деструктурирующих объявлений**, где вы распаковываете объект в несколько переменных одной строкой:

```kotlin
data class Point(val x: Int, val y: Int)

val point = Point(3, 7)
val (x, y) = point
println(x)               // 3
println(point.component2()) // 7
```

Порядок переменных следует порядку свойств, а не их именам. Используйте `_`, чтобы пропустить ненужное:

```kotlin
val (_, onlyY) = point
```

---

Сгенерированный `equals()` делает `==` **структурным** сравнением: два экземпляра равны, когда каждое свойство первичного конструктора равно. Оператор `===` работает иначе: он проверяет, указывают ли оба имени на **один и тот же объект** в памяти.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, same data
println(a === b) // false, two different objects
println(a === a) // true
```

Поскольку `hashCode()` генерируется вместе с `equals()`, экземпляры data class также корректно ведут себя внутри `Set` или в качестве ключей `Map`: дубликаты схлопываются.

```kotlin
println(setOf(a, b).size) // 1
```

Обычный класс не генерирует ничего из этого, поэтому для него `==` сводится к сравнению идентичности.

---

Сгенерированные члены учитывают только свойства, объявленные в **первичном конструкторе**. Свойство, объявленное в **теле** класса, является обычным свойством: оно не входит в `toString()`, `equals()`, `hashCode()` или `copy()`.

```kotlin
data class Item(val name: String) {
    var quantity: Int = 0
}

val a = Item("nail")
a.quantity = 5
println(a) // Item(name=nail)
```

Об этом легко забыть, поэтому помещайте в первичный конструктор всё, что идентифицирует объект, а производное или временное состояние оставляйте в теле.

Класс `sealed` описывает **закрытый** набор вариантов: разрешены только подклассы, написанные в том же пакете и модуле, поэтому компилятор знает их все.

```kotlin
sealed class Shape
data class Circle(val radius: Int) : Shape()
data class Square(val side: Int) : Shape()
```

Выигрыш — **исчерпывающий `when`**: когда вы ветвитесь по sealed-типу и покрываете каждый подкласс, ветку `else` можно не писать. Добавьте позже новый подкласс, и компилятор укажет на каждый `when`, который вы забыли обновить, вместо того чтобы молча уйти в `else`.

```kotlin
fun name(shape: Shape): String = when (shape) {
    is Circle -> "circle"
    is Square -> "square"
}
```

После `is Circle` значение подвергается умному приведению, поэтому `shape.radius` доступно внутри этой ветки без ручного приведения типа.
