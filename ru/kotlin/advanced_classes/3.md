# --description--

Сгенерированный `equals()` делает `==` **структурным** сравнением: два экземпляра равны, когда каждое свойство первичного конструктора равно. Оператор `===` работает иначе: он проверяет, указывают ли оба имени на **один и тот же объект** в памяти.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, одинаковые данные
println(a === b) // false, два разных объекта
println(a === a) // true
```

Поскольку `hashCode()` генерируется вместе с `equals()`, экземпляры data class также корректно ведут себя внутри `Set` или в качестве ключей `Map`: дубликаты схлопываются.

```kotlin
println(setOf(a, b).size) // 1
```

Обычный класс не генерирует ничего из этого, поэтому для него `==` сводится к сравнению идентичности.

# --asserts--

Два пользователя, созданные с одинаковыми данными, должны иметь одинаковые данные

```kotlin
    tryCatch(sameData(User(1, "Ann"), User(1, "Ann")))
```

Два пользователя, созданные с разными данными, не должны иметь одинаковые данные

```kotlin
    tryCatch(!sameData(User(1, "Ann"), User(2, "Ann")))
```

Два отдельно созданных пользователя не должны быть одним и тем же экземпляром

```kotlin
    tryCatch(!sameInstance(User(1, "Ann"), User(1, "Ann")))
```

Один и тот же пользователь, сравнённый с самим собой, должен быть тем же экземпляром

```kotlin
    val user = User(3, "Bo")
    tryCatch(sameInstance(user, user))
```

`User` должен генерировать `hashCode()`, поэтому множество из двух равных пользователей содержит один элемент

```kotlin
    tryCatch(setOf(User(4, "Cy"), User(4, "Cy")).size == 1)
```

```kotlin
data class User(val id: Int, val name: String)

fun sameData(a: User, b: User): Boolean {
    return a == b
}

fun sameInstance(a: User, b: User): Boolean {
    return a === b
}
```
