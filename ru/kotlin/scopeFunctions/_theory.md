**Функции области видимости** выполняют блок кода *внутри контекста объекта*. Они не добавляют в язык новых возможностей: они лишь делают код, работающий с одним объектом, короче и легче для чтения. В Kotlin их пять: `let`, `run`, `with`, `apply` и `also`.

Они различаются только по **двум** пунктам: как объект упоминается внутри блока и что возвращает вызов. Начнём с `let`: внутри его блока объект называется `it`, а вызов возвращает **результат последнего выражения** блока.
```kotlin
val word = "kotlin"
val letters = word.let { it.length } // 6
println(letters)
```
Без `let` вам понадобилась бы временная переменная; с ним объект доступен под коротким именем `it`, пока длится блок.

---

Поскольку `let` возвращает значение своего последнего выражения, это удобный способ **превратить значение во что-то другое**, не вводя промежуточную переменную:
```kotlin
val price = 12
val label = price.let { "$it EUR" }
println(label) // 12 EUR
```
Внутри блока вы можете использовать `it` столько раз, сколько нужно:
```kotlin
println("kiwi".let { "${it.uppercase()} has ${it.length} letters" })
// KIWI has 4 letters
```

---

`let` становится по-настоящему полезным после безопасного вызова. `?.let { ... }` выполняет блок **только** когда значение не `null`, и внутри блока `it` — это значение, не допускающее null, поэтому дополнительная проверка не нужна:
```kotlin
val email: String? = "ada@example.com"
email?.let { println("Sending to ${it.uppercase()}") }
```
Когда значение равно `null`, всё выражение равно `null` и блок никогда не выполняется, поэтому Элвис-оператор `?:` — естественный партнёр для подстановки запасного значения:
```kotlin
fun label(city: String?): String {
    return city?.let { "City: $it" } ?: "No city"
}
```

---

Внутри блока `let` вы не обязаны называть объект `it`: вы можете дать параметру лямбды имя, что сохраняет код читаемым, когда блоки вложены друг в друга или когда `it` не говорит ничего полезного.
```kotlin
val price: Int? = 12
println(price?.let { amount -> "$amount EUR" }) // 12 EUR
```
То же именование работает для каждой функции области видимости, использующей `it`, то есть для `let` и `also`.

---

`apply` движется сразу по обеим осям: внутри своего блока объект — это получатель `this` (так что его члены можно использовать **без какого-либо префикса**), а вызов возвращает **сам объект**, а не результат блока.

Именно это сочетание делает `apply` инструментом для **настройки** объекта прямо в момент его создания:
```kotlin
class Server {
    var host = "localhost"
    var port = 80
}

val server = Server().apply {
    host = "example.com"
    port = 8080
}
println("${server.host}:${server.port}") // example.com:8080
```
`host` и `port` внутри блока — это `this.host` и `this.port`; поскольку `apply` возвращает настроенный `Server`, результат можно сразу присвоить переменной.

---

`apply` не ограничен объектами, которые вы только что создали: он работает с любым объектом, и поскольку он возвращает объект обратно, всё выражение можно использовать везде, где ожидается этот объект.
```kotlin
val box = Box()
box.apply { label = "tools" }        // changes box and returns it
println(listOf(Box().apply { label = "nails" }).size) // 1
```
Блок — это обычный блок кода, поэтому он может содержать столько инструкций, сколько нужно.

---

`also` — зеркальное отражение `apply`: объект упоминается как `it`, а вызов возвращает **сам объект**. Поскольку результат блока выбрасывается, `also` предназначен для **побочных эффектов**, таких как журналирование или проверка, и его можно вставить в середину цепочки, не меняя того, что она производит:
```kotlin
val total = listOf(1, 2, 3)
    .also { println("size: ${it.size}") } // size: 3
    .sum()
println(total) // 6
```
Читайте это как *«и также сделай с ним это»*: значение продолжает течь к следующему шагу нетронутым.

---

Когда блоку нужен объект как **аргумент** чего-то другого, `also` читается лучше, чем `apply`: `it` можно передать напрямую, тогда как `this` пришлось бы выписывать явно.
```kotlin
val names = mutableListOf<String>()
val user = "ada".also { names.add(it) }
println(user)  // ada
println(names) // [ada]
```
Значением выражения остаётся `"ada"`: `also` лишь наблюдает, как оно проходит мимо.

---

`run` — это `let` с другим способом именования объекта: внутри блока объект — это `this`, поэтому его члены не нуждаются в префиксе, а вызов возвращает **результат последнего выражения**.

Он подходит, когда вы читаете несколько членов одного объекта, чтобы вычислить одно значение:
```kotlin
class Rect(val w: Int, val h: Int)

val area = Rect(3, 4).run { w * h }
println(area) // 12
```
Сравните его с `apply`, который использует `this` точно так же, но возвращает сам объект вместо результата блока.

---

`with` делает ту же работу, что и `run`, но **не** является расширением: объект передаётся первым аргументом, а не является получателем вызова через точку.
```kotlin
val text = with(StringBuilder()) {
    append("Hello")
    append(", world")
    toString()
}
println(text) // Hello, world
```
Внутри блока объект — это `this`, а вызов возвращает последнее выражение, точно как `run`. Предпочитайте `with`, когда у вас уже есть объект, не допускающий null, и вы хотите сгруппировать на нём несколько вызовов; `run` — когда объект получается из цепочки вызовов или может понадобиться безопасный вызов (`obj?.run { ... }`).

---

Теперь все пять функций области видимости на столе, и каждая из них — просто точка на двух осях:
- `let` - объект — это `it`, возвращает результат блока
- `run` - объект — это `this`, возвращает результат блока
- `with` - объект — это `this` (передаётся как аргумент), возвращает результат блока
- `apply` - объект — это `this`, возвращает сам объект
- `also` - объект — это `it`, возвращает сам объект

Выбирайте нужную строку: `it` читается лучше, когда вы передаёте объект дальше чему-то другому, `this` — когда вы затрагиваете многие его члены; возвращайте результат блока, когда вам нужно новое значение, и сам объект, когда вы хотите продолжать работать с ним.
