**Функция-расширение** добавляет новую функцию к существующему типу, не трогая его исходный код.
Вы пишете `fun`, затем тип, который хотите расширить (**тип получателя**), точку и имя функции:
```kotlin
fun Int.squared(): Int {
    return this * this
}
println(4.squared()) // 16
```
Внутри функции `this` — это значение, на котором вызвана функция, оно называется **получателем**: в `4.squared()` это `4`.
Когда расширение объявлено, вы вызываете его через точку точно так же, как функцию, которая с самого начала была частью `Int`.

---

Расширения работают с любым типом, даже с теми, к которым у вас нет исходного кода. `String` приходит из стандартной библиотеки, но вы всё равно можете добавить ему новые функции:
```kotlin
fun String.whisper(): String {
    return this.lowercase() + "..."
}
println("HELLO".whisper()) // hello...
```
Внутри расширения можно опускать `this.` при обращении к другим членам получателя: `lowercase()` сам по себе означает `this.lowercase()`, а `length` — `this.length`.

---

Функция-расширение может принимать параметры, как и любая другая функция. Получатель остаётся слева от точки, а параметры идут в скобках:
```kotlin
fun Int.isDivisibleBy(other: Int): Boolean {
    return this % other == 0
}
println(12.isDivisibleBy(4)) // true
println(12.isDivisibleBy(5)) // false
```
Тип перед точкой — обычный тип, поэтому точно так же можно расширить `List<Int>`, `Double` или написанный вами класс.

---

Расширение **не** изменяет класс, который оно расширяет, и не добавляет в него новый член. Компилятор просто переписывает вызов: `"kotlin".first3()` превращается в вызов функции, куда `"kotlin"` передаётся как `this`.
```kotlin
fun String.first3(): String = take(3)
val word = "kotlin"
println(word.first3()) // kot
```
Именно поэтому можно расширять финальные классы вроде `String` и `Int`: внутри них ничего не меняется, расширение живёт только в вашем коде.

---

Кроме функций можно добавить **свойство-расширение**. Оно объявляется через `val`, тип получателя, точку и имя, после которых идёт `get()`, вычисляющий значение при каждом чтении свойства:
```kotlin
val String.wordCount: Int
    get() = split(" ").size

println("Kotlin is fun".wordCount) // 3
```
Свойство-расширение ничего не может хранить: у него нет поля хранения, поэтому инициализатор вроде `val String.label = "text"` — ошибка компиляции. Оно может только вычислять значение из получателя.
Свойства-расширения нельзя объявлять внутри функции (локальные свойства-расширения запрещены), в отличие от функций-расширений.

---

Свойства-расширения читаются без скобок, точно так же, как встроенное `length` у `String`. Это естественный выбор, когда значение описывает получателя, а не делает что-то с ним:
```kotlin
val Int.isNegative: Boolean
    get() = this < 0

println((-3).isNegative) // true
println(7.isNegative)    // false
```
Обратите внимание на скобки вокруг `-3`: без них `-3.isNegative` сначала прочитало бы свойство у `3`, а затем попыталось бы поставить минус перед `Boolean`, что не компилируется.

---

Тип получателя может быть **nullable**. Расширение для `String?` можно вызвать на переменной, которая может содержать `null`, и внутри функции `this` имеет тип `String?`, поэтому случай `null` вы обрабатываете сами, обычно с помощью оператора Элвис `?:`, знакомого по урокам о nullability:
```kotlin
fun String?.orDash(): String {
    return this ?: "-"
}
val name: String? = null
println(name.orDash())  // -
println("Ada".orDash()) // Ada
```
Вызов `name.orDash()` на значении `null` безопасен: `?.` не нужен, потому что сама функция принимает получателя `null`.

---

Внутри расширения с nullable-получателем можно также использовать безопасный вызов `this?.`, чтобы обратиться к членам значения только тогда, когда оно не `null`. Стандартная библиотека использует ту же идею в функциях вроде `isNullOrEmpty()`:
```kotlin
fun String?.firstOrQuestion(): Char {
    return this?.firstOrNull() ?: '?'
}
val text: String? = null
println(text.firstOrQuestion())    // ?
println("Kotlin".firstOrQuestion()) // K
```

---

Когда у класса уже есть член с тем же именем и теми же параметрами, что и у расширения, **член всегда побеждает**: расширение никогда не вызывается, а компилятор предупреждает, что оно перекрыто.
```kotlin
class Box {
    fun describe(): String = "member"
}
fun Box.describe(): String = "extension"

println(Box().describe()) // member
```
Расширение не может переопределить или заменить существующее поведение; оно может только добавлять новые функции и свойства. Чтобы расширение было выбрано, ему нужно имя или список параметров, которых у класса ещё нет.

---

Расширение может работать сразу с целым семейством типов благодаря **параметру типа**: заполнителю для типа, объявленному в угловых скобках сразу после `fun`, который Kotlin подставляет при каждом вызове. Это делает расширение **обобщённым**:
```kotlin
fun <T> List<T>.second(): T {
    return this[1]
}
println(listOf(1, 2, 3).second())      // 2
println(listOf("a", "b").second())     // b
```
Для `listOf(1, 2, 3)` заполнитель `T` — это `Int`, для `listOf("a", "b")` — `String`, поэтому одна и та же функция каждый раз возвращает нужный тип.

---

Параметр типа можно использовать в любом месте сигнатуры: как тип возвращаемого значения, как nullable `T?` или внутри другого типа. Обобщённое расширение, которое может ничего не найти, возвращает `T?`, как встроенная `firstOrNull()`:
```kotlin
fun <T> List<T>.lastOrDefault(default: T): T {
    return if (isEmpty()) default else this[size - 1]
}
println(listOf(1, 2).lastOrDefault(0))          // 2
println(emptyList<String>().lastOrDefault("-")) // -
```
Внутри функции можно использовать `size`, `isEmpty()` и индексацию точно так же, как у любого списка, потому что получатель — это `List<T>`.

---

Можно расширить и **companion object** класса, если класс его объявляет, пусть даже пустым. Тип получателя записывается как `ClassName.Companion`, и расширение затем вызывается на имени класса, как фабричная функция:
```kotlin
class Temperature(val degrees: Int) {
    companion object
}
fun Temperature.Companion.freezing(): Temperature = Temperature(0)

println(Temperature.freezing().degrees) // 0
```
Класс и расширение — оба объявления верхнего уровня, поэтому их нужно писать вне `main`.

---

Расширение companion object может принимать параметры, что делает его удобным местом для альтернативных конструкторов, преобразующих из других единиц измерения или форматов:
```kotlin
class Distance(val meters: Int) {
    companion object
}
fun Distance.Companion.fromKilometers(km: Int): Distance = Distance(km * 1000)

println(Distance.fromKilometers(3).meters) // 3000
```

---

Место объявления расширения определяет, где его можно использовать, то есть его **область видимости**:
- на верхнем уровне файла оно доступно во всём файле и в остальном пакете
- внутри функции это локальное расширение, доступное только в этой функции
- внутри класса это **расширение-член**, доступное только внутри этого класса

Расширение-член может читать свойства класса, в котором живёт, поэтому оно объединяет двух получателей: экземпляр класса и значение, на котором вызвано:
```kotlin
class Greeter(val greeting: String) {
    fun String.greet(): String = "$greeting, $this!"
    fun welcome(name: String): String = name.greet()
}
println(Greeter("Hello").welcome("Ada")) // Hello, Ada!
```
Внутри `greet` значение `greeting` приходит из `Greeter`, а `this` — это `String`, на котором вызвана функция. Вне класса `"Ada".greet()` — ошибка компиляции.

---

Функцию-расширение ровно с **одним** параметром можно пометить как `infix`. Инфиксную функцию можно вызывать без точки и скобок, с получателем слева и аргументом справа, что читается почти как предложение:
```kotlin
infix fun Int.percentOf(total: Int): Int = total * this / 100

println(20 percentOf 50)   // 10
println(20.percentOf(50))  // 10, the normal call still works
```
Kotlin использует это и для некоторых встроенных функций: `1 to "one"` создаёт `Pair`, а `1 until 5` создаёт диапазон.

---

Чтобы функцию можно было пометить как `infix`, она должна быть членом или расширением, принимать ровно один параметр, и у этого параметра не должно быть значения по умолчанию. Всё остальное — ошибка компиляции:
```kotlin
infix fun Int.add(other: Int): Int = this + other          // ok
infix fun add(a: Int, b: Int): Int = a + b                 // error: not a member or extension
infix fun Int.add(a: Int, b: Int): Int = this + a + b      // error: two parameters
```
По приоритету инфиксные вызовы находятся между арифметикой и сравнением: `1 add 2 * 3` — это `1 add 6`, а `1 add 2 == 3` сравнивает результат с `3`.
