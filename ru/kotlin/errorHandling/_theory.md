**Исключение** — это способ Kotlin сообщить о том, что инструкцию невозможно выполнить. Превращение `"abc"` в число, деление целого числа на ноль или чтение за пределами списка — всё это выбрасывает исключение.

```kotlin
fun main() {
    println("before")
    val n = "abc".toInt()
    println("after")
}
```
Эта программа выводит `before` и затем останавливается. `toInt()` не может прочитать `"abc"`, поэтому **выбрасывает** `NumberFormatException`; ничто в программе не обрабатывает его, поэтому Kotlin завершает программу с сообщением об ошибке, и `after` никогда не выводится.

Вы также можете выбросить исключение сами с помощью ключевого слова `throw`:
```kotlin
throw Exception("something went wrong")
```

Исключение, которое никто не обрабатывает, — это не предупреждение: это конец выполнения.

---

Чтобы программа не завершалась, поместите рискованную инструкцию в блок `try`, а восстановление опишите в блоке `catch`:
```kotlin
try {
    println("abc".toInt())
} catch (e: Exception) {
    println("cannot read that number")
}
println("still running")
```
Kotlin выполняет блок `try`; как только инструкция внутри него выбрасывает исключение, остаток блока пропускается, и управление переходит к блоку `catch`. Имя в скобках — здесь `e` — это объект исключения, а `Exception` — перехватываемый тип.

Когда блок `catch` завершится, программа продолжит обычную работу со строки, следующей за всей конструкцией `try`/`catch`.

---

Перехват `Exception` перехватывает всё подряд, а это редко то, что нужно: опечатка в другом месте блока тоже была бы скрыта. Вместо этого указывайте **точный тип**, восстановление после которого вы умеете выполнять.

У каждого сбоя есть свой тип. `"abc".toInt()` выбрасывает `NumberFormatException`, поэтому перехватывать нужно именно его:
```kotlin
try {
    println("abc".toInt())
} catch (e: NumberFormatException) {
    println("that is not a number")
}
```
Если внутри блока выбрасывается исключение другого типа, этот `catch` не совпадает, и исключение продолжает выходить за пределы функции.

---

За одним `try` может следовать несколько блоков `catch`, каждый из которых обрабатывает свой тип:
```kotlin
val letters = listOf("a", "b")
val index = 5
val text = "abc"
try {
    println(letters[index] + text.toInt())
} catch (e: NumberFormatException) {
    println("not a number")
} catch (e: IndexOutOfBoundsException) {
    println("no such letter")
} catch (e: Exception) {
    println("something else went wrong")
}
```
Kotlin проверяет блоки **сверху вниз** и выполняет первый блок, чей тип совпадает. Выполняется только один блок.

Поэтому порядок важен. `NumberFormatException` и `IndexOutOfBoundsException` — оба являются разновидностями `Exception`, поэтому `catch (e: Exception)`, записанный первым, совпадал бы с любым сбоем, и блоки ниже него никогда не выполнялись бы. Пишите самый конкретный тип первым, а самый общий — последним.

---

В конце можно добавить блок `finally`. Он выполняется **при любом исходе**: после успешного `try`, после восстановившегося `catch` и даже когда исключение вообще не перехвачено.

```kotlin
try {
    println("reading")
    println("abc".toInt())
} catch (e: NumberFormatException) {
    println("bad number")
} finally {
    println("closing")
}
```
```
reading
bad number
closing
```
Поэтому это место для очистки, которую нельзя пропустить, например закрытия файла. `try` требует минимум `catch` или `finally`, но может иметь и оба.

---

В Kotlin `try` — это не только инструкция: это **выражение**, которое производит значение. Значение — это последнее выражение того блока, который выполнился, — блока `try`, когда ничего не сорвалось, или блока `catch`, когда сорвалось.

```kotlin
val n = try { "abc".toInt() } catch (e: NumberFormatException) { 0 }
println(n) // 0
```
Это идиоматичный приём в Kotlin. Вместо того чтобы объявлять `var`, присваивать ему значение в двух местах и надеяться, что каждый путь его установит, вы получаете один `val`, который всегда содержит пригодное значение.

Обратите внимание, что блок `finally` никогда не меняет значение: он выполняется только ради своих побочных эффектов.

---

Поскольку `try` — это выражение, его можно использовать везде, где ожидается значение, — в том числе как всё тело функции, записанной через `=`:
```kotlin
fun length(text: String): Int = try {
    text.toInt()
} catch (e: NumberFormatException) {
    -1
}
```
Оба блока должны производить значение одного и того же типа, здесь `Int`. Запишите запасное значение последним выражением блока `catch`; внутри ни одного из блоков нет `return`.

---

Выбрасывание и перехват не бесплатны, и для распространённых преобразований Kotlin предлагает более дешёвый вариант, который просто возвращает `null` вместо выбрасывания: `toIntOrNull()`, `toDoubleOrNull()`, `toLongOrNull()`.

```kotlin
println("42".toIntOrNull())  // 42
println("abc".toIntOrNull()) // null
```
В сочетании с элвис-оператором `?:`, который подставляет замену, когда значение слева равно `null`, вся конструкция `try`/`catch` сжимается в одну строку:
```kotlin
val n = "abc".toIntOrNull() ?: 0
println(n) // 0
```
Используйте `try`/`catch`, когда сбой действительно исключителен; используйте `toIntOrNull()`, когда плохой ввод ожидаем.

---

Ваши собственные функции могут отказывать плохому вводу так же, как это делает стандартная библиотека, — с помощью `throw`. Библиотека уже предоставляет тип для самого распространённого случая: `IllegalArgumentException` означает «переданное вами значение неприемлемо».

```kotlin
fun half(n: Int): Int {
    if (n < 0) throw IllegalArgumentException("n must not be negative")
    return n / 2
}
```
`throw` завершает функцию немедленно — до `return` ниже него выполнение никогда не доходит. Решает, что с этим делать, вызывающий код:
```kotlin
try { println(half(-4)) }
catch (e: IllegalArgumentException) { println("rejected") }
```
Выбросить исключение лучше, чем тихо вернуть выдуманное значение: неверный ответ уходит далеко, а исключение останавливается у первого вызывающего, готового его обработать.

---

Каждое исключение несёт текст, с которым оно было создано. Внутри блока `catch` вы читаете его через свойство `message` объекта исключения:
```kotlin
try {
    throw IllegalArgumentException("price must be positive")
} catch (e: IllegalArgumentException) {
    println(e.message) // price must be positive
}
```
`message` допускает null, потому что исключение может быть создано без какого-либо текста; `e.message ?: "unknown"` даёт безопасную замену, когда вам нужен обычный `String`.

Предпочитайте выводить `e.message`, а не сам объект исключения: собственный текст объекта включает ещё и имя класса, что является шумом для того, кто читает вывод.

---

Писать `if (...) throw IllegalArgumentException(...)` для каждого аргумента становится шумно, поэтому Kotlin предоставляет два сокращения, которые читаются как обычные предложения:

```kotlin
require(n >= 0) { "n must not be negative" }   // выбрасывает IllegalArgumentException
check(started) { "not started" }               // выбрасывает IllegalStateException
```
Оба принимают условие и блок, создающий сообщение, и оба выбрасывают исключение, **когда условие ложно**. Единственная разница — тип исключения, и эта разница — сообщение читателю:

* `require` охраняет **аргументы**, переданные вызывающим, и завершается ошибкой с `IllegalArgumentException`.
* `check` охраняет **состояние** объекта или программы и завершается ошибкой с `IllegalStateException`.

Блок вычисляется только при неудачной проверке, поэтому построение сообщения ничего не стоит, когда всё идёт хорошо.

---

Когда ни один из встроенных типов не описывает ваш сбой, объявите собственный. Исключение — это обычный класс, расширяющий `Exception` и передающий свой текст родителю:

```kotlin
class InsufficientFundsException(message: String) : Exception(message)
```
Эта одна строка — полный тип исключения. Он выбрасывается и перехватывается как любой другой, а `e.message` возвращает текст, с которым он был создан:
```kotlin
try {
    throw InsufficientFundsException("balance too low")
} catch (e: InsufficientFundsException) {
    println(e.message) // balance too low
}
```
Выигрыш — в точности: вызывающий код может перехватить только `InsufficientFundsException` и позволить всем остальным сбоям продолжить путь.

---

`runCatching` выполняет блок и никогда не выпускает исключение наружу. Вместо этого он возвращает `Result` — объект, хранящий **либо** значение, которое произвёл блок, **либо** исключение, которое он выбросил:

```kotlin
val ok = runCatching { "42".toInt() }
val bad = runCatching { "abc".toInt() }

println(ok.isSuccess)   // true
println(bad.isFailure)  // true
```
Значение затем извлекается, а вы выбираете, чем должен стать сбой:
```kotlin
println(ok.getOrNull())      // 42
println(bad.getOrNull())     // null
println(bad.getOrElse { 0 }) // 0
```
`getOrNull()` превращает сбой в `null`, а `getOrElse { ... }` выполняет блок, чтобы построить замену. В месте вызова ничего не выбрасывается, поэтому сбой можно пронести дальше и обработать позже.
