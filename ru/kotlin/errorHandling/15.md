# --description--

`Result` можно также изучать, не разворачивая его. `onFailure` выполняет свой блок только тогда, когда результат хранит исключение, `onSuccess` — только тогда, когда он хранит значение, и **оба возвращают тот же `Result`**, поэтому вызовы можно выстраивать в цепочку:

```kotlin
runCatching { "abc".toInt() }
    .onFailure { println("could not read it") }
    .onSuccess { println("read $it") }
```
Внутри блока исключение (или значение) доступно как `it`, поэтому `it.message` — это текст сбоя.

Что возвращает `onFailure`?

# --answers--

- Тот же `Result`, на котором он был вызван, поэтому после него можно выстроить в цепочку другой вызов, например `onSuccess`
- Значение, хранящееся внутри `Result`
- `null` всегда, когда `Result` хранит исключение
- Новый `Result`, который всегда считается успешным
