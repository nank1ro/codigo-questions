Некоторая работа не завершается мгновенно: загрузка файла, чтение из базы данных, ожидание таймера. Если бы программа просто останавливалась и ждала, в это время не могло бы происходить ничего другого. Swift решает эту проблему с помощью **асинхронных функций**.

Функция, помеченная **`async`**, может приостановиться посреди работы и продолжить позже. Ключевое слово ставится после списка параметров, перед стрелкой:
```swift
func fetchNumber() async -> Int {
    return 42
}
```
Вызов тоже отличается: перед вызовом нужно написать **`await`**. `await` отмечает точное место, где программа может приостановиться, и даёт готовое значение, как только функция завершится:
```swift
let n = await fetchNumber()
print(n)
// выводит 42
```
На верхнем уровне Swift-скрипта `await` уже поддерживается, поэтому асинхронные функции можно вызывать напрямую, без какой-либо дополнительной настройки. Забытые `async` или `await` — это ошибка компиляции, а не тихая ошибка.

---

Асинхронная функция остаётся обычной функцией: она может принимать параметры и возвращать значение любого типа. Меняются только две вещи: ключевое слово `async` в сигнатуре и `await` в каждом месте вызова:
```swift
func price(of quantity: Int) async -> Double {
    return Double(quantity) * 2.5
}

let total = await price(of: 4)
print(total)
// выводит 10.0
```
Возвращаемое значение — обычный `Double`, а не обёртка: когда `await` завершён, вы работаете с ним в точности как обычно.

---

Асинхронные функции обычно строятся друг на друге. Внутри `async`-функции можно вызывать с `await` любую другую `async`-функцию, а результат используется как любое обычное значение:
```swift
func base() async -> Int {
    return 10
}

func withBonus() async -> Int {
    let value = await base()
    return value + 5
}

print(await withBonus())
// выводит 15
```
`await` разрешён только внутри асинхронного контекста: `async`-функции или верхнего уровня скрипта. Обычная не-`async` функция не может использовать `await`.

---

Работа, которая происходит во времени, часто завершается ошибкой: сервер недоступен, файл отсутствует, входные данные неверны. Такая функция помечается **`async throws`** и вызывается с **`try await`**:
```swift
enum LoadError: Error {
    case missing
}

func load(_ name: String) async throws -> String {
    if name.isEmpty {
        throw LoadError.missing
    }
    return "file: \(name)"
}
```
Чтобы обработать ошибку, вы заворачиваете вызов в блок `do` и перехватываете её:
```swift
do {
    let text = try await load("")
    print(text)
} catch {
    print("could not load")
}
// выводит could not load
```
Порядок ключевых слов фиксирован: сначала `try`, затем `await`.

---

Когда вам неважно, *почему* вызов завершился ошибкой, `try?` короче, чем блок `do`. Он превращает бросающий вызов в **опциональное значение**: значение при успехе, `nil` при неудаче. В сочетании с `await` это записывается как `try? await`:
```swift
let value = try? await parse("42")  // Optional(42)
let broken = try? await parse("x")  // nil
```
Поскольку результат опциональный, он сразу подходит для `if let`:
```swift
if let value = try? await parse("x") {
    print(value)
} else {
    print("not a number")
}
```
Используйте `try? await` для быстрого запасного варианта, а `do` / `catch` — когда важна сама ошибка.

---

Несколько вызовов с `await`, записанных один за другим, выполняются **последовательно**: второй вызов даже не начнётся, пока первый не вернёт результат. Код читается сверху вниз, в точности как обычный код:
```swift
func step(_ name: String) async -> String {
    print("start \(name)")
    return "done \(name)"
}

let a = await step("A")
print(a)
let b = await step("B")
print(b)
// start A
// done A
// start B
// done B
```
Это то, что нужно, когда второй вызов требует результат первого. Когда вызовы независимы, ожидание одного перед запуском другого — потерянное время, и следующие упражнения показывают, как этого избежать.

---

Чтобы запустить два независимых вызова одновременно, объявите их с помощью **`async let`**. Работа начинается сразу, и программа продолжает выполняться, не ожидая:
```swift
async let left = step("A")
async let right = step("B")
```
Значения ещё нет, поэтому использовать привязку напрямую нельзя: `await` ставится там, где значение наконец понадобилось. Один `await` перед выражением покрывает все `async let` внутри него:
```swift
let both = await left + right
```
Если каждый вызов занимает одну секунду, последовательной версии нужны две секунды, а версии с `async let` — около одной, потому что два вызова перекрываются.

---

Когда результаты нужны по отдельности, соберите несколько привязок `async let` в кортеж и примените `await` ко всему кортежу сразу:
```swift
async let city = fetchCity()
async let country = fetchCountry()
let (a, b) = await (city, country)
```
Оба вызова уже выполнялись; единственный `await` ждёт, пока не завершится более медленный из них. Помните, что `async let` только запускает работу: если `await` для `async let` так и не был написан, оно отменяется и неявно ожидается при выходе из области видимости.

---

`async let` привязан к области видимости, в которой он написан. Чтобы запустить параллельную работу и сохранить её дескриптор, используйте **`Task`**. Замыкание, переданное в `Task { }`, выполняется само по себе, а задачу можно сохранить, передать или вернуть:
```swift
let job = Task {
    return await double(21)
}
```
Результат позже читается через **`.value`**, к которому применяется `await`:
```swift
print(await job.value)
// выводит 42
```
Тип дескриптора говорит, что он создаёт и что может бросить: `Task<Int, Never>` — это задача, которая возвращает `Int` и никогда не бросает. В отличие от `async let`, `Task` можно создать из обычного, не асинхронного кода.

---

`Task.sleep` приостанавливает текущую задачу на некоторое время, ничего не блокируя. Его можно прервать, поэтому это бросающий асинхронный вызов, требующий `try await`. Длительность задаётся вспомогательными свойствами вроде `.seconds`, `.milliseconds` или `.nanoseconds`:
```swift
func slowGreeting() async throws -> String {
    try await Task.sleep(for: .milliseconds(50))
    return "hello"
}
```
Это стандартный способ сымитировать медленную работу в примере вместо реального сетевого вызова. Заметьте, что программа не замирает: пока одна задача спит, остальные продолжают выполняться.

---

Теперь разницу между последовательным и параллельным выполнением можно измерить. Пусть `work` спит одну секунду, прежде чем вернуть результат:
```swift
func work(_ n: Int) async -> Int {
    try? await Task.sleep(for: .seconds(1))
    return n
}
```
Ожидание вызовов по одному занимает около **двух** секунд, потому что вторая пауза начинается только после окончания первой:
```swift
let a = await work(1)
let b = await work(2)
```
Запуск их с `async let` занимает около **одной** секунды, потому что обе паузы перекрываются:
```swift
async let a = work(1)
async let b = work(2)
let sum = await a + b
```
Запись `await work(1) + await work(2)` в одной строке ничего не меняет: два вызова по-прежнему вычисляются один за другим. Параллельность приходит от `async let` или задач, а не от форматирования строки.

---

`async let` подходит, когда при написании кода известно количество вызовов. Для списка, размер которого известен только во время выполнения, используйте **группу задач**.

`withTaskGroup(of:)` открывает группу, `addTask` запускает по одной дочерней задаче на каждый элемент, а затем группа читается с помощью `for await`, который выдаёт результаты по мере их готовности:
```swift
let total = await withTaskGroup(of: Int.self) { group in
    for n in numbers {
        group.addTask {
            return await square(n)
        }
    }
    var sum = 0
    for await value in group {
        sum += value
    }
    return sum
}
```
`of: Int.self` объявляет, что возвращает каждая дочерняя задача. Весь вызов `withTaskGroup` — одно выражение, поэтому перед ним нужен единственный `await`, и он не вернёт результат, пока не завершится каждая дочерняя задача.

---

Группа задач выдаёт результаты в **порядке завершения**, а не в порядке добавления задач. Самая быстрая дочерняя задача приходит первой, поэтому сбор значений в массив даёт непредсказуемый порядок.

Когда порядок важен, есть два решения. Если значения можно просто переупорядочить, отсортируйте их в конце:
```swift
return values.sorted()
```
Если каждый результат принадлежит определённой позиции, пусть каждая задача возвращает пару `(index, value)`, и записывайте её в подготовленный массив:
```swift
for (index, word) in words.enumerated() {
    group.addTask {
        return (index, await lengthOf(word))
    }
}
var result = Array(repeating: 0, count: words.count)
for await (index, value) in group {
    result[index] = value
}
```
Для суммы, максимума или количества не нужно ни то ни другое, потому что порядок значений не меняет ответ.
