# --description--

Хороший комментарий объясняет, **почему** код что-то делает, а не **что** он делает. Код уже показывает, что происходит; повторять это словами — значит добавлять шум, который устаревает, как только код меняется:
```swift
// set timeout to 30
let timeout = 30
```
Причина, стоящая за числом, — это как раз то, о чём читатель не может догадаться:
```swift
// the server drops idle connections after 35 seconds, so stop earlier
let timeout = 30
```
Если комментарий лишь пересказывает строку под ним, удалите его или замените причиной.
