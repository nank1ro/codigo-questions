**Комментарий** — это заметка, написанная внутри исходного кода для тех, кто его читает. Компилятор полностью игнорирует комментарии, поэтому они никогда не меняют то, что делает программа.

Самый простой комментарий — **однострочный**: он начинается с `//` и продолжается до конца строки.
```swift
// Greets the user
print("Hello")
```
Используйте комментарии, чтобы объяснить, для чего нужен фрагмент кода или почему он написан именно так.

---

Комментарию не нужна отдельная строка: он может идти после кода в той же строке. Это **завершающий комментарий**, и это хорошее место для короткой заметки об этой конкретной инструкции:
```swift
let retries = 3 // give up after three attempts
```
Всё от `//` до конца строки игнорируется, а код перед ним выполняется как обычно.

---

Поскольку компилятор полностью удаляет комментарии, добавление или удаление комментария никогда не меняет поведение программы. Выполняется только тот код, который **не** закомментирован.

Это делает `//` быстрым способом отключить строку кода, не удаляя её. Это называется **закомментировать**:
```swift
var total = 10
// total = total + 5
print(total) // prints 10
```
Вторая строка теперь комментарий, поэтому `total` остаётся `10`. Убрав `//`, вы вернёте строку к жизни.

Закомментировать удобно, пока вы экспериментируете, но не забывайте убирать за собой: код, который остаётся закомментированным надолго, только запутывает того, кто прочитает его следующим.

---

Когда комментарию нужно больше одной строки, Swift предлагает **многострочный комментарий** (его также называют блочным): он начинается с `/*` и заканчивается `*/`, а всё между ними игнорируется, включая переводы строк.
```swift
/*
  Prints the welcome banner.
  Called once when the app starts.
*/
print("Welcome!")
```
Блочный комментарий может быть и коротким и уместиться в одной строке: `/* like this */`.

---

В отличие от `//`, который заканчивается в конце строки, комментарий `/*` заканчивается только на `*/`. Если забыть его закрыть, компилятор посчитает весь следующий код частью комментария и сообщит об ошибке:
```swift
let width = 10 /* in centimetres
print(width) // still inside the comment: error, the comment is never closed
```
И `//`, и `/* */` работают как завершающие комментарии, но с `/*` всегда убеждайтесь, что `*/` на месте.

---

Во многих языках блочные комментарии не могут содержать другие блочные комментарии, но в Swift они **могут быть вложенными**: каждому `/*` должен соответствовать свой `*/`, и комментарий заканчивается только тогда, когда закрыт самый внешний из них.
```swift
/* outer /* inner */ still a comment */
print("done")
```
Здесь `still a comment */` — часть внешнего комментария, поэтому выводится только `done`. Именно это позволяет закомментировать целый блок кода, даже если в нём уже есть комментарий `/* */`.

---

Чтобы закомментировать сразу несколько строк, оберните их в один блочный комментарий вместо того, чтобы добавлять `//` к каждой строке:
```swift
var total = 100
/*
total = total - 30
total = total - 20
*/
print(total) // prints 100
```
Благодаря вложенности это работает, даже когда одна из этих строк уже содержит комментарий `/* */`.

---

Частое применение блочных комментариев — **заголовочный комментарий**: короткий блок, размещённый прямо над функцией, который говорит, что она делает и что означают её параметры.
```swift
/*
Returns the number of seconds in the given minutes.
minutes is a whole number, never negative.
*/
func toSeconds(_ minutes: Int) -> Int {
    return minutes * 60
}
```
Теперь тот, кто вызывает `toSeconds`, может прочитать заголовок вместо тела. Держите заголовок рядом с функцией, чтобы они обновлялись вместе.

---

В Swift есть третий вид комментариев — **документирующий комментарий**: однострочный комментарий, начинающийся с `///` (три косые черты) и размещённый прямо над функцией, типом или свойством.
```swift
/// Returns the greeting for `name`.
func greet(_ name: String) -> String {
    return "Hi, \(name)!"
}
```
Для компилятора это просто комментарий, но такие инструменты, как Xcode, читают его и показывают как справку по `greet`. Документирующие комментарии поддерживают **Markdown**, поэтому можно использовать обратные кавычки для кода, `**жирный**` и списки.

---

Первая строка документирующего комментария — это **краткое описание**: короткое предложение о том, что делает функция. Пишите его в третьем лице, как будто описываете функцию: "Returns...", "Adds...", "Checks...".
```swift
/// Returns `true` when `n` is divisible by two.
func isEven(_ n: Int) -> Bool {
    return n % 2 == 0
}
```
Комментарий должен находиться прямо над объявлением, без пустой строки между ними, иначе Xcode не свяжет его с функцией.

---

Документирующие комментарии бывают и в блочной форме: `/**` открывает его, а `*/` закрывает — точно как многострочный комментарий, но со второй звёздочкой в начале.
```swift
/**
 Returns the greeting for `name`.

 The result always ends with an exclamation mark.
 */
func greet(_ name: String) -> String {
    return "Hi, \(name)!"
}
```
Для инструментов `/// текст` и `/** текст */` означают одно и то же; `///` — самый распространённый выбор в коде на Swift, а `/** */` удобен для длинных описаний. Обычный комментарий `/* */` или `//` документацией **не** является, даже если он расположен над функцией.

---

После краткого описания документирующий комментарий может описать параметры и возвращаемое значение с помощью особых элементов списка Markdown, которые распознаёт Xcode:
```swift
/// Returns the number of seconds in the given minutes.
/// - Parameter minutes: a whole number of minutes, never negative
/// - Returns: `minutes` multiplied by sixty
func toSeconds(_ minutes: Int) -> Int {
    return minutes * 60
}
```
Порядок всегда одинаков: сначала краткое описание, затем `- Parameter имя:` для каждого параметра, затем `- Returns:`.

---

Некоторые комментарии следуют соглашению, которое понимают редакторы. В Swift самые распространённые **маркеры**:
- `// MARK: - Title` помечает раздел файла, чтобы он появился в меню навигации Xcode
- `// TODO: ...` отмечает то, что ещё предстоит написать
- `// FIXME: ...` отмечает код, о котором известно, что он неверен и должен быть исправлен

```swift
// MARK: - Setup
let limit = 10
// TODO: read the limit from the settings
// FIXME: crashes when the list is empty
```
Для компилятора это обычные комментарии; Xcode перечисляет их, чтобы незавершённую работу было легко найти. Когда работа сделана, удалите маркер: устаревший `TODO` вводит в заблуждение.

---

`TODO` обычно стоит рядом с заглушкой, которая позволяет коду компилироваться, пока не написана настоящая реализация. Когда вы завершаете работу, замените заглушку и уберите маркер в том же изменении, чтобы комментарий никогда не лгал о состоянии кода.

---

`FIXME` отличается от `TODO`: код уже существует, но известно, что он неверен. Хороший `FIXME` говорит, в чём ошибка, и по возможности приводит пример, который её показывает, чтобы следующий человек мог быстро её исправить. Как и с `TODO`, удалите маркер, когда ошибка исправлена, но сохраните документирующий комментарий — он по-прежнему верен.

---

Хороший комментарий объясняет, **почему** код что-то делает, а не **что** он делает. Код уже показывает, что происходит; повторять это словами — значит добавлять шум, который устаревает, как только код меняется:
```swift
// set timeout to 30
let timeout = 30
```
Причина, стоящая за числом, — это как раз то, о чём читатель не может догадаться:
```swift
// the server drops idle connections after 35 seconds, so stop earlier
let timeout = 30
```
Если комментарий лишь пересказывает строку под ним, удалите его или замените причиной.
