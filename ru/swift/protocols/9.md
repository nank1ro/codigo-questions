# --description--

Расширение **протокола** — другой инструмент: оно добавляет члены каждому соответствующему типу, как существующему, так и будущему. Так вы даёте требованию **реализацию по умолчанию**:
```swift
protocol Greeter {
    var name: String { get }
    func greet() -> String
}

extension Greeter {
    func greet() -> String {
        return "Hi, \(name)"
    }
}

struct Person: Greeter {
    var name: String
}

print(Person(name: "Ada").greet()) // Hi, Ada
```
`Person` никогда не пишет `greet()` и всё же соответствует. Внутри расширения протокола можно использовать любое требование протокола — здесь `name`, — потому что любой соответствующий тип гарантированно его имеет.

Корзина с `fig` и `plum` должна выдавать сводку `2 items`

```swift
tryCatch(Fruits(items: ["fig", "plum"]).summary() == "2 items")
```

Пустая корзина должна выдавать сводку `0 items`

```swift
tryCatch(Fruits(items: []).summary() == "0 items")
```

Корзина с тремя фруктами должна выдавать сводку `3 items`

```swift
tryCatch(Fruits(items: ["fig", "plum", "pear"]).summary() == "3 items")
```

Другой тип `Basket`, не записывающий метод, должен выдавать сводку `1 items`

```swift
tryCatch(_Veg(items: ["pea"]).summary() == "1 items")
```

```swift
protocol Basket {
    var items: [String] { get }
    func summary() -> String
}

extension Basket {
    func summary() -> String {
        return "\(items.count) items"
    }
}

struct Fruits: Basket {
    var items: [String]
}
```
