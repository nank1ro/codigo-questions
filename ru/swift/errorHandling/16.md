# --description--

Всё в этой главе отвечает на один вопрос: кто разбирается со сбоем?

Выбрасывающая ошибку функция отказывается на него отвечать. Она называет, что пошло не так, — вариант перечисления `Error`, несущий всё, что понадобится обработчику, — и передаёт решение выше. Затем вызывающий код выбирает инструмент: `do`/`catch`, чтобы реагировать по каждому варианту отдельно, `try?` и `??`, чтобы вернуться к значению по умолчанию, `defer`, чтобы прибраться на выходе в любом случае.

Именно в этом разделении весь смысл. Функция, обнаружившая проблему, редко знает, что должно произойти дальше, а код, который это знает, редко хочет повторять проверку.

# --instructions--

Напишите валидатор, используя всё из этой главы:
- дайте `FormError` второй вариант `tooLong`, несущий `maximum` типа `Int`
- `validate` выбрасывает `FormError.empty`, когда имя пустое, выбрасывает `FormError.tooLong(maximum: 10)`, когда имя длиннее 10 символов, и иначе возвращает само имя
- `safeName` возвращает проверенное имя или `"guest"`, когда `validate` выбрасывает ошибку

Пример использования:
```swift
print(safeName(""))
// выводит guest
```

func _kind(_ name: String) -> String {
    do {
        return try validate(name)
    } catch FormError.empty {
        return "empty"
    } catch FormError.tooLong(let maximum) {
        return "max \(maximum)"
    } catch {
        return "other"
    }
}

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
