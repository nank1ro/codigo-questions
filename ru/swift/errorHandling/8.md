# --description--

Иногда неважно *почему* что-то завершилось неудачей, — важно лишь то, что это произошло. `try?` превращает вызов с `throws` в **опциональное значение**: значение при успехе, `nil` при выброшенной ошибке.
```swift
enum ParseError: Error {
    case notANumber
}

func toInt(_ text: String) throws -> Int {
    guard let value = Int(text) else {
        throw ParseError.notANumber
    }
    return value
}

if let number = try? toInt("42") {
    print(number) // 42
}
```
Никакого `do`, никакого `catch`: сбой спрятан в опциональное значение, разворачивать которое вы уже умеете. Плата за это — потерянное значение ошибки, поэтому прибегайте к `try?` только тогда, когда сообщать действительно не о чем.
