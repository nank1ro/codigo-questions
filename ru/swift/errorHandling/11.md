# --description--

Когда функция выбрасывает ошибку, всё после `throw` пропускается — включая строку, которая должна была закрыть файл или освободить блокировку. `defer` решает эту проблему: он регистрирует блок сразу, а выполняет его, когда заканчивается текущая область видимости, каким бы образом она ни закончилась.
```swift
func load() throws {
    print("open")
    defer { print("close") }
    throw FileError.missing
}
```
Этот вызов печатает `open`, затем `close`, и только потом ошибка уходит вызывающему коду. Вернись функция обычным образом, `close` всё равно напечатался бы — в этом и смысл. Разместите очистку рядом с подготовкой и перестаньте беспокоиться о том, каким выходом завершится код.

# --seed--

```swift
enum TaskError: Error {
    case failed
}

func steps(_ shouldFail: Bool) -> [String] {
    var log: [String] = []
    func run() throws {
        log.append("start")
        
        if shouldFail {
            throw TaskError.failed
        }
        log.append("done")
    }
    do {
        try run()
    } catch {
        log.append("caught")
    }
    return log
}
```

# --asserts--

на успешном пути журнал должен быть `start`, `done`, `cleanup`

```swift
let _ok: [String] = steps(false)
tryCatch(_ok == ["start", "done", "cleanup"])
```

на пути с ошибкой журнал должен быть `start`, `cleanup`, `caught`

```swift
let _bad: [String] = steps(true)
tryCatch(_bad == ["start", "cleanup", "caught"])
```

очистка должна выполняться на обоих путях

```swift
tryCatch(steps(false).contains("cleanup") && steps(true).contains("cleanup"))
```

очистка должна выполняться ровно один раз на пути с ошибкой

```swift
let _once: [String] = steps(true)
tryCatch(_once.filter { $0 == "cleanup" }.count == 1)
```
