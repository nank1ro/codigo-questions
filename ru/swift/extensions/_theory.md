**Расширение** добавляет новую функциональность существующему типу: стандартному типу библиотеки вроде `Int` или `String` или написанной вами структуре либо классу.
Вы пишете ключевое слово `extension`, за которым следует имя типа, и помещаете новые члены между фигурными скобками:
```swift
extension Int {
    func squared() -> Int {
        return self * self
    }
}
print(4.squared()) // 16
```
Внутри расширения `self` — это значение, для которого вызван метод: в `4.squared()` это `4`. Как только расширение создано, каждый `Int` в программе получает новый метод — в точности так, будто он был частью `Int` с самого начала.

---

Расширения работают с любым типом, даже с тем, для которого у вас нет исходного кода. `String` берётся из стандартной библиотеки, но вы всё равно можете добавить ей новые методы:
```swift
extension String {
    func whisper() -> String {
        return self.lowercased() + "..."
    }
}
print("HELLO".whisper()) // hello...
```
Внутри расширения можно опускать `self.` при вызове других членов типа: одно лишь `lowercased()` означает `self.lowercased()`.

---

Расширение не создаёт новый тип и не копирует старый: оно добавляет члены самому типу, поэтому каждое существующее и будущее значение этого типа получает их.
Вот почему расширения так полезны с типами, которые вы не можете редактировать, например с типами из стандартной библиотеки или фреймворка: вы не можете открыть файл, где определён `Int`, но можете расширить его из любого файла вашей программы.
```swift
extension Int {
    func isDivisible(by other: Int) -> Bool {
        return self % other == 0
    }
}
let n = 12
print(n.isDivisible(by: 4)) // true
```

---

Помимо методов, расширение может добавлять **вычисляемые свойства**: свойства, которые не хранят значение, а вычисляют его при каждом чтении.
Вычисляемое свойство объявляется с помощью `var`, аннотации типа и тела между фигурными скобками, которое возвращает значение:
```swift
extension Int {
    var isNegative: Bool {
        return self < 0
    }
}
print((-3).isNegative) // true
print(7.isNegative)    // false
```
Оно читается как любое свойство, без круглых скобок: `7.isNegative`, а не `7.isNegative()`.

---

Вычисляемые свойства в расширениях естественно подходят и для `String`. Метод `reversed()` возвращает символы в обратном порядке, а `String(...)` превращает их обратно в строку:
```swift
extension String {
    var backwards: String {
        return String(reversed())
    }
}
print("swift".backwards) // tfiws
```
Как и с методами, `reversed()` внутри расширения означает `self.reversed()`.

---

Расширения могут добавлять вычисляемые свойства, но **не хранимые свойства**: это не компилируется:
```swift
extension Int {
    var label = "number" // error: extensions must not contain stored properties
}
```
Хранимое свойство требует места внутри каждого экземпляра типа. Значения `Int` уже существуют по всей вашей программе и даже в коде, скомпилированном задолго до вашего расширения, поэтому их раскладка памяти не может измениться. Вычисляемому свойству место не нужно, потому что это просто код, который выполняется при чтении свойства.

---

`Int`, `String`, массивы и структуры — это **типы значений**: метод не может изменить значение, для которого он вызван, если он не помечен как `mutating`. Расширения тоже могут добавлять мутирующие методы:
```swift
extension Int {
    mutating func increment() {
        self += 1
    }
}
var count = 1
count.increment()
print(count) // 2
```
Внутри мутирующего метода можно присваивать `self`. Значение должно храниться в `var`: вызов `increment()` для константы `let` — ошибка компиляции.

---

Мутирующий метод может принимать параметры, как любой другой метод, и может полностью заменить `self` вместо обновления на месте:
```swift
extension Int {
    mutating func reset(to value: Int) {
        self = value
    }
}
var score = 42
score.reset(to: 0)
print(score) // 0
```

---

Расширение может добавлять типу новые **инициализаторы**. Для структуры это лучшее место для них: `init`, написанный внутри тела структуры, заменяет автоматический memberwise-инициализатор, а добавленный в расширении сохраняет его.
Новый инициализатор обычно делегирует существующему с помощью `self.init(...)`:
```swift
struct Size {
    var width: Double
    var height: Double
}
extension Size {
    init(square side: Double) {
        self.init(width: side, height: side)
    }
}
let a = Size(square: 3)          // from the extension
let b = Size(width: 2, height: 5) // memberwise, still available
```

---

Расширения нужны не только для чужих типов. Обычный способ организовать собственный код — хранить хранимые свойства в теле структуры или класса, а поведение добавлять в одном или нескольких расширениях, каждое из которых группирует связанные члены:
```swift
struct Circle {
    var radius: Double
}
extension Circle {
    var diameter: Double {
        return radius * 2
    }
    func grown(by amount: Double) -> Circle {
        return Circle(radius: radius + amount)
    }
}
```
Члены, добавленные в расширении, могут использовать хранимые свойства напрямую, в точности как если бы они были написаны внутри типа.

---

Расширение также может заставить тип соответствовать **протоколу** — списку требований, которые тип обещает реализовать. Напишите имя протокола после имени типа, разделив их двоеточием, и добавьте требуемые члены в тело.
`CustomStringConvertible` — стандартный протокол с одним требованием, вычисляемым свойством `description` типа `String`, которое `print` использует для отображения значения:
```swift
struct Dog {
    var name: String
}
extension Dog: CustomStringConvertible {
    var description: String {
        return "Dog named \(name)"
    }
}
print(Dog(name: "Rex")) // Dog named Rex
```
Хранение каждого соответствия протоколу в отдельном расширении — обычный способ организовать тип в Swift.

---

`Array` — обобщённый тип: `[Int]` и `[String]` — оба массивы, но с разным типом **`Element`**. Расширение `Array` применяется ко всем им, что является проблемой, когда новый член имеет смысл лишь для некоторых элементов: нельзя складывать числа, которые являются строками.
Условие `where` ограничивает расширение массивами, чей `Element` имеет заданный тип:
```swift
extension Array where Element == Int {
    var largest: Int {
        var result = Int.min
        for number in self {
            if number > result {
                result = number
            }
        }
        return result
    }
}
print([3, 9, 2].largest) // 9
```
`[3, 9, 2].largest` работает, а `["a", "b"].largest` — ошибка компиляции: свойства не существует у `[String]`.

---

Расширения могут добавлять **статические** члены: свойства и методы, принадлежащие самому типу, а не отдельному значению, помеченные ключевым словом `static` и доступные через имя типа.
`static let` разрешён, даже если он хранит значение, потому что существует только одна копия для всего типа, а не по одной на экземпляр:
```swift
extension Int {
    static let answer = 42
    static func zeroes(_ count: Int) -> [Int] {
        return Array(repeating: 0, count: count)
    }
}
print(Int.answer)     // 42
print(Int.zeroes(3))  // [0, 0, 0]
```
У статического члена нет значения `self` для работы: `Int.answer` читается на типе, а не на числе.

---

Статические методы в расширениях — хорошее место для небольших фабричных функций, создающих значение типа. `String(repeating:count:)` — стандартный инициализатор, который повторяет фрагмент текста заданное число раз:
```swift
extension String {
    static func dashes(_ count: Int) -> String {
        return String(repeating: "-", count: count)
    }
}
print(String.dashes(4)) // ----
```

---

Расширения могут только **добавлять** члены, но никогда не заменяют и не переопределяют существующие. `override` принадлежит подклассам, которые являются другим типом по сравнению с родителем; расширение — тот же тип, поэтому объявление уже существующего метода является ошибкой повторного объявления:
```swift
struct Dog {
    func speak() -> String {
        return "Woof"
    }
}
extension Dog {
    func speak() -> String { // error: invalid redeclaration of 'speak()'
        return "Bark"
    }
}
```
Если вам нужно другое поведение, добавьте метод с новым именем или напишите подкласс, если тип — класс.
