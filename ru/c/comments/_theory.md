**Комментарий** — это текст внутри исходного кода, предназначенный для людей, а не для компилятора. Компилятор отбрасывает комментарии, прежде чем собрать программу, поэтому их можно использовать, чтобы объяснить, для чего нужен код, оставить напоминание или зафиксировать принятое решение.

Самый распространённый вид — **однострочный комментарий**: всё от `//` до конца строки игнорируется.
```c
// Greet the user
printf("Hello\n");
```
Первая строка ничего не делает при запуске программы; только `printf` выводит текст.

---

Поскольку компилятор полностью удаляет комментарии, добавление или удаление комментария никогда не меняет то, что делает программа. Выполняется только код, который **не** закомментирован.

Поэтому `//` — это быстрый способ выключить строку кода, не удаляя её. Это называется **комментированием**:
```c
int total = 10;
// total = total + 5;
printf("%d\n", total); // prints "10"
```
Вторая строка теперь комментарий, поэтому `total` остаётся равным `10`. Если убрать `//`, строка снова заработает.

Комментирование удобно во время экспериментов, но не забывайте прибираться: код, который долго остаётся закомментированным, только путает того, кто будет читать его после вас.

---

Когда комментарий занимает больше одной строки, в C есть **многострочный комментарий** (его также называют блочным): он начинается с `/*` и заканчивается `*/`, а всё между ними игнорируется, включая переносы строк.
```c
/*
  Prints the welcome banner.
  Called once when the program starts.
*/
printf("Welcome!\n");
```
Блочный комментарий может быть коротким и умещаться на одной строке: `/* like this */`.

В отличие от `//`, который останавливается в конце строки, комментарий `/*` останавливается только на `*/`. Если забыть его закрыть, компилятор сочтёт весь последующий код частью комментария.

---

Блочные комментарии **не вкладываются** друг в друга. Компилятор завершает комментарий `/*` на самом первом найденном `*/`, сколько бы `/*` ни встретилось до него:
```c
/* outer /* inner */ still code */
```
Здесь комментарий заканчивается сразу после `inner`, поэтому `still code */` компилируется как код и приводит к ошибке.

Это важно, когда нужно закомментировать блок, внутри которого уже есть комментарий `/* */`: внутренний `*/` преждевременно закроет внешний комментарий. В таком случае вместо этого поставьте `//` в начале каждой строки.

---

Комментарию не обязательно занимать отдельную строку: он может идти за кодом в той же строке. Это **комментарий в конце строки** — хорошее место для короткой заметки о конкретной инструкции:
```c
int retries = 3; // give up after three attempts
```
И `//`, и `/* */` работают как комментарии в конце строки, но будьте осторожны с `/*`: поскольку он останавливается только на `*/`, незакрытый `/*` в конце строки поглотит все последующие строки, и программа перестанет компилироваться.

---

Распространённое применение блочных комментариев — **комментарий-заголовок**: небольшой блок прямо над функцией, в котором сказано, что она делает, что означают её параметры и что она возвращает.
```c
/*
 * Returns the number of seconds in the given minutes.
 * minutes: a whole number of minutes, never negative
 */
int to_seconds(int minutes) {
    return minutes * 60;
}
```
Тот, кто вызовет `to_seconds`, сможет прочитать заголовок вместо тела функции. Держите заголовок рядом с функцией, чтобы их обновляли вместе.

---

Компилятор заменяет каждый комментарий одним пробелом. Это значит, что комментарий `/* */` может стоять везде, где допустим пробел, даже в середине инструкции или выражения:
```c
int area = width /* cm */ * height /* cm */;
```
Это иногда полезно, чтобы подписать операнды или аргументы вызова. Комментарий `//` так не может: он закомментировал бы остаток строки, включая код после него.

---

Программисты ставят несколько общепринятых ключевых слов в начало комментария, чтобы пометить незавершённую работу:

- `TODO` помечает то, что ещё нужно написать
- `FIXME` помечает код, о котором известно, что он неверен и который нужно исправить

```c
// TODO: validate the input before using it
// FIXME: crashes when the list is empty
```
Редакторы и инструменты умеют перечислять такие метки, поэтому незавершённую работу легко найти. Когда работа сделана, удалите метку: устаревший `TODO` только вводит в заблуждение.

---

Хороший комментарий объясняет, **почему** код что-то делает, а не **что** он делает. Код и так показывает, что происходит; повторение словами добавляет шум и устаревает, как только код меняется:
```c
// multiply price by 90 and divide by 100
return price * 90 / 100;
```
Причина, стоящая за числами, — это то, что читатель не сможет угадать:
```c
// launch discount: members get 10% off until the end of June
return price * 90 / 100;
```
Если комментарий лишь повторяет строку под ним, удалите его или замените причиной.

---

Соберём всё вместе: используйте `//` для коротких заметок и комментариев в конце строки, `/* */` для длинных блоков и комментариев-заголовков, помечайте незавершённую работу через `TODO` или `FIXME`, а закомментированный код и устаревшие метки удаляйте, когда они больше не нужны.
