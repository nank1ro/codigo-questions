Иногда у переменной ещё **нет значения**, которое можно было бы хранить: пользователь не вошёл в систему, поиск ничего не нашёл, настройка так и не была выбрана. Python представляет это специальным значением `None`.
`None` — это значение, как и любое другое: его можно присваивать, печатать и передавать в функции. Его тип — `NoneType`, и во всей программе существует ровно **один** `None`, поэтому каждый написанный вами `None` ссылается на один и тот же объект:
```python
winner = None
print(winner)                 # None
print(type(winner).__name__)  # NoneType
print(winner is None)         # True
```
`None` — это не `0`, не пустая строка и не `False`: это отдельное значение, которое означает "здесь ничего нет".

---

Каждый вызов функции даёт значение, даже если функция, кажется, ничего не возвращает. Функция **без** инструкции `return` или с пустым `return` возвращает `None`:
```python
def say_hello():
    print("hello")

result = say_hello()
print(result)  # None
```
Именно поэтому вызов `print(my_list.append(3))` показывает `None`: `append` изменяет список на месте и не возвращает ничего.
Функция, которая только выполняет действие (печать, сохранение, изменение списка), обычно возвращает `None`, а функция, которая что-то вычисляет, должна явно вернуть результат с помощью `return`.

---

Чтобы проверить, содержит ли переменная `None`, используйте `is` и `is not`, но никогда `==`:
```python
if user is None:
    print("nobody logged in")
if user is not None:
    print("welcome")
```
`==` спрашивает "*равны* ли эти значения?", и любой класс может ответить на этот вопрос по-своему, определив метод `__eq__`. `is` спрашивает "являются ли они *одним и тем же объектом*?", и ничто не может изменить ответ.
Поскольку `None` существует только в одном экземпляре, `is None` всегда корректен и немного быстрее, а `== None` может дать неожиданный ответ для объектов с собственным `__eq__`.

---

`None` считается **ложным** в условии, поэтому `if not value:` даёт `True`, когда `value` — это `None`. Соблазнительно использовать это как проверку на `None`, но тот же тест будет `True` и для `0`, `""`, `[]` и любого другого пустого значения:
```python
count = 0
if not count:
    print("missing?")   # printed, but 0 is a real value!
```
Когда "нет значения" и "пустое значение" должны обрабатываться по-разному, сначала проверьте `is None`, а затем истинность:
```python
if count is None:
    print("no count yet")
elif not count:
    print("count is zero")
```
Используйте `if not value:` только тогда, когда вы действительно хотите обрабатывать `None` и пустые значения одинаково.

---

Параметр может иметь **значение по умолчанию**, которое используется, когда вызывающий код опускает аргумент. `None` — обычное значение по умолчанию для случая "не предоставлено":
```python
def greet(name=None):
    if name is None:
        name = "stranger"
    print("Hello, " + name)

greet()       # Hello, stranger
greet("Ada")  # Hello, Ada
```
Это важно для списков и словарей. Значение по умолчанию вычисляется **один раз**, при определении функции, поэтому `def add(item, items=[])` использует один и тот же список во всех вызовах, где `items` опущен, и элементы накапливаются. Решение — использовать `None` по умолчанию и создавать новый список внутри функции:
```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

---

Чтение отсутствующего ключа из словаря с помощью `[]` вызывает `KeyError`. Метод `get` — безопасная альтернатива: он возвращает значение, когда ключ существует, и `None`, когда его нет:
```python
ages = {"Ada": 36}
print(ages.get("Ada"))    # 36
print(ages.get("Grace"))  # None
```
`get` принимает второй аргумент — значение, которое нужно вернуть **вместо** `None`, когда ключ отсутствует:
```python
print(ages.get("Grace", 0))  # 0
```
Это самый распространённый способ появления `None` в повседневном коде: поиск, который ничего не нашёл.

---

Функция, которая возвращает число **или** `None`, должна сообщать об этом в своей сигнатуре. **Аннотация типа** — это аннотация, которая документирует ожидаемый тип: `name: str` для параметра и `-> int` для возвращаемого значения. Python не требует соблюдать аннотации, но редакторы и читатели полагаются на них:
```python
def parse_age(text: str) -> int | None:
    if text.isdigit():
        return int(text)
    return None
```
`int | None` читается как "`int` или `None`". Более старая запись `Optional[int]` из модуля `typing` означает ровно то же самое, и вы всё ещё встретите её в существующем коде.
Каждый раз, видя `| None` в сигнатуре, не забывайте проверять результат перед использованием.

---

Функции, которые могут получить `None`, часто начинаются с **защитной проверки**: условия `if`, которое завершает функцию досрочно, когда не с чем работать. Остальная часть функции может затем считать, что значение присутствует, не оборачивая весь код в `else`:
```python
def shout(text):
    if text is None:
        return None
    return text.upper() + "!"
```
Защитные проверки идут первыми, в том порядке, в котором проверки должны выполняться: нельзя вызвать `text.split()`, не зная, что `text` — не `None`.

---

Оператор `or` не возвращает `True` или `False`: он возвращает свой **левый** операнд, если тот истинен, и **правый** операнд в противном случае. Это даёт способ предоставить запасное значение в одну строку:
```python
name = None
print(name or "anonymous")  # anonymous
name = "Ada"
print(name or "anonymous")  # Ada
```
Хитрость в том, что `or` смотрит на истинность, а не на `None`: `0`, `""` и `[]` тоже заменяются запасным значением. Используйте `x or fallback`, только когда каждое пустое значение тоже должно становиться запасным.

---

Когда `0` или `""` нужно сохранить, а заменить только `None`, для запасного значения требуется явная проверка `is None`. Компактная форма — **условное выражение** `a if condition else b`, которое вычисляется в `a`, когда условие истинно, и в `b` в противном случае:
```python
timeout = 0
seconds = timeout if timeout is not None else 30
print(seconds)  # 0, not 30
```

---

Список может содержать `None` рядом с настоящими значениями, например показания, которые не удалось снять, или ответы, которые были пропущены. Большинство операций не принимают его: `sum([8, None])` вызывает `TypeError`.
Отфильтруйте значения `None` с помощью генератора списка, условие которого — `is not None`:
```python
readings = [3, None, 5]
valid = [r for r in readings if r is not None]
print(valid)  # [3, 5]
```
Использование `if r` вместо этого отбросило бы и каждый `0`, поэтому будьте явны, когда ноль — допустимое показание.

---

Поиск с последующей проверкой на `None` обычно требует двух строк: одна для сохранения результата, другая для его проверки. Оператор **выражения присваивания** `:=`, по прозвищу *walrus*, присваивает значение **внутри** выражения, поэтому оба шага помещаются в `if`:
```python
ages = {"Ada": 36}
if (age := ages.get("Ada")) is not None:
    print(age + 1)  # 37
```
Скобки обязательны: без них `:=` попытается присвоить всё сравнение целиком. После `if` переменная `age` остаётся доступной, как и любая другая переменная.

---

Не всякое "не найдено" сообщается с помощью `None`. Некоторые старые функции возвращают вместо него **сторожевое** значение — обычное значение, которому придан особый смысл. Строковый метод `find` возвращает индекс подстроки или `-1`, когда её нет:
```python
print("banana".find("n"))  # 2
print("banana".find("x"))  # -1
```
Функция `re.match(pattern, text)` из модуля `re` проверяет, начинается ли `text` с `pattern`, и возвращает объект совпадения или `None`, когда совпадения нет.
`None` — более безопасное соглашение: `-1` является допустимым индексом, поэтому `text[text.find("x")]` молча возвращает последний символ вместо того, чтобы завершиться ошибкой, в то время как использование `None` в качестве индекса вызывает ошибку сразу.

---

`None` нельзя упорядочивать: `None < 1` вызывает `TypeError`, потому что Python понятия не имеет, будет ли "ничто" меньше или больше числа.
Это важно, когда `None` используется в качестве начального значения поиска, например "лучшее значение из увиденных, если оно есть". Каждое сравнение должно быть защищено проверкой `is None`, размещённой **первой**, чтобы `or` сокращал вычисление и сравнение пропускалось, когда пока не с чем сравнивать:
```python
if best is None or value > best:
    best = value
```
Написанное наоборот, `value > best or best is None` сравнивало бы с `None` на первой итерации и аварийно завершалось.
