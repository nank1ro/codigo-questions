Некоторые операции занимают время: чтение файла, обращение к серверу, ожидание таймера. Python может выполнять такой код **асинхронно** с помощью модуля `asyncio`, так что одна задача может ждать, не блокируя остальные.

Функция, определённая с `async def`, — это **функция-сопрограмма**. Её вызов не выполняет тело: она возвращает **объект-сопрограмму**, описывающий работу, которую нужно сделать. `asyncio.run(coro)` запускает цикл событий, выполняет сопрограмму до завершения и останавливает цикл:
```python
import asyncio

async def greet():
    print("hello")

asyncio.run(greet())  # hello
```
`asyncio.run` — это точка входа асинхронной программы; её вызывают один раз из обычного синхронного кода.

---

Сопрограмма может принимать параметры и возвращать значение с помощью `return` точно так же, как обычная функция. Значение недоступно в момент создания объекта-сопрограммы — только после того, как сопрограмма была выполнена. `asyncio.run` возвращает то, что вернула сопрограмма:
```python
import asyncio

async def double(n):
    return n * 2

result = asyncio.run(double(21))
print(result)  # 42
```
Всё, что вы знаете о функциях, работает и внутри `async def`: локальные переменные, условия, циклы и несколько инструкций `return`.

---

`await` приостанавливает текущую сопрограмму, пока ожидаемая операция не завершится, а затем отдаёт её результат. Пока сопрограмма приостановлена, цикл событий свободно выполняет другие сопрограммы. `await` разрешён только внутри `async def`.

`asyncio.sleep(seconds)` — простейший ожидаемый объект: он ждёт указанное время, не блокируя цикл. В отличие от `time.sleep`, его нужно ожидать с помощью `await`:
```python
import asyncio

async def countdown():
    print("ready")
    await asyncio.sleep(0.05)
    print("go")

asyncio.run(countdown())
```
Программа выводит `ready`, ждёт 50 миллисекунд и выводит `go`. Запись `asyncio.sleep(0.05)` без `await` создаёт объект-сопрограмму, но никогда не запускает его, поэтому никакого ожидания не происходит.

---

Вызова функции-сопрограммы недостаточно, чтобы её выполнить. Вызов лишь создаёт объект-сопрограмму; тело выполняется, когда этот объект ожидают с `await` или передают в `asyncio.run`:
```python
async def hello():
    print("hi")

hello()  # nothing is printed
```
Python даже предупреждает об этом: `RuntimeWarning: coroutine 'hello' was never awaited`. Забытый `await` — самая распространённая асинхронная ошибка: код выглядит вызванным, но никогда не выполняется, а переменная, которая должна была хранить его результат, вместо этого хранит объект-сопрограмму.

---

Сопрограммы вызывают друг друга с помощью `await`. Сопрограмма может ожидать любую другую сопрограмму, получать её возвращаемое значение и продолжать работу — совсем как цепочка вызовов функций:
```python
import asyncio

async def fetch_price(item):
    await asyncio.sleep(0.01)  # simulates a slow lookup
    return 10

async def total(item, quantity):
    price = await fetch_price(item)
    return price * quantity

print(asyncio.run(total("pen", 3)))  # 30
```
Через `asyncio.run` проходит только самая внешняя сопрограмма; до каждой внутренней добираются с помощью `await`. Если бы `total` была обычной `def`, она вообще не могла бы использовать `await`: ключевое слово `async` распространяется на каждую функцию в цепочке, которой нужно ждать.

---

Ожидание сопрограмм одна за другой выполняет их **последовательно**: три ожидания по 10 миллисекунд занимают 30 миллисекунд. `asyncio.gather` выполняет несколько сопрограмм **конкурентно**: пока одна спит, остальные продвигаются вперёд, поэтому три ожидания вместе занимают около 10 миллисекунд. Она возвращает список с результатами в том же порядке, что и аргументы:
```python
import asyncio

async def double(n):
    await asyncio.sleep(0.01)
    return n * 2

async def main():
    results = await asyncio.gather(double(1), double(2), double(3))
    print(results)  # [2, 4, 6]

asyncio.run(main())
```
Саму `gather` нужно ожидать с `await`, и она принимает сопрограммы как отдельные аргументы. Чтобы передать список, распакуйте его: `asyncio.gather(*coroutines)`.

---

Конкурентность окупается, когда количество операций не фиксировано. Создайте объекты-сопрограммы в списковом включении, распакуйте их в `gather` и ожидайте всю партию сразу:
```python
import asyncio

async def fetch(url):
    await asyncio.sleep(0.02)
    return len(url)

async def fetch_all(urls):
    return await asyncio.gather(*[fetch(u) for u in urls])

print(asyncio.run(fetch_all(["a.com", "bb.com"])))  # [5, 6]
```
Десять url-адресов по-прежнему занимают суммарно около 20 миллисекунд вместо 200, а результаты остаются в порядке url-адресов.

---

С `gather` сопрограммы сменяют друг друга на каждом `await`. Сопрограмма выполняется, пока не ожидает что-то, что ещё не готово, — тогда цикл переключается на другую. Поэтому побочные эффекты вроде `print` происходят в том порядке, в котором сопрограммы **возобновляются**, а не в том, в каком они были переданы:
```python
import asyncio

async def step(name, delay):
    await asyncio.sleep(delay)
    print(name)
    return name

async def main():
    print(await asyncio.gather(step("a", 0.03), step("b", 0.01)))

asyncio.run(main())
```
Это выводит `b`, затем `a`, затем `['a', 'b']`: `b` просыпается первой, но список результатов сохраняет порядок аргументов.

---

Небольшая асинхронная программа следует фиксированной форме: импортируйте `asyncio`, определите функции-сопрограммы, определите сопрограмму `main`, которая ожидает их с `await`, и в конце один раз вызовите `asyncio.run(main())`.

---

`asyncio.create_task(coro)` оборачивает сопрограмму в **задачу** (Task) и планирует её выполнение в фоне. В отличие от `await`, он возвращается немедленно, поэтому текущая сопрограмма может продолжать работать, пока задача выполняется. На самом деле задача стартует в следующий раз, когда текущая сопрограмма приостановится на `await`. Последующее ожидание задачи с `await` даёт её результат:
```python
import asyncio

async def background():
    print("task started")
    await asyncio.sleep(0.01)
    return "task done"

async def main():
    task = asyncio.create_task(background())
    print("main continues")
    print(await task)

asyncio.run(main())
```
Это сначала выводит `main continues`, потому что `background` стартует только тогда, когда `main` ожидает с `await`, а затем `task started` и `task done`.

---

Задача продолжает выполняться независимо от того, ждёт ли её кто-нибудь. Создайте её заранее, выполняйте другую работу и ожидайте её с `await` только там, где нужен её результат: ожидание короче, потому что часть задачи уже выполнена в фоне. Задачу также можно проверить с помощью `task.done()`, которая возвращает `True`, как только задача завершилась.

---

Исключение, возникшее внутри сопрограммы, не появляется там, где был создан объект-сопрограмма: оно возникает в `await`, который её выполняет, или в `asyncio.run` — для самой внешней. Поэтому `try`/`except` должен обрамлять именно **`await`**:
```python
import asyncio

async def load(path):
    await asyncio.sleep(0.01)
    if path == "":
        raise FileNotFoundError("empty path")
    return "contents"

async def safe_load(path):
    try:
        return await load(path)
    except FileNotFoundError:
        return ""

print(asyncio.run(safe_load("")))  # prints an empty line
```
Исключение, которое никто не перехватывает, распространяется через каждый `await` вплоть до `asyncio.run`, который выбрасывает его заново в синхронном коде — совсем как обычный стек вызовов.

---

Когда одна из сопрограмм, переданных в `gather`, выбрасывает исключение, оно распространяется до строки `await asyncio.gather(...)`, и результаты остальных теряются, хотя они продолжают выполняться. Передача `return_exceptions=True` меняет это: `gather` никогда не выбрасывает исключений, а объект исключения занимает место отсутствующего результата в списке:
```python
import asyncio

async def ok():
    return 1

async def fail():
    raise ValueError("bad")

async def main():
    results = await asyncio.gather(ok(), fail(), return_exceptions=True)
    print(results)  # [1, ValueError('bad')]

asyncio.run(main())
```
Затем каждый элемент можно проверить с помощью `isinstance(result, Exception)`, чтобы отделить неудачи от значений.

---

`asyncio.wait_for(awaitable, timeout)` ожидает переданный объект, но сдаётся по истечении `timeout` секунд: операция отменяется и выбрасывается `TimeoutError`, который можно перехватить, как любое исключение:
```python
import asyncio

async def slow():
    await asyncio.sleep(0.05)
    return "done"

async def main():
    try:
        result = await asyncio.wait_for(slow(), timeout=0.01)
        print(result)
    except TimeoutError:
        print("timed out")

asyncio.run(main())  # timed out
```
С таймаутом `0.1` тот же код вывел бы `done`. `asyncio.TimeoutError` — это другое имя встроенного `TimeoutError`.

---

Обработка завершившейся неудачей сопрограммы следует синхронному шаблону: сопрограмма выбрасывает исключение, вызывающий оборачивает `await` в `try`/`except` и решает, что делать с объектом ошибки, например выводя его сообщение с помощью `print(e)`.

---

Эти элементы естественно сочетаются. Чтобы выполнить много операций конкурентно, каждая со своим лимитом времени, оберните каждую в небольшую сопрограмму, которая применяет `wait_for` и перехватывает `TimeoutError`, а затем соберите обёртки с помощью `gather`:
```python
async def guarded(coro, limit):
    try:
        return await asyncio.wait_for(coro, timeout=limit)
    except TimeoutError:
        return None
```
`gather(*[guarded(job(x), limit) for x in items])` затем возвращает значение для каждой задачи, завершившейся вовремя, и `None` для каждой, которая не успела, — в исходном порядке, а вся партия занимает не более примерно `limit` секунд.
