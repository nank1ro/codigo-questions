# --description--

Хороший комментарий объясняет, **почему** код что-то делает, а не **что** он делает. Код и так показывает, что происходит; повторение его словами лишь добавляет шум и устаревает, как только код меняется:
```python
# set timeout to 30
timeout = 30
```
Причина, стоящая за числом, — это то, что читатель не сможет угадать:
```python
# the server drops idle connections after 35 seconds, so stop earlier
timeout = 30
```
Если комментарий лишь повторяет строку под ним, удалите его или замените причиной. Лучшие комментарии — те, которые говорят то, чего не может сказать код.
