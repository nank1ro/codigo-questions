**Комментарий** — это заметка внутри исходного кода, написанная для тех, кто его читает. Python полностью игнорирует комментарии, поэтому они никогда не меняют то, что делает программа.

Единственный вид комментариев, который есть в Python, — **однострочный комментарий**: он начинается с `#` и продолжается до конца строки.
```python
# Приветствует пользователя
print("Hello")
```
Используйте комментарии, чтобы объяснить, для чего нужен фрагмент кода или почему он написан именно так.

---

Комментарий не обязательно занимает отдельную строку: он может следовать за кодом в той же строке. Это **встроенный комментарий**, и это хорошее место для короткой заметки именно об этой инструкции:
```python
retries = 3  # сдаться после трёх попыток
```
Всё от `#` до конца строки игнорируется, а код перед ним выполняется как обычно.

Руководство по стилю Python, **PEP 8**, требует здесь небольшого оформления: как минимум **два пробела** между кодом и `#` и **один пробел** после `#`. Комментарию на отдельной строке нужен только пробел после `#`.

---

Поскольку Python полностью отбрасывает комментарии, добавление или удаление комментария никогда не меняет то, что делает программа. Выполняется только код, который **не** закомментирован.

Поэтому `#` — быстрый способ выключить строку кода, не удаляя её. Это называется **закомментированием**:
```python
total = 10
# total = total + 5
print(total)  # выводит 10
```
Вторая строка теперь комментарий, поэтому `total` остаётся `10`. Удалите `#` — и строка снова оживёт.

Закомментирование удобно во время экспериментов, но не забывайте прибираться: код, который долго остаётся закомментированным, только путает того, кто будет читать его следующим.

---

Во многих языках есть второй вид комментариев — **блочный комментарий**, который занимает несколько строк, например `/* ... */`. В Python такого синтаксиса нет: есть только `#`.

Когда объяснению нужно больше одной строки, поставьте `#` в начале каждой строки:
```python
# Выводит приветственный баннер.
# Вызывается один раз при запуске приложения.
print("Welcome!")
```
Тот же приём закомментирует сразу несколько строк кода: один `#` на строку. Любой редактор умеет добавлять и убирать такие `#` у целого выделения одним сочетанием клавиш, так что на деле это дешевле, чем кажется.

---

Часто можно встретить **строку в тройных кавычках**, используемую так, будто это блочный комментарий:
```python
"""
This looks like a comment,
but it is a string.
"""
print("done")
```
Строка между `"""` и `"""` может занимать несколько строк, а строка, записанная сама по себе, — это корректная инструкция: Python создаёт её, ничего с ней не делает и выбрасывает. Ничего не выводится, поэтому результат выглядит как комментарий.

Но комментарием она не является. Это строковый литерал, поэтому правила кавычек остаются в силе: непарная кавычка или лишняя `"""` внутри сломают программу, тогда как внутри комментария `#` допустимо всё. Такая строка может и случайно стать docstring, если окажется первой инструкцией файла, класса или функции. Во всех остальных местах она просто никуда не попадает: CPython выбрасывает всю инструкцию ещё при компиляции.

Так что чтобы выключить код, используйте `#`. У строки в тройных кавычках своя собственная роль — она начинается в следующем упражнении.

---

Когда строка является **первой инструкцией** внутри функции, Python считает её документацией этой функции. Она называется **docstring**:
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"
```
По соглашению docstring записывают в тройных двойных кавычках, `"""`, даже если она умещается в одну строку, чтобы позже её можно было расширить, не меняя кавычки.

Пишите краткое описание в третьем лице, как будто описываете функцию: "Returns...", "Adds...", "Checks...". Docstring должна идти раньше любой другой инструкции в теле, иначе это просто обычная строка.

---

Docstring не выбрасывается: Python сохраняет её в атрибуте `__doc__` функции, поэтому программа может читать собственную документацию во время работы:
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"

print(greet.__doc__)  # Возвращает приветствие для name.
```
Когда у функции нет docstring, `__doc__` равно `None`. Именно это выводит `help(greet)` и показывает редактор, когда вы наводите курсор на имя.

---

Задокументировать можно и файл. Строка, записанная как **самая первая инструкция файла**, до любых импортов и определений, — это **docstring модуля**: она говорит, для чего нужен весь файл.
```python
"""Tools for working with rectangles."""

def area(width, height):
    """Returns the area of a rectangle."""
    return width * height
```
Засчитывается только первая инструкция. Комментарий может стоять над ней, но любой настоящий код между ними превращает строку обратно в обычную, бесполезную строку.

---

С классами всё работает так же: строка, стоящая первой инструкцией в теле класса, — это docstring этого класса, и она хранится в `__doc__`:
```python
class Point:
    """A point on a grid."""

    def __init__(self, x, y):
        self.x = x
        self.y = y

print(Point.__doc__)  # A point on a grid.
```
У каждого метода внутри класса тоже может быть свой docstring, который читается через `Point.__init__.__doc__`. Итак, три места, где допустим docstring, — это начало модуля, начало класса и начало функции.

---

Docstring и комментарии `#` выглядят похоже, но отвечают на разные вопросы.

**Docstring** — для тех, кто **использует** код: что делает функция, что она ожидает и что возвращает. Она сохраняется в `__doc__`, её читает `help()`, показывают редакторы и собирают инструменты документации.

**Комментарий** — для тех, кто **читает** код: почему эта строка написана именно так, что означает странное число, какую ошибку он обходит. Он существует только в файле с исходным кодом и исчезает, как только программа запускается.

```python
def timeout():
    """Returns the number of seconds to wait for the server."""
    # сервер разрывает неактивные соединения через 35 секунд
    return 30
```
Итог: документация функции идёт в docstring, а заметки о реализации — в комментарии.

---

Когда одной строки мало, docstring разрастается в фиксированную структуру, описанную в **PEP 257**: краткое описание в одну строку, пустая строка, затем подробности, а закрывающая `"""` — на отдельной строке.
```python
def to_seconds(minutes):
    """Returns the number of seconds in the given minutes.

    minutes is a whole number and is never negative.
    """
    return minutes * 60
```
Пустая строка важна: инструменты показывают первую строку отдельно, как краткое описание, и оставляют остальное тем, кто захочет читать дальше.

---

Docstring должен быть **первой строкой тела**, выше всех остальных инструкций. Строка, записанная после `return` или где угодно ещё в теле, — просто строка: `__doc__` остаётся `None`, и никакой инструмент её никогда не покажет.

---

Некоторые комментарии следуют соглашению, которое понимают редакторы. Самые распространённые **маркеры**:
- `# TODO: ...` помечает то, что ещё нужно написать
- `# FIXME: ...` помечает код, который заведомо неверен и требует исправления

```python
limit = 10
# TODO: считать лимит из настроек
```
Для Python это обычные комментарии; редакторы собирают их в отдельную панель, так что незавершённую работу легко найти. `TODO` обычно стоит рядом с заглушкой, которая позволяет программе работать, пока настоящий код не написан.

Закончив работу, замените заглушку и удалите маркер одним изменением, чтобы комментарий никогда не лгал о состоянии кода.

---

Комментарий над функцией, объясняющий, что делает функция, находится не там. Для этого существует docstring: он прикреплён к функции, его находит `help()` и показывают редакторы, а комментарий `#` над `def` невидим для них всех.

```python
# складывает a и b
def add(a, b):
    return a + b
```
Сдвиньте ту же фразу на строку вниз, в тройные кавычки, — и она станет настоящей документацией:
```python
def add(a, b):
    """Returns the sum of a and b."""
    return a + b
```

---

Python ищет `#` только в коде и никогда — внутри **строки**. Между кавычками `#` — обычный символ:
```python
print("black is #000000")  # a hex colour
```
Первый `#` — часть текста, а второй начинает настоящий комментарий. То же верно для `"""` внутри комментария `#`: там это просто три символа кавычек, которые ничего не начинают.

---

Хороший комментарий объясняет, **почему** код что-то делает, а не **что** он делает. Код и так показывает, что происходит; повторение его словами лишь добавляет шум и устаревает, как только код меняется:
```python
# задаёт timeout равным 30
timeout = 30
```
Причина, стоящая за числом, — это то, что читатель не сможет угадать:
```python
# сервер разрывает неактивные соединения через 35 секунд, поэтому останавливайся раньше
timeout = 30
```
Если комментарий лишь повторяет строку под ним, удалите его или замените причиной. Лучшие комментарии — те, которые говорят то, чего не может сказать код.
