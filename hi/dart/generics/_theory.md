एक `List` केवल मान नहीं रखती, वह **एक ही टाइप** के मान रखती है। टाइप को कलेक्शन के नाम के ठीक बाद कोणीय कोष्ठकों (angle brackets) के बीच लिखा जाता है:

```dart
List<String> names = ['Ada', 'Grace'];
List<int> scores = [10, 20];
```

यहाँ `String` और `int` **टाइप आर्ग्युमेंट** हैं, और जो टाइप एक आर्ग्युमेंट लेता है उसे **जेनेरिक** कहा जाता है। लिस्ट क्लास एक बार लिखी जाती है, और `List<String>` तथा `List<int>` उससे बने दो अलग-अलग टाइप होते हैं।

इसका फ़ायदा यह है कि कंपाइलर जानता है कि अंदर क्या है:

```dart
names.add(42);          // error: 42 is not a String
print(names.first.toUpperCase()); // fine: first is a String
```

---

`List` ही एकमात्र जेनेरिक कलेक्शन नहीं है। एक `Set` एक टाइप आर्ग्युमेंट लेता है, और एक `Map` **दो** लेता है: एक कीज़ के लिए और एक वैल्यूज़ के लिए, इसी क्रम में।

```dart
Set<String> tags = {'new', 'sale'};
Map<String, int> ages = {'Ada': 36, 'Grace': 45};
```

एक खाली कलेक्शन लिटरल को उसकी सामग्री से नहीं पढ़ा जा सकता, इसलिए आप टाइप आर्ग्युमेंट लिटरल पर ही लिखते हैं:

```dart
final counts = <String, int>{};
final seen = <String>{};
counts['fig'] = 3;
```

जैसे ही टाइप ज्ञात हो जाते हैं, कलेक्शन से निकाली गई हर चीज़ का टाइप पहले से सही होता है: `ages['Ada']` एक `int?` है, कोई रहस्यमय मान नहीं।

---

Dart में `dynamic` नाम का टाइप भी है, जिसका अर्थ है "कुछ भी चलेगा"। एक `List<dynamic>` हर मान स्वीकार करती है, इसलिए वह एक `List<String>` से अधिक सुविधाजनक लगती है:

```dart
List<dynamic> things = ['Ada', 'Grace'];
things.add(42);                    // accepted
print(things.first.toUpperCase()); // accepted
```

लेकिन पकड़ यह है कि कोड लिखते समय कुछ भी जाँचा नहीं जाता। `dynamic` मान पर किया गया हर कॉल प्रोग्राम चलने के दौरान सुलझाया जाता है, इसलिए `things.first.toUpperCse()` जैसी टाइपो खुशी-खुशी कंपाइल हो जाती है और उपयोगकर्ता के सामने धमाका करती है।

जेनेरिक्स इसका विकल्प हैं: एक ही कोड जो **किसी भी** टाइप के साथ काम करे, जबकि उसका हर उपयोग अब भी **एक** टाइप के लिए जाँचा जाता है। यही इस विषय का पूरा उद्देश्य है।

---

आप Dart के साथ आने वाली जेनेरिक क्लासों तक सीमित नहीं हैं: आप अपनी खुद की घोषित कर सकते हैं। एक **टाइप पैरामीटर** क्लास के नाम के बाद कोणीय कोष्ठकों के बीच लिखा जाता है, और वहाँ से वह बॉडी के अंदर एक सामान्य टाइप की तरह काम करता है:

```dart
class Box<T> {
  final T value;

  Box(this.value);

  T unwrap() => value;
}
```

`T` केवल एक प्लेसहोल्डर है। यह तब भरा जाता है जब एक `Box` बनाया जाता है, चाहे स्पष्ट रूप से और चाहे इन्फ़रेंस से:

```dart
final a = Box<int>(7);   // Box<int>
final b = Box('fig');    // Box<String>, inferred from the argument
print(a.value + 1);      // 8, the compiler knows value is an int
```

अक्षर कुछ खास नहीं होता: `T` "टाइप" के लिए एक परंपरा है, बस इतना ही।

---

एक फंक्शन अपने आप में भी जेनेरिक हो सकता है, बिना किसी जेनेरिक क्लास में रहे। टाइप पैरामीटर नाम और पैरामीटर लिस्ट के बीच लिखा जाता है:

```dart
T firstOf<T>(List<T> items) => items.first;

print(firstOf(['fig', 'kiwi'])); // fig, T is String here
print(firstOf([10, 20]));        // 10, T is int here
```

एक ही फंक्शन बॉडी, एक बार जाँची हुई, हर टाइप के लिए दोबारा उपयोग की जाने वाली। टाइप आर्ग्युमेंट आमतौर पर आर्ग्युमेंट्स से इन्फ़र कर लिया जाता है, लेकिन जब इन्फ़रेंस के पास कुछ न हो तो उसे स्पष्ट रूप से भी लिखा जा सकता है:

```dart
final empty = firstOf<String>(<String>[]); // throws, but the type is clear
```

क्लास के अंदर मेथड्स भी बिल्कुल वही नियम मानते हैं।

---

एक जेनेरिक क्लास के अंदर टाइप पैरामीटर हर जगह दिखाई देता है: फ़ील्ड्स में, कंस्ट्रक्टर पैरामीटर्स में, मेथड सिग्नेचर में और मेथड बॉडी में। इसे एक बार, क्लास के नाम के पास, घोषित किया जाता है, और हर सदस्य उसका उपयोग कर सकता है।

```dart
class Holder<T> {
  final T item;

  Holder(this.item);

  String describe() => 'holding $item';
}
```

ऑब्जेक्ट बनाना ही टाइप तय करता है: `Holder<String>('fig')` `item` को एक `String` बनाता है, `Holder<int>(3)` उसे एक `int` बनाता है।

---

एक क्लास एक से अधिक टाइप पैरामीटर भी घोषित कर सकती है, कॉमा से अलग करके। `Map<K, V>` इसका बिल्ट-इन उदाहरण है: एक टाइप कीज़ के लिए, एक वैल्यूज़ के लिए।

```dart
class Entry<K, V> {
  final K key;
  final V value;

  Entry(this.key, this.value);
}

final e = Entry<String, int>('age', 30);
```

**क्रम** टाइप का हिस्सा है: `Entry<String, int>` और `Entry<int, String>` असंबंधित टाइप हैं, और एक का मान दूसरे को असाइन नहीं किया जा सकता। टाइप पैरामीटर को रिटर्न टाइप में दोबारा क्रम में भी लगाया जा सकता है, जिससे एक मेथड ऑब्जेक्ट का पलटा हुआ संस्करण लौटा सकता है:

```dart
Entry<V, K> get flipped => Entry(value, key);
```

---

साउंड नल सेफ़्टी के साथ प्रश्न चिह्न दो अलग-अलग जगहों पर आ सकता है, और दोनों का अर्थ अलग-अलग होता है:

```dart
Box<int?> a = Box(null); // a box that exists and holds a nullable int
Box<int>? b = null;      // no box at all, but if there is one it holds an int
```

`Box<int?>` में **टाइप आर्ग्युमेंट** नलेबल है, इसलिए `a.value` का टाइप `int?` है और वह `null` हो सकता है, जबकि `a` स्वयं हमेशा मौजूद रहता है। `Box<int>?` में **वेरिएबल** नलेबल है, इसलिए `b` `null` हो सकता है और उसके अंदर पहुँचने के लिए आपको `b?.value` या `b!.value` चाहिए।

एक सादा `T` का अर्थ है `T extends Object?`, इसलिए `Box<int?>` जैसा नलेबल टाइप आर्ग्युमेंट पूरी तरह वैध है।

---

यह अंतर तुरंत समझ आ जाता है जैसे ही आप मान का उपयोग करते हैं। एक `Box<int?>` पर आप फ़ील्ड को सामान्य तरीके से पढ़ते हैं और फिर उसके अंदर वाले `null` से निपटते हैं, जबकि एक `Box<int>?` पर आपको पहले गायब बॉक्स को पार करना पड़ता है:

```dart
Box<int?> a = Box(null);
print(a.value ?? 0); // 0, the box is there, its content is null

Box<int>? b = null;
print(b?.value ?? 0); // 0, the box itself is missing
```

एक `Box<int>?` पर `b.value` लिखना तो कंपाइल होता ही नहीं: Dart किसी ऐसी चीज़ का फ़ील्ड पढ़ने से इनकार करता है जो मौजूद न हो सकती।

---

एक बिना-बाउंड वाला `T` कुछ भी हो सकता है, इसलिए बॉडी के अंदर आप केवल वही उपयोग कर सकते हैं जो हर ऑब्जेक्ट के पास होता है। यह कोड कंपाइल नहीं होता:

```dart
T twice<T>(T value) => value + value; // error: + is not defined for T
```

एक **बाउंड** इसे ठीक कर देता है। `T extends num` लिखने का अर्थ है "`T` केवल एक संख्या हो सकता है", और बदले में बॉडी `num` जो कुछ भी पेश करता है वह सब उपयोग कर सकती है:

```dart
T twice<T extends num>(T value) => (value + value) as T;

num half<T extends num>(T value) => value / 2;
```

बाउंड कॉल साइट पर जाँचा जाता है: `half(4)` और `half(2.5)` ठीक हैं, `half('fig')` एक कंपाइल-टाइम एरर है। बाउंड दोनों दिशाओं में एक वादा है, अंदर अधिक ताक़त के बदले संकरे आर्ग्युमेंट।

---

बाउंड के लिए कीवर्ड हमेशा `extends` होता है, तब भी जब बाउंड कोई सुपरक्लास नहीं बल्कि एक इंटरफ़ेस हो। टाइप पैरामीटर लिस्ट में `implements` नहीं होता।

```dart
num biggerOf<T extends num>(T a, T b) => a > b ? a : b;
```

बाउंड के बिना, `a > b` कंपाइल नहीं होता: तुलना ऑपरेटर `num` से जुड़ा है, हर ऑब्जेक्ट से नहीं।

---

एक बाउंड टाइप पैरामीटर को स्वयं भी उल्लेखित कर सकता है। `Comparable<T>` उन सब चीज़ों का इंटरफ़ेस है जो `compareTo` के ज़रिए जानती हैं कि अपने ही क़िस्म से खुद की तुलना कैसे करनी है:

```dart
print('fig'.compareTo('kiwi')); // negative: fig comes first
print('kiwi'.compareTo('fig')); // positive
print('fig'.compareTo('fig'));  // zero
```

इसलिए `T extends Comparable<T>` पढ़ा जाता है "कोई भी टाइप जिसकी तुलना उसके अपने ही जैसे से हो सकती है", और यही एक सॉर्टिंग या अधिकतम फंक्शन को चाहिए होता है:

```dart
T maxOf<T extends Comparable<T>>(T a, T b) => a.compareTo(b) >= 0 ? a : b;

print(maxOf('fig', 'kiwi')); // kiwi
```

`String` और `DateTime` दोनों इसे सीधे संतुष्ट करते हैं। `int` और `double` `Comparable<num>` इम्प्लीमेंट करते हैं, इसलिए संख्याओं की एक सूची आसानी से `num` की तरह तुलना की जाती है।

---

वही बाउंड सबसे छोटे एलिमेंट के लिए भी उतना ही अच्छा काम करता है: बदलती केवल तुलना का चिह्न है। `compareTo` एक ऋणात्मक संख्या लौटाता है जब रिसीवर पहले आता है, इसलिए `item.compareTo(best) < 0` का अर्थ है "यह वाला छोटा है"।

---

एक जेनेरिक क्लास किसी भी दूसरी क्लास की तरह नामित और **फ़ैक्टरी** कंस्ट्रक्टर रख सकती है, और टाइप पैरामीटर उनके अंदर उपलब्ध होता है। एक फ़ैक्टरी कंस्ट्रक्टर ऑब्जेक्ट खुद नहीं बनाता: वह एक बॉडी चलाता है और एक ऑब्जेक्ट लौटाता है, जिससे वह इंस्टेंस को अपनी मर्ज़ी से चुन, दोबारा इस्तेमाल या बना सकता है।

```dart
class Box<T> {
  final T value;

  Box(this.value);

  factory Box.first(List<T> items) => Box(items.first);
}

final b = Box<int>.first([5, 6]);
print(b.value); // 5
```

टाइप आर्ग्युमेंट क्लास पर लगता है, कंस्ट्रक्टर के नाम पर नहीं: `Box<int>.first(...)`। फ़ैक्टरी के अंदर `<T>[]` एक असली खाली `List<T>` होता है, इसलिए फ़ैक्टरी एक ऐसे टाइप के लिए डिफ़ॉल्ट मान बनाने की स्वाभाविक जगह है जो आपको अभी ज्ञात नहीं है।

---

बिना बाउंड लिखा टाइप पैरामीटर वास्तव में बिना-बाउंड नहीं होता: `class Box<T>`, `class Box<T extends Object?>` का संक्षिप्त रूप है। इसीलिए `Box<int?>` स्वीकार किया जाता है, और इसीलिए क्लास के अंदर आप कभी नहीं मान सकते कि `value` नॉन-नल है।

नलेबल टाइप आर्ग्युमेंट मना करने के लिए, पैरामीटर को `Object` से बाउंड करें:

```dart
class Strict<T extends Object> {
  final T value;
  Strict(this.value);
}

final ok = Strict<int>(7);
final bad = Strict<int?>(null);
// error: Type argument 'int?' doesn't conform to the bound 'Object'
```

`Object` `null` को छोड़कर हर चीज़ का टाइप है, इसलिए `T extends Object` पढ़ा जाता है "कुछ भी, बशर्ते वह सचमुच मौजूद हो"।

---

एक `typedef` किसी टाइप को एक नाम देता है, और वह अपने टाइप पैरामीटर भी ले सकता है। आम वजह यह है कि फंक्शन टाइप्स के एक परिवार को हर उपयोग पर खुलकर लिखने की बजाय एक बार नाम दे दिया जाए:

```dart
typedef Transform<I, O> = O Function(I input);

final Transform<String, int> length = (word) => word.length;
print(length('kiwi')); // 4
```

`Transform<String, int>` केवल `int Function(String)` लिखने का दूसरा तरीका है, इसलिए दोनों आपस में बदल-बदलाकर उपयोग हो सकते हैं। फ़ायदा पठनीयता का है: `Transform<I, O> transform` घोषित पैरामीटर बताता है कि फंक्शन किस काम का है, जबकि `O Function(I)` केवल यह कि वह कैसा दिखता है।

एक जेनेरिक typedef और एक जेनेरिक फंक्शन सहज रूप से मिलकर काम करते हैं, जिसमें फंक्शन के अपने टाइप पैरामीटर typedef के पैरामीटर भर देते हैं।
