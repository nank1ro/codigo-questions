# --description--

`Exception` एक इंटरफ़ेस है, इसलिए आपकी अपनी क्लास भी वह हो सकती है। एक कस्टम अपवाद विफलता को वह नाम देता है जिसे एक `on` क्लॉज़ चुन सकता है, और वे फ़ील्ड देता है जिन्हें एक हैंडलर पढ़ सकता है:

```dart
class EmptyCartException implements Exception {
  final String message;

  EmptyCartException(this.message);

  @override
  String toString() => 'EmptyCartException: $message';
}

throw EmptyCartException('nothing to pay for');
```

तीन हिस्से रखने लायक हैं: `implements Exception` ताकि क्लास बाकी विफलताओं की श्रेणी में आए, विवरण ले जाने वाला एक `final` फ़ील्ड, और एक ओवरराइड किया हुआ `toString()` ताकि unhandled-exception रिपोर्ट पढ़ने योग्य रहे। वह ओवरराइड न हो तो Dart बस क्लास का नाम प्रिंट करता है और विवरण खो जाता है।

# --instructions--

एक क्लास `InvalidEmailException` परिभाषित करें जो `Exception` को implement करती है, जिसमें कंस्ट्रक्टर से सेट होने वाला एक `final String` फ़ील्ड `message` हो, और एक `toString()` हो जो `'InvalidEmailException: '` के बाद संदेश लौटाता है।

फिर एक फंक्शन `checkEmail` लिखें जो एक `String` `email` लेता है और उसे लौटाता है, पर `InvalidEmailException('missing @')` फेंकता है जब ईमेल में `'@'` न हो।

उदाहरण:
```dart
print(checkEmail('ada@dart.dev')); // ada@dart.dev
```

```dart
class InvalidEmailException implements Exception {
  final String message;

  InvalidEmailException(this.message);

  @override
  String toString() => 'InvalidEmailException: $message';
}

String checkEmail(String email) {
  if (!email.contains('@')) {
    throw InvalidEmailException('missing @');
  }
  return email;
}
```
