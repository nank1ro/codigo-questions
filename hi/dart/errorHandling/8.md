# --description--

कभी-कभी हैंडलर रिकवर करने की सही जगह नहीं होती: आप केवल विफलता को *देखना* चाहते हैं और उसे उस कॉलर तक जाने देना चाहते हैं जो वास्तव में उसे संभाल सकता है। `rethrow` कीवर्ड यही करता है, एक `catch` या `on ... catch` ब्लॉक के अंदर:

```dart
try {
  return int.parse(text);
} on FormatException {
  log.add('bad input: $text');
  rethrow;
}
```

`rethrow` **वही** वस्तु आगे भेजता है, इसलिए कॉलर को मूल विफलता दिखती है। इसके बजाय `throw e` लिखना भी चल जाएगा, पर वह यात्रा फिर से शुरू कर देता है और खो देता है कि विफलता पहले कहाँ हुई थी।

उसी कथन का एक `finally` ब्लॉक फिर भी चलता है, बाहर निकलते समय भी।

# --instructions--

एक फंक्शन `parseOrLog` लिखें जो एक `String` `text` और एक `List<String>` `log` लेता है, और `int.parse(text)` लौटाता है।

जब टेक्स्ट कोई पूर्ण संख्या न हो, तो `log` में स्ट्रिंग `'bad input: '` जोड़ें जिसके बाद टेक्स्ट हो, फिर `FormatException` को फिर से फेंकें ताकि कॉलर को वह अब भी दिखे।

उदाहरण:
```dart
final log = <String>[];
print(parseOrLog('42', log)); // 42
```
