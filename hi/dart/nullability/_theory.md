आप पहले से जानते हैं कि टाइप के साथ वेरिएबल कैसे घोषित किया जाता है, जैसे `String name = 'Ada';`। पर कभी-कभी कोई मान बस **मौजूद ही नहीं** होता: बिना उपनाम वाला उपयोगकर्ता, ऐसी खोज जिसमें कुछ नहीं मिला, ऐसा टेक्स्ट जिसे संख्या में नहीं बदला जा सकता। Dart अनुपस्थित मान को `null` से दर्शाता है।

Dart 2.12 से भाषा में **साउंड नल सेफ़्टी** है: `String` जैसा सामान्य टाइप **कभी भी** `null` नहीं रख सकता। उसे असाइन करने की कोशिश कंपाइल एरर है, इसलिए प्रोग्राम चलता तक नहीं:

```dart
String name = null; // error: a value of type 'Null' can't be assigned to 'String'
```

अनुपस्थित मान की अनुमति देने के लिए आप टाइप के बाद प्रश्नचिह्न `?` जोड़ते हैं। `String?` या तो `String` रखता है या `null`, और `null` प्रिंट करने पर `null` शब्द दिखता है:

```dart
String? nickname = null;
print(nickname); // null

nickname = 'Ada';
print(nickname); // Ada
```

बिना `?` वाले टाइप **नॉन-नलेबल** कहलाते हैं, `?` वाले टाइप **नलेबल** होते हैं।

---

**बिना मान के** घोषित किया गया नलेबल वेरिएबल `null` से शुरू होता है, इसलिए `= null` छोड़ा जा सकता है:

```dart
int? age;
print(age); // null
```

नॉन-नलेबल वेरिएबल के लिए ऐसा कोई डिफ़ॉल्ट नहीं है: Dart ऐसे किसी भी कोड को कंपाइल करने से मना कर देता है जो मान असाइन होने से पहले उसे पढ़ता है।

```dart
int count;
print(count); // error: 'count' must be assigned before it can be used
```

---

`null` पर मेथड कॉल करना या प्रॉपर्टी पढ़ना क्रैश कर देगा, इसलिए Dart आपको नलेबल मान पर सामान्य डॉट के साथ ऐसा नहीं करने देता:

```dart
String? text;
print(text.length); // error: the property 'length' can't be unconditionally accessed
```

**नल-अवेयर एक्सेस** ऑपरेटर `?.` इसे हल करता है: अगर मान `null` है तो पूरा एक्सप्रेशन `null` होता है और आगे कुछ भी मूल्यांकित नहीं होता, वरना यह सामान्य `.` की तरह काम करता है:

```dart
String? text = 'Dart';
print(text?.length); // 4

text = null;
print(text?.length); // null
```

चूँकि परिणाम `null` हो सकता है, इसका टाइप नलेबल है: `text?.length` एक `int?` है, `int` नहीं।

---

अक्सर अनुपस्थित मान को किसी **डिफ़ॉल्ट** से बदलना चाहिए। **if-null** ऑपरेटर `??` बाएँ ऑपरेंड को लौटाता है जब वह `null` नहीं है, वरना दाएँ ऑपरेंड को:

```dart
String? nickname;
print(nickname ?? 'anonymous'); // anonymous

nickname = 'Ada';
print(nickname ?? 'anonymous'); // Ada
```

`??` केवल `null` पर प्रतिक्रिया करता है: खाली स्ट्रिंग `''` या संख्या `0` असली मान हैं, इसलिए वे बने रहते हैं।

`??` का `?.` के साथ अच्छा मेल है, क्योंकि `?.` नलेबल परिणाम देता है:

```dart
String? text;
print(text?.length ?? 0); // 0
```

---

नल सेफ़्टी का बड़ा फ़ायदा यह है कि `null` से जुड़ी अधिकांश गलतियाँ **कंपाइलर** पकड़ता है, आपके उपयोगकर्ता नहीं। अब तक के नियम:

- नॉन-नलेबल टाइप (`String`, `int`, `List<int>`...) कभी `null` नहीं हो सकता
- नलेबल टाइप (`String?`, `int?`, `List<int>?`...) हो सकता है, और बिना मान के घोषित होने पर `null` से शुरू होता है
- नलेबल मान पर `.` कंपाइल नहीं होता: `?.` का उपयोग करें या `??` से डिफ़ॉल्ट दें

---

**if-null असाइनमेंट** ऑपरेटर `??=` किसी वेरिएबल को मान **केवल तभी** असाइन करता है जब वह वेरिएबल इस समय `null` हो; वरना उसे वैसा ही छोड़ देता है:

```dart
int? retries;
retries ??= 3;
print(retries); // 3

retries ??= 10;
print(retries); // 3, it already had a value
```

यह map की एंट्रियों पर भी काम करता है, जो नलेबल होती हैं क्योंकि कोई की मौजूद न भी हो सकती है:

```dart
var stock = {'apple': 4};
stock['pear'] ??= 1;  // added
stock['apple'] ??= 9; // ignored
print(stock); // {apple: 4, pear: 1}
```

---

कभी-कभी **आप** जानते हैं कि किसी बिंदु पर नलेबल मान `null` नहीं है, भले ही कंपाइलर यह न बता सके। **नल असर्शन** ऑपरेटर `!` यह वादा करते हुए कि मान मौजूद है, `String?` को `String` में बदल देता है:

```dart
String? text = 'Dart';
String sure = text!;
print(sure.length); // 4
```

सावधान रहें: `!` जाँच को कंपाइल समय से रन टाइम पर खिसका देता है। अगर मान सचमुच `null` **हुआ**, तो प्रोग्राम एरर फेंकता है और रुक जाता है:

```dart
String? text;
print(text!.length); // Null check operator used on a null value
```

`!` का उपयोग कम से कम करें, और केवल तब जब वहाँ `null` होना वैसे भी एक बग होता।

---

नलेबल मान पर देखे गए तीन ऑपरेटरों का अंतर याद रखें:

- `?.` मान के `null` होने पर `null` लौटाता है, और कभी एरर नहीं फेंकता
- `??` `null` को डिफ़ॉल्ट से बदल देता है
- `!` मानता है कि मान मौजूद है और न होने पर **रन टाइम पर एरर फेंकता है**

इनमें से कोई भी कंपाइल एरर नहीं है: कंपाइलर आपके `!` पर भरोसा करता है, और केवल चलता हुआ प्रोग्राम ही जान सकता है कि वादा टूट गया।

---

नलेबल मान की जाँच `if` से करना `!` से अधिक सुरक्षित है, और Dart इसके लिए आपको पुरस्कृत करता है। `if (x != null)` जैसी जाँच के बाद कंपाइलर जानता है कि ब्लॉक के भीतर `x` `null` नहीं हो सकता, इसलिए वहाँ वह `x` को नॉन-नलेबल मानता है। इसे **टाइप प्रमोशन** कहते हैं:

```dart
int twice(int? n) {
  if (n != null) {
    return n * 2; // here n is an int, no ! needed
  }
  return 0;
}
```

प्रमोशन जल्दी रिटर्न के बाद भी काम करता है:

```dart
int twice(int? n) {
  if (n == null) return 0;
  return n * 2; // n is an int from here on
}
```

प्रमोशन **लोकल वेरिएबल्स और पैरामीटर्स** पर लागू होता है, जिनका मान जाँच और उपयोग के बीच आपकी जानकारी के बिना नहीं बदल सकता।

---

टाइप प्रमोशन ऐसी क्लास **फ़ील्ड** पर काम **नहीं** करता जिसे बाहर से बदला जा सकता है, क्योंकि जाँच और उपयोग के बीच कोई दूसरा कोड (सबक्लास में ओवरराइड किया गया गेटर, कोई दूसरा मेथड) उसे फिर से `null` कर सकता है:

```dart
class Box {
  int? value;

  int doubled() {
    if (value != null) {
      return value * 2; // error: 'value' can't be unconditionally accessed
    }
    return 0;
  }
}
```

मानक हल यह है कि फ़ील्ड को किसी **लोकल वेरिएबल** में कॉपी कर लें, जिसका प्रमोशन होता है:

```dart
int doubled() {
  final v = value;
  if (v != null) {
    return v * 2;
  }
  return 0;
}
```

---

नॉन-नलेबल फ़ील्ड को सामान्यतः कंस्ट्रक्टर में मान मिलना चाहिए। जब मान केवल **बाद में** पता चलता है (फ़ाइल पढ़ने के बाद, कनेक्शन खोलने के बाद...), तो आप फ़ील्ड को `late` चिह्नित कर सकते हैं: कंपाइलर इनिशियलाइज़र की अनुपस्थिति स्वीकार कर लेता है और भरोसा करता है कि आप पढ़ने से पहले फ़ील्ड को मान दे देंगे।

```dart
class Connection {
  late String host;

  void open() {
    host = 'example.com';
  }
}
```

ऐसी `late` फ़ील्ड पढ़ना जिसे अभी तक मान नहीं मिला है, रन टाइम पर `LateInitializationError` फेंकता है। `!` की तरह `late` भी कंपाइल-समय की गारंटी के बदले रन-टाइम जाँच लेता है, इसलिए यह एक वादा है जिसे आपको निभाना है।

`late` को इनिशियलाइज़र के साथ भी जोड़ा जा सकता है, जो फिर **आलसी रूप से** चलता है, यानी वेरिएबल पहली बार पढ़े जाने पर:

```dart
late String report = buildReport(); // buildReport() runs only when report is used
```

---

नलेबिलिटी यह तय करती है कि आप **नेम्ड पैरामीटर** कैसे घोषित करते हैं। नलेबल टाइप वाला नेम्ड पैरामीटर वैकल्पिक होता है: कॉल करने वाला उसे छोड़ दे तो वह बस `null` होता है।

```dart
String label({String? title}) => title ?? 'untitled';

print(label());               // untitled
print(label(title: 'Notes')); // Notes
```

नॉन-नलेबल टाइप और बिना डिफ़ॉल्ट मान वाले नेम्ड पैरामीटर के छोड़े जाने पर उसके पास कोई मान नहीं होता, इसलिए Dart आपसे उसे `required` चिह्नित करने को कहता है; तब कॉल करने वाले को उसे हमेशा देना होगा:

```dart
String label({required String name, String? title}) { ... }

label(name: 'Ada');               // ok
label(name: 'Ada', title: 'Dr.'); // ok
label(title: 'Dr.');              // error: the named parameter 'name' is required
```

---

नलेबिलिटी किसी कलेक्शन के **एलिमेंट्स** पर भी लागू होती है। `List<int>` में कभी `null` नहीं होता, जबकि `List<int?>` में हो सकता है:

```dart
List<int?> scores = [7, null, 9];
```

`List<int>?` से अंतर पर ध्यान दें, जो ऐसी लिस्ट है जो स्वयं अनुपस्थित हो सकती है पर मौजूद होने पर केवल असली संख्याएँ रखती है।

`null` एलिमेंट्स हटाने के लिए `nonNulls` केवल मौजूद मानों वाला `Iterable` लौटाता है, जिसका टाइप बिना `?` के होता है:

```dart
var present = scores.nonNulls.toList(); // List<int>
print(present); // [7, 9]
```

`whereType<int>()` भी यही करता है और तब भी काम करता है जब लिस्ट में कई टाइप मिले हों।

---

कई लाइब्रेरी फंक्शन यह बताने के लिए `null` का उपयोग करते हैं कि कुछ **नहीं किया जा सका**। स्ट्रिंग को संख्या में बदलना इसका क्लासिक उदाहरण है: टेक्स्ट के संख्या न होने पर `int.parse` `FormatException` फेंकता है, जबकि `int.tryParse` उसके बजाय `null` लौटाता है और तय करना आप पर छोड़ देता है:

```dart
print(int.tryParse('42'));  // 42
print(int.tryParse('4x2')); // null
print(int.tryParse(''));    // null
```

`int.tryParse` का रिटर्न टाइप `int?` है, इसलिए आपने जो सीखा है वह सब लागू होता है: डिफ़ॉल्ट के लिए `??`, चेन करने के लिए `?.`, और प्रमोशन के लिए `if` जाँच। `double.tryParse` भी इसी तरह काम करता है।

---

दो और ऑपरेटरों का नल-अवेयर रूप होता है।

**नल-अवेयर कैस्केड** `?..` कैस्केड ऑपरेशनों की शृंखला तभी चलाता है जब ऑब्जेक्ट `null` न हो, वरना सभी को छोड़ देता है:

```dart
List<int>? numbers;
numbers?..add(1)..add(2); // nothing happens, numbers is still null
```

**नल-अवेयर स्प्रेड** `...?` किसी नलेबल कलेक्शन के एलिमेंट्स को लिटरल में डालता है, और कलेक्शन के `null` होने पर कुछ नहीं जोड़ता:

```dart
List<int>? extra;
print([0, ...?extra]); // [0]

extra = [1, 2];
print([0, ...?extra]); // [0, 1, 2]
```

`?` के बिना, `List<int>?` पर `...extra` कंपाइल एरर होता।

---

असली डेटा में खाली जगहें भरी होती हैं: खाली छोड़ा गया फ़ॉर्म फ़ील्ड, फ़ाइल में गायब कोई कॉलम, ऐसी स्ट्रिंग जो पूरी तरह संख्या नहीं है। इस अध्याय के औज़ार इन्हें संभालने के लिए स्वाभाविक रूप से मिलकर काम करते हैं: अनुपस्थित एलिमेंट्स हटाने के लिए `nonNulls`, सुरक्षित रूप से बदलने के लिए `int.tryParse`, और जो नहीं बदला जा सका उससे निपटने के लिए `??` या `if` जाँच।
