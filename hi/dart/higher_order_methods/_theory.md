एक **हायर-ऑर्डर मेथड** वह मेथड है जो एक फंक्शन को आर्ग्युमेंट के रूप में लेता है। Dart के कलेक्शन उनमें से बहुत कुछ प्रदान करते हैं, और आपके द्वारा पास किया गया फंक्शन आमतौर पर एरो सिंटैक्स `(x) => ...` से लिखा गया एक अनामित फंक्शन होता है।

`map` उनमें सबसे सामान्य है: यह हर तत्व पर फंक्शन को कॉल करता है और परिणाम उत्पन्न करता है, प्रत्येक तत्व के लिए एक, जिससे मूल कलेक्शन अपरिवर्तित रहता है:

```dart
final numbers = [1, 2, 3];
print(numbers.map((n) => n * 2)); // (2, 4, 6)
print(numbers);                   // [1, 2, 3]
```

आउटपुट में **गोल कोष्ठकों** पर ध्यान दें। `map` एक `List` नहीं लौटाता: यह एक `Iterable` लौटाता है, एक ऐसा अनुक्रम जिसमें आप चल सकते हैं। वास्तविक सूची वापस पाने के लिए, उस पर **`toList()`** कॉल करें:

```dart
final doubled = numbers.map((n) => n * 2).toList();
print(doubled); // [2, 4, 6]
```

आउटपुट में वर्ग कोष्ठक इस बात का संकेत हैं कि आप एक `List` देख रहे हैं, और गोल कोष्ठक इस बात का कि आप एक साधारण `Iterable` देख रहे हैं।

---

`where` एक ऐसा फंक्शन लेता है जो एक `bool` लौटाता है, जिसे **predicate** कहा जाता है, और केवल उन्हीं तत्वों को रखता है जिनके लिए वह `true` उत्तर देता है। बचे हुए तत्वों का क्रम कभी नहीं बदलता:

```dart
final numbers = [4, -2, 7, 0];
print(numbers.where((n) => n > 0).toList()); // [4, 7]
```

`map` की तरह, `where` एक `Iterable` लौटाता है और कभी भी मूल कलेक्शन को संशोधित नहीं करता, इसलिए परिणाम को एक `List` में बदलने का काम फिर से `toList()` ही करता है।

अन्य भाषाओं में इस मेथड को `filter` कहा जाता है; Dart में यह `where` है।

---

`map` को दिया गया फंक्शन उन तत्वों के समान टाइप लौटाने के लिए बाध्य नहीं है जो उसे मिलते हैं। स्ट्रिंग्स की सूची को उनकी लंबाई में मैप करना एक `List<String>` को एक `Iterable<int>` में बदल देता है, जिसे `toList()` फिर एक `List<int>` बना देता है:

```dart
final words = ['fig', 'kiwi'];
print(words.map((w) => w.length).toList()); // [3, 4]
```

परिणाम में हमेशा **मूल जितने ही तत्व**, उसी क्रम में होते हैं: `map` तत्वों को बदलता है, यह कभी कोई तत्व जोड़ता या हटाता नहीं।

---

कुछ हायर-ऑर्डर मेथड नया कलेक्शन बनाने के बजाय कलेक्शन के बारे में एक प्रश्न का उत्तर देते हैं। वे एक predicate लेते हैं और एक `bool` लौटाते हैं:

- `any` तब `true` होता है जब **कम से कम एक** तत्व predicate को संतुष्ट करता हो
- `every` तब `true` होता है जब **सभी** तत्व उसे संतुष्ट करते हों

```dart
final numbers = [1, 2, 3];
print(numbers.any((n) => n > 2));   // true
print(numbers.every((n) => n > 2)); // false
```

दोनों जैसे ही उत्तर निश्चित हो जाता है, रुक जाते हैं: `any` पहले मैच करने वाले तत्व पर, `every` पहले उस तत्व पर जो मैच नहीं करता।

एक खाली कलेक्शन पर `any` `false` होता है और `every` `true`: पहले को सिद्ध करने के लिए कोई तत्व नहीं होता, और दूसरे को तोड़ने के लिए भी कोई नहीं।

---

`map` और `where` **आलसी (lazy)** हैं: उन्हें कॉल करने पर कुछ भी नहीं चलता। वे एक `Iterable` लौटाते हैं जो स्रोत और फंक्शन को याद रखता है, और फंक्शन केवल तब कॉल होता है जब कोई चीज़ परिणाम में चलती है, एक बार में एक तत्व।

```dart
final numbers = [1, 2, 3];
final doubled = numbers.map((n) => n * 2); // nothing computed yet
print(doubled.first);                      // computes only 2
```

`toList()` ही वह चीज़ है जो अनुक्रम को **materialise** करती है: वह उसमें शुरुआत से अंत तक चलती है और हर परिणाम को एक वास्तविक `List` में संग्रहीत करती है।

आलस्य के दो परिणाम हैं जिन्हें याद रखना उपयोगी है। एक आलसी `Iterable` हर बार पुनर्गणना की जाती है जब आप उस पर iterate करते हैं, इसलिए `toList()` से एक बार materialise करना सस्ता होता है जब आपको मान एक से अधिक बार चाहिए हों। और वह मूल कलेक्शन को देखती रहती है, इसलिए उस कलेक्शन को बदलने से यह बदल जाता है कि `Iterable` क्या उत्पन्न करती है:

```dart
final numbers = [1, 2, 3];
final lazy = numbers.map((n) => n * 2);
final eager = numbers.map((n) => n * 2).toList();
numbers.add(4);
print(lazy.toList()); // [2, 4, 6, 8]
print(eager);         // [2, 4, 6]
```

---

`fold` एक पूरे कलेक्शन को एक **एकल मान** में जोड़ता है। यह दो आर्ग्युमेंट लेता है: **accumulator** का प्रारंभिक मान, और एक फंक्शन जो अब तक के accumulator और अगले तत्व को प्राप्त करता है और नया accumulator लौटाता है:

```dart
final numbers = [1, 2, 3, 4];
final total = numbers.fold(0, (acc, n) => acc + n);
print(total); // 10
```

यहाँ `acc` `0` से शुरू होता है, फिर `1`, `3`, `6` बनता है और अंत में `10` हो जाता है।

accumulator को संख्या होना ज़रूरी नहीं, न ही तत्वों के समान टाइप का होना ज़रूरी है: `''` से शुरू करके टेक्स्ट जोड़ने से किसी भी तत्वों की सूची से एक `String` बनती है।

एक विवरण जो ध्यान में रखना चाहिए: Dart accumulator का टाइप प्रारंभिक मान से **और** उस जगह से निकालता है जहाँ परिणाम उपयोग किया जाता है। `print(...)` के अंदर अपेक्षित टाइप अज्ञात होता है, इसलिए पहले परिणाम को एक वेरिएबल में संग्रहीत करें (या `fold<int>(...)` लिखें), अन्यथा कंपाइलर शिकायत करता है कि वह accumulator पर `+` का उपयोग नहीं कर सकता।

---

`reduce` `fold` का छोटा संबंधी है। यह कोई प्रारंभिक मान नहीं लेता: **पहला तत्व** ही प्रारंभिक accumulator होता है, और फंक्शन हर शेष तत्व के लिए चलता है:

```dart
final numbers = [1, 2, 3, 4];
print(numbers.reduce((a, b) => a + b)); // 10
```

प्रारंभिक मान न होने के कारण, परिणाम में हमेशा **तत्वों के समान टाइप** होता है, और एक खाली कलेक्शन पर `reduce` कॉल करने से एक `StateError` उत्पन्न होता है: शुरू करने के लिए कोई पहला तत्व नहीं होता। `fold` में ऐसी कोई समस्या नहीं है, इसीलिए वह सुरक्षित डिफ़ॉल्ट है।

`reduce` तब सर्वश्रेष्ठ होता है जब आप कई तत्वों में से एक तत्व खोज रहे हों, जैसे सबसे बड़ा:

```dart
print(numbers.reduce((a, b) => a > b ? a : b)); // 4
```

---

`firstWhere` उन सभी के बजाय predicate से मेल खाने वाला **पहला** तत्व लौटाता है:

```dart
final words = ['fig', 'kiwi', 'banana'];
print(words.firstWhere((w) => w.length > 3)); // kiwi
```

जब कुछ भी मेल न खाए तो लौटाने के लिए कोई तत्व नहीं होता, इसलिए `firstWhere` एक `StateError` उत्पन्न करता है। त्रुटि के बजाय एक उत्तर देने के लिए, नामित आर्ग्युमेंट **`orElse`** पास करें: एक ऐसा फंक्शन जो कोई पैरामीटर नहीं लेता और fallback मान उत्पन्न करता है।

```dart
print(words.firstWhere((w) => w.length > 10, orElse: () => 'none')); // none
```

`orElse` एक साधारण मान नहीं, बल्कि एक फंक्शन है, इसलिए वह केवल तब कॉल होता है जब खोज असफल हो। `orElse: 'none'` लिखना कंपाइल नहीं होता।

---

जब आप `map` को दिया गया फंक्शन प्रत्येक तत्व के लिए एक कलेक्शन लौटाता है, तो आपके पास कलेक्शनों का एक अनुक्रम बन जाता है। **`expand`** वही काम करता है लेकिन फिर उन सबको जोड़कर एक सपाट अनुक्रम बना देता है:

```dart
final numbers = [1, 2];
print(numbers.map((n) => [n, -n]).toList());    // [[1, -1], [2, -2]]
print(numbers.expand((n) => [n, -n]).toList()); // [1, -1, 2, -2]
```

क्रम बना रहता है: पहले तत्व द्वारा उत्पन्न सब कुछ पहले आता है, फिर दूसरे तत्व द्वारा उत्पन्न सब कुछ, और इसी तरह।

क्योंकि लौटाया गया कलेक्शन किसी भी आकार का हो सकता है, `expand` यह भी तरीका है कि शुरुआत से **अधिक या कम** तत्व उत्पन्न किए जाएँ: किसी तत्व के लिए एक खाली सूची लौटाना उसे बस हटा देता है।

```dart
print(['a b', 'c'].expand((s) => s.split(' ')).toList()); // [a, b, c]
```

---

`take(n)` **पहले** `n` तत्व रखता है और `skip(n)` उन्हें छोड़ देता है। दोनों में से कोई फंक्शन नहीं लेता, लेकिन दोनों एक आलसी `Iterable` लौटाते हैं, इसलिए वे बाकी हायर-ऑर्डर मेथड के बीच स्वाभाविक रूप से फिट हो जाते हैं:

```dart
final scores = [10, 20, 30, 40, 50];
print(scores.take(2).toList()); // [10, 20]
print(scores.skip(3).toList()); // [40, 50]
```

मौजूद से अधिक तत्व मांगना त्रुटि नहीं है: आपको बस जो मौजूद है वही मिलता है, या एक खाली परिणाम।

`takeWhile` और `skipWhile` predicate वाले संस्करण हैं। वे शुरुआत से तब तक तत्व लेते या छोड़ते हैं **जब तक** predicate सत्य है, और पहले उस तत्व पर रुक जाते हैं जो उसे असफल कर देता है, भले ही बाद के तत्व फिर से मेल खाते हों:

```dart
print(scores.takeWhile((s) => s < 35).toList()); // [10, 20, 30]
```

---

Dart में कोई `sorted` मेथड नहीं है। `sort` `List` का होता है, वह सूची को **in place** पुनर्व्यवस्थित करता है और कुछ भी लौटाता है नहीं:

```dart
final numbers = [3, 1, 2];
numbers.sort();
print(numbers); // [1, 2, 3]
```

चूंकि वह `void` लौटाता है, आप परिणाम का उपयोग बिल्कुल नहीं कर सकते: `final sorted = numbers.sort();` एक ऐसा मान देता है जिसे पढ़ने से कंपाइलर इनकार कर देता है। एक क्रमबद्ध **प्रतिलिपि** बनाने की मुहावरेदार विधि है `toList()` के बाद cascade `..sort()`: `toList()` प्रतिलिपि बनाती है, और `..` उस पर `sort` चलाता है जबकि अभी भी प्रतिलिपि स्वयं लौटाता है।

```dart
final numbers = [3, 1, 2];
final sorted = numbers.toList()..sort();
print(sorted);  // [1, 2, 3]
print(numbers); // [3, 1, 2], untouched
```

`sort` एक **comparator** भी स्वीकार करता है: दो तत्वों का एक फंक्शन जो ऋणात्मक संख्या लौटाता है जब पहला तत्व दूसरे से पहले आता हो, `0` जब वे बराबर हों, और अन्यथा धनात्मक संख्या। `compareTo` ठीक यही उत्पन्न करता है, इसलिए किसी भी कुंजी के अनुसार क्रमित करना एक एक-पंक्ति का काम है:

```dart
final words = ['kiwi', 'fig', 'banana'];
print(words.toList()..sort((a, b) => a.length.compareTo(b.length)));
// [fig, kiwi, banana]
```

---

`fold` और `reduce` एक जैसे दिखते हैं, और उनमें से चुनाव दो प्रश्नों पर टिका है: क्या कलेक्शन खाली हो सकता है, और क्या परिणाम का टाइप तत्वों के समान होता है?

```dart
final words = ['fig', 'kiwi'];
final joined = words.reduce((a, b) => '$a, $b'); // String from Strings
final letters = words.fold(0, (acc, w) => acc + w.length); // int from Strings
print(joined);  // fig, kiwi
print(letters); // 7
```

`reduce` कभी भी केवल एक तत्व टाइप ही लौटा सकता है, क्योंकि वह एक तत्व से शुरू होता है। `fold` एक ऐसे मान से शुरू होता है जिसे आप चुनते हैं, इसलिए accumulator एक `int` जो गिनती कर रहा हो, एक `String` जो बढ़ रही हो, या यहाँ तक कि बनती हुई एक `List` भी हो सकता है। और चूंकि वह प्रारंभिक मान पहले से मौजूद है, एक खाली कलेक्शन पर `fold` बस उसी प्रारंभिक मान को अपरिवर्तित लौटा देता है, जबकि `reduce` के पास लौटाने को कुछ नहीं होता और वह त्रुटि उत्पन्न कर देता है।

---

इनमें से हर मेथड एक `Iterable` लौटाता है, और हर `Iterable` में वही मेथड फिर से होते हैं। यही उन्हें **शृंखलाबद्ध (chained)** करने देता है: पूरी गणना बाएँ से दाएँ एक पाइपलाइन जैसी पढ़ी जाती है, जहाँ हर कदम पिछले कदम के उत्पन्न किए पर काम करता है।

```dart
final words = ['kiwi', 'fig', 'banana', 'date'];
print(words.where((w) => w.length == 4).map((w) => w.toUpperCase()).toList());
// [KIWI, DATE]
```

केवल अंतिम कदम को `toList()` की आवश्यकता है: बीच में उसे कॉल करने से एक ऐसी सूची बनती जिसे कोई रखता ही नहीं।

शृंखला के साथ टाइप बदलता रहता है, और इसके साथ यह भी बदलता है कि अगला फंक्शन क्या प्राप्त करता है: एक `List<String>` पर `where` के बाद आपके पास अभी भी स्ट्रिंग्स होती हैं, लेकिन `map((w) => w.length)` के बाद अगला कदम संख्याएँ देखता है।

चूंकि हर कदम आलसी है, क्रम केवल परिणाम के लिए ही नहीं, किए गए कार्य के लिए भी मायने रखता है: पहले `where` से छँटाई करने का मतलब है कि `map` कम तत्वों पर कॉल होता है।

---

इन मेथड में कुछ भी विशेष नहीं है: उनके पैरामीटर के रूप में बस एक **फंक्शन** होता है, और आपके अपने फंक्शन भी यही कर सकते हैं। फंक्शन पैरामीटर का टाइप पहले रिटर्न टाइप, फिर `Function`, और फिर कोष्ठकों में पैरामीटर टाइप लिखा जाता है:

```dart
List<int> applyAll(List<int> numbers, int Function(int) operation) {
  return numbers.map(operation).toList();
}
```

कॉल करने वाला तय करता है **क्या** होता है, और फंक्शन तय करता है **किस पर** होता है। ध्यान दें कि `operation` सीधे `map` को कैसे सौंपा जाता है: एक फंक्शन मान किसी अन्य मान की तरह आगे पास किया जा सकता है।

आर्ग्युमेंट एक अनामित फंक्शन हो सकता है, या किसी मौजूदा फंक्शन का **नाम**, बिना कोष्ठक लिखा हुआ। कोष्ठक जोड़ने से उसे पास करने के बजाय कॉल कर दिया जाएगा:

```dart
int square(int n) => n * n;

print(applyAll([1, 2, 3], square));       // [1, 4, 9]
print(applyAll([1, 2, 3], (n) => n + 1)); // [2, 3, 4]
```

---

एक फंक्शन एक फंक्शन भी **लौटा** सकता है। रिटर्न टाइप बिल्कुल फंक्शन पैरामीटर टाइप की तरह लिखा जाता है, और लौटाया गया मान आमतौर पर एक अनामित फंक्शन होता है:

```dart
int Function(int) multiplier(int factor) {
  return (n) => n * factor;
}
```

`multiplier(3)` कुछ भी गुणा नहीं करता: वह एक नया फंक्शन बनाकर लौटाता है जो `3` से गुणा करता है। फिर उस फंक्शन को किसी अन्य मान की तरह संग्रहीत, कॉल या `map` को पास किया जाता है:

```dart
final triple = multiplier(3);
print(triple(5));                       // 15
print([1, 2, 3].map(triple).toList());  // [3, 6, 9]
```

लौटाया गया फंक्शन `multiplier` के समाप्त होने के बाद भी `factor` को याद रखता है। एक फंक्शन जो अपने निर्माण के दायरे (scope) के वेरिएबल को बनाए रखता है, उसे **closure** कहा जाता है, और यही इस तरह के फंक्शन फैक्ट्री को संभव बनाता है।

---

इन सबको एक साथ रखने पर, ये मेथड अधिकांश हाथ से लिखे लूप की जगह ले लेते हैं। एक पाइपलाइन आमतौर पर तीन चरणों में पढ़ी जाती है: `where` से तत्वों को **चुनें**, `map` से उन्हें **बदलें**, फिर `fold` से उन्हें **जोड़ें**:

```dart
final prices = [12, 40, 7];
final cheapTotal = prices.where((p) => p < 20).fold(0, (acc, p) => acc + p);
print(cheapTotal); // 19
```

चूंकि `fold` अपना प्रारंभिक मान स्वयं चुनता है, वह एक शृंखला को ऐसे टाइप के साथ भी समाप्त कर सकता है जिसका तत्वों से कोई लेना-देना नहीं, जैसे एक बार में एक टुकड़ा बढ़ती हुई एक `String`:

```dart
final words = ['fig', 'kiwi'];
final firstLetters = words.fold('', (acc, w) => acc + w[0]);
print(firstLetters); // fk
```

हर चरण छोटा रहता है और बताता है कि वह क्या करता है, और यही असली कारण है कि उन्हें तीनों काम एक साथ करने वाले लूप से बेहतर क्यों माना जाता है।
