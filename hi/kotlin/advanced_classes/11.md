# --description--

एक `interface` बताता है कि एक टाइप क्या कर सकता है। उसके मेंबर डिफ़ॉल्ट रूप से ऐब्स्ट्रैक्ट होते हैं, लेकिन एक इंटरफ़ेस एक **डिफ़ॉल्ट इम्प्लीमेंटेशन** भी दे सकता है — एक बॉडी जिसे हर इम्प्लीमेंट करने वाली क्लास मुफ़्त में इनहेरिट करती है और ओवरराइड कर सकती है:

```kotlin
interface Greeter {
    val name: String              // abstract, class को इसे प्रदान करना होगा
    fun greet(): String = "Hi, $name"  // डिफ़ॉल्ट कार्यान्वयन
}

class Person(override val name: String) : Greeter

class Robot(override val name: String) : Greeter {
    override fun greet(): String = "BEEP $name"
}

println(Person("Ann").greet()) // Hi, Ann
println(Robot("R2").greet())   // BEEP R2
```

एक इंटरफ़ेस स्टेट संग्रहीत नहीं कर सकता (उसके पास कोई बैकिंग फ़ील्ड नहीं होता), इसलिए एक ऐब्स्ट्रैक्ट प्रॉपर्टी को क्लास को इम्प्लीमेंट करना पड़ता है, आमतौर पर कंस्ट्रक्टर में `override val` के साथ। एक क्लास के विपरीत, एक टाइप जितने चाहे इंटरफ़ेस इम्प्लीमेंट कर सकता है।

# --instructions--

एक इंटरफ़ेस `Greeter` घोषित करें जिसमें `String` टाइप की एक ऐब्स्ट्रैक्ट `val` प्रॉपर्टी `name` और एक मेथड `greet(): String` हो जिसका डिफ़ॉल्ट इम्प्लीमेंटेशन `"Ann"` नाम के लिए `"Hello, Ann!"` लौटाता है।

फिर एक क्लास `Person` घोषित करें जो `Greeter` इम्प्लीमेंट करती है और अपने कंस्ट्रक्टर में `name` लेती है, और एक क्लास `Pirate` जो भी `Greeter` इम्प्लीमेंट करती है लेकिन `"Bo"` नाम के लिए `"Ahoy, Bo!"` लौटाने के लिए `greet()` को ओवरराइड करती है।
