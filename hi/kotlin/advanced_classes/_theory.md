एक `data class` एक ऐसी क्लास होती है जिसका काम **डेटा रखना** होता है। प्राइमरी कंस्ट्रक्टर में घोषित की गई प्रॉपर्टी के आधार पर कंपाइलर आपके लिए चार मेंबर जनरेट करता है:

- `toString()`, एक पढ़ने योग्य `ClassName(prop=value, ...)` टेक्स्ट
- `equals()` और `hashCode()`, ताकि एक ही डेटा वाले दो इंस्टेंस बराबर गिने जाएँ
- `copy()`, जो मौजूदा मानों का दोबारा उपयोग करके एक नया इंस्टेंस बनाता है

```kotlin
data class Book(val title: String, val pages: Int)

val book = Book("Dune", 412)
println(book)          // Book(title=Dune, pages=412)
println(book.copy())   // Book(title=Dune, pages=412)
```

**नामित आर्ग्युमेंट्स** के साथ `copy()` सचमुच चमकता है: आप केवल उन्हीं प्रॉपर्टी को नाम देते हैं जिन्हें आप बदलना चाहते हैं, और बाकी हर मान वैसे का वैसा आगे चला जाता है।

```kotlin
println(book.copy(pages = 500)) // Book(title=Dune, pages=500)
```

मूल ऑब्जेक्ट कभी बदलता नहीं है: `copy()` एक बिल्कुल नया ऑब्जेक्ट लौटाता है।

---

प्राइमरी कंस्ट्रक्टर की हर प्रॉपर्टी के लिए एक data class एक `componentN()` फ़ंक्शन भी जनरेट करती है: पहली प्रॉपर्टी के लिए `component1()`, दूसरी के लिए `component2()`, और आगे भी इसी तरह।

ये फ़ंक्शन **डीस्ट्रक्चरिंग घोषणाओं** (destructuring declarations) को ताकत देते हैं, जिनमें आप एक ऑब्जेक्ट को एक ही पंक्ति में कई वेरिएबल में खोलते हैं:

```kotlin
data class Point(val x: Int, val y: Int)

val point = Point(3, 7)
val (x, y) = point
println(x)               // 3
println(point.component2()) // 7
```

वेरिएबल का क्रम प्रॉपर्टी के क्रम का पालन करता है, उनके नामों का नहीं। जिसकी आपको ज़रूरत नहीं है उसे छोड़ने के लिए `_` का उपयोग करें:

```kotlin
val (_, onlyY) = point
```

---

जनरेट किया गया `equals()` `==` को एक **स्ट्रक्चरल** तुलना बनाता है: दो इंस्टेंस तब बराबर होते हैं जब प्राइमरी कंस्ट्रक्टर की हर प्रॉपर्टी बराबर हो। `===` ऑपरेटर अलग है, वह पूछता है कि क्या दोनों नाम मेमोरी में **एक ही ऑब्जेक्ट** की ओर इशारा करते हैं।

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, समान data
println(a === b) // false, दो अलग-अलग objects
println(a === a) // true
```

चूंकि `hashCode()`, `equals()` के साथ जनरेट होता है, data class इंस्टेंस एक `Set` के अंदर या `Map` कीज़ की तरह भी सही व्यवहार करते हैं: डुप्लिकेट एक में मिल जाते हैं।

```kotlin
println(setOf(a, b).size) // 1
```

एक साधारण क्लास इनमें से कुछ भी जनरेट नहीं करती, इसलिए उसके लिए `==` पहचान (identity) पर लौट आता है।

---

जनरेट किए गए मेंबर केवल **प्राइमरी कंस्ट्रक्टर** में घोषित प्रॉपर्टी को ही देखते हैं। क्लास **बॉडी** में घोषित कोई प्रॉपर्टी एक साधारण प्रॉपर्टी होती है: वह `toString()`, `equals()`, `hashCode()` या `copy()` का हिस्सा नहीं होती।

```kotlin
data class Item(val name: String) {
    var quantity: Int = 0
}

val a = Item("nail")
a.quantity = 5
println(a) // Item(name=nail)
```

यह भूलना आसान है, इसलिए प्राइमरी कंस्ट्रक्टर में वह सब कुछ रखें जो ऑब्जेक्ट की पहचान करता है, और बॉडी में डिराइव्ड या अस्थायी स्टेट रखें।

---

एक `sealed` क्लास विकल्पों का एक **बंद** सेट बताती है: केवल वही सब-क्लासेस मान्य हैं जो उसी पैकेज और मॉड्यूल में लिखी गई हैं, इसलिए कंपाइलर उन सबको जानता है।

```kotlin
sealed class Shape
data class Circle(val radius: Int) : Shape()
data class Square(val side: Int) : Shape()
```

इसका फ़ायदा **एग्ज़ॉस्टिव `when`** है: जब आप एक sealed टाइप पर ब्रांच करते हैं और हर सब-क्लास को कवर करते हैं, तो आप `else` ब्रांच हटा सकते हैं। बाद में कोई नई सब-क्लास जोड़ेंगे तो कंपाइलर चुपचाप `else` लेने के बजाय हर उस `when` की रिपोर्ट करेगा जिसे अपडेट करना आप भूल गए।

```kotlin
fun name(shape: Shape): String = when (shape) {
    is Circle -> "circle"
    is Square -> "square"
}
```

`is Circle` के बाद मान स्मार्ट कास्ट हो जाता है, इसलिए उस ब्रांच के अंदर `shape.radius` बिना किसी मैनुअल कास्ट के उपलब्ध होता है।

---

कभी-कभी आपको किसी चीज़ का ठीक **एक** इंस्टेंस चाहिए होता है: एक logger, एक registry, एक ऐप्लिकेशन कॉन्फ़िगरेशन। `class` की जगह `object` लिखने से वह सिंगलटन आपके लिए घोषित हो जाता है:

```kotlin
object Registry {
    var size = 0
    fun add() {
        size++
    }
}

Registry.add()
println(Registry.size) // 1
```

इंस्टेंस पहली बार उपयोग करने पर बनता है, और आप नाम को ही सीधे उपयोग करते हैं — न कोई `Registry()` कॉल होती है और न कोई कंस्ट्रक्टर। एक `object` में प्रॉपर्टी, मेथड और `init` ब्लॉक हो सकते हैं, और वह इंटरफ़ेस इम्प्लीमेंट कर सकता है या किसी क्लास का विस्तार कर सकता है।

---

एक `companion object` वह सिंगलटन होता है जो एक क्लास से जुड़ा होता है। कॉन्स्टेंट के अलावा, उसका स्वाभाविक काम **फ़ैक्टरी फ़ंक्शन** रखना है: ऐसे फ़ंक्शन जो इंस्टेंस बनाने से पहले इनपुट की जांच करते हैं या उसे रूपांतरित करते हैं, और जो `null` लौटा सकते हैं जब इनपुट का कोई मतलब न हो।

कंस्ट्रक्टर को `private` चिह्नित करने से हर कॉलर को फ़ैक्टरी से गुज़रना पड़ता है:

```kotlin
class Age private constructor(val years: Int) {
    companion object {
        fun of(years: Int): Age? = if (years >= 0) Age(years) else null
    }
}

println(Age.of(30)?.years) // 30
println(Age.of(-1))        // null
```

कंपेनियन को क्लास के नाम पर कॉल किया जाता है, `Age.of(...)`, और वह प्राइवेट कंस्ट्रक्टर तक पहुँच सकता है क्योंकि वह क्लास के अंदर रहता है।

---

एक `interface` बताता है कि एक टाइप क्या कर सकता है। उसके मेंबर डिफ़ॉल्ट रूप से ऐब्स्ट्रैक्ट होते हैं, लेकिन एक इंटरफ़ेस एक **डिफ़ॉल्ट इम्प्लीमेंटेशन** भी दे सकता है — एक बॉडी जिसे हर इम्प्लीमेंट करने वाली क्लास मुफ़्त में इनहेरिट करती है और ओवरराइड कर सकती है:

```kotlin
interface Greeter {
    val name: String              // abstract, class को इसे प्रदान करना होगा
    fun greet(): String = "Hi, $name"  // डिफ़ॉल्ट कार्यान्वयन
}

class Person(override val name: String) : Greeter

class Robot(override val name: String) : Greeter {
    override fun greet(): String = "BEEP $name"
}

println(Person("Ann").greet()) // Hi, Ann
println(Robot("R2").greet())   // BEEP R2
```

एक इंटरफ़ेस स्टेट संग्रहीत नहीं कर सकता (उसके पास कोई बैकिंग फ़ील्ड नहीं होता), इसलिए एक ऐब्स्ट्रैक्ट प्रॉपर्टी को क्लास को इम्प्लीमेंट करना पड़ता है, आमतौर पर कंस्ट्रक्टर में `override val` के साथ। एक क्लास के विपरीत, एक टाइप जितने चाहे इंटरफ़ेस इम्प्लीमेंट कर सकता है।

---

एक `abstract` क्लास एक इंटरफ़ेस और एक साधारण क्लास के बीच आती है: उसका इंस्टेंस नहीं बनाया जा सकता, और वह **ऐब्स्ट्रैक्ट** मेंबर — जिनकी कोई बॉडी नहीं होती और जिन्हें ओवरराइड किया जाना ज़रूरी है — को कंक्रीट मेंबर के साथ मिलाती है, जिन्हें सब-क्लासेस जैसे हैं वैसे ही इनहेरिट कर लेती हैं।

```kotlin
abstract class Vehicle(val name: String) {
    abstract fun wheels(): Int
    fun describe(): String = "$name has ${wheels()} wheels"
}

class Bike(name: String) : Vehicle(name) {
    override fun wheels(): Int = 2
}

println(Bike("BMX").describe()) // BMX has 2 wheels
```

एक इंटरफ़ेस के विपरीत, एक ऐब्स्ट्रैक्ट क्लास का एक कंस्ट्रक्टर होता है और वह प्रॉपर्टी में स्टेट संग्रहीत कर सकती है — इसीलिए सब-क्लास `name` को `: Vehicle(name)` के साथ ऊपर भेजती है। एक क्लास केवल एक क्लास का विस्तार कर सकती है, इसलिए जब सब-क्लासेस डेटा साझा करती हैं तो ऐब्स्ट्रैक्ट क्लास चुनें, और जब वे केवल व्यवहार साझा करती हैं तो इंटरफ़ेस चुनें। ऐब्स्ट्रैक्ट मेंबर `open` जोड़े बिना ही ओवरराइड किए जा सकते हैं।

---

किसी दूसरी क्लास के अंदर घोषित क्लास डिफ़ॉल्ट रूप से **नेस्टेड** होती है। वह बाहरी इंस्टेंस के बारे में कुछ नहीं जानती और आप उसे बाहरी क्लास के नाम से बनाते हैं:

```kotlin
class Outer {
    class Nested {
        fun hello() = "hi"
    }
}

println(Outer.Nested().hello()) // hi
```

`inner` कीवर्ड जोड़ें और स्थिति बदल जाती है: एक `inner` क्लास बाहरी इंस्टेंस का संदर्भ रखती है, इसलिए वह बाहरी प्रॉपर्टी पढ़ सकती है, और आप उसे **एक इंस्टेंस से** बनाते हैं:

```kotlin
class Counter(val step: Int) {
    inner class Doubler {
        fun value() = step * 2
    }
}

println(Counter(5).Doubler().value()) // 10
```

एक `inner` क्लास के अंदर, `this` भीतरी ऑब्जेक्ट होता है; जब आपको बाहरी वाला स्पष्ट रूप से चाहिए हो तो `this@Counter` का उपयोग करें।

---

इस टॉपिक के टुकड़े आमतौर पर आपस में जुड़ते हैं: एक `enum class`, जिसकी entries अपनी प्रॉपर्टी साथ रखती हैं, टैग के एक निश्चित सेट को मॉडल करती है, जबकि एक `data class` वह पेलोड रखता है जो उनके साथ आता है।

```kotlin
enum class Speed(val surcharge: Int) {
    STANDARD(0),
    EXPRESS(15)
}

data class Order(val total: Int, val speed: Speed)

val order = Order(100, Speed.EXPRESS)
println(order.total + order.speed.surcharge) // 115
```
