एक `data class` एक ऐसी क्लास होती है जिसका काम **डेटा रखना** होता है। प्राइमरी कंस्ट्रक्टर में घोषित की गई प्रॉपर्टी के आधार पर कंपाइलर आपके लिए चार मेंबर जनरेट करता है:

- `toString()`, एक पढ़ने योग्य `ClassName(prop=value, ...)` टेक्स्ट
- `equals()` और `hashCode()`, ताकि एक ही डेटा वाले दो इंस्टेंस बराबर गिने जाएँ
- `copy()`, जो मौजूदा मानों का दोबारा उपयोग करके एक नया इंस्टेंस बनाता है

```kotlin
data class Book(val title: String, val pages: Int)

val book = Book("Dune", 412)
println(book)          // Book(title=Dune, pages=412)
println(book.copy())   // Book(title=Dune, pages=412)
```

**नामित आर्ग्युमेंट्स** के साथ `copy()` सचमुच चमकता है: आप केवल उन्हीं प्रॉपर्टी को नाम देते हैं जिन्हें आप बदलना चाहते हैं, और बाकी हर मान वैसे का वैसा आगे चला जाता है।

```kotlin
println(book.copy(pages = 500)) // Book(title=Dune, pages=500)
```

मूल ऑब्जेक्ट कभी बदलता नहीं है: `copy()` एक बिल्कुल नया ऑब्जेक्ट लौटाता है।

---

प्राइमरी कंस्ट्रक्टर की हर प्रॉपर्टी के लिए एक data class एक `componentN()` फ़ंक्शन भी जनरेट करती है: पहली प्रॉपर्टी के लिए `component1()`, दूसरी के लिए `component2()`, और आगे भी इसी तरह।

ये फ़ंक्शन **डीस्ट्रक्चरिंग घोषणाओं** (destructuring declarations) को ताकत देते हैं, जिनमें आप एक ऑब्जेक्ट को एक ही पंक्ति में कई वेरिएबल में खोलते हैं:

```kotlin
data class Point(val x: Int, val y: Int)

val point = Point(3, 7)
val (x, y) = point
println(x)               // 3
println(point.component2()) // 7
```

वेरिएबल का क्रम प्रॉपर्टी के क्रम का पालन करता है, उनके नामों का नहीं। जिसकी आपको ज़रूरत नहीं है उसे छोड़ने के लिए `_` का उपयोग करें:

```kotlin
val (_, onlyY) = point
```

---

जनरेट किया गया `equals()` `==` को एक **स्ट्रक्चरल** तुलना बनाता है: दो इंस्टेंस तब बराबर होते हैं जब प्राइमरी कंस्ट्रक्टर की हर प्रॉपर्टी बराबर हो। `===` ऑपरेटर अलग है, वह पूछता है कि क्या दोनों नाम मेमोरी में **एक ही ऑब्जेक्ट** की ओर इशारा करते हैं।

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, same data
println(a === b) // false, two different objects
println(a === a) // true
```

चूंकि `hashCode()`, `equals()` के साथ जनरेट होता है, data class इंस्टेंस एक `Set` के अंदर या `Map` कीज़ की तरह भी सही व्यवहार करते हैं: डुप्लिकेट एक में मिल जाते हैं।

```kotlin
println(setOf(a, b).size) // 1
```

एक साधारण क्लास इनमें से कुछ भी जनरेट नहीं करती, इसलिए उसके लिए `==` पहचान (identity) पर लौट आता है।

---

जनरेट किए गए मेंबर केवल **प्राइमरी कंस्ट्रक्टर** में घोषित प्रॉपर्टी को ही देखते हैं। क्लास **बॉडी** में घोषित कोई प्रॉपर्टी एक साधारण प्रॉपर्टी होती है: वह `toString()`, `equals()`, `hashCode()` या `copy()` का हिस्सा नहीं होती।

```kotlin
data class Item(val name: String) {
    var quantity: Int = 0
}

val a = Item("nail")
a.quantity = 5
println(a) // Item(name=nail)
```

यह भूलना आसान है, इसलिए प्राइमरी कंस्ट्रक्टर में वह सब कुछ रखें जो ऑब्जेक्ट की पहचान करता है, और बॉडी में डिराइव्ड या अस्थायी स्टेट रखें।

---

एक `sealed` क्लास विकल्पों का एक **बंद** सेट बताती है: केवल वही सब-क्लासेस मान्य हैं जो उसी पैकेज और मॉड्यूल में लिखी गई हैं, इसलिए कंपाइलर उन सबको जानता है।

```kotlin
sealed class Shape
data class Circle(val radius: Int) : Shape()
data class Square(val side: Int) : Shape()
```

इसका फ़ायदा **एग्ज़ॉस्टिव `when`** है: जब आप एक sealed टाइप पर ब्रांच करते हैं और हर सब-क्लास को कवर करते हैं, तो आप `else` ब्रांच हटा सकते हैं। बाद में कोई नई सब-क्लास जोड़ेंगे तो कंपाइलर चुपचाप `else` लेने के बजाय हर उस `when` की रिपोर्ट करेगा जिसे अपडेट करना आप भूल गए।

```kotlin
fun name(shape: Shape): String = when (shape) {
    is Circle -> "circle"
    is Square -> "square"
}
```

`is Circle` के बाद मान स्मार्ट कास्ट हो जाता है, इसलिए उस ब्रांच के अंदर `shape.radius` बिना किसी मैनुअल कास्ट के उपलब्ध होता है।
