एक **लैम्ब्डा** बिना नाम का एक छोटा फ़ंक्शन होता है, जिसे सीधे कर्ली ब्रेसिज़ के बीच एक एक्सप्रेशन के रूप में लिखा जाता है।
पहले पैरामीटर आते हैं, फिर एक एरो `->`, फिर बॉडी:
```kotlin
val add = { a: Int, b: Int -> a + b }
```
लैम्ब्डा किसी भी अन्य मान की तरह एक मान है: आप इसे एक वेरिएबल में संग्रहीत कर सकते हैं और बाद में कोष्ठकों के साथ कॉल कर सकते हैं, बिल्कुल एक फ़ंक्शन की तरह:
```kotlin
println(add(2, 3)) // 5
```
बिना पैरामीटर वाले लैम्ब्डा में तो कोई एरो ही नहीं होता: `val hello = { println("Hello!") }`।

---

हर लैम्ब्डा का एक **फ़ंक्शन टाइप** होता है, जिसे कोष्ठकों में लिखे पैरामीटर टाइप, एक एरो और रिटर्न टाइप के रूप में लिखा जाता है।
लैम्ब्डा `{ a: Int, b: Int -> a + b }` का टाइप `(Int, Int) -> Int` है: यह दो `Int` मान लेता है और एक `Int` लौटाता है।
जब आप वेरिएबल पर फ़ंक्शन टाइप घोषित करते हैं, तो लैम्ब्डा के अंदर पैरामीटर टाइप छोड़े जा सकते हैं, क्योंकि कंपाइलर उन्हें पहले से जानता है:
```kotlin
val add: (Int, Int) -> Int = { a, b -> a + b }
val greet: (String) -> Unit = { name -> println("Hi, $name") }
```
जो लैम्ब्डा कुछ नहीं लौटाता उसका रिटर्न टाइप `Unit` होता है।

---

लैम्ब्डा की बॉडी कई लाइनों तक फैल सकती है। कोई `return` कीवर्ड नहीं होता: **अंतिम एक्सप्रेशन** का मान ही वह होता है जो लैम्ब्डा लौटाता है।
```kotlin
val describe: (Int) -> String = { n ->
    val half = n / 2
    "half of $n is $half" // returned
}
println(describe(10)) // half of 10 is 5
```
चूंकि Kotlin में `if` एक एक्सप्रेशन है, इसलिए यह अंतिम लाइन हो सकता है और परिणाम तय कर सकता है:
```kotlin
val parity: (Int) -> String = { n -> if (n % 2 == 0) "even" else "odd" }
```

---

जब एक लैम्ब्डा में ठीक **एक** पैरामीटर होता है, तो आप उसे घोषित करना छोड़ सकते हैं: Kotlin उसे आपके लिए `it` नाम दे देता है।
```kotlin
// val double: (Int) -> Int = { n -> n * 2 }
val double: (Int) -> Int = { it * 2 } // same thing
```
`it` केवल तब मौजूद होता है जब पैरामीटर स्पष्ट रूप से घोषित नहीं किया गया हो, और केवल एक-पैरामीटर वाले लैम्ब्डा के लिए।
यह छोटे लैम्ब्डा को संक्षिप्त रखता है, लेकिन लंबी बॉडी के लिए एक असली नाम ज़्यादा स्पष्ट होता है।

---

लैम्ब्डा ज़्यादातर दूसरे फ़ंक्शनों के आर्ग्युमेंट के रूप में उपयोग किए जाते हैं। Collections कई ऐसे फ़ंक्शन प्रदान करते हैं जो एक लैम्ब्डा लेते हैं:
- `forEach` हर तत्व के लिए लैम्ब्डा को एक बार चलाता है
- `map` हर तत्व के लिए लैम्ब्डा के परिणाम के साथ एक नई लिस्ट बनाता है
```kotlin
val numbers = listOf(1, 2, 3)
val doubled = numbers.map({ it * 2 }) // [2, 4, 6]
```
जब लैम्ब्डा **अंतिम** आर्ग्युमेंट होता है, तो आप उसे कोष्ठकों के बाहर ले जा सकते हैं; और जब वह एकमात्र आर्ग्युमेंट होता है, तो कोष्ठकों को पूरी तरह हटाया जा सकता है। इसे **trailing lambda** सिंटैक्स कहते हैं और यही इसे लिखने का सामान्य तरीका है:
```kotlin
val doubled = numbers.map { it * 2 }
doubled.forEach { println(it) }
```

---

जो लैम्ब्डा एक `Boolean` लौटाता है उसे **प्रेडिकेट** कहते हैं। कई collection फ़ंक्शन एक प्रेडिकेट लेते हैं:
- `filter` केवल वही तत्व रखता है जिनके लिए प्रेडिकेट `true` होता है
- `count` लौटाता है कि कितने तत्व इसे संतुष्ट करते हैं
- `any` और `all` बताते हैं कि कोई या हर तत्व इसे संतुष्ट करता है या नहीं
```kotlin
val numbers = listOf(1, 2, 3, 4, 5, 6)
println(numbers.filter { it % 2 == 0 }) // [2, 4, 6]
println(numbers.count { it > 4 })        // 2
println(numbers.any { it > 5 })          // true
```
कॉल को **चेन** किया जा सकता है: हर फ़ंक्शन एक नई लिस्ट लौटाता है जिस पर अगला काम करता है।
```kotlin
println(numbers.filter { it % 2 == 0 }.map { it * 10 }) // [20, 40, 60]
```

---

लैम्ब्डा सॉर्टिंग और एग्रीगेशन को भी संचालित करते हैं:
- `sortedBy` एक नई लिस्ट लौटाता है जो लैम्ब्डा द्वारा हर तत्व के लिए निकाले गए मान के आधार पर क्रमबद्ध होती है; `sortedByDescending` इसका उल्टा करता है
- `reduce` सभी तत्वों को एक मान में जोड़ता है: लैम्ब्डा को अब तक जमा हुआ परिणाम और अगला तत्व प्राप्त होता है
```kotlin
val words = listOf("kiwi", "fig", "banana")
println(words.sortedBy { it.length })          // [fig, kiwi, banana]
println(words.sortedByDescending { it.length }) // [banana, kiwi, fig]

val numbers = listOf(1, 2, 3, 4)
println(numbers.reduce { acc, n -> acc + n })   // 10
```
`reduce` पहले तत्व को `acc` के रूप में लेकर शुरू होता है, फिर बाकी हर तत्व के लिए लैम्ब्डा चलाता है।

---

`reduce` के साथ परिणाम का आकार लैम्ब्डा पर निर्भर करता है। दो मानों को जोड़ने वाली कोई भी क्रिया काम करती है: एक योग, एक गुणन, या दोनों में से बड़ा मान रखना।
```kotlin
val numbers = listOf(3, 9, 4)
println(numbers.reduce { acc, n -> if (n > acc) n else acc }) // 9
```
ध्यान दें कि `reduce` एक खाली लिस्ट पर अपवाद (exception) फेंकता है, क्योंकि शुरू करने के लिए कोई पहला तत्व नहीं होता।

---

एक लैम्ब्डा अपने आस-पास घोषित वेरिएबल का उपयोग कर सकता है, तब भी जब उन्हें घोषित करने वाला कोड आगे बढ़ चुका हो। इसे **क्लोज़र** कहते हैं: लैम्ब्डा उन वेरिएबल को *कैप्चर* कर लेता है जिनकी उसे ज़रूरत होती है।
कई अन्य भाषाओं के विपरीत, Kotlin एक लैम्ब्डा को कैप्चर किए गए `var` को **बदलने** की अनुमति देता है:
```kotlin
var clicks = 0
val onClick = { clicks++ }
onClick()
onClick()
println(clicks) // 2
```
`onClick` का हर कॉल उसी `clicks` वेरिएबल को अपडेट करता है जिसे बाहरी कोड देखता है।

---

चूंकि लैम्ब्डा एक मान है, इसलिए एक फ़ंक्शन उसे **लौटा** सकता है। रिटर्न टाइप एक फ़ंक्शन टाइप होता है:
```kotlin
fun multiplier(factor: Int): (Int) -> Int {
    return { it * factor }
}
val triple = multiplier(3)
println(triple(5)) // 15
```
लौटाया गया लैम्ब्डा `factor` को कैप्चर करता है, इसलिए `multiplier` का हर कॉल एक अलग फ़ंक्शन बनाता है।
जो फ़ंक्शन दूसरे फ़ंक्शन लेते हैं या लौटाते हैं, उन्हें **हायर-ऑर्डर फ़ंक्शन** कहते हैं।

---

लौटाया गया लैम्ब्डा फ़ंक्शन के अंदर घोषित एक `var` को कैप्चर कर सकता है। वह वेरिएबल फ़ंक्शन के लौटने के बाद भी जीवित रहता है, और केवल वही लैम्ब्डा उस तक पहुँच सकता है: यह निजी स्थिति (private state) है।
```kotlin
fun makeGreeter(): () -> String {
    var calls = 0
    return { calls++; "hello #$calls" }
}
val greeter = makeGreeter()
println(greeter()) // hello #1
println(greeter()) // hello #2
```
`makeGreeter()` का हर कॉल एक नया `calls` घोषित करता है, इसलिए दो ग्रीटर स्वतंत्र रूप से गिनती करते हैं।

---

आप अपने हायर-ऑर्डर फ़ंक्शन भी लिख सकते हैं: फ़ंक्शन टाइप वाला पैरामीटर उस आकार का कोई भी लैम्ब्डा स्वीकार करता है, और फ़ंक्शन के अंदर आप उसे एक सामान्य फ़ंक्शन की तरह कॉल करते हैं।
```kotlin
fun repeatTwice(text: String, transform: (String) -> String): String {
    return transform(transform(text))
}
println(repeatTwice("a", { it + "!" })) // a!!
println(repeatTwice("a") { it + "!" })  // same, with a trailing lambda
```
फ़ंक्शन पैरामीटर को **अंत में** रखना ही वह चीज़ है जो कॉल करने वालों के लिए trailing lambda सिंटैक्स उपलब्ध कराती है।

---

जब वह फ़ंक्शन जिसकी आपको ज़रूरत है पहले से मौजूद हो, तो उसे लैम्ब्डा में लपेटने की कोई ज़रूरत नहीं है: एक **फ़ंक्शन रेफ़रेंस** `::name` एक नाम वाले फ़ंक्शन को मेल खाते फ़ंक्शन टाइप वाले मान में बदल देता है।
```kotlin
fun isEven(n: Int) = n % 2 == 0
val numbers = listOf(1, 2, 3, 4)
println(numbers.filter { isEven(it) }) // [2, 4]
println(numbers.filter(::isEven))      // [2, 4], same thing
```
मेंबर फ़ंक्शन अपने टाइप के ज़रिए रेफ़र किए जाते हैं, जैसे `String::uppercase`:
```kotlin
println(listOf("a", "b").map(String::uppercase)) // [A, B]
```

---

एक **अनाम फ़ंक्शन** `fun` से घोषित ऐसा फ़ंक्शन होता है जिसका कोई नाम नहीं होता। यह एक फ़ंक्शन मान बनाने का दूसरा तरीका है:
```kotlin
val square = fun(x: Int): Int {
    return x * x
}
println(square(4)) // 16
```
लैम्ब्डा से अलग, यह अपना रिटर्न टाइप स्पष्ट रूप से घोषित कर सकता है और मान देने के लिए `return` का उपयोग करता है।
अनाम फ़ंक्शन और लैम्ब्डा आपस में बदले जा सकते हैं: दोनों को `map`, `filter` या किसी भी फ़ंक्शन टाइप लेने वाले फ़ंक्शन को पास किया जा सकता है।

---

हायर-ऑर्डर फ़ंक्शन फ़ंक्शन लेते भी हैं और लौटाते भी हैं। एक क्लासिक उदाहरण है **कंपोज़िशन**: एक नया फ़ंक्शन बनाना जो एक फ़ंक्शन चलाता है और उसके परिणाम को दूसरे फ़ंक्शन में भेजता है।
```kotlin
fun andThen(first: (Int) -> Int, second: (Int) -> Int): (Int) -> Int {
    return { n -> second(first(n)) }
}
val addOneThenDouble = andThen({ it + 1 }, { it * 2 })
println(addOneThenDouble(3)) // 8
```
लौटाया गया लैम्ब्डा `first` और `second` दोनों को कैप्चर करता है, इसलिए यह `andThen` के लौटने के बहुत बाद तक भी काम करता रहता है।

---

कुछ फ़ंक्शन **receiver वाला लैम्ब्डा** लेते हैं: लैम्ब्डा के अंदर, `this` एक विशिष्ट ऑब्जेक्ट होता है, इसलिए आप उसके मेंबर को उसका नाम दिए बिना सीधे कॉल कर सकते हैं।
`buildString` इसका एक सामान्य उदाहरण है: उसके लैम्ब्डा के अंदर `this` एक `StringBuilder` होता है, इसलिए `append` को ऐसे कॉल किया जा सकता है मानो वह एक लोकल फ़ंक्शन हो:
```kotlin
val text = buildString {
    append("Hello")
    append(", ")
    append("world")
}
println(text) // Hello, world
```
`buildString` अंतिम स्ट्रिंग लौटाता है। यह लूप में `+` से कंकैटिनेट करने का एक सुविधाजनक विकल्प है।
