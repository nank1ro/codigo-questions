**उच्च-क्रम मेथड** वह मेथड है जो किसी फ़ंक्शन को आर्ग्युमेंट के रूप में लेती है। Kotlin के कलेक्शन ऐसी कई मेथड देते हैं, और आप जो फ़ंक्शन पास करते हैं वह आमतौर पर एक **लैम्ब्डा** होता है: कर्ली ब्रेसेस के बीच लिखा गया एक छोटा अनाम फ़ंक्शन।
`map` सबसे आम है: यह हर एलिमेंट पर लैम्ब्डा को कॉल करती है और परिणामों के साथ एक **नई लिस्ट** लौटाती है, मूल लिस्ट अछूती रहती है:
```kotlin
val numbers = listOf(1, 2, 3)
val doubled = numbers.map { it * 2 }
println(doubled) // [2, 4, 6]
println(numbers) // [1, 2, 3]
```
जब लैम्ब्डा में केवल एक पैरामीटर हो तो उसे घोषित करने की ज़रूरत नहीं: Kotlin उसे `it` नाम देता है। लैम्ब्डा मेथड के नाम के बाद, गोल कोष्ठकों के बाहर लिखा जाता है, और जब लैम्ब्डा ही एकमात्र आर्ग्युमेंट हो तो कोष्ठक छोड़े जा सकते हैं। यही **trailing lambda** सिंटैक्स है और इस विषय के हर अभ्यास में इसका उपयोग होता है।

---

`filter` एक ऐसा लैम्ब्डा लेती है जो `Boolean` लौटाता है, जिसे **प्रेडिकेट** कहते हैं, और केवल उन एलिमेंट्स के साथ एक नई लिस्ट लौटाती है जिनके लिए प्रेडिकेट `true` है:
```kotlin
val numbers = listOf(4, -2, 7, 0)
println(numbers.filter { it > 0 }) // [4, 7]
```
`it` के बजाय आप पैरामीटर को नाम दे सकते हैं, जिसके बाद एक तीर `->` आता है। नाम वाला पैरामीटर लंबे लैम्ब्डा को पढ़ने में आसान बनाता है, और जब एक लैम्ब्डा दूसरे के भीतर नेस्टेड हो तो यह ज़रूरी है, क्योंकि भीतरी `it` बाहरी एलिमेंट को छिपा देता है:
```kotlin
val minLength = 4
val words = listOf("fig", "banana", "kiwi")
println(words.filter { word -> word.length >= minLength }) // [banana, kiwi]
```

---

`forEach` हर एलिमेंट के लिए लैम्ब्डा को एक बार चलाती है और कुछ नहीं लौटाती। यह `for` लूप का उच्च-क्रम विकल्प है, और इसका उपयोग प्रिंट करने जैसे साइड इफ़ेक्ट्स के लिए होता है:
```kotlin
listOf("a", "b").forEach { println(it) }
```
`forEachIndexed` आपको हर एलिमेंट की स्थिति भी देती है। इसके लैम्ब्डा में **दो** पैरामीटर होते हैं, इसलिए उन्हें नाम देना ज़रूरी है: `it` केवल ठीक एक पैरामीटर वाले लैम्ब्डा के लिए मौजूद होता है।
```kotlin
listOf("a", "b").forEachIndexed { index, letter ->
    println("$index: $letter") // 0: a, फिर 1: b
}
```

---

`reduce` सभी एलिमेंट्स को एक ही मान में जोड़ देती है। इसका लैम्ब्डा दो पैरामीटर लेता है: **संचायक** (अब तक का परिणाम) और अगला एलिमेंट। यह पहले एलिमेंट को संचायक बनाकर शुरू करती है और बाकी हर एलिमेंट के लिए लैम्ब्डा चलाती है:
```kotlin
val numbers = listOf(1, 2, 3, 4)
println(numbers.reduce { acc, n -> acc + n }) // 10
```
खाली लिस्ट पर `reduce` एक एक्सेप्शन फेंकती है, क्योंकि शुरू करने के लिए कोई पहला एलिमेंट नहीं होता। `fold` इसे ठीक करती है: आप संचायक का **आरंभिक मान** आर्ग्युमेंट के रूप में देते हैं, और लैम्ब्डा हर एलिमेंट के लिए चलता है, पहले वाले सहित:
```kotlin
println(numbers.fold(0) { acc, n -> acc + n })   // 10
println(listOf<Int>().fold(0) { acc, n -> acc + n }) // 0
```
`fold` के साथ संचायक का टाइप एलिमेंट्स से अलग भी हो सकता है, जैसे संख्याओं की लिस्ट से एक `String` बनाना।

---

कुछ उच्च-क्रम मेथड नई कलेक्शन बनाने के बजाय कलेक्शन के बारे में किसी सवाल का जवाब देती हैं। ये सभी एक प्रेडिकेट लेती हैं:
- `any` `true` लौटाती है यदि **कम से कम एक** एलिमेंट उसे संतुष्ट करे
- `all` `true` लौटाती है यदि **हर** एलिमेंट उसे संतुष्ट करे
- `none` `true` लौटाती है यदि **कोई भी** एलिमेंट उसे संतुष्ट न करे
- `count` लौटाती है कि **कितने** एलिमेंट उसे संतुष्ट करते हैं
```kotlin
val numbers = listOf(1, 2, 3)
println(numbers.any { it > 2 })   // true
println(numbers.all { it > 2 })   // false
println(numbers.none { it > 2 })  // false
println(numbers.count { it > 1 }) // 2
```
खाली लिस्ट पर `any` `false` लौटाती है, जबकि `all` और `none` `true` लौटाती हैं: कोई एलिमेंट नहीं है जो नियम तोड़े।

---

एग्रीगेशन मेथड पूरी कलेक्शन को एक मान में बदल देती हैं:
- `sum()` संख्याओं की लिस्ट को जोड़ती है, जबकि `sumOf` उस मान को जोड़ती है जो लैम्ब्डा हर एलिमेंट के लिए निकालता है
- `maxByOrNull` और `minByOrNull` वह **एलिमेंट** लौटाती हैं जिसके लिए लैम्ब्डा सबसे बड़ा या सबसे छोटा मान देता है, या खाली लिस्ट पर `null`
```kotlin
val words = listOf("fig", "banana", "kiwi")
println(words.sumOf { it.length })      // 13
println(words.minByOrNull { it.length }) // fig
println(listOf(1, 2, 3).sum())           // 6
```
`maxOf { it.length }` के साथ अंतर पर ध्यान दें, जो उस एलिमेंट के बजाय सबसे बड़ा **मान** (`6`) लौटाती है जिसने उसे उत्पन्न किया।

---

`sortedBy` एक नई लिस्ट लौटाती है जो उस मान के अनुसार क्रमबद्ध होती है जो लैम्ब्डा हर एलिमेंट के लिए निकालता है, सबसे छोटे से ऊपर की ओर। `sortedByDescending` सबसे बड़े से नीचे की ओर क्रमबद्ध करती है। जब आप एलिमेंट्स की स्वयं तुलना करना चाहते हैं, तो `sorted()` और `sortedDescending()` को किसी लैम्ब्डा की ज़रूरत नहीं:
```kotlin
val words = listOf("kiwi", "fig", "banana")
println(words.sortedBy { it.length })            // [fig, kiwi, banana]
println(words.sortedByDescending { it.length })  // [banana, kiwi, fig]
println(words.sorted())                          // [banana, fig, kiwi]
```
यह क्रमबद्धता **स्थिर** है: समान कुंजी वाले एलिमेंट अपना मूल सापेक्ष क्रम बनाए रखते हैं। मूल लिस्ट कभी नहीं बदली जाती।

---

`take(n)` पहले `n` एलिमेंट्स के साथ एक नई लिस्ट लौटाती है, और `drop(n)` पहले `n` एलिमेंट्स के **बिना** एक नई लिस्ट लौटाती है। इनमें से कोई भी लैम्ब्डा नहीं लेती, लेकिन इन्हें अक्सर ऐसी मेथड के बाद जोड़ा जाता है जो लैम्ब्डा लेती है:
```kotlin
val numbers = listOf(5, 3, 8, 1)
println(numbers.take(2))                    // [5, 3]
println(numbers.drop(2))                    // [8, 1]
println(numbers.sortedDescending().take(2)) // [8, 5]
```
`takeWhile` और `dropWhile` प्रेडिकेट वाले संस्करण हैं: ये शुरुआत से एलिमेंट्स तब तक लेती या छोड़ती हैं **जब तक** प्रेडिकेट `true` है, और पहले ऐसे एलिमेंट पर रुक जाती हैं जो उसे संतुष्ट नहीं करता:
```kotlin
println(numbers.takeWhile { it > 2 }) // [5, 3, 8]
```

---

`groupBy` एक कलेक्शन को `Map` में बाँटती है: लैम्ब्डा हर एलिमेंट की **कुंजी** निकालता है, और हर कुंजी उन एलिमेंट्स की लिस्ट से जुड़ी होती है जिन्होंने उसे उत्पन्न किया, उनके मूल क्रम में:
```kotlin
val words = listOf("fig", "kiwi", "pear")
val byLength = words.groupBy { it.length }
println(byLength)    // {3=[fig], 4=[kiwi, pear]}
println(byLength[4]) // [kiwi, pear]
```
परिणाम का टाइप `Map<K, List<T>>` होता है, जहाँ `K` लैम्ब्डा द्वारा लौटाया गया टाइप है और `T` एलिमेंट्स का टाइप है। कुंजियाँ उसी क्रम में आती हैं जिसमें वे पहली बार मिलती हैं।

---

जब लैम्ब्डा हर एलिमेंट के लिए एक **लिस्ट** लौटाता है, तो `map` लिस्टों की लिस्ट बनाती है। `flatMap` वही करती है लेकिन फिर उन सभी लिस्टों को एक ही सपाट लिस्ट में जोड़ देती है:
```kotlin
val numbers = listOf(1, 2)
println(numbers.map { listOf(it, -it) })     // [[1, -1], [2, -2]]
println(numbers.flatMap { listOf(it, -it) }) // [1, -1, 2, -2]
```
क्रम बना रहता है: पहले एलिमेंट से बने सभी मान पहले आते हैं, फिर दूसरे के, और इसी तरह आगे। यदि आपके पास पहले से लिस्टों की लिस्ट है, तो `flatten()` उन्हें बिना लैम्ब्डा के जोड़ देती है।

---

`zip` दो लिस्टों के एलिमेंट्स को स्थान दर स्थान जोड़ती है। लैम्ब्डा के बिना यह `Pair` मानों की लिस्ट लौटाती है, जिनके दोनों हिस्से `.first` और `.second` से पढ़े जाते हैं; लैम्ब्डा के साथ, हर स्थान के दोनों एलिमेंट उसे दिए जाते हैं और परिणाम एक लिस्ट में इकट्ठे होते हैं:
```kotlin
val names = listOf("Ann", "Bob")
val ages = listOf(31, 25)
println(names.zip(ages))                            // [(Ann, 31), (Bob, 25)]
println(names.zip(ages) { name, age -> "$name:$age" }) // [Ann:31, Bob:25]
```
परिणाम दोनों लिस्टों में से **छोटी** वाली जितना लंबा होता है: लंबी वाली के अतिरिक्त एलिमेंट नज़रअंदाज़ कर दिए जाते हैं।

---

लैम्ब्डा का रूप उससे मेल खाना चाहिए जिसकी मेथड अपेक्षा करती है:
- जो मेथड एक बार में एक एलिमेंट पर काम करती हैं (`map`, `filter`, `sortedBy`, `groupBy`...) वे **एक पैरामीटर** वाला लैम्ब्डा लेती हैं, जहाँ `it` उपलब्ध होता है
- `reduce`, `fold`, `forEachIndexed` और लैम्ब्डा वाली `zip` **दो** मान देती हैं, इसलिए पैरामीटरों को `a, b ->` के साथ स्पष्ट रूप से नाम देना ज़रूरी है
```kotlin
val numbers = listOf(1, 2, 3)
numbers.map { it * 2 }                  // ठीक: एक पैरामीटर, it उपलब्ध है
numbers.reduce { acc, n -> acc + n }    // ठीक: दो पैरामीटर, नाम के साथ
numbers.reduce { it + 1 }               // त्रुटि: दो पैरामीटर के साथ it मौजूद नहीं होता
```
पैरामीटरों को नाम देना हमेशा अनुमत है, एक ही होने पर भी: `numbers.map { n -> n * 2 }`।

---

उच्च-क्रम मेथड को **श्रृंखला में जोड़ा** जा सकता है: हर एक नई कलेक्शन लौटाती है जिस पर अगली काम करती है, इसलिए पूरी गणना बाएँ से दाएँ चलने वाली पाइपलाइन की तरह पढ़ी जाती है:
```kotlin
val words = listOf("kiwi", "fig", "banana", "date")
println(words.filter { it.length == 4 }.map { it.uppercase() }.sorted()) // [DATE, KIWI]
```
मैप के पास भी उच्च-क्रम मेथड हैं। `mapValues` कुंजियाँ बनाए रखती है और हर मान को लैम्ब्डा के परिणाम से बदल देती है, जिसे `.key` और `.value` के साथ **एंट्री** मिलती है:
```kotlin
val byLength = words.groupBy { it.length }      // {4=[kiwi, date], 3=[fig], 6=[banana]}
println(byLength.mapValues { it.value.size })   // {4=2, 3=1, 6=1}
```

---

एक श्रृंखला में `it` का टाइप हर चरण पर बदलता है: `List<String>` पर `filter` के बाद आपके पास अब भी स्ट्रिंग्स हैं, लेकिन `map { it.length }` के बाद आपके पास `List<Int>` है, इसलिए अगला लैम्ब्डा संख्याएँ देखता है।
```kotlin
val words = listOf("kiwi", "fig")
println(words.map { it.length }.filter { it > 3 }) // [4]
```
हर चरण एक **नई** लिस्ट लौटाता है और पिछली को कभी नहीं छूता, इसलिए एक श्रृंखला को नाम वाले मध्यवर्ती मानों में बाँटा जा सकता है और परिणाम नहीं बदलता।

---

एक लैम्ब्डा के भीतर दूसरा उच्च-क्रम कॉल हो सकता है। भीतरी लैम्ब्डा के अंदर `it` **भीतरी** एलिमेंट को दर्शाता है और बाहरी को छिपा देता है, इसलिए बाहरी पैरामीटर को स्पष्ट नाम दें ताकि दोनों तक पहुँच बनी रहे:
```kotlin
val sales = listOf("north" to 120, "south" to 80, "north" to 30)
val byRegion = sales.groupBy { it.first }
val totals = byRegion.mapValues { entry -> entry.value.sumOf { it.second } }
println(totals) // {north=150, south=80}
```
`"north" to 120` एक `Pair` बनाता है। यहाँ बाहरी लैम्ब्डा मैप की एक एंट्री पर काम करता है, जबकि भीतरी उस एंट्री की लिस्ट के पेयर्स पर।

---

एक `Map` को एंट्रीज़ की लिस्ट की तरह संसाधित किया जा सकता है: `filter` और `map` सीधे मैप पर काम करती हैं और हर एंट्री को `.key` तथा `.value` के साथ पाती हैं। मैप पर `filter` एक मैप लौटाती है, जबकि `map` एक लिस्ट लौटाती है। `sortedBy` जैसी क्रमबद्ध करने वाली मेथड मैप पर परिभाषित नहीं हैं: पहले `scores.entries` से होकर जाएँ, जो एंट्रीज़ की कलेक्शन है:
```kotlin
val scores = mapOf("Ann" to 90, "Bob" to 72)
println(scores.filter { it.value > 80 })              // {Ann=90}
println(scores.entries.sortedBy { it.value }.map { it.key }) // [Bob, Ann]
```
`scores.entries` सभी एंट्रीज़ का समुच्चय है; `scores.keys` और `scores.values` केवल एक-एक पक्ष देते हैं।
