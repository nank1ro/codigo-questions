**स्कोप फंक्शन** किसी ऑब्जेक्ट के *संदर्भ के अंदर* एक कोड ब्लॉक चलाते हैं। वे भाषा में नई सुविधाएँ नहीं जोड़ते: वे बस एक ही ऑब्जेक्ट पर काम करने वाले कोड को छोटा और पढ़ने में आसान बनाते हैं। Kotlin में उनके पाँच रूप हैं: `let`, `run`, `with`, `apply` और `also`।

वे केवल **दो** बातों पर अलग होते हैं: ब्लॉक के अंदर ऑब्जेक्ट को कैसे संदर्भित किया जाता है, और कॉल क्या वापस देता है। हम `let` से शुरुआत करते हैं: इसके ब्लॉक के अंदर ऑब्जेक्ट को `it` कहा जाता है, और कॉल ब्लॉक की **आखिरी एक्सप्रेशन का परिणाम** लौटाता है।
```kotlin
val word = "kotlin"
val letters = word.let { it.length } // 6
println(letters)
```
`let` के बिना आपको एक अस्थायी वेरिएबल की ज़रूरत होती; इसके साथ ऑब्जेक्ट छोटे नाम `it` के रूप में तब तक उपलब्ध रहता है जब तक ब्लॉक चलता है।

---

चूंकि `let` अपनी आखिरी एक्सप्रेशन का मान लौटाता है, यह बिना किसी मध्यवर्ती वेरिएबल के नाम दिए एक मान को **किसी और चीज़ में बदलने** का एक आसान तरीका है:
```kotlin
val price = 12
val label = price.let { "$it EUR" }
println(label) // 12 EUR
```
ब्लॉक के अंदर आप `it` का उपयोग जितनी बार चाहें कर सकते हैं:
```kotlin
println("kiwi".let { "${it.uppercase()} has ${it.length} letters" })
// KIWI has 4 letters
```

---

सेफ कॉल के बाद `let` सचमुच बहुत उपयोगी हो जाता है। `?.let { ... }` ब्लॉक को **केवल** तब चलाता है जब मान `null` न हो, और ब्लॉक के अंदर `it` एक non-null मान होता है, इसलिए किसी अतिरिक्त जांच की ज़रूरत नहीं होती:
```kotlin
val email: String? = "ada@example.com"
email?.let { println("Sending to ${it.uppercase()}") }
```
जब मान `null` होता है तो पूरी एक्सप्रेशन `null` हो जाती है और ब्लॉक कभी नहीं चलता, इसलिए फॉलबैक देने के लिए Elvis ऑपरेटर `?:` इसका स्वाभाविक साथी है:
```kotlin
fun label(city: String?): String {
    return city?.let { "City: $it" } ?: "No city"
}
```

---

`let` ब्लॉक के अंदर ऑब्जेक्ट को `it` कहना ज़रूरी नहीं है: आप लैम्ब्डा पैरामीटर को एक नाम दे सकते हैं, जिससे कोड तब पढ़ने में आसान रहता है जब ब्लॉक नेस्टेड हों या जब `it` कुछ उपयोगी न बताए।
```kotlin
val price: Int? = 12
println(price?.let { amount -> "$amount EUR" }) // 12 EUR
```
यही नामकरण हर उस स्कोप फंक्शन के साथ काम करता है जो `it` का उपयोग करता है, यानी `let` और `also` के लिए।

---

`apply` दोनों अक्षों पर एक साथ आगे बढ़ता है: इसके ब्लॉक के अंदर ऑब्जेक्ट रिसीवर `this` होता है (इसलिए इसके सदस्यों का उपयोग **बिना किसी प्रीफिक्स** के किया जा सकता है), और कॉल **ऑब्जेक्ट स्वयं** लौटाता है, ब्लॉक का परिणाम नहीं।

यही संयोजन `apply` को ऑब्जेक्ट को **कॉन्फ़िगर** करने का उपकरण बनाता है, ठीक वहीं जहाँ आप उसे बनाते हैं:
```kotlin
class Server {
    var host = "localhost"
    var port = 80
}

val server = Server().apply {
    host = "example.com"
    port = 8080
}
println("${server.host}:${server.port}") // example.com:8080
```
ब्लॉक के अंदर `host` और `port` वास्तव में `this.host` और `this.port` हैं; चूंकि `apply` कॉन्फ़िगर किया हुआ `Server` वापस देता है, इसे सीधे असाइन किया जा सकता है।

---

`apply` केवल उन ऑब्जेक्ट्स तक सीमित नहीं है जिन्हें आपने अभी-अभी बनाया है: यह किसी भी ऑब्जेक्ट पर काम करता है, और चूंकि यह ऑब्जेक्ट वापस देता है, आप पूरी एक्सप्रेशन का उपयोग वहीं कर सकते हैं जहाँ ऑब्जेक्ट अपेक्षित हो।
```kotlin
val box = Box()
box.apply { label = "tools" }        // changes box and returns it
println(listOf(Box().apply { label = "nails" }).size) // 1
```
ब्लॉक कोड का एक सामान्य ब्लॉक है, इसलिए इसमें आपकी ज़रूरत के जितने स्टेटमेंट हो सकते हैं।

---

`also`, `apply` का दर्पण प्रतिबिंब है: ऑब्जेक्ट को `it` के रूप में संदर्भित किया जाता है, और कॉल **ऑब्जेक्ट स्वयं** लौटाता है। चूंकि ब्लॉक का परिणाम छोड़ दिया जाता है, `also` लॉगिंग या जांच जैसे **साइड इफ़ेक्ट** के लिए होता है, और इसे चेन के बीच में डाला जा सकता है बिना यह बदले कि चेन क्या बनाती है:
```kotlin
val total = listOf(1, 2, 3)
    .also { println("size: ${it.size}") } // size: 3
    .sum()
println(total) // 6
```
इसे *"और इसके साथ यह भी करो"* के रूप में पढ़ें: मान अछूता रहते हुए अगले चरण तक बहता रहता है।

---

जब ब्लॉक को ऑब्जेक्ट किसी और चीज़ के **आर्गुमेंट** के रूप में चाहिए होता है, तो `also`, `apply` से बेहतर पढ़ा जाता है: `it` को सीधे सौंपा जा सकता है, जबकि `this` को स्पष्ट रूप से लिखना पड़ता।
```kotlin
val names = mutableListOf<String>()
val user = "ada".also { names.add(it) }
println(user)  // ada
println(names) // [ada]
```
एक्सप्रेशन का मान फिर भी `"ada"` है: `also` केवल उसे निकलते हुए देखता है।

---

`run`, `let` ही है बस ऑब्जेक्ट को नाम देने के दूसरे तरीके के साथ: ब्लॉक के अंदर ऑब्जेक्ट `this` होता है, इसलिए इसके सदस्यों को किसी प्रीफिक्स की ज़रूरत नहीं होती, और कॉल **आखिरी एक्सप्रेशन का परिणाम** लौटाता है।

यह तब उपयुक्त है जब आप एक मान निकालने के लिए उसी ऑब्जेक्ट के कई सदस्य पढ़ते हैं:
```kotlin
class Rect(val w: Int, val h: Int)

val area = Rect(3, 4).run { w * h }
println(area) // 12
```
इसकी तुलना `apply` से करें, जो `this` का उपयोग बिल्कुल इसी तरह करता है लेकिन ब्लॉक के परिणाम की जगह ऑब्जेक्ट लौटाता है।

---

`with` वही काम करता है जो `run`, लेकिन यह एक्सटेंशन **नहीं** है: ऑब्जेक्ट डॉट कॉल का रिसीवर होने की बजाय पहले आर्गुमेंट के रूप में पास किया जाता है।
```kotlin
val text = with(StringBuilder()) {
    append("Hello")
    append(", world")
    toString()
}
println(text) // Hello, world
```
ब्लॉक के अंदर ऑब्जेक्ट `this` होता है और कॉल आखिरी एक्सप्रेशन लौटाता है, बिल्कुल `run` की तरह। `with` को तब प्राथमिकता दें जब आपके पास पहले से एक non-null ऑब्जेक्ट हो और आप उस पर कई कॉल को एक साथ समूहित करना चाहते हों; `run` को तब प्राथमिकता दें जब ऑब्जेक्ट किसी चेन से निकले या उसे सेफ कॉल की ज़रूरत हो सकती हो (`obj?.run { ... }`)।

---

अब पाँचों स्कोप फंक्शन सामने हैं, और हर एक दो अक्षों पर बस एक बिंदु है:
- `let` - ऑब्जेक्ट `it` है, ब्लॉक का परिणाम लौटाता है
- `run` - ऑब्जेक्ट `this` है, ब्लॉक का परिणाम लौटाता है
- `with` - ऑब्जेक्ट `this` है (आर्गुमेंट के रूप में पास), ब्लॉक का परिणाम लौटाता है
- `apply` - ऑब्जेक्ट `this` है, ऑब्जेक्ट लौटाता है
- `also` - ऑब्जेक्ट `it` है, ऑब्जेक्ट लौटाता है

जिस पंक्ति की ज़रूरत है उसे चुनें: `it` तब बेहतर पढ़ा जाता है जब आप ऑब्जेक्ट को किसी और चीज़ को सौंपते हैं, `this` तब बेहतर पढ़ा जाता है जब आप उसके कई सदस्यों को छूते हैं; नया मान चाहने पर ब्लॉक का परिणाम लौटाएं, ऑब्जेक्ट के साथ काम करते रहने पर ऑब्जेक्ट लौटाएं।
