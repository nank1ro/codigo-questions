**एक्सटेंशन फ़ंक्शन** किसी मौजूदा टाइप के सोर्स कोड को छुए बिना उसमें एक नया फ़ंक्शन जोड़ता है।
आप `fun` लिखते हैं, फिर वह टाइप जिसे आप एक्सटेंड करना चाहते हैं (**रिसीवर टाइप**), एक डॉट, और फ़ंक्शन का नाम:
```kotlin
fun Int.squared(): Int {
    return this * this
}
println(4.squared()) // 16
```
फ़ंक्शन के अंदर `this` वह मान है जिस पर फ़ंक्शन कॉल किया जाता है, इसे **रिसीवर** कहते हैं: `4.squared()` में यह `4` है।
एक बार एक्सटेंशन बन जाने पर, आप उसे डॉट के साथ ठीक वैसे ही कॉल करते हैं जैसे कोई फ़ंक्शन शुरू से ही `Int` का हिस्सा रहा हो।

---

एक्सटेंशन किसी भी टाइप पर काम करते हैं, उन पर भी जिनका सोर्स कोड आपके पास नहीं है। `String` स्टैंडर्ड लाइब्रेरी से आता है, फिर भी आप उसे नए फ़ंक्शन दे सकते हैं:
```kotlin
fun String.whisper(): String {
    return this.lowercase() + "..."
}
println("HELLO".whisper()) // hello...
```
एक्सटेंशन के अंदर रिसीवर के दूसरे मेंबर इस्तेमाल करते समय आप `this.` छोड़ सकते हैं: अकेला `lowercase()` का मतलब `this.lowercase()` है, और अकेला `length` का मतलब `this.length` है।

---

एक्सटेंशन फ़ंक्शन किसी भी दूसरे फ़ंक्शन की तरह पैरामीटर ले सकता है। रिसीवर डॉट के बाईं ओर रहता है और पैरामीटर कोष्ठकों के बीच आते हैं:
```kotlin
fun Int.isDivisibleBy(other: Int): Boolean {
    return this % other == 0
}
println(12.isDivisibleBy(4)) // true
println(12.isDivisibleBy(5)) // false
```
डॉट से पहले वाला टाइप एक सामान्य टाइप है, इसलिए आप उसी तरह `List<Int>`, `Double` या अपनी लिखी हुई क्लास को भी एक्सटेंड कर सकते हैं।

---

एक्सटेंशन उस क्लास को **नहीं** बदलता जिसे वह एक्सटेंड करता है और न ही उसमें कोई नया मेंबर डालता है। कंपाइलर बस कॉल को दोबारा लिख देता है: `"kotlin".first3()` उस फ़ंक्शन का कॉल बन जाता है जिसमें `"kotlin"` को `this` के रूप में भेजा जाता है।
```kotlin
fun String.first3(): String = take(3)
val word = "kotlin"
println(word.first3()) // kot
```
इसीलिए आप `String` और `Int` जैसी फ़ाइनल क्लासों को एक्सटेंड कर सकते हैं: उनके अंदर कुछ नहीं बदलता, एक्सटेंशन सिर्फ़ आपके कोड में रहता है।

---

फ़ंक्शनों के अलावा आप एक **एक्सटेंशन प्रॉपर्टी** भी जोड़ सकते हैं। इसे `val`, रिसीवर टाइप, एक डॉट और नाम के साथ घोषित किया जाता है, और उसके बाद एक `get()` आता है जो हर बार प्रॉपर्टी पढ़े जाने पर मान की गणना करता है:
```kotlin
val String.wordCount: Int
    get() = split(" ").size

println("Kotlin is fun".wordCount) // 3
```
एक्सटेंशन प्रॉपर्टी कुछ भी संग्रहीत नहीं कर सकती: उसके पास बैकिंग फ़ील्ड नहीं होता, इसलिए `val String.label = "text"` जैसा इनिशियलाइज़र कंपाइल एरर है। वह केवल रिसीवर से अपना मान गणना कर सकती है।
एक्सटेंशन फ़ंक्शनों के विपरीत, एक्सटेंशन प्रॉपर्टी किसी फ़ंक्शन के अंदर घोषित नहीं की जा सकती (लोकल एक्सटेंशन प्रॉपर्टी की अनुमति नहीं है)।

---

एक्सटेंशन प्रॉपर्टी कोष्ठकों के बिना पढ़ी जाती हैं, ठीक वैसे ही जैसे `String` की अंतर्निहित `length`। जब मान रिसीवर के साथ कुछ करने के बजाय उसका वर्णन करता है, तब ये स्वाभाविक विकल्प होती हैं:
```kotlin
val Int.isNegative: Boolean
    get() = this < 0

println((-3).isNegative) // true
println(7.isNegative)    // false
```
`-3` के चारों ओर कोष्ठकों पर ध्यान दें: उनके बिना `-3.isNegative` पहले `3` की प्रॉपर्टी पढ़ेगा और फिर एक `Boolean` को ऋणात्मक बनाने की कोशिश करेगा, जो कंपाइल नहीं होता।

---

रिसीवर टाइप **नलेबल** हो सकता है। `String?` पर बना एक्सटेंशन ऐसे वेरिएबल पर भी कॉल किया जा सकता है जिसमें `null` हो सकता है, और फ़ंक्शन के अंदर `this` एक `String?` होता है, इसलिए `null` वाली स्थिति आप खुद संभालते हैं, आमतौर पर एल्विस ऑपरेटर `?:` से जो आपने नलेबिलिटी वाले पाठों में देखा था:
```kotlin
fun String?.orDash(): String {
    return this ?: "-"
}
val name: String? = null
println(name.orDash())  // -
println("Ada".orDash()) // Ada
```
`null` मान पर `name.orDash()` कॉल करना सुरक्षित है: `?.` की ज़रूरत नहीं, क्योंकि फ़ंक्शन खुद `null` रिसीवर स्वीकार करता है।

---

नलेबल रिसीवर वाले एक्सटेंशन के अंदर आप सेफ़ कॉल `this?.` का भी उपयोग कर सकते हैं ताकि मान के मेंबर तक तभी पहुँचें जब वह `null` न हो। स्टैंडर्ड लाइब्रेरी `isNullOrEmpty()` जैसे फ़ंक्शनों में यही विचार इस्तेमाल करती है:
```kotlin
fun String?.firstOrQuestion(): Char {
    return this?.firstOrNull() ?: '?'
}
val text: String? = null
println(text.firstOrQuestion())    // ?
println("Kotlin".firstOrQuestion()) // K
```

---

जब किसी क्लास में पहले से ही एक्सटेंशन जैसे नाम और पैरामीटर वाला मेंबर मौजूद हो, तो **मेंबर हमेशा जीतता है**: एक्सटेंशन कभी कॉल नहीं होता, और कंपाइलर चेतावनी देता है कि वह ढँक गया है।
```kotlin
class Box {
    fun describe(): String = "member"
}
fun Box.describe(): String = "extension"

println(Box().describe()) // member
```
एक्सटेंशन मौजूदा व्यवहार को ओवरराइड या प्रतिस्थापित नहीं कर सकता; वह केवल नए फ़ंक्शन और प्रॉपर्टी जोड़ सकता है। चुने जाने के लिए एक्सटेंशन को ऐसा नाम या पैरामीटर सूची चाहिए जो क्लास के पास पहले से न हो।

---

**टाइप पैरामीटर** की मदद से एक एक्सटेंशन एक साथ कई टाइप्स के परिवार पर काम कर सकता है: टाइप पैरामीटर एक टाइप के लिए प्लेसहोल्डर है, जिसे `fun` के तुरंत बाद कोण कोष्ठकों में घोषित किया जाता है और Kotlin हर कॉल पर उसे भर देता है। इससे एक्सटेंशन **जेनेरिक** बन जाता है:
```kotlin
fun <T> List<T>.second(): T {
    return this[1]
}
println(listOf(1, 2, 3).second())      // 2
println(listOf("a", "b").second())     // b
```
`listOf(1, 2, 3)` के साथ प्लेसहोल्डर `T` `Int` है, `listOf("a", "b")` के साथ वह `String` है, इसलिए वही फ़ंक्शन हर बार सही टाइप लौटाता है।

---

टाइप पैरामीटर सिग्नेचर में कहीं भी इस्तेमाल हो सकता है: रिटर्न टाइप के रूप में, नलेबल `T?` के रूप में, या किसी दूसरे टाइप के अंदर। ऐसा जेनेरिक एक्सटेंशन जिसे शायद कुछ न मिले, `T?` लौटाता है, जैसे अंतर्निहित `firstOrNull()`:
```kotlin
fun <T> List<T>.lastOrDefault(default: T): T {
    return if (isEmpty()) default else this[size - 1]
}
println(listOf(1, 2).lastOrDefault(0))          // 2
println(emptyList<String>().lastOrDefault("-")) // -
```
फ़ंक्शन के अंदर आप `size`, `isEmpty()` और इंडेक्सिंग ठीक वैसे ही इस्तेमाल कर सकते हैं जैसे किसी भी लिस्ट पर, क्योंकि रिसीवर एक `List<T>` है।

---

आप किसी क्लास के **कम्पेनियन ऑब्जेक्ट** को भी एक्सटेंड कर सकते हैं, बशर्ते क्लास ने एक घोषित किया हो, चाहे वह खाली ही क्यों न हो। रिसीवर टाइप `ClassName.Companion` लिखा जाता है, और फिर एक्सटेंशन को क्लास के नाम पर कॉल किया जाता है, जैसे कोई फ़ैक्ट्री फ़ंक्शन:
```kotlin
class Temperature(val degrees: Int) {
    companion object
}
fun Temperature.Companion.freezing(): Temperature = Temperature(0)

println(Temperature.freezing().degrees) // 0
```
क्लास और एक्सटेंशन दोनों टॉप-लेवल घोषणाएँ हैं, इसलिए उन्हें `main` के बाहर लिखा जाना चाहिए।

---

कम्पेनियन एक्सटेंशन पैरामीटर ले सकता है, जिससे वह ऐसे वैकल्पिक कंस्ट्रक्टरों के लिए सुविधाजनक जगह बन जाता है जो किसी दूसरी इकाई या फ़ॉर्मैट से रूपांतरण करते हैं:
```kotlin
class Distance(val meters: Int) {
    companion object
}
fun Distance.Companion.fromKilometers(km: Int): Distance = Distance(km * 1000)

println(Distance.fromKilometers(3).meters) // 3000
```

---

आप एक्सटेंशन कहाँ घोषित करते हैं यह तय करता है कि उसे कहाँ इस्तेमाल किया जा सकता है, यानी उसका **स्कोप**:
- फ़ाइल के टॉप लेवल पर, वह पूरी फ़ाइल में और बाकी पैकेज में उपलब्ध होता है
- किसी फ़ंक्शन के अंदर, वह लोकल एक्सटेंशन होता है, केवल उसी फ़ंक्शन में इस्तेमाल योग्य
- किसी क्लास के अंदर, वह **मेंबर एक्सटेंशन** होता है, केवल उसी क्लास के अंदर इस्तेमाल योग्य

मेंबर एक्सटेंशन उस क्लास की प्रॉपर्टी पढ़ सकता है जिसमें वह रहता है, इसलिए वह दो रिसीवर जोड़ता है: क्लास का इंस्टेंस और वह मान जिस पर उसे कॉल किया जाता है:
```kotlin
class Greeter(val greeting: String) {
    fun String.greet(): String = "$greeting, $this!"
    fun welcome(name: String): String = name.greet()
}
println(Greeter("Hello").welcome("Ada")) // Hello, Ada!
```
`greet` के अंदर `greeting` `Greeter` से आता है और `this` वह `String` है जिस पर फ़ंक्शन कॉल होता है। क्लास के बाहर `"Ada".greet()` एक कंपाइल एरर है।

---

ठीक **एक** पैरामीटर वाले एक्सटेंशन फ़ंक्शन को `infix` चिह्नित किया जा सकता है। इनफ़िक्स फ़ंक्शन को डॉट और कोष्ठकों के बिना कॉल किया जा सकता है, रिसीवर बाईं ओर और आर्ग्युमेंट दाईं ओर, जो लगभग एक वाक्य जैसा पढ़ा जाता है:
```kotlin
infix fun Int.percentOf(total: Int): Int = total * this / 100

println(20 percentOf 50)   // 10
println(20.percentOf(50))  // 10, the normal call still works
```
Kotlin कुछ अंतर्निहित फ़ंक्शनों के लिए भी इसका उपयोग करता है: `1 to "one"` एक `Pair` बनाता है, और `1 until 5` एक रेंज बनाता है।

---

`infix` चिह्नित होने के लिए फ़ंक्शन का मेंबर या एक्सटेंशन होना ज़रूरी है, उसे ठीक एक पैरामीटर लेना चाहिए, और उस पैरामीटर का कोई डिफ़ॉल्ट मान नहीं हो सकता। बाकी सब कंपाइल एरर है:
```kotlin
infix fun Int.add(other: Int): Int = this + other          // ok
infix fun add(a: Int, b: Int): Int = a + b                 // error: not a member or extension
infix fun Int.add(a: Int, b: Int): Int = this + a + b      // error: two parameters
```
इनफ़िक्स कॉल की प्राथमिकता अंकगणित और तुलना के बीच होती है: `1 add 2 * 3` का मतलब `1 add 6` है, जबकि `1 add 2 == 3` परिणाम की तुलना `3` से करता है।
