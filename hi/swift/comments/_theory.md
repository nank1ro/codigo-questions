**कमेंट** सोर्स कोड के अंदर लिखा गया एक नोट है, जो उसे पढ़ने वाले लोगों के लिए होता है। कंपाइलर कमेंट्स को पूरी तरह अनदेखा करता है, इसलिए वे कभी नहीं बदलते कि प्रोग्राम क्या करता है।

सबसे सरल कमेंट **सिंगल-लाइन कमेंट** है: यह `//` से शुरू होता है और लाइन के अंत तक चलता है।
```swift
// Greets the user
print("Hello")
```
कमेंट्स का उपयोग यह समझाने के लिए करें कि कोड का कोई हिस्सा किस लिए है, या उसे उस तरह क्यों लिखा गया है।

---

कमेंट को अपनी अलग लाइन की ज़रूरत नहीं होती: वह कोड के बाद उसी लाइन पर आ सकता है। यह **ट्रेलिंग कमेंट** है, और उस विशेष स्टेटमेंट के बारे में छोटा नोट लिखने के लिए अच्छी जगह है:
```swift
let retries = 3 // give up after three attempts
```
`//` से लाइन के अंत तक सब कुछ अनदेखा कर दिया जाता है, जबकि उससे पहले का कोड हमेशा की तरह चलता है।

---

चूँकि कंपाइलर कमेंट्स को पूरी तरह हटा देता है, कमेंट जोड़ने या हटाने से प्रोग्राम का व्यवहार कभी नहीं बदलता। केवल वही कोड चलता है जो कमेंट **नहीं** किया गया है।

इससे `//` किसी लाइन को हटाए बिना बंद करने का तेज़ तरीका बन जाता है। इसे **कमेंट आउट करना** कहते हैं:
```swift
var total = 10
// total = total + 5
print(total) // prints 10
```
दूसरी लाइन अब कमेंट है, इसलिए `total` `10` ही रहता है। `//` हटाने पर वह लाइन फिर से जीवित हो जाती है।

प्रयोग करते समय कमेंट आउट करना सुविधाजनक है, लेकिन सफ़ाई करना न भूलें: लंबे समय तक कमेंट किया रह गया कोड अगले पढ़ने वाले को केवल भ्रमित करता है।

---

जब किसी कमेंट को एक से अधिक लाइन चाहिए, तो Swift **मल्टी-लाइन कमेंट** (जिसे ब्लॉक कमेंट भी कहते हैं) देता है: यह `/*` से शुरू होकर `*/` पर खत्म होता है, और बीच का सब कुछ अनदेखा कर दिया जाता है, लाइन ब्रेक भी।
```swift
/*
  Prints the welcome banner.
  Called once when the app starts.
*/
print("Welcome!")
```
ब्लॉक कमेंट छोटा भी हो सकता है और एक ही लाइन पर रह सकता है: `/* like this */`।

---

`//` के विपरीत, जो लाइन के अंत पर रुक जाता है, `/*` कमेंट केवल `*/` पर रुकता है। अगर आप उसे बंद करना भूल जाएँ, तो कंपाइलर बाद के पूरे कोड को कमेंट का हिस्सा मान लेता है और एरर देता है:
```swift
let width = 10 /* in centimetres
print(width) // still inside the comment: error, the comment is never closed
```
`//` और `/* */` दोनों ट्रेलिंग कमेंट के रूप में काम करते हैं, लेकिन `/*` के साथ हमेशा सुनिश्चित करें कि `*/` मौजूद हो।

---

कई भाषाओं में ब्लॉक कमेंट के अंदर दूसरा ब्लॉक कमेंट नहीं आ सकता, लेकिन Swift में वे **नेस्ट हो सकते हैं**: हर `/*` का अपना `*/` होना चाहिए, और कमेंट तभी खत्म होता है जब सबसे बाहरी बंद होता है।
```swift
/* outer /* inner */ still a comment */
print("done")
```
यहाँ `still a comment */` बाहरी कमेंट का हिस्सा है, इसलिए केवल `done` प्रिंट होता है। इसी वजह से आप कोड के पूरे ब्लॉक को कमेंट आउट कर सकते हैं, भले ही उस ब्लॉक में पहले से कोई `/* */` कमेंट हो।

---

एक साथ कई लाइनों को कमेंट आउट करने के लिए, हर लाइन में `//` जोड़ने के बजाय उन्हें एक ही ब्लॉक कमेंट में लपेट दें:
```swift
var total = 100
/*
total = total - 30
total = total - 20
*/
print(total) // prints 100
```
नेस्टिंग की वजह से यह तब भी काम करता है जब उन लाइनों में से किसी में पहले से `/* */` कमेंट हो।

---

ब्लॉक कमेंट्स का एक आम उपयोग **हेडर कमेंट** है: फ़ंक्शन के ठीक ऊपर रखा गया छोटा ब्लॉक जो बताता है कि वह क्या करता है और उसके पैरामीटर्स का क्या अर्थ है।
```swift
/*
Returns the number of seconds in the given minutes.
minutes is a whole number, never negative.
*/
func toSeconds(_ minutes: Int) -> Int {
    return minutes * 60
}
```
जो कोई `toSeconds` को कॉल करता है वह अब बॉडी के बजाय हेडर पढ़ सकता है। हेडर को फ़ंक्शन के पास ही रखें ताकि दोनों साथ अपडेट हों।

---

Swift में कमेंट का तीसरा प्रकार भी है, **डॉक्युमेंटेशन कमेंट**: एक सिंगल-लाइन कमेंट जो `///` (तीन स्लैश) से शुरू होता है और किसी फ़ंक्शन, टाइप या प्रॉपर्टी के ठीक ऊपर रखा जाता है।
```swift
/// Returns the greeting for `name`.
func greet(_ name: String) -> String {
    return "Hi, \(name)!"
}
```
कंपाइलर के लिए यह सिर्फ़ एक कमेंट है, लेकिन Xcode जैसे टूल इसे पढ़कर `greet` के हेल्प टेक्स्ट के रूप में दिखाते हैं। डॉक्युमेंटेशन कमेंट्स **मार्कडाउन** का समर्थन करते हैं, इसलिए आप कोड के लिए बैकटिक, `**बोल्ड**` और लिस्ट इस्तेमाल कर सकते हैं।

---

डॉक्युमेंटेशन कमेंट की पहली लाइन **सारांश** होती है: एक छोटा वाक्य जो बताता है कि फ़ंक्शन क्या करता है। इसे तीसरे पुरुष में लिखें, मानो फ़ंक्शन का वर्णन कर रहे हों: "Returns...", "Adds...", "Checks..."।
```swift
/// Returns `true` when `n` is divisible by two.
func isEven(_ n: Int) -> Bool {
    return n % 2 == 0
}
```
कमेंट डिक्लेरेशन के ठीक ऊपर होना चाहिए, बीच में कोई खाली लाइन नहीं, वरना Xcode उसे फ़ंक्शन से नहीं जोड़ता।

---

डॉक्युमेंटेशन कमेंट ब्लॉक रूप में भी आते हैं: `/**` उसे खोलता है और `*/` उसे बंद करता है, बिल्कुल मल्टी-लाइन कमेंट की तरह लेकिन शुरुआत में एक दूसरा तारांकन (asterisk) के साथ।
```swift
/**
 Returns the greeting for `name`.

 The result always ends with an exclamation mark.
 */
func greet(_ name: String) -> String {
    return "Hi, \(name)!"
}
```
टूल्स के लिए `/// टेक्स्ट` और `/** टेक्स्ट */` का एक ही अर्थ है; Swift कोड में `///` सबसे आम विकल्प है, जबकि `/** */` लंबे विवरणों के लिए सुविधाजनक है। सादा `/* */` या `//` कमेंट डॉक्युमेंटेशन **नहीं** है, भले ही वह फ़ंक्शन के ऊपर रखा हो।

---

सारांश के बाद, डॉक्युमेंटेशन कमेंट विशेष मार्कडाउन लिस्ट आइटम्स से पैरामीटर्स और रिटर्न वैल्यू का वर्णन कर सकता है, जिन्हें Xcode पहचानता है:
```swift
/// Returns the number of seconds in the given minutes.
/// - Parameter minutes: a whole number of minutes, never negative
/// - Returns: `minutes` multiplied by sixty
func toSeconds(_ minutes: Int) -> Int {
    return minutes * 60
}
```
क्रम हमेशा एक ही रहता है: पहले सारांश, फिर हर पैरामीटर के लिए `- Parameter name:`, फिर `- Returns:`।

---

कुछ कमेंट्स ऐसी परंपरा का पालन करते हैं जिसे एडिटर समझते हैं। Swift में सबसे आम **मार्कर** ये हैं:
- `// MARK: - Title` फ़ाइल के किसी सेक्शन को नाम देता है, ताकि वह Xcode के नेविगेशन मेन्यू में दिखे
- `// TODO: ...` उस चीज़ को चिह्नित करता है जिसे अभी लिखा जाना बाकी है
- `// FIXME: ...` उस कोड को चिह्नित करता है जो ज्ञात रूप से ग़लत है और ठीक किया जाना चाहिए

```swift
// MARK: - Setup
let limit = 10
// TODO: read the limit from the settings
// FIXME: crashes when the list is empty
```
कंपाइलर के लिए ये सामान्य कमेंट हैं; Xcode इन्हें सूचीबद्ध करता है ताकि बचा हुआ काम आसानी से मिल जाए। काम पूरा होने पर मार्कर हटा दें: पुराना पड़ चुका `TODO` भ्रामक होता है।

---

`TODO` आमतौर पर किसी प्लेसहोल्डर के पास होता है जो असली इंप्लीमेंटेशन लिखे जाने तक कोड को कंपाइल होने लायक बनाए रखता है। जब आप काम पूरा करें, तो उसी बदलाव में प्लेसहोल्डर बदलें और मार्कर हटा दें, ताकि कमेंट कोड की स्थिति के बारे में कभी झूठ न बोले।

---

`FIXME` `TODO` से अलग है: कोड पहले से मौजूद है, लेकिन वह ज्ञात रूप से ग़लत है। अच्छा `FIXME` बताता है कि बग क्या है और, जहाँ संभव हो, ऐसा उदाहरण देता है जो उसे दिखाए, ताकि अगला व्यक्ति उसे जल्दी ठीक कर सके। `TODO` की तरह, बग ठीक होने पर मार्कर हटा दें, लेकिन डॉक्युमेंटेशन कमेंट रखें, जो अब भी सही है।

---

अच्छा कमेंट यह समझाता है कि कोड कुछ **क्यों** करता है, यह नहीं कि वह **क्या** करता है। कोड पहले ही दिखा देता है कि क्या होता है; उसे शब्दों में दोहराना केवल शोर बढ़ाता है और कोड बदलते ही पुराना पड़ जाता है:
```swift
// set timeout to 30
let timeout = 30
```
संख्या के पीछे का कारण वही है जिसे पढ़ने वाला अंदाज़ा नहीं लगा सकता:
```swift
// the server drops idle connections after 35 seconds, so stop earlier
let timeout = 30
```
अगर कोई कमेंट सिर्फ़ नीचे की लाइन को दोहराता है, तो उसे हटा दें या उसकी जगह कारण लिखें।
