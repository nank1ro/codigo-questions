कुछ काम तुरंत पूरे नहीं होते: कोई फ़ाइल डाउनलोड करना, डेटाबेस से पढ़ना, किसी टाइमर का इंतज़ार करना। अगर प्रोग्राम बस रुककर इंतज़ार करता, तो इस बीच कुछ और नहीं हो सकता था। Swift इसका समाधान **एसिंक्रोनस फ़ंक्शन्स** से करता है।

**`async`** से चिह्नित फ़ंक्शन बीच में रुकने और बाद में फिर से शुरू होने की अनुमति रखता है। यह कीवर्ड पैरामीटर लिस्ट के बाद, एरो से पहले आता है:
```swift
func fetchNumber() async -> Int {
    return 42
}
```
इसे कॉल करना भी अलग है: आपको कॉल के आगे **`await`** लिखना होता है। `await` वह सटीक जगह दर्शाता है जहाँ प्रोग्राम रुक सकता है, और फ़ंक्शन के पूरा होने पर आपको सादा मान दे देता है:
```swift
let n = await fetchNumber()
print(n)
// prints 42
```
Swift स्क्रिप्ट में टॉप लेवल पहले से `await` को सपोर्ट करता है, इसलिए आप बिना किसी अतिरिक्त सेटअप के सीधे एसिंक्रोनस फ़ंक्शन्स को कॉल कर सकते हैं। `async` या `await` भूलना एक कंपाइल एरर है, कोई चुपचाप चलता बग नहीं।

---

एक एसिंक्रोनस फ़ंक्शन अब भी एक साधारण फ़ंक्शन ही है: यह पैरामीटर ले सकता है और किसी भी टाइप का मान लौटा सकता है। सिर्फ़ दो चीज़ें बदलती हैं, सिग्नेचर में `async` कीवर्ड और हर कॉल साइट पर `await`:
```swift
func price(of quantity: Int) async -> Double {
    return Double(quantity) * 2.5
}

let total = await price(of: 4)
print(total)
// prints 10.0
```
लौटाया गया मान एक सामान्य `Double` है, कोई रैपर नहीं: `await` के पूरा होने के बाद आप इसके साथ बिल्कुल पहले की तरह काम करते हैं।

---

एसिंक्रोनस फ़ंक्शन्स आम तौर पर एक-दूसरे के ऊपर बने होते हैं। किसी `async` फ़ंक्शन के अंदर आप किसी भी दूसरे `async` फ़ंक्शन को `await` कर सकते हैं, और परिणाम किसी सामान्य मान की तरह ही उपयोग होता है:
```swift
func base() async -> Int {
    return 10
}

func withBonus() async -> Int {
    let value = await base()
    return value + 5
}

print(await withBonus())
// prints 15
```
`await` केवल एक एसिंक्रोनस कॉन्टेक्स्ट के अंदर ही अनुमत है: कोई `async` फ़ंक्शन, या स्क्रिप्ट का टॉप लेवल। एक साधारण, गैर-`async` फ़ंक्शन कुछ भी `await` नहीं कर सकता।

---

समय के साथ होने वाला काम अक्सर विफल होता है: सर्वर डाउन है, कोई फ़ाइल गायब है, इनपुट गलत है। ऐसे फ़ंक्शन को **`async throws`** से चिह्नित किया जाता है, और उसे **`try await`** के साथ कॉल किया जाता है:
```swift
enum LoadError: Error {
    case missing
}

func load(_ name: String) async throws -> String {
    if name.isEmpty {
        throw LoadError.missing
    }
    return "file: \(name)"
}
```
एरर को संभालने के लिए आप कॉल को एक `do` ब्लॉक में लपेटकर उसे कैच करते हैं:
```swift
do {
    let text = try await load("")
    print(text)
} catch {
    print("could not load")
}
// prints could not load
```
कीवर्ड्स का क्रम तय है: `try` पहले आता है, फिर `await`।

---

जब आपको परवाह न हो कि कॉल *क्यों* विफल हुई, तब `try?` एक `do` ब्लॉक से छोटा होता है। यह एक throwing कॉल को **ऑप्शनल** में बदल देता है: सफलता पर मान, विफलता पर `nil`। `await` के साथ मिलाकर इसे `try? await` लिखा जाता है:
```swift
let value = try? await parse("42")  // Optional(42)
let broken = try? await parse("x")  // nil
```
क्योंकि परिणाम ऑप्शनल है, यह सीधे एक `if let` में फिट हो जाता है:
```swift
if let value = try? await parse("x") {
    print(value)
} else {
    print("not a number")
}
```
किसी तुरंत फ़ॉलबैक के लिए `try? await` का उपयोग करें, और `do` / `catch` का उपयोग तब करें जब एरर खुद मायने रखता है।

---

एक-दूसरे के बाद लिखी कई `await` कॉल्स **क्रमिक (sequentially)** रूप से चलती हैं: दूसरी कॉल तब तक शुरू भी नहीं होती जब तक पहली वापस न आ जाए। कोड ऊपर से नीचे पढ़ा जाता है, बिल्कुल साधारण कोड की तरह:
```swift
func step(_ name: String) async -> String {
    print("start \(name)")
    return "done \(name)"
}

let a = await step("A")
print(a)
let b = await step("B")
print(b)
// start A
// done A
// start B
// done B
```
यही आप चाहते हैं जब दूसरी कॉल को पहली के परिणाम की ज़रूरत होती है। जब कॉल्स स्वतंत्र हों, तो दूसरी शुरू करने से पहले एक के लिए इंतज़ार करना बर्बाद हुआ समय है, और अगले एक्सरसाइज़ दिखाते हैं कि इससे कैसे बचें।

---

दो स्वतंत्र कॉल्स को एक साथ चलाने के लिए, उन्हें **`async let`** से घोषित करें। काम तुरंत शुरू हो जाता है, और प्रोग्राम इंतज़ार किए बिना आगे बढ़ता रहता है:
```swift
async let left = step("A")
async let right = step("B")
```
मान अभी उपलब्ध नहीं होता, इसलिए आप बाइंडिंग को सीधे उपयोग नहीं कर सकते: आपको उसे उस जगह `await` करना होता है जहाँ आपको अंततः उसकी ज़रूरत होती है। एक्सप्रेशन के आगे लगा एक `await` उसके अंदर के हर `async let` को कवर कर लेता है:
```swift
let both = await left + right
```
अगर हर कॉल में एक सेकंड लगता है, तो क्रमिक वर्ज़न को दो सेकंड चाहिए जबकि `async let` वर्ज़न को लगभग एक लगता है, क्योंकि दोनों कॉल्स ओवरलैप हो जाती हैं।

---

जब आपको परिणाम अलग-अलग चाहिए हों, तो कई `async let` बाइंडिंग्स को एक टपल में इकट्ठा करें और पूरे टपल को एक ही बार में `await` करें:
```swift
async let city = fetchCity()
async let country = fetchCountry()
let (a, b) = await (city, country)
```
दोनों कॉल्स पहले से चल रही थीं; एक `await` तब तक इंतज़ार करता है जब तक दोनों में से धीमी पूरी न हो जाए। याद रखें कि `async let` केवल काम शुरू करता है: जिस `async let` को आप कभी await नहीं करते, वह कैंसिल हो जाता है और स्कोप खत्म होने पर इंप्लिसिटली await किया जाता है।

---

`async let` उस स्कोप से बंधा होता है जहाँ उसे लिखा गया है। समानांतर काम शुरू करने और उस पर एक हैंडल रखने के लिए, एक **`Task`** का उपयोग करें। `Task { }` को दिया गया क्लोज़र अपने आप पर चलता है, और टास्क को स्टोर, पास या रिटर्न किया जा सकता है:
```swift
let job = Task {
    return await double(21)
}
```
परिणाम बाद में **`.value`** से पढ़ा जाता है, जिसे await किया जाता है:
```swift
print(await job.value)
// prints 42
```
हैंडल का टाइप बताता है कि वह क्या देता है और क्या throw कर सकता है: `Task<Int, Never>` एक ऐसा टास्क है जो एक `Int` लौटाता है और कभी throw नहीं करता। `async let` के विपरीत, एक `Task` साधारण, गैर-एसिंक्रोनस कोड से बनाया जा सकता है।

---

`Task.sleep` मौजूदा टास्क को कुछ समय के लिए रोक देता है, बिना किसी और चीज़ को ब्लॉक किए। इसे बीच में बाधित किया जा सकता है, इसलिए यह एक throwing एसिंक्रोनस कॉल है और इसे `try await` चाहिए। अवधि `.seconds`, `.milliseconds` या `.nanoseconds` जैसे हेल्पर्स से दी जाती है:
```swift
func slowGreeting() async throws -> String {
    try await Task.sleep(for: .milliseconds(50))
    return "hello"
}
```
असली नेटवर्क कॉल की जगह, किसी उदाहरण में धीमा काम दिखाने का यही मानक तरीका है। ध्यान दें कि इससे प्रोग्राम फ्रीज़ नहीं होता: जब एक टास्क सोता है, बाकी चलते रहते हैं।

---

अब क्रमिक और एक साथ (concurrent) चलने वाले काम के बीच का अंतर मापा जा सकता है। मान लीजिए `work` लौटने से पहले एक सेकंड सोता है:
```swift
func work(_ n: Int) async -> Int {
    try? await Task.sleep(for: .seconds(1))
    return n
}
```
कॉल्स को एक-एक करके await करने में लगभग **दो** सेकंड लगते हैं, क्योंकि दूसरा स्लीप तभी शुरू होता है जब पहला खत्म हो चुका होता है:
```swift
let a = await work(1)
let b = await work(2)
```
उन्हें `async let` से शुरू करने में लगभग **एक** सेकंड लगता है, क्योंकि दोनों स्लीप ओवरलैप हो जाते हैं:
```swift
async let a = work(1)
async let b = work(2)
let sum = await a + b
```
`await work(1) + await work(2)` को एक ही पंक्ति पर लिखने से कुछ नहीं बदलता: दोनों कॉल्स अब भी एक के बाद एक इवैल्यूएट होती हैं। कंकरेंसी `async let` से या टास्क्स से आती है, कभी भी पंक्ति की फ़ॉर्मैटिंग से नहीं।

---

`async let` तब काम करता है जब आपको कोड लिखते समय पता हो कि कितनी कॉल्स हैं। किसी ऐसी लिस्ट के लिए जिसका आकार केवल रन टाइम पर पता चलता है, एक **टास्क ग्रुप** का उपयोग करें।

`withTaskGroup(of:)` एक ग्रुप खोलता है, `addTask` हर आइटम के लिए एक चाइल्ड टास्क शुरू करता है, और फिर ग्रुप को `for await` से पढ़ा जाता है, जो परिणामों को उनके पूरा होते ही देता है:
```swift
let total = await withTaskGroup(of: Int.self) { group in
    for n in numbers {
        group.addTask {
            return await square(n)
        }
    }
    var sum = 0
    for await value in group {
        sum += value
    }
    return sum
}
```
`of: Int.self` घोषित करता है कि हर चाइल्ड टास्क क्या लौटाता है। पूरा `withTaskGroup` कॉल एक एक्सप्रेशन है, इसलिए उसके आगे एक ही `await` चाहिए, और वह तब तक लौटता नहीं जब तक हर चाइल्ड टास्क पूरा न हो जाए।

---

एक टास्क ग्रुप परिणाम **पूरा होने के क्रम (completion order)** में देता है, न कि उस क्रम में जिसमें टास्क्स जोड़े गए थे। सबसे तेज़ चाइल्ड टास्क पहले आता है, इसलिए मानों को एक ऐरे में इकट्ठा करने पर क्रम अप्रत्याशित मिलता है।

जब क्रम मायने रखता है तो दो उपाय हैं। अगर मानों को बस दोबारा क्रमित किया जा सकता है, तो अंत में उन्हें सॉर्ट करें:
```swift
return values.sorted()
```
अगर हर परिणाम एक स्थान से जुड़ा है, तो हर टास्क को एक जोड़ा `(index, value)` लौटाने दें और उसे एक तैयार ऐरे में लिखें:
```swift
for (index, word) in words.enumerated() {
    group.addTask {
        return (index, await lengthOf(word))
    }
}
var result = Array(repeating: 0, count: words.count)
for await (index, value) in group {
    result[index] = value
}
```
एक योग, अधिकतम मान या गिनती को किसी उपाय की ज़रूरत नहीं, क्योंकि मानों का क्रम उत्तर नहीं बदलता।
