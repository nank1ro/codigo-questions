कभी-कभी कोई मान बस मौजूद नहीं होता: बिना मध्य नाम वाला उपयोगकर्ता, ऐसी खोज जिसे कुछ नहीं मिलता, या ऐसा टेक्स्ट जिसे संख्या में नहीं बदला जा सकता।
Swift एक अनुपस्थित मान को `nil` से दर्शाता है, लेकिन एक सामान्य वेरिएबल इसे कभी नहीं रख सकता:
```swift
var age: Int = nil // error: 'nil' cannot initialize type 'Int'
```
किसी अनुपस्थित मान की अनुमति देने के लिए आप टाइप के बाद प्रश्न चिह्न `?` जोड़कर एक **ऑप्शनल** टाइप घोषित करते हैं।
एक `Int?` या तो `Int` या `nil` रखता है:
```swift
var age: Int? = 30
age = nil // अनुमत
```
बिना मान के घोषित किया गया ऑप्शनल वेरिएबल `nil` से शुरू होता है।

---

आप `==` और `!=` का उपयोग करके किसी ऑप्शनल की तुलना `nil` से कर सकते हैं, और इसकी तुलना सीधे रैप किए गए टाइप के एक सामान्य मान से भी कर सकते हैं:
```swift
var score: Int? = 10
print(score == nil) // false
print(score == 10)  // true
```
याद रखें कि `Int?` और `Int` दो अलग-अलग टाइप हैं: एक `Int?` खाली हो सकता है, एक `Int` कभी खाली नहीं होता।

---

एक ऑप्शनल एक डिब्बे की तरह है: अंदर के मान का उपयोग करने से पहले आपको उसे खोलना होता है, जिसे Swift **अनरैपिंग** कहता है।
सबसे तेज़ तरीका है विस्मयादिबोधक चिह्न `!` के साथ **फोर्स्ड अनरैपिंग**:
```swift
let score: Int? = 10
print(score! + 5) // 15
```
`!` Swift को बताता है "मुझे यकीन है कि यहाँ एक मान मौजूद है"। यदि आप गलत हैं और ऑप्शनल `nil` है, तो प्रोग्राम तुरंत एक रनटाइम क्रैश के साथ रुक जाता है:
```swift
let missing: Int? = nil
print(missing! + 5) // Fatal error: Unexpectedly found nil
```
इसीलिए फोर्स्ड अनरैपिंग को खतरनाक माना जाता है: इसका उपयोग केवल तभी करें जब आपको यकीन हो कि मान मौजूद है।

---

फोर्स्ड अनरैपिंग तभी सुरक्षित है जब आपने पहले ही जाँच लिया हो कि ऑप्शनल `nil` नहीं है:
```swift
if score != nil {
    print(score! * 2)
}
```

---

`nil` की जाँच करना और फिर फोर्स्ड अनरैप करना अधिक लंबा है। Swift `if let` के साथ **ऑप्शनल बाइंडिंग** प्रदान करता है, जो एक ही चरण में ऑप्शनल को अनरैप करता है और मान को एक नए कॉन्स्टेंट में संग्रहीत करता है:
```swift
let score: Int? = 10
if let value = score {
    print("Score: \(value)") // value एक Int है, Int? नहीं
} else {
    print("No score")
}
```
`if` का बॉडी केवल तभी चलता है जब ऑप्शनल में कोई मान हो; इसके अंदर `value` एक सामान्य `Int` है, `Int?` नहीं, और इसके लिए `!` की आवश्यकता नहीं है।

---

जब किसी अनुपस्थित मान का अर्थ है "यहीं रुक जाओ", तो `guard let`, `if let` से अधिक स्पष्ट है।
यह ऑप्शनल को अनरैप करता है और, यदि वह विफल होता है, तो `else` ब्लॉक चलाता है, जिसे वर्तमान स्कोप से बाहर निकलना होता है (`return`, `break`, `continue` या `throw` के साथ):
```swift
func greet(_ name: String?) {
    guard let name = name else {
        print("Nobody here")
        return
    }
    print("Hello, \(name)!") // यहाँ से आगे name एक String है
}
```
`if let` के विपरीत, अनरैप किया गया कॉन्स्टेंट फ़ंक्शन के बाकी हिस्से के लिए उपलब्ध रहता है, इसलिए मुख्य पथ को `if` के अंदर नेस्ट नहीं किया जाता।

---

`guard let` का एक विशिष्ट उपयोग फ़ंक्शन के शुरुआत में इनपुट को सत्यापित करना और मान के अनुपस्थित होने पर एक फॉलबैक मान लौटाना है:
```swift
func length(of text: String?) -> Int {
    guard let text = text else { return 0 }
    return text.count
}
```

---

अक्सर आप किसी ऑप्शनल से केवल उसका मान या एक डिफ़ॉल्ट मान चाहते हैं।
**nil-coalescing ऑपरेटर** `??` ठीक यही करता है: यदि ऑप्शनल में कोई मान है तो यह उसे अनरैप करता है, अन्यथा यह अपने दाईं ओर के मान को लौटाता है:
```swift
let score: Int? = nil
let points = score ?? 0 // points एक Int है जो 0 के बराबर है
```
डिफ़ॉल्ट मान का टाइप रैप किए गए मान के समान होना चाहिए।
आप कई `??` को श्रृंखलाबद्ध कर सकते हैं: पहला `nil` न होने वाला मान जीतता है।
```swift
let a: Int? = nil
let b: Int? = 7
print(a ?? b ?? 0) // 7
```

---

`??` किसी ऑप्शनल को एक सामान्य मान में बदलने का सबसे छोटा तरीका है जब एक उचित डिफ़ॉल्ट मान मौजूद हो:
```swift
func volume(from setting: Int?) -> Int {
    return setting ?? 50
}
```

---

`??` को श्रृंखलाबद्ध करते समय, Swift बाएँ से दाएँ मूल्यांकन करता है और पहले ऐसे मान पर रुक जाता है जो `nil` नहीं है; अंतिम डिफ़ॉल्ट मान का उपयोग तभी होता है जब उससे पहले का हर ऑप्शनल `nil` हो।

---

किसी ऑप्शनल पर किसी प्रॉपर्टी को एक्सेस करने या किसी मेथड को कॉल करने के लिए पहले उसे अनरैप करना आवश्यक होगा।
`?.` के साथ **ऑप्शनल चेनिंग** यह आपके लिए करती है: यदि ऑप्शनल `nil` है तो पूरी अभिव्यक्ति `nil` बन जाती है, अन्यथा एक्सेस आगे बढ़ता है:
```swift
let name: String? = "swift"
let upper = name?.uppercased() // "SWIFT" रखने वाला String?
```
परिणाम हमेशा एक ऑप्शनल होता है, भले ही प्रॉपर्टी स्वयं ऑप्शनल न हो।
चेन आपकी आवश्यकता के अनुसार जितनी लंबी हो सकती है, और वे `??` के साथ अच्छी तरह मेल खाती हैं:
```swift
class User {
    var nickname: String? = "ace"
}
let user: User? = User()
print(user?.nickname?.count ?? 0) // 3
```

---

ऑप्शनल चेनिंग तब चमकती है जब डेटा कई स्तरों पर अनुपस्थित हो सकता है: एक ऑब्जेक्ट `nil` हो सकता है, और उसकी प्रॉपर्टीज़ में से एक भी `nil` हो सकती है।
एक ही `?.` चेन बिना किसी `if` के दोनों स्थितियों को संभालती है।

---

एक ही `if let` या `guard let` कई ऑप्शनल्स को एक साथ अनरैप कर सकता है: बाइंडिंग्स को कॉमा से अलग करें।
बॉडी तभी चलती है जब हर ऑप्शनल में कोई मान हो:
```swift
let first: String? = "Ada"
let last: String? = "Lovelace"
if let first = first, let last = last {
    print("\(first) \(last)")
}
```
आप बाइंडिंग्स के बाद एक बूलियन शर्त भी जोड़ सकते हैं, जैसे `if let n = number, n > 0`।

---

कई ऑप्शनल्स को एक ही `if let` में बाइंड करना कोड को सरल रखता है: एक ही `else` शाखा हर अनुपस्थित मान की स्थिति को कवर करती है।

---

कई ऑपरेशन विफल हो सकते हैं, और Swift एक ऑप्शनल लौटाकर विफलता की सूचना देता है।
टेक्स्ट को संख्या में बदलना इसका क्लासिक उदाहरण है: `Int("42")` `42` रखने वाला एक `Int?` लौटाता है, जबकि `Int("abc")` `nil` लौटाता है।
`Int("3.5")` भी `nil` है, क्योंकि टेक्स्ट एक पूर्ण संख्या नहीं है; दशमलव के लिए `Double("3.5")` का उपयोग करें।
```swift
let typed = "42"
if let number = Int(typed) {
    print(number + 1) // 43
}
```
अन्य उदाहरण हैं `array.first` (खाली ऐरे के लिए `nil`) और `dictionary[key]` (कुंजी अनुपस्थित होने पर `nil`)।

---

क्योंकि एक कन्वर्ज़न विफल हो सकता है, इसका परिणाम हमेशा एक ऑप्शनल होता है और इसे उपयोग से पहले अनरैप किया जाना चाहिए, भले ही आपको यकीन हो कि टेक्स्ट एक वैध संख्या है।

---

विफल हो सकने वाले कन्वर्ज़न्स स्वाभाविक रूप से `guard let` के साथ जोड़ी बनाते हैं: कन्वर्ट करें, परिणाम `nil` होने पर बाहर निकलें, फिर सामान्य मान के साथ काम करें।

---

कभी-कभी आप किसी ऑप्शनल के अंदर के मान को बदलना चाहते हैं और परिणाम को ऑप्शनल ही रखना चाहते हैं, बिना हाथ से अनरैप और फिर से रैप किए।
ऑप्शनल्स के पास एक `map` मेथड होता है: यदि कोई मान है तो यह क्लोज़र को उस पर लागू करता है, अन्यथा `nil` लौटाता है।
```swift
let score: Int? = 10
let doubled = score.map { $0 * 2 } // 20 रखने वाला Int?
let missing: Int? = nil
let stillMissing = missing.map { $0 * 2 } // nil
```
एक विफल हो सकने वाले कन्वर्ज़न के साथ मिलाकर यह `Int(text).map { $0 + 1 }` जैसी एक संक्षिप्त पाइपलाइन बनाता है।
