# --description--

इस अध्याय में हर चीज़ एक ही सवाल का जवाब देती है: विफलता से कौन निपटता है?

थ्रो करने वाला फ़ंक्शन इसका जवाब देने से इनकार करता है। वह बताता है कि क्या गलत हुआ — एक `Error` enum का एक case, जिसमें वह सब कुछ होता है जो हैंडलर को चाहिए होगा — और फ़ैसला ऊपर की ओर सौंप देता है। इसके बाद कॉलर एक टूल चुनता है: `do`/`catch` से हर case पर अलग-अलग प्रतिक्रिया देने के लिए, `try?` और `??` से किसी डिफ़ॉल्ट पर वापस जाने के लिए, `defer` से बाहर निकलते समय, चाहे कुछ भी हो, सफ़ाई करने के लिए।

यही बँटवारा पूरी बात है। जो फ़ंक्शन समस्या को पहचानता है उसे शायद ही कभी पता होता है कि आगे क्या होना चाहिए, और जो कोड यह जानता है वह शायद ही कभी जाँच को दोहराना चाहता है।

# --instructions--

इस अध्याय की सब चीज़ों का उपयोग करके एक वैलिडेटर लिखें:
- `FormError` को `Int` टाइप का `maximum` रखने वाला दूसरा case `tooLong` दें
- `validate`, नाम खाली होने पर `FormError.empty` थ्रो करे, 10 अक्षरों से लंबा होने पर `FormError.tooLong(maximum: 10)` थ्रो करे, और अन्यथा नाम लौटाए
- `safeName`, सत्यापित नाम लौटाए, या `validate` के थ्रो करने पर `"guest"` लौटाए

फ़ंक्शन कॉल का उदाहरण:
```swift
print(safeName(""))
// prints guest
```

func _kind(_ name: String) -> String {
    do {
        return try validate(name)
    } catch FormError.empty {
        return "empty"
    } catch FormError.tooLong(let maximum) {
        return "max \(maximum)"
    } catch {
        return "other"
    }
}

# --solutions--

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
