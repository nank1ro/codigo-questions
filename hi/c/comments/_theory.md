टिप्पणी (**comment**) आपके सोर्स कोड के अंदर मौजूद वह टेक्स्ट है जो कंपाइलर के लिए नहीं, बल्कि लोगों के लिए होती है। प्रोग्राम बनाने से पहले कंपाइलर टिप्पणियों को हटा देता है, इसलिए आप उनका उपयोग यह बताने के लिए कर सकते हैं कि कोड किस लिए है, रिमाइंडर छोड़ने के लिए या किसी निर्णय को नोट करने के लिए।

सबसे आम प्रकार **एकल-पंक्ति टिप्पणी** है: `//` से उस पंक्ति के अंत तक की हर चीज़ को नज़रअंदाज़ कर दिया जाता है।
```c
// Greet the user
printf("Hello\n");
```
प्रोग्राम चलने पर पहली पंक्ति कुछ नहीं करती; केवल `printf` ही आउटपुट देता है।

---

क्योंकि कंपाइलर टिप्पणियों को पूरी तरह हटा देता है, टिप्पणी जोड़ने या हटाने से प्रोग्राम के काम करने के तरीके में कभी बदलाव नहीं आता। केवल वही कोड चलता है जो टिप्पणी **नहीं** किया गया है।

इसी वजह से `//`, कोड की पंक्ति को डिलीट किए बिना उसे बंद करने का एक त्वरित तरीका है। इसे **कमेंटिंग आउट** कहा जाता है:
```c
int total = 10;
// total = total + 5;
printf("%d\n", total); // prints "10"
```
अब दूसरी पंक्ति एक टिप्पणी है, इसलिए `total` का मान `10` ही रहता है। `//` हटाने पर वह पंक्ति फिर से जीवित हो जाती है।

प्रयोग करते समय कमेंटिंग आउट सुविधाजनक है, लेकिन सफ़ाई करना याद रखें: लंबे समय तक कमेंट आउट पड़ा रहने वाला कोड उसे पढ़ने वाले अगले व्यक्ति को केवल उलझन में ही डालता है।

---

जब एक टिप्पणी को एक से अधिक पंक्तियों की आवश्यकता हो, तो C **बहु-पंक्ति टिप्पणी** (जिसे ब्लॉक टिप्पणी भी कहा जाता है) देता है: यह `/*` से शुरू होकर `*/` पर समाप्त होती है, और इनके बीच की हर चीज़, लाइन ब्रेक सहित, नज़रअंदाज़ कर दी जाती है।
```c
/*
  Prints the welcome banner.
  Called once when the program starts.
*/
printf("Welcome!\n");
```
ब्लॉक टिप्पणी छोटी भी हो सकती है और एक ही पंक्ति पर रह भी सकती है: `/* like this */`।

`//` के विपरीत, जो पंक्ति के अंत पर रुक जाता है, `/*` टिप्पणी केवल `*/` पर रुकती है। यदि आप उसे बंद करना भूल जाएँ, तो कंपाइलर उसके बाद के पूरे कोड को टिप्पणी का हिस्सा मान लेगा।

---

ब्लॉक टिप्पणियाँ **नेस्ट नहीं होतीं**। कंपाइलर `/*` टिप्पणी को जिस पहले `*/` पर पाता है, उसी पर समाप्त कर देता है, चाहे उससे पहले कितने ही `/*` क्यों न आए हों:
```c
/* outer /* inner */ still code */
```
यहाँ टिप्पणी `inner` के ठीक बाद समाप्त हो जाती है, इसलिए `still code */` कोड के रूप में कंपाइल होता है और एक एरर उत्पन्न करता है।

यह तब मायने रखता है जब आप किसी ऐसे ब्लॉक को कमेंट आउट करना चाहते हों जिसके अंदर पहले से `/* */` टिप्पणी मौजूद है: अंदर वाली `*/` आपकी बाहरी टिप्पणी को बहुत जल्दी बंद कर देगी। ऐसे में, हर पंक्ति के आगे `//` लगा दें।

---

टिप्पणी को अपनी अलग पंक्ति की ज़रूरत नहीं होती: यह उसी पंक्ति पर कोड के बाद आ सकती है। इसे **ट्रेलिंग टिप्पणी** कहा जाता है, और यह उस विशिष्ट स्टेटमेंट के बारे में एक छोटा नोट लिखने की अच्छी जगह है:
```c
int retries = 3; // give up after three attempts
```
`//` और `/* */` दोनों ट्रेलिंग टिप्पणी के रूप में काम करते हैं, लेकिन `/*` से सावधान रहें: चूँकि यह केवल `*/` पर रुकता है, पंक्ति के अंत में बिना बंद किया `/*` उसके बाद की पंक्तियों को निगल जाता है, और प्रोग्राम अब कंपाइल नहीं होता।

---

ब्लॉक टिप्पणियों का एक आम उपयोग **हेडर टिप्पणी** है: फ़ंक्शन के ठीक ऊपर रखा गया एक छोटा ब्लॉक, जो बताता है कि वह क्या करता है, उसके पैरामीटर का क्या अर्थ है और वह क्या लौटाता है।
```c
/*
 * Returns the number of seconds in the given minutes.
 * minutes: a whole number of minutes, never negative
 */
int to_seconds(int minutes) {
    return minutes * 60;
}
```
जो कोई भी `to_seconds` को कॉल करे, वह अब बॉडी की जगह हेडर पढ़ सकता है। हेडर को फ़ंक्शन के पास ही रखें ताकि दोनों को साथ-साथ अपडेट किया जा सके।

---

कंपाइलर हर टिप्पणी को एक सिंगल स्पेस से बदल देता है। इसका मतलब है कि `/* */` टिप्पणी वहीं कहीं भी आ सकती है जहाँ एक स्पेस आ सकता है, यहाँ तक कि किसी स्टेटमेंट या एक्सप्रेशन के बीच में भी:
```c
int area = width /* cm */ * height /* cm */;
```
यह कभी-कभी ऑपरेंड या कॉल के आर्गुमेंट को लेबल करने के लिए उपयोगी होता है। `//` टिप्पणी यह नहीं कर सकती, क्योंकि वह उसके बाद के कोड सहित पंक्ति के शेष भाग को कमेंट आउट कर देगी।

---

प्रोग्रामर टिप्पणी की शुरुआत में कुछ परंपरागत कीवर्ड का उपयोग अधूरे काम को दर्शाने के लिए करते हैं:

- `TODO` उस चीज़ को दर्शाता है जिसे अभी भी लिखा जाना बाकी है
- `FIXME` उस कोड को दर्शाता है जो गलत होना ज्ञात है और जिसे ठीक किया जाना ज़रूरी है

```c
// TODO: validate the input before using it
// FIXME: crashes when the list is empty
```
एडिटर और टूल इन मार्करों की सूची बना सकते हैं, इसलिए लंबित काम ढूँढना आसान होता है। काम पूरा होते ही मार्कर को डिलीट कर दें: पुराना `TODO` भ्रामक होता है।

---

अच्छी टिप्पणी यह बताती है कि कोड कुछ **क्यों** करता है, न कि वह **क्या** करता है। कोड पहले से ही दिखा देता है कि क्या होता है; उसे शब्दों में दोहराना केवल शोर जोड़ता है और जैसे ही कोड बदलता है, वह पुरानी पड़ जाती है:
```c
// multiply price by 90 and divide by 100
return price * 90 / 100;
```
संख्याओं के पीछे का कारण ही वह चीज़ है जिसका अंदाज़ा कोई पाठक नहीं लगा सकता:
```c
// launch discount: members get 10% off until the end of June
return price * 90 / 100;
```
यदि कोई टिप्पणी केवल अपने नीचे की पंक्ति को दोहराती है, तो उसे डिलीट कर दें या उसे कारण से बदल दें।

---

सबको जोड़ते हुए: छोटे नोट और ट्रेलिंग टिप्पणियों के लिए `//`, लंबे ब्लॉक और हेडर टिप्पणियों के लिए `/* */` का उपयोग करें, अधूरे काम को `TODO` या `FIXME` से दर्शाएँ, और कमेंट आउट किए गए कोड तथा पुराने मार्करों को हटा दें जब वे अब आवश्यक न हों।
