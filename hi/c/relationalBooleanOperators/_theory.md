**संबंधात्मक ऑपरेटर** दो मानों की तुलना करते हैं। परिणाम कोई विशेष टाइप नहीं होता: वह एक `int` होता है जो तुलना सही होने पर `1` और सही न होने पर `0` होता है। C में उनमें से छह हैं:
```c
printf("%d\n", 5 == 5); // equal: prints "1"
printf("%d\n", 5 != 5); // not equal: prints "0"
printf("%d\n", 3 < 5);  // less than: prints "1"
printf("%d\n", 3 > 5);  // greater than: prints "0"
printf("%d\n", 5 <= 5); // less than or equal: prints "1"
printf("%d\n", 4 >= 5); // greater than or equal: prints "0"
```
Because the result is an `int`, it is printed with `%d` and can be stored in an `int` variable like any other number.

---

एक फंक्शन तुलना को सीधे लौटा सकता है: कॉलर को `1` या `0` प्राप्त होता है।
```c
int is_big(int n) {
    return n > 100;
}

printf("%d\n", is_big(250)); // prints "1"
```
`>` और `>=` (या `<` और `<=`) में से चुनाव तय करता है कि सीमा मान गिना जाएगा या नहीं: `n >= 100`, `100` के लिए `1` है, `n > 100` `0` है।

---

C की सबसे आम गलती जहाँ `==` चाहिए हो वहाँ `=` लिखना है। अकेला `=` एक **असाइनमेंट** है, और C में असाइनमेंट एक व्यंजक होता है जिसका मान वही होता है जो असाइन किया गया था:
```c
int x = 3;
printf("%d\n", x == 7); // compares: prints "0", x is still 3
printf("%d\n", x = 7);  // assigns: prints "7", x is now 7
```
`=` वाला कोड फिर भी कंपाइल हो जाता है, इसलिए `if (x = 0)` लिखी शर्त उसे जाँचने की बजाय चुपचाप `x` को `0` सेट कर देती है। ज़्यादातर कंपाइलर इसके लिए एक चेतावनी प्रिंट करते हैं: उसे पढ़ें।

---

**तार्किक ऑपरेटर** शर्तों को जोड़ते हैं। **and** ऑपरेटर `&&` केवल तब `1` देता है जब दोनों पक्ष सही हों, **or** ऑपरेटर `||` तब `1` देता है जब कम से कम एक पक्ष सही हो:
```c
int t = 25;
printf("%d\n", t > 20 && t < 30); // prints "1"
printf("%d\n", t < 20 || t > 30); // prints "0"
```
C में **कोई भी शून्येतर मान सही गिना जाता है** और केवल `0` गलत गिना जाता है, इसलिए `5 && 1`, `1` है और `0 || -3`, `1` है। `&&` और `||` का परिणाम सदैव ठीक `1` या `0` होता है।

---

एक वेरिएबल जिसमें `0` या कोई शून्येतर मान हो, उसे अपने आप में शर्त की तरह इस्तेमाल किया जा सकता है: अकेला `holiday` मतलब है "holiday शून्येतर है", `holiday != 0` लिखने की ज़रूरत नहीं है।
```c
int is_open(int weekday, int holiday) {
    return weekday && !holiday;
}
```
**not** ऑपरेटर `!` एक शर्त को उलट देता है: `!0`, `1` है और किसी भी शून्येतर मान का `!`, `0` होता है।

---

चूँकि `!` कोई भी शून्येतर मान `0` में और `0` को `1` में बदल देता है, इसे दो बार लगाने से मान ठीक `0` या `1` में सामान्यीकृत हो जाता है: `!!42`, `1` है, `!!0` `0` है।
```c
int count = 3;
printf("%d %d\n", !count, !!count); // prints "0 1"
```
यह तब काम आता है जब कोई फंक्शन कोई भी शून्येतर संख्या लौटाए और आप एक साफ़ `1` चाहते हों।

---

C99 से हेडर `stdbool.h` टाइप `bool` और स्थिरांक `true` (जो `1` है) तथा `false` (जो `0` है) उपलब्ध कराता है:
```c
#include <stdbool.h>

bool open = true;
bool full = 3 > 5;
printf("%d %d\n", open, full); // prints "1 0"
```
एक `bool` अंदरखाने फिर भी एक पूर्णांक ही है: उसे `%d` से प्रिंट किया जाता है, और वह `&&`, `||` तथा `!` के साथ ठीक किसी तुलना के परिणाम की तरह काम करता है। बस यह आशय को सादे `int` की तुलना में ज़्यादा स्पष्ट कर देता है।

---

हाँ/नहीं सवाल का जवाब देने वाला फंक्शन `bool` लौटाना चाहिए। एक `bool` पैरामीटर पहले से ही एक शर्त है, इसलिए उसे सीधे `&&` या `||` के ऑपरेंड की तरह इस्तेमाल करें: `citizen == true` नहीं, `age >= 18 && citizen` लिखें।
```c
bool can_enter(int age, bool member) {
    return age >= 16 && member;
}
```
इन अभ्यासों में `stdbool.h` पहले से ही आपके कोड के ऊपर शामिल किया गया है।

---

`&&` और `||` **short-circuit evaluation** का उपयोग करते हैं: जैसे ही परिणाम पता चल जाता है, वे रुक जाते हैं।
- `&&` के साथ, यदि बायाँ पक्ष `0` है तो दायाँ पक्ष कभी मूल्यांकित नहीं होता
- `||` के साथ, यदि बायाँ पक्ष शून्येतर है तो दायाँ पक्ष कभी मूल्यांकित नहीं होता

इससे बाईं ओर की जाँच दाईं ओर की खतरनाक संक्रिया की रक्षा कर सकती है:
```c
int ok = count != 0 && total / count > 2;
```
जब `count` `0` होता है, तो विभाजन कभी निष्पादित नहीं होता, इसलिए प्रोग्राम क्रैश नहीं होता।

---

Short-circuit evaluation फ़ंक्शन कॉल्स को भी छोड़ देता है। `1 || check()` में फंक्शन `check` कभी कॉल नहीं होता, इसलिए उसका कोई भी साइड इफ़ेक्ट, जैसे काउंटर को अपडेट करना, नहीं होता।
```c
int calls = 0;

int check() {
    calls++;
    return 1;
}
```
इस बात को ध्यान में रखें जब `&&` या `||` के दाईं ओर का कोई फंक्शन ऐसा कुछ करता हो जो आप पर निर्भर करता है।

---

ऑपरेटरों की एक **प्राथमिकता** होती है जो तय करती है कि पहले क्या गणना होगी:
1. `!` सबसे पहले लागू होता है
2. फिर संबंधात्मक तुलनाएँ `<`, `>`, `<=`, `>=`
3. फिर समता तुलनाएँ `==`, `!=`
4. फिर `&&`
5. फिर `||`

इसलिए `a > 0 && a < 10` को कोष्ठकों की ज़रूरत नहीं है, और `a && b || c` का मतलब `(a && b) || c` है क्योंकि `&&`, `||` से ज़्यादा कसकर बंधता है। अलग समूहन बलपूर्वक लागू करने या आशय को पढ़ने योग्य बनाने के लिए कोष्ठकों का उपयोग करें।

---

एक `char` एक छोटा पूर्णांक है, इसलिए वर्णों की तुलना उन्हीं ऑपरेटरों से होती है। सिंगल कोट्स में लिखे कैरेक्टर लिटरल से तुलना करें: डबल कोट्स में `"a"` एक स्ट्रिंग है, जिसकी इस तरह तुलना नहीं हो सकती।
```c
char answer = 'y';
printf("%d\n", answer == 'y'); // prints "1"
```
लगातार वर्णों जैसे `'0'`, `'1'`, ... `'9'` या `'a'`, `'b'`, ... `'z'` के कोड लगातार होते हैं, इसलिए वर्णों पर रेंज जाँच ठीक संख्याओं पर जाँच की तरह काम करती है:
```c
bool is_lower(char c) {
    return c >= 'a' && c <= 'z';
}
```

---

गणित की तरह तुलनाओं को श्रृंखला में न जोड़ें। `1 <= x <= 10` कंपाइल हो जाता है, लेकिन उसका मूल्यांकन `(1 <= x) <= 10` की तरह होता है: पहली तुलना `0` या `1` देती है, और उसकी फिर `10` से तुलना होती है, इसलिए पूरा व्यंजक सदैव `1` होता है।
```c
int x = 20;
printf("%d\n", 1 <= x <= 10);       // prints "1" (wrong!)
printf("%d\n", 1 <= x && x <= 10);  // prints "0"
```
सदैव दोनों तुलनाएँ स्पष्ट रूप से लिखें और उन्हें `&&` से जोड़ें।

---

जब कोई शर्त `&&` और `||` को मिलाती है, तो प्रत्येक भाग को कोष्ठकों में समूहित करें, भले ही प्राथमिकता पहले से ही सही काम करती हो: नियम एक नज़र में पढ़ने योग्य हो जाता है।
```c
bool free_entry = (age < 12 || age >= 65) && !holiday;
```
शेषफल ऑपरेटर `%` का `==` के साथ सहज जोड़ बनता है: `n % 4 == 0`, `1` होता है जब `n`, `4` से विभाज्य हो।
