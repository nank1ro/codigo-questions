एक ऐरे से एक बार में एक इंडेक्स पर मान पढ़ना बोझिल है:
```javascript
const point = [3, 7];
const x = point[0];
const y = point[1];
```
**डिस्ट्रक्चरिंग** वही काम एक ही पंक्ति में कर देता है। `=` के बाईं ओर आप एक ऐसा पैटर्न लिखते हैं जो ऐरे जैसा ही दिखता है, और उसके अंदर का हर नाम उसी स्थिति पर रखे एलिमेंट को प्राप्त कर लेता है:
```javascript
const point = [3, 7];
const [x, y] = point;
console.log(x, y);
// prints 3 7
```
पैटर्न को पूरे ऐरे को कवर करने की ज़रूरत नहीं है: अतिरिक्त एलिमेंट सीधे अनदेखे कर दिए जाते हैं, और जिस नाम का कोई मेल खाता एलिमेंट नहीं होता वह `undefined` हो जाता है।

---

डिस्ट्रक्चरिंग सबसे ज़्यादा काम तब आता है जब ऐरे कहीं से आता है: किसी फंक्शन का आर्ग्युमेंट, या किसी कॉल का परिणाम। ऐरे को पास रखकर हर जगह इंडेक्स से पढ़ने के बजाय, आप उसे एक बार खोल लेते हैं और हर हिस्से को एक असली नाम दे देते हैं:
```javascript
function middle(range) {
    const [start, end] = range;
    return (start + end) / 2;
}
console.log(middle([0, 10]));
// prints 5
```
मूल ऐरे में कुछ भी कॉपी नहीं होता या बदला नहीं जाता, पैटर्न केवल उससे पढ़ता है।

---

कभी-कभी ऐरे के अंदर गहराई पर बस एक ही एलिमेंट मायने रखता है। आप पैटर्न में कोई स्थिति खाली छोड़ सकते हैं, उसे अलग करने वाले कॉमा को रखते हुए: ऐसी खाली स्थिति को **होल** कहते हैं, और वह एलिमेंट को बिना नाम दिए छोड़ देती है:
```javascript
const rgb = [255, 128, 64];
const [, , blue] = rgb;
console.log(blue);
// prints 64
```
नामों की नहीं, कॉमा की गिनती करें: हर कॉमा पैटर्न को एक स्थिति आगे बढ़ा देता है, चाहे उससे पहले कोई नाम हो या न हो।

---

ऐरे हमेशा पैटर्न की अपेक्षा जितना लंबा नहीं होता। किसी नाम के बाद `= value` लिखने से उसे एक **डिफ़ॉल्ट** मिल जाता है, जिसका उपयोग तब होता है जब ऐरे में उस स्थिति पर कुछ भी न हो:
```javascript
const size = [1920];
const [width, height = 1080] = size;
console.log(width, height);
// prints 1920 1080
```
डिफ़ॉल्ट केवल तब मूल्यांकित होता है जब उसकी ज़रूरत हो, इसलिए वह फंक्शन कॉल भी हो सकता है, और डिफ़ॉल्ट किसी भी स्थिति को दिया जा सकता है, सिर्फ़ आख़िरी वाले को नहीं।

---

एक पैटर्न किसी साधारण असाइनमेंट के बाईं ओर भी खड़ा हो सकता है, बिना आगे `const` या `let` के, और तब वह उन वेरिएबल में लिखता है जो पहले से मौजूद हैं। इससे दो मानों को आपस में बदलना एक ही पंक्ति का काम बन जाता है, बिना किसी टेम्पररी वेरिएबल के:
```javascript
let a = 1;
let b = 2;
[a, b] = [b, a];
console.log(a, b);
// prints 2 1
```
दाईं ओर पहले बनाई जाती है, इसलिए असाइनमेंट होने तक दोनों पुराने मान टेम्पररी ऐरे के अंदर पहले से सुरक्षित होते हैं। पिछली पंक्ति के सेमीकोलन का ध्यान रखें: वरना `[` से शुरू होने वाली पंक्ति को उससे पहले आई चीज़ का इंडेक्स समझ लिया जाता।

---

ऑब्जेक्ट्स को भी डिस्ट्रक्चर किया जा सकता है, चौकोर ब्रैकेट की जगह घुंघराले ब्रेसिज़ के साथ। यहाँ स्थिति का कोई मतलब नहीं: हर नाम को उस **कुंजी** से मिलाया जाता है जिसकी वर्तनी बिल्कुल वैसी ही हो:
```javascript
const user = { name: "Ada", age: 36 };
const { age, name } = user;
console.log(name, age);
// prints Ada 36
```
पैटर्न में `age` और `name` की जगह बदलने से कुछ नहीं बदलता, और पैटर्न में जिन कुंजियों का ज़िक्र नहीं है वे वैसी की वैसी छूट जाती हैं। जिस नाम की कोई मेल खाती कुंजी नहीं होती वह `undefined` हो जाता है।

---

ऑब्जेक्ट पैटर्न और डिफ़ॉल्ट ठीक वैसे ही आपस में जुड़ते हैं जैसे ऐरे वाले, जिससे वे किसी कॉन्फ़िगरेशन ऑब्जेक्ट को पढ़ने का एक साफ़-सुथरा तरीका बन जाते हैं जिसकी कुंजियाँ हो भी सकती हैं और नहीं भी:
```javascript
const options = { theme: "dark" };
const { theme, lang = "en" } = options;
console.log(theme, lang);
// prints dark en
```
चूँकि पूरा पैटर्न एक ही कथन है, कोई फंक्शन अपनी पहली ही पंक्ति पर आर्ग्युमेंट से ज़रूरत की हर चीज़ खोल सकता है।

---

ऑब्जेक्ट पैटर्न अपने वेरिएबल का नाम कुंजियों के आधार पर रखता है, जो अटपटा लगता है जब कुंजियाँ रहस्यमय हों या नाम पहले से लिए हुए हों। `key: newName` लिखने से वेरिएबल **रीनेम** हो जाता है:
```javascript
const row = { n: "Ada", y: 1815 };
const { n: name, y: born } = row;
console.log(name, born);
// prints Ada 1815
```
इसे इस तरह पढ़ें: "`n` लो, उसे `name` कहो"। कोलन कोई टाइप घोषित नहीं करता, और `n` खुद कभी वेरिएबल के रूप में नहीं बनता, केवल `name` बनता है। रीनेम किए हुए नाम को डिफ़ॉल्ट भी मिल सकता है, जो उसके बाद लिखा जाता है: `{ n: name = "unknown" }`।

---

डिफ़ॉल्ट का एक नियम है जो सबको चौंकाता है: वे **केवल** `undefined` पर लागू होते हैं। कोई कुंजी जो मौजूद है और `null`, `0`, `""` या `false` रखती है, एक असली मान है, इसलिए पैटर्न उसे ले लेता है और डिफ़ॉल्ट कभी उपयोग नहीं होता:
```javascript
const { count = 10 } = { count: 0 };
console.log(count);
// prints 0
```
यहाँ `null` का व्यवहार `0` जैसा ही है, भले ही वह किसी API रिस्पॉन्स में अक्सर "कोई मान नहीं" का मतलब होता है। जब `null` को भी बदलना हो, तो पहले डिस्ट्रक्चर करें और उसके बाद `??` से फ़ॉलबैक लें।

---

जहाँ कोई कुंजी दूसरा ऑब्जेक्ट या ऐरे रखती है, वहाँ पैटर्न बस आगे बढ़ता जाता है और उस आकृति का भी वर्णन कर देता है:
```javascript
const user = { name: "Ada", address: { city: "London" } };
const { address: { city } } = user;
console.log(city);
// prints London
```
इस पंक्ति से क्या बनता है, इससे सावधान रहें: `address: { city }` का मतलब है "`address` के अंदर जाओ", "मुझे `address` दो" नहीं, इसलिए केवल `city` वेरिएबल बनता है। दोनों पाने के लिए कुंजी का दो बार ज़िक्र करें: `const { address, address: { city } } = user;`। ऐरे और ऑब्जेक्ट पैटर्न आपस में आराम से नेस्ट होते हैं, जैसे `{ tags: [first] }`।

---

ऐरे का सिर लेना और पूँछ बचा लेना इतनी आम ज़रूरत है कि पैटर्न के पास इसके लिए अपना सिंटैक्स है। आख़िरी नाम के आगे तीन बिंदु उसे एक **रेस्ट एलिमेंट** बना देते हैं, और वह हर बचा हुआ एलिमेंट एक बिल्कुल नए ऐरे में इकट्ठा कर लेता है:
```javascript
const queue = ["a", "b", "c"];
const [next, ...waiting] = queue;
console.log(next, waiting);
// prints a [ 'b', 'c' ]
```
रेस्ट एलिमेंट पैटर्न में आख़िर में ही आना चाहिए और उसे डिफ़ॉल्ट नहीं मिल सकता: जब कुछ न बचे तो वह सीधा एक खाली ऐरे होता है।

---

ऑब्जेक्ट पैटर्न का भी रेस्ट होता है, और वहाँ वह पैटर्न में जिन कुंजियों का ज़िक्र नहीं हुआ उन सबको एक नए ऑब्जेक्ट में इकट्ठा कर लेता है:
```javascript
const user = { id: 1, name: "Ada", city: "London" };
const { id, ...profile } = user;
console.log(profile);
// prints { name: 'Ada', city: 'London' }
```
किसी ऑब्जेक्ट की एक कुंजी के बिना कॉपी बनाने का यह सबसे छोटा तरीका है: मूल ऑब्जेक्ट को कभी छुआ नहीं जाता, और रेस्ट ऑब्जेक्ट एक नया होता है जो बाकी मान रखता है।

---

फंक्शन घोषणा में पैटर्न किसी पैरामीटर के नाम की जगह ले सकता है, ताकि खोलना उसी समय हो जब कॉल किया जाता है:
```javascript
function area({ width, height }) {
    return width * height;
}
console.log(area({ width: 4, height: 3 }));
// prints 12
```
बॉडी के अंदर कोई ऑब्जेक्ट वेरिएबल बिल्कुल नहीं होता, केवल `width` और `height`। कॉल करने वाला एक ऑब्जेक्ट पास करता है, लेकिन सिग्नेचर साफ़ बता देता है कि फंक्शन कौन-सी कुंजियाँ पढ़ता है, और कुंजियाँ किसी भी क्रम में आ सकती हैं।

---

डिफ़ॉल्ट के साथ डिस्ट्रक्चर किया हुआ पैरामीटर एक साफ़ ऑप्शन्स ऑब्जेक्ट बनाता है, लेकिन वह तब भी टूट जाता है जब कॉल करने वाला कुछ भी पास न करे: `undefined` से कुंजी पढ़ना एक `TypeError` फेंकता है। पूरे पैटर्न को `{}` का डिफ़ॉल्ट देने से यह ठीक हो जाता है:
```javascript
function createUser({ name = "guest", admin = false } = {}) {
    return `${name}/${admin}`;
}
console.log(createUser());
// prints guest/false
```
इस पंक्ति को बाहर से अंदर पढ़ें: `= {}` एक खाली ऑब्जेक्ट दे देता है जब आर्ग्युमेंट मौजूद न हो, और तब हर अंदरूनी डिफ़ॉल्ट अपनी कुंजी भर देता है।

---

`Object.entries(obj)` किसी ऑब्जेक्ट को `[key, value]` जोड़ों के ऐरे में बदल देता है। `for...of` लूप के हेड में एक ऐरे पैटर्न रखें और लूप चलते समय हर जोड़ा खुल जाता है:
```javascript
const ages = { ada: 36, bob: 41 };
for (const [name, age] of Object.entries(ages)) {
    console.log(`${name} is ${age}`);
}
// prints ada is 36
// prints bob is 41
```
किसी ऑब्जेक्ट पर चलने का यह सबसे पढ़ने-योग्य तरीका है: न कोई इंडेक्स, न कोई लुकअप, बस वही दो नाम जिनकी आपको परवाह है। `Object.keys` और `Object.values` हर एक केवल एक पक्ष देते हैं, `Object.entries` दोनों देता है।

---

अब तक देखा गया सब कुछ एक ही सिंटैक्स का हिस्सा है, इसलिए टुकड़े आराम से आपस में जुड़ते हैं: एक ऑब्जेक्ट पैटर्न दूसरे ऑब्जेक्ट पैटर्न को नेस्ट कर सकता है, जो डिफ़ॉल्ट के साथ रीनेम की हुई कुंजी रख सकता है, रेस्ट एलिमेंट पर ख़त्म होने वाले ऐरे पैटर्न के बगल में। तब एक ही पंक्ति पूरी आकृति का वर्णन कर देती है जिसकी फंक्शन को अपेक्षा होती है:
```javascript
function head({ title, tags: [main, ...extra] }) {
    return `${title} [${main}] +${extra.length}`;
}
console.log(head({ title: "Post", tags: ["js", "web", "dev"] }));
// prints Post [js] +2
```
इसे पढ़ने-योग्य रखें: जो पैटर्न अब दो-चार पंक्तियों में नहीं समाता, वह आम तौर पर इसका संकेत है कि फंक्शन बहुत ज़्यादा माँग रहा है।
