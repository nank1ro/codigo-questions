एक **रेगुलर एक्सप्रेशन** (या **रेगेक्स**) टेक्स्ट की एक आकृति का वर्णन करने वाला एक छोटा पैटर्न है। आप इसका उपयोग "क्या इस स्ट्रिंग में कोई संख्या है?" या "शब्द `cat` कहाँ आता है?" जैसे प्रश्नों के उत्तर देने के लिए करते हैं।

JavaScript में इसे लिखने का सबसे छोटा तरीका एक **रेगेक्स लिटरल** है: दो स्लैश के बीच का पैटर्न।
```javascript
const pattern = /cat/;
```
पैटर्न के साधारण वर्ण स्वयं से मेल खाते हैं, इसलिए `/cat/` किसी स्ट्रिंग में कहीं भी `c`, `a`, `t` तीन वर्णों से मेल खाता है।

पैटर्न के साथ आप जो सबसे सरल काम कर सकते हैं वह यह पूछना है कि वह किसी स्ट्रिंग में आता है या नहीं। **`test`** मेथड टेक्स्ट लेता है और `true` या `false` लौटाता है:
```javascript
console.log(/cat/.test("the cat sleeps"));
// prints true
console.log(/cat/.test("the dog sleeps"));
// prints false
```
ध्यान दें कि `test` स्ट्रिंग में *कहीं भी* पैटर्न खोजता है; पूरी स्ट्रिंग के मेल खाना ज़रूरी नहीं है।

---

पैटर्न तब उपयोगी बनते हैं जब वे किसी एक सटीक वर्ण के बजाय वर्ण के एक *प्रकार* का वर्णन करते हैं। कुछ **एस्केप सीक्वेंस** ज़्यादातर ज़रूरतें पूरी कर देते हैं:
- `\d` कोई भी अंक, `0` से `9` तक
- `\w` कोई भी वर्ड कैरेक्टर: एक अक्षर, एक अंक या `_`
- `\s` कोई भी व्हाइटस्पेस: एक स्पेस, एक टैब, एक न्यूलाइन

```javascript
console.log(/\d/.test("room 12"));
// prints true
console.log(/\d/.test("lobby"));
// prints false
```
एक **क्वांटिफ़ायर** बताता है कि पिछला भाग कितनी बार दोहराया जा सकता है। सबसे सामान्य `+` है, जिसका अर्थ है "एक या अधिक":
```javascript
console.log(/\d+/.test("42"));
// prints true
```
इसलिए `/\d/` एक अकेले अंक से मेल खाता है और `/\d+/` अंकों की एक शृंखला से मेल खाता है। साधारण `test` के लिए दोनों एक जैसा व्यवहार करते हैं, क्योंकि दोनों को केवल एक अंक के मौजूद होने की ज़रूरत होती है।

---

`/\d+/` जैसा लिटरल लिखते ही स्थिर हो जाता है। जब पैटर्न को **रन टाइम पर बनाना** हो, तो **`RegExp` कंस्ट्रक्टर** का उपयोग करें, जो पैटर्न को एक स्ट्रिंग के रूप में लेता है:
```javascript
const word = "cat";
const pattern = new RegExp(word);
console.log(pattern.test("the cat sleeps"));
// prints true
```
यहाँ एक जाल है। एक स्ट्रिंग के अंदर बैकस्लैश *स्ट्रिंग* के लिए एक एस्केप सीक्वेंस शुरू करता है, इसलिए वह रेगेक्स तक पहुँचने से पहले ही गायब हो जाता है। पैटर्न में एक वास्तविक बैकस्लैश रखने के लिए आपको उसे दोगुना करना होगा:
```javascript
const digits = new RegExp("\\d+");
// the same pattern as /\d+/
```
इसके बजाय `new RegExp("\d+")` लिखने पर पैटर्न `/d+/` मिलता है, जो अंक नहीं बल्कि अक्षर `d` से मेल खाता है।

जब कोड लिखते समय पैटर्न ज्ञात हो तो लिटरल को प्राथमिकता दें; वह छोटा होता है और उसमें दोगुने बैकस्लैश की ज़रूरत नहीं होती।

---

दो और बिल्डिंग ब्लॉक आपको लगभग कोई भी टेक्स्ट आकृति बताने देते हैं।

एक **कैरेक्टर क्लास** वर्गाकार कोष्ठकों के बीच वर्णों का एक समूह है; वह उनमें से ठीक एक से मेल खाता है। एक डैश एक रेंज लिखता है, और शुरुआत में `^` समूह को नकार देता है:
```javascript
/[aeiou]/   // one vowel
/[a-z]/     // one lowercase letter
/[A-Z0-9]/  // one uppercase letter or one digit
/[^0-9]/    // one character that is not a digit
```
**क्वांटिफ़ायर** बताते हैं कि पिछला भाग कितनी बार दोहराया जाता है: `+` एक या अधिक, `*` शून्य या अधिक, `?` शून्य या एक, और `{n}` ठीक `n` बार।

अंत में, **एंकर** पैटर्न को टेक्स्ट के सिरों से बाँधते हैं: `^` का अर्थ है "यहाँ शुरू" और `$` का अर्थ है "यहाँ अंत"। इनके बिना एक पैटर्न स्ट्रिंग में कहीं भी मेल खा सकता है, इसलिए `/\d{2}/.test("abc12def")` का मान `true` है। दोनों एंकरों के साथ पूरी स्ट्रिंग के मेल खाना ज़रूरी हो जाता है:
```javascript
console.log(/^\d{2}$/.test("abc12def"));
// prints false
console.log(/^\d{2}$/.test("12"));
// prints true
```

---

`test` केवल हाँ या ना बताता है। मेल खाने वाला टेक्स्ट स्वयं पाने के लिए स्ट्रिंग पर **`match`** कॉल करें:
```javascript
const match = "order 42 shipped".match(/\d+/);
```
जब कुछ भी मेल नहीं खाता, तो `match` `null` लौटाता है। जब कुछ मेल खाता है, तो वह एक ऐरे-जैसा परिणाम लौटाता है:
- `match[0]` वह टेक्स्ट है जो मेल खाया था
- `match.index` वह स्थिति है जहाँ मेल शुरू होता है
- `match.input` पूरी स्ट्रिंग है जो खोजी गई थी

```javascript
console.log(match[0]);
// prints 42
console.log(match.index);
// prints 6
```
चूँकि परिणाम `null` हो सकता है, `match[0]` पढ़ने से पहले उसे जाँचें।

---

चूँकि पैटर्न के न आने पर `match` `null` लौटाता है, `match[0]` को सीधे पढ़ने पर `TypeError: Cannot read properties of null` आ जाता है। उसे सुरक्षित रखें:
```javascript
function firstWord(text) {
  const match = text.match(/[a-z]+/);
  if (match === null) {
    return "";
  }
  return match[0];
}
```
नलिश कोअलेसिंग ऑपरेटर उसी सुरक्षा को एक पंक्ति में लिख देता है, क्योंकि `match` के `null` होने पर `match?.[0]` का मान `undefined` होता है:
```javascript
return text.match(/[a-z]+/)?.[0] ?? "";
```

---

पैटर्न के एक भाग के चारों ओर कोष्ठक लगाने से एक **कैप्चर ग्रुप** बनता है: उस भाग से मेल खाने वाला टेक्स्ट अलग रख लिया जाता है ताकि आप उसे वापस पढ़ सकें।

ग्रुप `match[0]` के बाद आते हैं, जिन्हें उनके खोलने वाले कोष्ठक के अनुसार बाएँ से दाएँ क्रमांकित किया जाता है:
```javascript
const match = "2026-09-12".match(/(\d{4})-(\d{2})-(\d{2})/);
console.log(match[0]);
// prints 2026-09-12
console.log(match[1]);
// prints 2026
console.log(match[3]);
// prints 12
```
इसलिए `match[0]` हमेशा पूरा मेल होता है, और `match[1]`, `match[2]`, ... ग्रुप होते हैं। ऐसा ग्रुप जो एक ऐसे पैटर्न का हिस्सा है जो बिल्कुल मेल नहीं खाता, पूरे `match` को `null` लौटाने पर मजबूर कर देता है।

---

केवल वही कैप्चर करें जो आपको चाहिए। एक ग्रुप सिर्फ़ किसी भाग को वापस पढ़ने का तरीका नहीं है; वह पाठक को यह भी बताता है कि पैटर्न का कौन-सा भाग मायने रखता है। एक समय पैटर्न में जहाँ आप केवल मिनट चाहते हैं, केवल मिनट को ग्रुप करें और बाकी को बिना ग्रुप छोड़ दें:
```javascript
const minutes = "at 14:35:02".match(/\d{2}:(\d{2}):\d{2}/)?.[1];
console.log(minutes);
// prints 35
```
पूरे पैटर्न का फिर भी मेल खाना ज़रूरी है, इसलिए घंटे और सेकंड फिर भी आवश्यक हैं; वे बस कैप्चर नहीं किए जाते। कम ग्रुप का मतलब है `match[1]`, `match[2]` और आगे पढ़ते समय याद रखने के लिए कम संख्याएँ।

---

कोष्ठकों की गिनती करना थकाऊ हो जाता है, और पैटर्न के बीच में एक ग्रुप जोड़ने से उसके बाद की हर चीज़ का क्रमांक बदल जाता है। एक **नेम्ड ग्रुप** दोनों समस्याओं से बचाता है: खोलने वाले कोष्ठक के ठीक बाद `?<name>` लिखें और उस भाग को `match.groups` से वापस पढ़ें:
```javascript
const match = "2026-09-12".match(/(?<year>\d{4})-(?<month>\d{2})-\d{2}/);
console.log(match.groups.year);
// prints 2026
console.log(match.groups.month);
// prints 09
```
नेम्ड ग्रुप अब भी क्रमांकित होते हैं, इसलिए `match[1]` काम करता रहता है, लेकिन `match.groups.year` बताता है कि मान का क्या अर्थ है। जब पैटर्न में कोई नेम्ड ग्रुप बिल्कुल न हो, तो `match.groups` का मान `undefined` होता है।

---

अब तक सब कुछ पहले मेल पर रुक जाता था। **फ्लैग**, जो एक लिटरल के बंद होने वाले स्लैश के बाद लिखे जाते हैं, इसे और खोज की अन्य बातों को बदल देते हैं:
- `g` ग्लोबल: केवल पहला नहीं, हर मेल खोजें
- `i` केस को अनदेखा करें, इसलिए `/cat/i` `Cat` और `CAT` से भी मेल खाता है

`g` फ्लैग के साथ `match` अलग तरह से व्यवहार करता है: वह मेल खाने वाली **स्ट्रिंग्स** की एक साधारण ऐरे लौटाता है, बिना `index` और बिना ग्रुप, या कोई मेल न होने पर `null` लौटाता है:
```javascript
const numbers = "a1 b22 c333".match(/\d+/g);
console.log(numbers);
// prints [ '1', '22', '333' ]
console.log(numbers.length);
// prints 3
```
फ्लैग को किसी भी क्रम में जोड़ा जा सकता है, जैसे `/cat/gi`। `RegExp` कंस्ट्रक्टर के साथ वे दूसरे तर्क में जाते हैं: `new RegExp("\\d+", "g")`।

---

`g` फ्लैग आपको हर मेल खाने वाली स्ट्रिंग देता है, लेकिन वह ग्रुप को छोड़ देता है। जब आपको *हर* मेल के ग्रुप चाहिए, तो **`matchAll`** का उपयोग करें। वह पूर्ण मेल ऑब्जेक्ट्स का एक इटरेटर लौटाता है, जिनमें से प्रत्येक बिल्कुल साधारण `match` के परिणाम जैसा होता है:
```javascript
const text = "a=1;b=2";
for (const match of text.matchAll(/(?<key>\w+)=(?<value>\w+)/g)) {
  console.log(`${match.groups.key} -> ${match.groups.value}`);
}
// prints a -> 1
// prints b -> 2
```
`matchAll` को `g` फ्लैग की आवश्यकता होती है; उसके बिना वह `TypeError` फेंकता है। चूँकि वह एक इटरेटर लौटाता है, एक वास्तविक ऐरे चाहने पर उसे `[...text.matchAll(pattern)]` से स्प्रेड करें, और ध्यान रखें कि पैटर्न के कभी मेल न खाने पर वह बिल्कुल कुछ नहीं देता।

---

**`replace`** एक नई स्ट्रिंग लौटाता है जिसमें मेल किसी और चीज़ से बदल दिया गया है। मूल स्ट्रिंग कभी नहीं बदलती।
```javascript
console.log("the cat sleeps".replace(/cat/, "dog"));
// prints the dog sleeps
```
रिप्लेसमेंट स्ट्रिंग के अंदर कुछ सीक्वेंस का एक विशेष अर्थ होता है:
- `$1`, `$2`, ... ग्रुप 1, ग्रुप 2, ... द्वारा कैप्चर किया गया टेक्स्ट
- `$<name>` एक नेम्ड ग्रुप द्वारा कैप्चर किया गया टेक्स्ट
- `$&` पूरा मेल

यही `replace` को सिर्फ़ बदलने वाला नहीं बल्कि फिर से लिखने का एक औज़ार बनाता है:
```javascript
console.log("2026-09-12".replace(/(\d{4})-(\d{2})-(\d{2})/, "$3/$2/$1"));
// prints 12/09/2026
```
`g` फ्लैग के बिना केवल **पहला** मेल बदला जाता है।

---

**पहले** मेल के बजाय **हर** मेल को फिर से लिखने के लिए आपके पास दो विकल्प हैं:
```javascript
console.log("a1 b2".replace(/\d/g, "#"));
// prints a# b#
console.log("a1 b2".replaceAll(/\d/g, "#"));
// prints a# b#
```
**`replaceAll`** दोनों में से अधिक स्पष्ट है, और वह पैटर्न के रूप में एक साधारण स्ट्रिंग भी स्वीकार करता है। जब आप उसे एक रेगेक्स देते हैं, तो उस रेगेक्स में `g` फ्लैग होना **ज़रूरी** है, अन्यथा वह `TypeError` फेंकता है; यही बात `replace` लिखने और केवल पहला मेल ठीक करने वाले चुपचाप रह जाने वाले बग को रोकती है।

---

रिप्लेसमेंट का एक स्ट्रिंग होना ज़रूरी नहीं। जब आप एक **फंक्शन** पास करते हैं, तो उसे हर मेल पर एक बार कॉल किया जाता है और जो कुछ वह लौटाता है वह उस मेल की जगह डाल दिया जाता है।

फंक्शन को पहले पूरा मेल मिलता है, फिर हर कैप्चर ग्रुप:
```javascript
console.log("hello world".replace(/\w+/g, (word) => word.length));
// prints 5 5

console.log("ann lee".replace(/(\w)(\w*)/g, (whole, first, rest) => first.toUpperCase() + rest));
// prints Ann Lee
```
मेल खाए टेक्स्ट से रिप्लेसमेंट की गणना करने का यही एकमात्र तरीका है, जो अकेले `$1` नहीं कर सकता।

---

**`split`** एक स्ट्रिंग को एक ऐरे में काटता है। एक साधारण स्ट्रिंग देने पर वह ठीक उसी टेक्स्ट पर काटता है, लेकिन एक रेगेक्स देने पर वह पैटर्न के हर मेल पर काटता है, जिससे एक ही कॉल बदलने वाले सेपरेटर संभाल लेती है:
```javascript
console.log("a, b;c".split(", "));
// prints [ 'a', 'b;c' ]
console.log("a, b;c".split(/[,;]\s*/));
// prints [ 'a', 'b', 'c' ]
```
सेपरेटर स्वयं परिणाम का हिस्सा नहीं होते। स्ट्रिंग की शुरुआत या अंत में सेपरेटर से सावधान रहें: वह ऐरे में एक खाली स्ट्रिंग बना देता है, क्योंकि उस तरफ एक खाली फ़ील्ड होती है।

---

एक आख़िरी फ्लैग सेट को पूरा करता है। डिफ़ॉल्ट रूप से `^` और `$` का अर्थ **पूरी स्ट्रिंग** की शुरुआत और अंत होता है, इसलिए `^` से एंकर किया गया पैटर्न केवल बिल्कुल शुरुआत में मेल खा सकता है, तब भी जब टेक्स्ट में कई पंक्तियाँ हों।

**`m`** (मल्टीलाइन) फ्लैग इसे बदल देता है: `^` और `$` तब हर न्यूलाइन के ठीक बाद और ठीक पहले भी मेल खाते हैं, इसलिए हर पंक्ति अपने आप पर एंकर हो जाती है:
```javascript
const text = "note a\nb\nnote c";
console.log(text.match(/^note.*/g));
// prints [ 'note a' ]
console.log(text.match(/^note.*/gm));
// prints [ 'note a', 'note c' ]
```
यहाँ दो बातें मायने रखती हैं। डिफ़ॉल्ट रूप से `.` एक न्यूलाइन से मेल नहीं खाता (केवल `s` फ्लैग इसे बदलता है), इसलिए `.*` स्वयं ही पंक्ति के अंत पर रुक जाता है। और `g` फ्लैग के साथ `match`, कुछ भी मेल न खाने पर एक खाली ऐरे नहीं बल्कि `null` लौटाता है, इसलिए जब आप एक ऐरे लौटाने का वादा करते हैं तो उसे `?? []` के साथ जोड़ें।
