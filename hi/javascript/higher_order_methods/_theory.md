JavaScript में फ़ंक्शन एक **मान** है: आप उसे किसी वेरिएबल में रख सकते हैं, किसी array में डाल सकते हैं और किसी दूसरे फ़ंक्शन को आर्ग्युमेंट के रूप में पास कर सकते हैं। जो फ़ंक्शन किसी फ़ंक्शन को आर्ग्युमेंट के रूप में लेता है, या कोई फ़ंक्शन लौटाता है, उसे **हायर-ऑर्डर फ़ंक्शन** कहते हैं। पास किए गए फ़ंक्शन को **callback** कहते हैं, क्योंकि लेने वाला ज़रूरत पड़ने पर *उसे वापस बुलाता* है:
```javascript
function shout(text) {
  return text.toUpperCase() + "!";
}
function twice(fn, value) {
  return fn(fn(value));
}
console.log(twice(shout, "hi"));
// prints HI!!
```
ध्यान दें कि `shout` को **बिना कोष्ठक के** पास किया गया है: `twice(shout, "hi")` फ़ंक्शन को ही सौंपता है, जबकि `twice(shout("hi"), "hi")` पहले `shout` को कॉल करता और उसका परिणाम, यानी स्ट्रिंग `"HI!"`, पास करता, जिसे कॉल नहीं किया जा सकता।

---

हायर-ऑर्डर फ़ंक्शन आपको *हर एलिमेंट के साथ क्या करना है* को *एलिमेंट्स पर कैसे चलना है* से अलग करने देते हैं। चलने वाला हिस्सा एक ही बार लिखा जाता है, और बाक़ी callback तय करता है:
```javascript
function each(items, action) {
  for (let i = 0; i < items.length; i++) {
    action(items[i]);
  }
}
each(["a", "b"], (letter) => console.log(letter));
// prints a and b on two lines
```
Callback को एक बार में एक एलिमेंट मिलता है। यह ऊपर की तरह इनलाइन लिखा arrow फ़ंक्शन हो सकता है, या किसी वेरिएबल में रखा कोई भी फ़ंक्शन। आगे आप जिन बिल्ट-इन array मेथड्स से मिलेंगे, वे भीतर से ठीक इसी तरह काम करते हैं।

---

बिल्ट-इन `map` वही करता है जो `transform` करता है: यह हर एलिमेंट के लिए callback को कॉल करता है और परिणामों को एक **नए array** में इकट्ठा करता है। `forEach` भी हर एलिमेंट के लिए callback को कॉल करता है, लेकिन कुछ इकट्ठा नहीं करता और हमेशा `undefined` लौटाता है; इसका उपयोग सिर्फ़ साइड इफ़ेक्ट के लिए करें, जैसे प्रिंट करना:
```javascript
const prices = [5, 10];
const doubled = prices.map((p) => p * 2);
prices.forEach((p) => console.log(p));
// prints 5 and 10 on two lines
console.log(doubled);
// prints [ 10, 20 ]
```
एक आम ग़लती है `forEach` के परिणाम को सहेजना या उसके बाद कोई और मेथड जोड़ना: जोड़ने के लिए कुछ है ही नहीं, क्योंकि वह `undefined` लौटाता है। सरल नियम: जब आपको नए मान चाहिए तब `map` का उपयोग करें, और जब सिर्फ़ कुछ *करना* हो तब `forEach` का।

---

दो और हायर-ऑर्डर मेथड रोज़मर्रा की ज़्यादातर ज़रूरतें पूरी कर देते हैं।
`filter(callback)` एक नया array लौटाता है जिसमें सिर्फ़ वही एलिमेंट होते हैं जिनके लिए callback `true` लौटाता है; इस तरह हाँ या ना में उत्तर देने वाले callback को **प्रेडिकेट** कहते हैं।
`reduce(callback, initialValue)` सभी एलिमेंट्स को एक ही मान में मिला देता है: callback को **संचायक** (अब तक का परिणाम) और मौजूदा एलिमेंट मिलते हैं, और वह नया संचायक लौटाता है। `reduce` का दूसरा आर्ग्युमेंट शुरुआती संचायक होता है:
```javascript
const numbers = [3, 8, 5];
console.log(numbers.filter((n) => n > 4));
// prints [ 8, 5 ]
console.log(numbers.reduce((sum, n) => sum + n, 0));
// prints 16
```
चूँकि `filter` और `map` array लौटाते हैं, आप उन्हें जोड़ सकते हैं और अंत में `reduce` लगा सकते हैं: `numbers.filter(...).map(...).reduce(...)`।

---

तीन मेथड किसी प्रेडिकेट की मदद से array के बारे में सवालों के जवाब देते हैं:
- `find(predicate)` वह **पहला** एलिमेंट लौटाता है जिसके लिए प्रेडिकेट `true` है, और कोई न हो तो `undefined`
- `some(predicate)` `true` लौटाता है अगर **कम से कम एक** एलिमेंट प्रेडिकेट को पूरा करता है
- `every(predicate)` `true` लौटाता है अगर **सभी** एलिमेंट उसे पूरा करते हैं (और ख़ाली array के लिए भी `true`)
```javascript
const scores = [72, 45, 90];
console.log(scores.find((s) => s < 60));
// prints 45
console.log(scores.some((s) => s === 90), scores.every((s) => s >= 60));
// prints true false
```
तीनों उत्तर मिलते ही रुक जाते हैं, इसलिए वे कभी ज़रूरत से ज़्यादा एलिमेंट नहीं देखते।

---

`sort(compare)` किसी array को **उसी जगह** क्रमबद्ध करता है, एक callback की मदद से जिसे दो एलिमेंट मिलते हैं और जो ऋणात्मक संख्या लौटाता है जब पहला पहले आना चाहिए, धनात्मक संख्या जब दूसरा पहले आना चाहिए, और `0` जब दोनों बराबर हों। संख्याओं के लिए `(a, b) => a - b` आरोही क्रम में और `(a, b) => b - a` अवरोही क्रम में क्रमबद्ध करता है।
बिना तुलना फ़ंक्शन के, `sort()` हर एलिमेंट को **स्ट्रिंग** में बदलकर एक-एक अक्षर की तुलना करता है, इसलिए `10` `9` से पहले आता है क्योंकि `"1"` `"9"` से छोटा है:
```javascript
console.log([10, 9, 1].sort());
// prints [ 1, 10, 9 ]
console.log([10, 9, 1].sort((a, b) => a - b));
// prints [ 1, 9, 10 ]
```
चूँकि `sort` array को बदल देता है, जब आपको मूल क्रम भी चाहिए तो एक कॉपी को क्रमबद्ध करें: `[...numbers].sort(...)`। स्ट्रिंग्स के लिए तुलना फ़ंक्शन के रूप में `(a, b) => a.localeCompare(b)` का उपयोग करें, जो पाठ को वर्णमाला क्रम में लगाता है।

---

तुलना फ़ंक्शन एलिमेंट्स के किसी भी हिस्से को देख सकता है, इसलिए ऑब्जेक्ट्स का array उनकी किसी एक प्रॉपर्टी की तुलना करके ही उस प्रॉपर्टी के अनुसार क्रमबद्ध हो जाता है:
```javascript
const items = [{ name: "b", size: 3 }, { name: "a", size: 1 }];
const bySize = [...items].sort((x, y) => x.size - y.size);
console.log(bySize.map((item) => item.name));
// prints [ 'a', 'b' ]
```
कॉपी को क्रमबद्ध करने से `items` अपने मूल क्रम में ही रहता है।

---

हायर-ऑर्डर फ़ंक्शन कोई फ़ंक्शन **लौटा** भी सकता है। लौटाया गया फ़ंक्शन उस जगह के वेरिएबल याद रखता है जहाँ वह बना था, बाहरी फ़ंक्शन के ख़त्म हो जाने के बाद भी: इसे **क्लोज़र** कहते हैं।
```javascript
function makeMultiplier(factor) {
  return function (n) {
    return n * factor;
  };
}
const triple = makeMultiplier(3);
console.log(triple(5));
// prints 15
console.log(makeMultiplier(10)(5));
// prints 50
```
`makeMultiplier` की हर कॉल अपने अलग `factor` वाला एक नया फ़ंक्शन बनाती है। इसी तरह एक ही साँचे से मिलते-जुलते फ़ंक्शनों का परिवार बनाया जाता है। यही बात arrow फ़ंक्शनों से भी लिखी जा सकती है: `const makeMultiplier = (factor) => (n) => n * factor;`।

---

क्लोज़र वेरिएबल के मान की कॉपी नहीं, बल्कि वेरिएबल से **जीवंत** जुड़ाव रखता है। जब एक ही कॉल में कई फ़ंक्शन बनते हैं, तो वे वही एक वेरिएबल साझा करते हैं, और एक के ज़रिए किया गया हर बदलाव दूसरों को दिखता है:
```javascript
function makeCounter() {
  let count = 0;
  return {
    increment: () => { count += 1; },
    value: () => count,
  };
}
const counter = makeCounter();
counter.increment();
counter.increment();
console.log(counter.value());
// prints 2
```
उन दो फ़ंक्शनों के अलावा बाहर से कोई `count` को न पढ़ सकता है और न रीसेट कर सकता है: यह वेरिएबल **निजी** है। `makeCounter()` की दूसरी कॉल पूरी तरह अलग `count` बनाती है।

---

चूँकि फ़ंक्शन मान होते हैं, आप एक ऐसा हायर-ऑर्डर फ़ंक्शन लिख सकते हैं जो दो फ़ंक्शनों को एक नए फ़ंक्शन में **जोड़** दे। `compose(f, g)` एक ऐसा फ़ंक्शन लौटाता है जो पहले `g` लगाता है और फिर परिणाम पर `f`, ठीक गणितीय संकेत *f(g(x))* की तरह:
```javascript
const compose = (f, g) => (x) => f(g(x));
const trim = (s) => s.trim();
const shout = (s) => s.toUpperCase();
const clean = compose(shout, trim);
console.log(clean("  hi  "));
// prints HI
```
क्रम मायने रखता है: `compose(f, g)` पहले `g` चलाता है, फिर `f`। इस तरह छोटे फ़ंक्शनों को जोड़कर प्रोग्राम बनाने को **फ़ंक्शन कंपोज़िशन** कहते हैं।

---

फ़ंक्शन लौटाने वाला फ़ंक्शन किसी callback को **ढालने** का भी स्वाभाविक तरीक़ा है। मान लीजिए आपके पास एक प्रेडिकेट है और `filter` के लिए आपको उसका उल्टा चाहिए: उसे दोबारा लिखने के बजाय उसे लपेट दीजिए:
```javascript
const isLong = (word) => word.length > 4;
const isShort = (word) => !isLong(word);
console.log(["tree", "forest"].filter(isShort));
// prints [ 'tree' ]
```
एक सामान्य `not(predicate)` यह काम किसी भी प्रेडिकेट के लिए कर देगा: यह एक नया फ़ंक्शन लौटाता है जो उसी आर्ग्युमेंट के साथ `predicate` को कॉल करता है और परिणाम को `!` से उलट देता है। `filter`, `find`, `some` और `every` के प्रेडिकेट को एलिमेंट पहले आर्ग्युमेंट के रूप में मिलता है, इसलिए रैपर को सिर्फ़ वही एक मान आगे भेजना होता है।

---

`reduce` का संचायक संख्या ही हो, यह ज़रूरी नहीं: वह स्ट्रिंग, array या ऑब्जेक्ट भी हो सकता है। ख़ाली ऑब्जेक्ट `{}` से शुरू करके आप एक ही चक्कर में गिनती या समूहीकरण कर सकते हैं। callback से **संचायक लौटाना** याद रखें, वरना अगले चरण को `undefined` मिलेगा:
```javascript
const votes = ["yes", "no", "yes"];
const tally = votes.reduce((acc, vote) => {
  acc[vote] = (acc[vote] ?? 0) + 1;
  return acc;
}, {});
console.log(tally);
// prints { yes: 2, no: 1 }
```
`acc[vote] ?? 0` मौजूदा गिनती पढ़ता है, और जब वह key अभी मौजूद नहीं है तो `0`।

---

हर फ़ंक्शन के पास `bind` मेथड होता है जो एक **नया** फ़ंक्शन लौटाता है जिसमें कुछ चीज़ें पहले से तय होती हैं। इसका पहला आर्ग्युमेंट नए फ़ंक्शन का `this` बन जाता है; बाक़ी आर्ग्युमेंट उन आर्ग्युमेंट्स से पहले रख दिए जाते हैं जिनके साथ नया फ़ंक्शन कॉल होगा (एक **आंशिक अनुप्रयोग**):
```javascript
function multiply(a, b) {
  return a * b;
}
const double = multiply.bind(null, 2);
console.log(double(21));
// prints 42
```
मेथड्स के लिए `this` तय करना मायने रखता है। जब कोई मेथड अपने ऑब्जेक्ट से बाहर निकालकर अकेले कॉल किया जाता है, तो `this` उस ऑब्जेक्ट को नहीं दर्शाता, इसलिए `this.name` `undefined` हो जाता है। `bind` उसे ऑब्जेक्ट से बाँध देता है:
```javascript
const user = {
  name: "Ana",
  hello() { return `Hi ${this.name}`; },
};
const loose = user.hello;
console.log(loose());
// prints Hi undefined
const bound = user.hello.bind(user);
console.log(bound());
// prints Hi Ana
```
मूल फ़ंक्शन कभी नहीं बदलता: `bind` हमेशा एक नया फ़ंक्शन बनाता है, जिसका `name` मूल नाम के आगे `bound ` लगाकर बनता है।

---

असली प्रोग्राम इन मेथड्स को एक **पाइपलाइन** में जोड़ते हैं: जिन एलिमेंट्स की परवाह है उन्हें छानें, उन्हें ज़रूरी मानों में बदलें, और उन्हें एक परिणाम में समेटें। बीच के array को स्थिरांकों में रखने से हर चरण पढ़ने लायक़ रहता है और उन्हें दोबारा उपयोग किया जा सकता है:
```javascript
const adults = people.filter((p) => p.age >= 18);
const names = adults.map((p) => p.name);
const totalAge = adults.reduce((sum, p) => sum + p.age, 0);
```
`names.join(", ")` स्ट्रिंग्स के array को एक ही स्ट्रिंग में बदल देता है जिसमें एलिमेंट अल्पविराम और स्पेस से अलग होते हैं।

---

क्लोज़र लौटाए गए फ़ंक्शन को कॉल्स के बीच **निजी स्थिति** बनाए रखने देते हैं। इसी तरह बना एक क्लासिक हेल्पर है `once(fn)`: यह एक ऐसा फ़ंक्शन लौटाता है जो `fn` को सिर्फ़ पहली बार कॉल होने पर चलाता है, परिणाम याद रखता है, और हर बाद की कॉल पर `fn` को दोबारा चलाए बिना वही परिणाम लौटाता है:
```javascript
let calls = 0;
const init = once(() => {
  calls += 1;
  return "ready";
});
console.log(init(), init(), calls);
// prints ready ready 1
```
रैपर को दो निजी वेरिएबल चाहिए: क्या `fn` पहले ही चल चुका है, और सहेजा गया परिणाम। दोनों क्लोज़र में रहते हैं, बाहरी दुनिया के लिए अदृश्य। रैपर के सभी आर्ग्युमेंट `fn` तक पहुँचाने के लिए रैपर को rest पैरामीटर `(...args)` के साथ घोषित करें और `fn(...args)` कॉल करें।

---

सब कुछ `groupBy(items, keyFn)` में मिल जाता है: यह एक हायर-ऑर्डर फ़ंक्शन है जिसे एक callback मिलता है जो हर एलिमेंट की **समूह key** तय करता है, और जो एक ऐसा ऑब्जेक्ट लौटाता है जिसमें हर key के साथ उस key वाले एलिमेंट्स का array जुड़ा होता है। ऑब्जेक्ट संचायक वाला `reduce` पूरा काम कर देता है:
```javascript
const byInitial = groupBy(["hi", "yo", "hey"], (w) => w[0]);
console.log(byInitial);
// prints { h: [ 'hi', 'hey' ], y: [ 'yo' ] }
```
हर एलिमेंट के लिए key निकालें, अगर उस key का array अभी नहीं है तो उसे बनाएँ (`acc[key] ?? []`), एलिमेंट जोड़ें और संचायक लौटाएँ। चूँकि `keyFn` कॉल करने वाला चुनता है, वही फ़ंक्शन शब्दों को पहले अक्षर से, लोगों को शहर से या संख्याओं को सम-विषम से समूहित कर देता है।
