**टिप्पणी** (comment) सोर्स कोड के अंदर लिखा गया एक नोट है, जो कोड पढ़ने वालों के लिए होता है। JavaScript टिप्पणियों को पूरी तरह अनदेखा कर देता है, इसलिए वे प्रोग्राम के काम को कभी नहीं बदलतीं।

सबसे सरल टिप्पणी **एकल-पंक्ति टिप्पणी** है: यह `//` से शुरू होती है और पंक्ति के अंत तक चलती है।
```javascript
// Greets the user
console.log("Hello");
```
टिप्पणियों का उपयोग यह समझाने के लिए करें कि कोड का कोई हिस्सा किसलिए है, या उसे इस तरह क्यों लिखा गया। ध्यान दें कि कुछ अन्य भाषाओं के विपरीत, JavaScript में `#` से टिप्पणी शुरू **नहीं** होती।

---

टिप्पणी को अपनी अलग पंक्ति की ज़रूरत नहीं होती: यह उसी पंक्ति में कोड के बाद आ सकती है। यह **इनलाइन टिप्पणी** (या ट्रेलिंग टिप्पणी) कहलाती है, और उस विशेष कथन के बारे में छोटा नोट लिखने के लिए यह अच्छी जगह है:
```javascript
const retries = 3; // give up after three attempts
```
`//` से पंक्ति के अंत तक सब कुछ अनदेखा कर दिया जाता है, जबकि उससे पहले का कोड सामान्य रूप से चलता है।

---

चूँकि टिप्पणियाँ अनदेखी कर दी जाती हैं, टिप्पणी जोड़ने या हटाने से प्रोग्राम का काम कभी नहीं बदलता। केवल वही कोड चलता है जो टिप्पणी में **नहीं** है।

इससे `//` कोड की एक पंक्ति को मिटाए बिना बंद करने का तेज़ तरीका बन जाता है। इसे **कमेंट आउट करना** कहते हैं:
```javascript
let total = 10;
// total = total + 5;
console.log(total); // prints 10
```
दूसरी पंक्ति अब एक टिप्पणी है, इसलिए `total` `10` ही रहता है। `//` हटाते ही वह पंक्ति फिर से जीवित हो जाती है।

प्रयोग करते समय कमेंट आउट करना सुविधाजनक है, पर सफ़ाई करना न भूलें: लंबे समय तक कमेंट किया हुआ कोड अगले पढ़ने वाले को केवल भ्रमित करता है।

---

जब किसी टिप्पणी को एक से अधिक पंक्तियाँ चाहिए, तो JavaScript **बहु-पंक्ति टिप्पणी** देता है (इसे ब्लॉक टिप्पणी भी कहते हैं): यह `/*` से शुरू होकर `*/` पर समाप्त होती है, और बीच का सब कुछ अनदेखा कर दिया जाता है, पंक्ति विराम भी।
```javascript
/*
  Prints the welcome banner.
  Called once when the app starts.
*/
console.log("Welcome!");
```
ब्लॉक टिप्पणी छोटी भी हो सकती है और एक ही पंक्ति में रह सकती है: `/* like this */`।

---

आप जिस भी प्रकार की टिप्पणी का उपयोग करें, नियम एक ही है: उसके अंदर का पाठ **कोड नहीं** है। टिप्पणी के अंदर का `console.log` कभी कुछ प्रिंट नहीं करता, और उसी पंक्ति में `//` के बाद लिखा कोड कभी नहीं चलता, भले ही पंक्ति असली कोड से शुरू होती हो:
```javascript
console.log("a"); // console.log("b");
/* console.log("c"); */
// prints only a
```
जब आपको यकीन न हो कि प्रोग्राम क्या प्रिंट करेगा, तो पहले मन ही मन हर टिप्पणी हटा दें और जो बचे उसे पढ़ें।

---

`//` के विपरीत, जो पंक्ति के अंत पर रुक जाता है, `/*` टिप्पणी केवल `*/` पर रुकती है। यदि आप इसे बंद करना भूल जाएँ, तो JavaScript आगे के सारे कोड को टिप्पणी का हिस्सा मान लेता है और सिंटैक्स त्रुटि बताता है:
```javascript
const width = 10; /* in centimetres
console.log(width); // still inside the comment: SyntaxError, the comment is never closed
```
`//` और `/* */` दोनों इनलाइन टिप्पणी के रूप में काम करते हैं, पर `/*` के साथ हमेशा सुनिश्चित करें कि `*/` मौजूद है।

---

JavaScript में ब्लॉक टिप्पणियाँ **नेस्ट नहीं की जा सकतीं**: टिप्पणी उस **पहले** `*/` पर समाप्त हो जाती है जो उसे मिलता है, चाहे उससे पहले कितने भी `/*` आए हों।
```javascript
/* outer /* inner */ still a comment */
console.log("done");
```
यहाँ टिप्पणी `inner` के तुरंत बाद समाप्त हो जाती है, इसलिए `still a comment */` को कोड की तरह पढ़ा जाता है और सिंटैक्स त्रुटि होती है। जब आप ऐसे ब्लॉक को कमेंट आउट करें जिसमें पहले से `/* */` टिप्पणी है, तो यह याद रखें: हर पंक्ति पर `//` लगाएँ, या पहले भीतरी टिप्पणी हटा दें।

---

एक साथ कई पंक्तियों को कमेंट आउट करने के लिए, हर पंक्ति पर `//` जोड़ने के बजाय उन्हें एक ही ब्लॉक टिप्पणी में लपेट दें:
```javascript
let total = 100;
/*
total = total - 30;
total = total - 20;
*/
console.log(total); // prints 100
```
चूँकि ब्लॉक के अंदर की पंक्तियाँ अनदेखी कर दी जाती हैं, `total` कभी नहीं बदलता। याद रखें कि यह तभी काम करता है जब उनमें से किसी पंक्ति में `*/` न हो।

---

JavaScript में टिप्पणी का एक तीसरा प्रकार भी है, **डॉक्युमेंटेशन टिप्पणी**, जो **JSDoc** प्रारूप में लिखी जाती है: यह `/**` (दो तारांकन) से शुरू होने वाली ब्लॉक टिप्पणी है जो सीधे किसी फ़ंक्शन के ऊपर रखी जाती है। इसके अंदर पंक्तियाँ आमतौर पर ` * ` से शुरू होती हैं और `@` से शुरू होने वाले विशेष **टैग** फ़ंक्शन का वर्णन करते हैं:
- हर पैरामीटर के लिए `@param {type} name description`
- लौटाए गए मान के लिए `@returns {type} description`

```javascript
/**
 * Returns the greeting for a person.
 * @param {string} name the name of the person
 * @returns {string} the greeting, ending with an exclamation mark
 */
function greet(name) {
  return `Hi, ${name}!`;
}
```
JavaScript के लिए यह केवल एक टिप्पणी है, पर संपादक इसे पढ़ते हैं और `greet` के सहायता पाठ के रूप में दिखाते हैं, साथ ही घुंघराले कोष्ठकों में लिखा प्रकार भी (`{number}`, `{string}`, `{boolean}`, `{number[]}`...)।

---

JSDoc टिप्पणी की पहली पंक्ति **सारांश** होती है: एक छोटा वाक्य जो बताता है कि फ़ंक्शन क्या करता है। इसे तीसरे पुरुष में लिखें, मानो फ़ंक्शन का वर्णन कर रहे हों: "Returns...", "Adds...", "Checks..."। इसके बाद टैग सूचीबद्ध करें, हर पंक्ति में एक:
```javascript
/**
 * Returns true when n is divisible by two.
 * @param {number} n the number to check
 * @returns {boolean} true for even numbers, false otherwise
 */
function isEven(n) {
  return n % 2 === 0;
}
```
टिप्पणी घोषणा के ठीक ऊपर होनी चाहिए, बीच में कोई खाली पंक्ति नहीं, अन्यथा संपादक उसे फ़ंक्शन से नहीं जोड़ते।

---

JSDoc टिप्पणी एक **अनुबंध** भी है: यह फ़ंक्शन को बुलाने वाले को बताती है कि क्या भेजना है और बदले में क्या मिलेगा, फ़ंक्शन का मुख्य भाग लिखे जाने से भी पहले। अक्सर टिप्पणी पढ़ लेना ही फ़ंक्शन को लागू करने के लिए काफ़ी होता है:
```javascript
/**
 * Returns the larger of two numbers.
 * @param {number} a the first number
 * @param {number} b the second number
 * @returns {number} a if it is greater than b, otherwise b
 */
function larger(a, b) {
  return a > b ? a : b;
}
```
हर `@param` उसी क्रम में एक पैरामीटर से मेल खाता है, और `@returns` हर संभव परिणाम का वर्णन करता है।

---

JSDoc टिप्पणी के अंदर क्रम हमेशा एक जैसा होता है: पहले सारांश, फिर हर पैरामीटर के लिए एक `@param` उसी क्रम में जिसमें वे घोषित हैं, और अंत में `@returns`। शुरुआती `/**` और समापन ` */` सब कुछ लपेटते हैं, और टिप्पणी उसी फ़ंक्शन के ठीक ऊपर बैठती है जिसका वह वर्णन करती है:
```javascript
/**
 * Returns the number of seconds in the given minutes.
 * @param {number} minutes a whole number of minutes
 * @returns {number} minutes multiplied by sixty
 */
function toSeconds(minutes) {
  return minutes * 60;
}
```

---

एक JavaScript फ़ाइल एक विशेष पंक्ति से शुरू हो सकती है जिसे **शेबैंग** (या हैशबैंग) कहते हैं: `#!` के बाद उस प्रोग्राम का पथ जो फ़ाइल को चलाएगा। यूनिक्स जैसी प्रणालियों पर यह आपको टर्मिनल से सीधे स्क्रिप्ट चलाने देता है, जैसे `./hello.js`, बिना पहले `node` टाइप किए:
```javascript
#!/usr/bin/env node
console.log("Hello from Node");
```
JavaScript इस पंक्ति को बिल्कुल एक टिप्पणी की तरह अनदेखा करता है, पर केवल तभी जब यह फ़ाइल की **सबसे पहली पंक्ति** हो: कहीं और `#!` एक सिंटैक्स त्रुटि है। `/usr/bin/env node` का अर्थ है "इस प्रणाली पर `node` खोजो और उसका उपयोग करो"।

---

एक अच्छी टिप्पणी बताती है कि कोड कुछ **क्यों** करता है, न कि वह **क्या** करता है। कोड पहले ही दिखा देता है कि क्या होता है; उसे शब्दों में दोहराने से शोर बढ़ता है और कोड बदलते ही वह पुरानी पड़ जाती है:
```javascript
// set timeout to 30
const timeout = 30;
```
उस संख्या के पीछे का कारण ही वह चीज़ है जिसका पाठक अनुमान नहीं लगा सकता:
```javascript
// the server drops idle connections after 35 seconds, so stop earlier
const timeout = 30;
```
यदि कोई टिप्पणी केवल नीचे की पंक्ति दोहराती है, तो उसे हटा दें या उसकी जगह कारण लिखें।

---

कुछ टिप्पणियाँ एक ऐसी परंपरा का पालन करती हैं जिसे संपादक समझते हैं। सबसे आम **चिह्न** ये हैं:
- `// TODO: ...` उस काम को दर्शाता है जो अभी लिखा जाना बाकी है
- `// FIXME: ...` उस कोड को दर्शाता है जिसके ग़लत होने की जानकारी है और जिसे ठीक करना ज़रूरी है

```javascript
const limit = 10;
// TODO: read the limit from the settings
// FIXME: crashes when the list is empty
```
JavaScript के लिए ये साधारण टिप्पणियाँ हैं; संपादक इन्हें सूचीबद्ध करते हैं ताकि बाकी बचा काम आसानी से मिल जाए। `TODO` आमतौर पर एक अस्थायी कोड के पास होता है जो असली कार्यान्वयन लिखे जाने तक कोड को चलता रखता है। जब आप काम पूरा कर लें, तो उसी बदलाव में अस्थायी कोड बदलें और चिह्न हटा दें: पुराना पड़ा `TODO` भ्रामक होता है।

---

`FIXME` `TODO` से अलग है: कोड पहले से मौजूद है, पर यह जानकारी है कि वह ग़लत है। एक अच्छा `FIXME` बताता है कि बग क्या है और, जहाँ संभव हो, एक उदाहरण भी देता है जो उसे दिखाता है, ताकि अगला व्यक्ति उसे जल्दी ठीक कर सके। `TODO` की तरह ही, बग ठीक हो जाने पर चिह्न हटा दें, पर JSDoc टिप्पणी बनाए रखें, जो अब भी सही है।
