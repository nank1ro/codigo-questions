# --description--

आगे कोई टाइप न होने वाला `except:` एक **bare except** है। यह हर चीज़ से मैच करता है, जिनमें वे अपवाद भी शामिल हैं जिनका उस क्रिया से कोई लेना-देना नहीं जिसे आप संभाल रहे थे, इसलिए नियम सीधा है: हमेशा उन्हीं टाइप्स का नाम लें जिनसे आप सच में उबर सकते हैं।

# --instructions--

यह कोड bare `except:` का उपयोग करने के बजाय किसी विशिष्ट अपवाद टाइप का नाम क्यों लेना चाहिए?
```python
try:
    total = int(amout)
except:
    total = 0
```

# --answers--

- क्योंकि bare `except:` असंबंधित फेल होने भी पकड़ लेता है, जैसे गलत स्पेलिंग वाले `amout` से पैदा हुआ `NameError`, तब असली बग चुपचाप `total = 0` बन जाता है
- क्योंकि bare `except:` धीमा होता है, क्योंकि Python को अपवाद की तुलना हर बिल्ट-इन क्लास से करनी पड़ती है
- क्योंकि bare `except:` केवल मॉड्यूल लेवल पर काम करता है और फंक्शन के अंदर `SyntaxError` उत्पन्न करता है
- क्योंकि bare `except:` कुछ भी नहीं पकड़ता, ताकि ब्लॉक खत्म होते ही अपवाद दोबारा उत्पन्न हो जाता है
