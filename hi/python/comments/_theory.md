एक **कमेंट** सोर्स कोड के अंदर लिखा गया एक नोट होता है, जो उसे पढ़ने वाले लोगों के लिए होता है। Python कमेंट्स को पूरी तरह अनदेखा कर देता है, इसलिए वे कभी भी प्रोग्राम के काम को नहीं बदलते।

Python का एकमात्र कमेंट प्रकार **सिंगल-लाइन कमेंट** है: यह `#` से शुरू होकर लाइन के अंत तक चलता है।
```python
# उपयोगकर्ता का अभिवादन करता है
print("Hello")
```
किसी कोड का उद्देश्य क्या है, या वह इस तरह क्यों लिखा गया, यह समझाने के लिए कमेंट्स का उपयोग करें।

---

कमेंट को अपनी अलग लाइन की ज़रूरत नहीं होती: यह उसी लाइन पर कोड के बाद आ सकता है। इसे **इनलाइन कमेंट** कहते हैं, और यह उस विशेष स्टेटमेंट के बारे में छोटा नोट लिखने की अच्छी जगह है:
```python
retries = 3  # तीन कोशिशों के बाद हार मान लें
```
`#` से लाइन के अंत तक की सब कुछ अनदेखा कर दिया जाता है, जबकि उससे पहले का कोड सामान्य रूप से चलता है।

Python की स्टाइल गाइड, **PEP 8**, यहाँ थोड़ी स्पेसिंग माँगती है: कोड और `#` के बीच कम से कम **दो स्पेस**, और `#` के बाद **एक स्पेस**। अपनी अलग लाइन पर लिखे कमेंट को केवल `#` के बाद की स्पेस चाहिए।

---

क्योंकि Python कमेंट्स को पूरी तरह हटा देता है, कमेंट जोड़ने या हटाने से प्रोग्राम के काम में कभी बदलाव नहीं आता। केवल वही कोड चलता है जो कमेंट **नहीं** किया गया है।

इसी वजह से `#` किसी कोड की लाइन को उसे हटाए बिना बंद करने का एक तेज़ तरीका है। इसे **कमेंट आउट करना** कहते हैं:
```python
total = 10
# total = total + 5
print(total)  # 10 प्रिंट करता है
```
दूसरी लाइन अब एक कमेंट है, इसलिए `total` `10` ही रहता है। `#` हटाने पर वह लाइन वापस जीवित हो जाती है।

कमेंट आउट करना प्रयोग करते समय सुविधाजनक है, लेकिन सफ़ाई करना याद रखें: लंबे समय तक कमेंट आउट पड़ा कोड आगे इसे पढ़ने वाले को केवल उलझाता है।

---

कई भाषाओं में दूसरे प्रकार का कमेंट होता है, एक **ब्लॉक कमेंट** जो कई लाइनों तक फैला होता है, जैसे `/* ... */`। Python में ऐसा कोई सिंटैक्स नहीं है: `#` ही सब कुछ है।

जब किसी समझाने के लिए एक से अधिक लाइन चाहिए, तो हर लाइन के आगे एक `#` लगाएँ:
```python
# स्वागत बैनर प्रिंट करता है।
# ऐप शुरू होने पर एक बार कॉल होता है।
print("Welcome!")
```
वही तरीका एक साथ कई लाइनों के कोड को कमेंट आउट करता है: हर लाइन पर एक `#`। हर एडिटर एक ही शॉर्टकट से चुने हुए पूरे हिस्से के लिए वे `#` जोड़ या हटा सकता है, इसलिए यह जितना लगता है उससे कम काम है।

---

आप अक्सर एक **ट्रिपल-कोटेड स्ट्रिंग** को ब्लॉक कमेंट की तरह उपयोग होते देखेंगे:
```python
"""
This looks like a comment,
but it is a string.
"""
print("done")
```
`"""` और `"""` के बीच की स्ट्रिंग कई लाइनों तक फैल सकती है, और अकेले लिखी स्ट्रिंग एक वैध स्टेटमेंट है: Python उसे बनाता है, उसके साथ कुछ नहीं करता और उसे फेंक देता है। कुछ भी प्रिंट नहीं होता, इसलिए नतीजा एक कमेंट जैसा दिखता है।

यह वह नहीं है। यह एक स्ट्रिंग लिटरल है, इसलिए कोटिंग के नियम लागू रहते हैं: इसके अंदर असंतुलित कोट या अतिरिक्त `"""` प्रोग्राम तोड़ देता है, जबकि `#` कमेंट के अंदर कुछ भी चलता है। यह गलती से docstring भी बन सकती है अगर वह किसी फ़ाइल, क्लास या फंक्शन का पहला स्टेटमेंट बन जाए। बाकी हर जगह वह बस कहीं नहीं जाती: CPython कंपाइल करते समय पूरा स्टेटमेंट फेंक देता है।

इसलिए, कोड को बंद करने के लिए `#` का उपयोग करें। ट्रिपल-कोटेड स्ट्रिंग का अपना काम है, जिसकी शुरुआत अगले एक्सरसाइज़ में होती है।

---

जब कोई स्ट्रिंग किसी फंक्शन के अंदर **पहला स्टेटमेंट** होती है, तो Python उसे उस फंक्शन का डॉक्यूमेंटेशन मानता है। इसे **docstring** कहते हैं:
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"
```
परंपरा के अनुसार docstring ट्रिपल डबल कोट्स, `"""`, के बीच लिखी जाती है, तब भी जब वह एक लाइन में समा जाए, ताकि बाद में कोट्स बदले बिना वह बढ़ सके।

समरी को तीसरे पुरुष में लिखें, मानो फंक्शन का वर्णन कर रहे हों: "Returns...", "Adds...", "Checks..."। docstring बॉडी के किसी भी दूसरे स्टेटमेंट से पहले आनी चाहिए, अन्यथा वह सिर्फ़ एक साधारण स्ट्रिंग है।

---

docstring फेंकी नहीं जाती: Python उसे फंक्शन के `__doc__` एट्रिब्यूट में संग्रहीत करता है, ताकि प्रोग्राम चलते समय अपना डॉक्यूमेंटेशन पढ़ सके:
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"

print(greet.__doc__)  # name के लिए अभिवादन लौटाता है।
```
जब किसी फंक्शन की docstring नहीं होती, तो `__doc__` `None` होता है। `help(greet)` यही प्रिंट करता है, और एडिटर भी नाम पर होवर करने पर यही दिखाता है।

---

एक फ़ाइल को भी डॉक्यूमेंट किया जा सकता है। **फ़ाइल के बिल्कुल पहले स्टेटमेंट** के रूप में लिखी स्ट्रिंग, किसी भी import या परिभाषा से पहले, **मॉड्यूल docstring** होती है: वह बताती है कि पूरी फ़ाइल किस काम के लिए है।
```python
"""Tools for working with rectangles."""

def area(width, height):
    """Returns the area of a rectangle."""
    return width * height
```
केवल पहला स्टेटमेंट गिना जाता है। एक कमेंट उसके ऊपर हो सकता है, लेकिन बीच में कोई भी असली कोड स्ट्रिंग को वापस एक साधारण, बेकार स्ट्रिंग बना देता है।

---

क्लासेस भी वैसे ही काम करते हैं: क्लास बॉडी के पहले स्टेटमेंट के रूप में रखी गई स्ट्रिंग उस क्लास की docstring होती है, और वह `__doc__` में संग्रहीत रहती है:
```python
class Point:
    """A point on a grid."""

    def __init__(self, x, y):
        self.x = x
        self.y = y

print(Point.__doc__)  # A point on a grid.
```
क्लास के अंदर हर मेथड की अपनी docstring भी हो सकती है, जिसे `Point.__init__.__doc__` से पढ़ा जाता है। इसलिए docstring स्वीकार करने वाली तीन जगहें हैं: मॉड्यूल का शीर्ष, क्लास का शीर्ष और फंक्शन का शीर्ष।

---

Docstrings और `#` कमेंट्स एक जैसे दिखते हैं लेकिन अलग-अलग सवालों के जवाब देते हैं।

**docstring** उनके लिए है जो कोड को **उपयोग** करते हैं: फंक्शन क्या करता है, क्या अपेक्षा रखता है और क्या वापस देता है। वह `__doc__` में बची रहती है, `help()` उसे पढ़ता है, एडिटर उसे दिखाते हैं, और डॉक्यूमेंटेशन टूल उसे इकट्ठा करते हैं।

**कमेंट** उनके लिए है जो कोड को **पढ़ते** हैं: यह लाइन इस तरह क्यों लिखी गई है, वह अजीब संख्या क्या दर्शाती है, वह किस बग के इर्द-गिर्द काम करती है। वह केवल सोर्स फ़ाइल में मौजूद होती है और प्रोग्राम चलते ही गायब हो जाती है।

```python
def timeout():
    """Returns the number of seconds to wait for the server."""
    # सर्वर 35 सेकंड बाद निष्क्रिय कनेक्शन हटा देता है
    return 30
```
यानी: फंक्शन का डॉक्यूमेंटेशन docstring में जाता है, इम्प्लीमेंटेशन के बारे में नोट्स कमेंट्स में जाते हैं।

---

जब एक लाइन काफ़ी न हो, तो docstring एक निश्चित लेआउट में बदल जाती है, जिसे **PEP 257** में बताया गया है: एक लाइन की समरी, एक खाली लाइन, फिर विवरण, और बंद करने वाला `"""` अपनी अलग लाइन पर।
```python
def to_seconds(minutes):
    """Returns the number of seconds in the given minutes.

    minutes is a whole number and is never negative.
    """
    return minutes * 60
```
खाली लाइन मायने रखती है: टूल पहली लाइन को अकेले, एक छोटे विवरण की तरह दिखाते हैं, और बाकी को उनके लिए रखते हैं जो और पढ़ना चाहें।

---

docstring को **बॉडी की पहली लाइन** होना चाहिए, हर दूसरे स्टेटमेंट के ऊपर। `return` के बाद, या बॉडी में कहीं और लिखी स्ट्रिंग सिर्फ़ एक स्ट्रिंग है: `__doc__` `None` ही रहता है और कोई टूल उसे कभी नहीं दिखाएगा।

---

कुछ कमेंट्स एक ऐसी परंपरा का पालन करते हैं जिसे एडिटर समझते हैं। सबसे आम **मार्कर** ये हैं:
- `# TODO: ...` उस चीज़ को चिह्नित करता है जिसे अभी लिखा जाना बाकी है
- `# FIXME: ...` उस कोड को चिह्नित करता है जो ज्ञात रूप से ग़लत है और ठीक किया जाना चाहिए

```python
limit = 10
# TODO: लिमिट को सेटिंग्स से पढ़ें
```
Python के लिए ये सामान्य कमेंट्स हैं; एडिटर इन्हें एक अलग पैनल में सूचीबद्ध करते हैं, ताकि बचा हुआ काम आसानी से मिल जाए। एक `TODO` आमतौर पर एक प्लेसहोल्डर के पास होता है जो असली कोड लिखे जाने तक प्रोग्राम को चलता रखता है।

जब आप काम पूरा कर लें, तो उसी बदलाव में प्लेसहोल्डर बदलें और मार्कर हटा दें, ताकि कमेंट कोड की स्थिति के बारे में कभी झूठ न बोले।

---

फंक्शन के ऊपर यह बताने के लिए रखा कमेंट कि फंक्शन क्या करता है, गलत जगह पर होता है। उसके लिए सही जगह docstring है: वह फंक्शन से जुड़ी होती है, `help()` उसे ढूंढता है और एडिटर उसे दिखाते हैं, जबकि `def` के ऊपर का `#` कमेंट इन सबके लिए अदृश्य होता है।

```python
# a और b जोड़ता है
def add(a, b):
    return a + b
```
उसी वाक्य को एक लाइन नीचे, ट्रिपल कोट्स के बीच रखने से वह असली डॉक्यूमेंटेशन बन जाता है:
```python
def add(a, b):
    """Returns the sum of a and b."""
    return a + b
```

---

Python `#` को केवल कोड में ढूंढता है, कभी भी **स्ट्रिंग** के अंदर नहीं। कोट्स के बीच `#` एक साधारण अक्षर है:
```python
print("black is #000000")  # a hex colour
```
पहला `#` टेक्स्ट का हिस्सा है, दूसरा एक असली कमेंट शुरू करता है। वही बात `#` कमेंट के अंदर `"""` पर भी लागू होती है: वहाँ वह बस तीन कोट अक्षर हैं, और कुछ शुरू नहीं करती।

---

एक अच्छा कमेंट यह बताता है कि कोड कोई काम **क्यों** करता है, **क्या** करता है नहीं। कोड पहले से दिखा देता है कि क्या होता है; उसे शब्दों में दोहराना शोर जोड़ता है और कोड बदलते ही वह पुराना पड़ जाता है:
```python
# timeout को 30 सेट करता है
timeout = 30
```
संख्या के पीछे का कारण ही वह चीज़ है जिसका अंदाज़ा पाठक नहीं लगा सकता:
```python
# सर्वर 35 सेकंड बाद निष्क्रिय कनेक्शन हटा देता है, इसलिए पहले ही रोक दें
timeout = 30
```
अगर कोई कमेंट सिर्फ़ अपने नीचे की लाइन को दोहराता है, तो उसे हटा दें या उसे कारण से बदल दें। सबसे अच्छे कमेंट वे हैं जो कुछ ऐसा बताते हैं जो कोड नहीं बता सकता।
