तुलना ऑपरेटर दो मानों की तुलना करते हैं और एक **बूलियन** लौटाते हैं, `True` या `False`: `==` बराबर, `!=` बराबर नहीं, `<` से छोटा, `>` से बड़ा, `<=` से छोटा या बराबर, `>=` से बड़ा या बराबर:
```python
age = 18
print(age == 18)  # True
print(age != 18)  # False
print(age < 18)   # False
print(age >= 18)  # True
```
परिणाम को किसी वेरिएबल में संग्रहीत किया जा सकता है या सीधे प्रदर्शित किया जा सकता है। एक अकेला `=` असाइनमेंट है, तुलना नहीं।

---

तुलना ऑपरेटर केवल संख्याओं तक सीमित नहीं हैं। स्ट्रिंग्स की तुलना उनके कोड पॉइंट्स का उपयोग करके अक्षर दर अक्षर की जाती है, इसलिए `"apple" < "banana"` `True` है और, क्योंकि हर बड़ा अक्षर छोटे अक्षरों से पहले आता है, `"Zoo" < "apple"` भी `True` है। लिस्ट और टपल की तुलना उसी तरह तत्व दर तत्व की जाती है:
```python
print("cat" < "dog")       # True
print([1, 2, 3] < [1, 3])  # True
print((1, 2) == (1, 2))    # True
```
तुलना एक एक्सप्रेशन है, इसलिए कोई फ़ंक्शन उसे `if` में लपेटने के बजाय सीधे `return a < b` कर सकता है।

---

तुलनाओं को **श्रृंखलाबद्ध** किया जा सकता है: `1 < x < 10` जाँचता है कि `x` `1` से बड़ा **और** `10` से छोटा है, ठीक `1 < x and x < 10` की तरह, लेकिन `x` का मूल्यांकन केवल एक बार होता है:
```python
x = 5
print(1 < x < 10)   # True
print(1 < x <= 5)   # True
print(10 < x < 20)  # False
```
किसी भी तुलना ऑपरेटर को श्रृंखलाबद्ध किया जा सकता है और हर एक अपने दोनों पड़ोसियों पर लागू होता है: `a < b == c` का अर्थ है `a < b and b == c`। श्रृंखला को एक रेंज `low < x < high` की तरह पढ़ना सबसे आम उपयोग है।

---

लॉजिकल ऑपरेटर बूलियन को जोड़ते हैं। `and` केवल तभी `True` होता है जब दोनों पक्ष `True` हों, `or` तब जब कम से कम एक पक्ष `True` हो, और `not` एक अकेले मान को उलट देता है:
```python
age = 20
member = False
print(age >= 18 and member)  # False
print(age >= 18 or member)   # True
print(not member)            # True
```
तुलनाओं की प्राथमिकता लॉजिकल ऑपरेटरों से अधिक होती है, इसलिए `age >= 18 and member` को कोष्ठकों की आवश्यकता नहीं है। `and` के अंदर `or` को समूहबद्ध करने के लिए कोष्ठक आवश्यक हैं: `a and (b or c)`।

---

जब `not`, `and` और `or` एक ही एक्सप्रेशन में आते हैं, तो Python पहले `not` लागू करता है, फिर `and`, फिर `or`। इसलिए `a or b and c` का अर्थ है `a or (b and c)`, और `not a == b` का अर्थ है `not (a == b)`:
```python
x = 6
print(x == 6 or x < 10 and x > 100)  # True: x == 6 or (False)
print(not x == 6)                    # False
```
जब कोई अलग समूहन अभीष्ट हो, तो कोष्ठक जोड़ें; वे एक्सप्रेशन को पढ़ने में भी आसान बनाते हैं।

---

हर मान का एक **सत्य मान** होता है। `bool(value)` `0`, `0.0`, `None`, खाली स्ट्रिंग `""` और `[]`, `{}` तथा `set()` जैसे खाली कंटेनरों के लिए `False` लौटाता है; बाकी हर मान सत्य है, जिसमें `"0"` और `[0]` भी शामिल हैं:
```python
print(bool(0), bool(""), bool(None))   # False False False
print(bool(42), bool("0"), bool([0]))  # True True True
```
`if`, `while`, `and`, `or` और `not` इसी नियम का उपयोग करते हैं, इसलिए `if items:` जाँचता है कि लिस्ट खाली नहीं है और `not name` जाँचता है कि स्ट्रिंग खाली है; `len(items) > 0` या `name == ""` लिखने की आवश्यकता नहीं है।

---

चूँकि `if value:` पहले से ही सत्य मान लागू करता है, `== True` या `== False` से तुलना करना अनावश्यक है और ग़लत भी हो सकता है: `2 == True` `False` है, फिर भी `2` सत्य है। मान की स्वयं जाँच करें:
```python
values = [0, 1, "", "a", None, [], [0]]
for value in values:
    if value:
        print(value)  # 1, a, [0]
```

---

`and` और `or` हमेशा `True` या `False` नहीं लौटाते: वे अपने **ऑपरेंड** में से एक लौटाते हैं। `a and b` `a` लौटाता है यदि वह असत्य है, अन्यथा `b`; `a or b` `a` लौटाता है यदि वह सत्य है, अन्यथा `b`:
```python
print(0 and "x")       # 0
print(3 and "x")       # x
print("" or "none")    # none
print("hi" or "none")  # hi
```
परिणाम ठीक तभी सत्य या असत्य होता है जब पूरा एक्सप्रेशन होता है, इसीलिए `if a and b:` फिर भी काम करता है। एक आम उपयोग डिफ़ॉल्ट मान है: `name = user_input or "guest"`।

---

लॉजिकल ऑपरेटर **शॉर्ट-सर्किट** होते हैं: `and` तभी रुक जाता है जब कोई ऑपरेंड असत्य हो और `or` तभी जब कोई सत्य हो, क्योंकि परिणाम पहले से ही ज्ञात होता है। बचे हुए ऑपरेंड का मूल्यांकन कभी नहीं होता, इसलिए यदि वे फ़ंक्शन कॉल हैं तो वे चलते नहीं हैं:
```python
def check(n):
    print("checking", n)
    return n > 0

check(-1) and check(5)  # prints only "checking -1"
check(2) or check(-3)   # prints only "checking 2"
```

---

`==` **मानों** की तुलना करता है; `is` **पहचान** की तुलना करता है, यानी कि क्या दोनों नाम बिल्कुल एक ही ऑब्जेक्ट को संदर्भित करते हैं। अलग-अलग बनाई गई दो बराबर लिस्ट `==` होती हैं पर `is` नहीं:
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` `None`, `True` और `False` जैसे सिंगलटन के लिए है: `value is None` या `value is not None` लिखें, कभी `value == None` नहीं, क्योंकि कोई क्लास `==` को कुछ भी लौटाने के लिए परिभाषित कर सकती है। संख्याओं या स्ट्रिंग्स के साथ `is` का उपयोग अविश्वसनीय है और Python इसकी चेतावनी देता है।

---

शॉर्ट-सर्किट मूल्यांकन उस ऑपरेशन को **सुरक्षित करने** का एक सुरक्षित तरीका है जो कुछ मानों पर विफल हो जाएगा। `word is not None and len(word) < 4` में, `len(word)` केवल तभी चलता है जब `word` `None` नहीं होता, इसलिए कॉल कभी त्रुटि नहीं उठाती। सुरक्षा जाँच पहले आनी चाहिए:
```python
def is_short(word):
    return word is not None and len(word) < 4

print(is_short(None))   # False
print(is_short("cat"))  # True
```
ध्यान रखें कि `and` एक ऑपरेंड लौटाता है: `word and len(word) < 4` `None` के लिए `None` और खाली स्ट्रिंग के लिए `""` देता है, `False` नहीं। जब बूलियन आवश्यक हो तो एक वास्तविक तुलना से सुरक्षित करें।

---

`in` ऑपरेटर **सदस्यता** की जाँच करता है: क्या कोई तत्व किसी लिस्ट, टपल या सेट में है, क्या कोई सबस्ट्रिंग किसी स्ट्रिंग में है, या क्या कोई कुंजी किसी डिक्शनरी में है। `not in` इसका निषेध है:
```python
fruits = ["apple", "pear"]
print("pear" in fruits)          # True
print("kiwi" not in fruits)      # True
print("ex" in "text")            # True
print("age" in {"name": "Ada"})  # False, only keys are checked
```
दोनों एक बूलियन लौटाते हैं और अंग्रेज़ी की तरह पढ़े जाते हैं, जो उन्हें लूप लिखने के बजाय सदस्यता जाँचने का पसंदीदा तरीका बनाता है।
