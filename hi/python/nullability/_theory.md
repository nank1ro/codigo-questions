कभी-कभी किसी वेरिएबल के पास रखने को अभी **कोई मान नहीं** होता: एक यूज़र जिसने अभी लॉग इन नहीं किया, एक सर्च जिसे कुछ नहीं मिला, एक सेटिंग जो कभी चुनी ही नहीं गई। Python इसे विशेष मान `None` से दर्शाता है।
`None` किसी भी दूसरे मान की तरह एक मान है: आप इसे असाइन कर सकते हैं, प्रिंट कर सकते हैं और फंक्शनों को पास कर सकते हैं। इसका टाइप `NoneType` है, और पूरे प्रोग्राम में ठीक **एक** ही `None` होता है, इसलिए आपके द्वारा लिखा गया हर `None` उसी ऑब्जेक्ट को रेफर करता है:
```python
winner = None
print(winner)                 # None
print(type(winner).__name__)  # NoneType
print(winner is None)         # True
```
`None` `0` नहीं है, खाली स्ट्रिंग नहीं है और न ही `False` है: यह एक अलग मान है जिसका मतलब है "यहाँ कुछ नहीं"।

---

हर फंक्शन कॉल एक मान पैदा करता है, तब भी जब फंक्शन कुछ लौटाता नहीं दिखता। **कोई** `return` स्टेटमेंट न रखने वाला फंक्शन, या खाली (bare) `return` रखने वाला फंक्शन, `None` लौटाता है:
```python
def say_hello():
    print("hello")

result = say_hello()
print(result)  # None
```
इसीलिए `print(my_list.append(3))` को कॉल करने पर `None` दिखता है: `append` लिस्ट को उसी जगह (in place) बदल देता है और कुछ भी लौटाता नहीं।
जो फंक्शन केवल कोई क्रिया करता है (प्रिंट करना, सेव करना, लिस्ट बदलना), वह आम तौर पर `None` लौटाता है, जबकि जो फंक्शन कुछ कैलकुलेट करता है उसे उसे साफ़ तौर पर `return` करना चाहिए।

---

यह जाँचने के लिए कि कोई वेरिएबल `None` रखता है या नहीं, `is` और `is not` का उपयोग करें, कभी भी `==` नहीं:
```python
if user is None:
    print("nobody logged in")
if user is not None:
    print("welcome")
```
`==` पूछता है "क्या ये मान *बराबर* हैं?", और कोई भी क्लास `__eq__` मेथड परिभाषित करके इस सवाल का अपने तरीके से जवाब दे सकती है। `is` पूछता है "क्या ये *एक ही ऑब्जेक्ट* हैं?", और इसका जवाब कुछ भी नहीं बदल सकता।
चूँकि `None` केवल एक ही होता है, `is None` हमेशा सही और थोड़ा तेज़ होता है, जबकि `== None` कस्टम `__eq__` वाले ऑब्जेक्ट्स के लिए चौंकाने वाला जवाब दे सकता है।

---

`None` एक कंडीशन में **false** गिना जाता है, इसलिए `if not value:` तब `True` होता है जब `value`, `None` हो। इसे `None` जाँच की तरह इस्तेमाल करना आकर्षक लगता है, लेकिन वही टेस्ट `0`, `""`, `[]` और हर दूसरे खाली मान के लिए भी `True` होता है:
```python
count = 0
if not count:
    print("missing?")   # printed, but 0 is a real value!
```
जब "कोई मान नहीं" और "खाली मान" को अलग-अलग ट्रीट करना हो, तो पहले `is None` जाँचें, फिर truthiness:
```python
if count is None:
    print("no count yet")
elif not count:
    print("count is zero")
```
`if not value:` का उपयोग केवल तब करें जब आप सच में `None` और खाली मानों को एक जैसा ट्रीट करना चाहते हों।

---

एक पैरामीटर में **डिफ़ॉल्ट मान** हो सकता है, जिसका उपयोग तब होता है जब कॉलर आर्ग्युमेंट छोड़ देता है। "प्रोवाइड नहीं किया गया" के लिए `None` आम डिफ़ॉल्ट है:
```python
def greet(name=None):
    if name is None:
        name = "stranger"
    print("Hello, " + name)

greet()       # Hello, stranger
greet("Ada")  # Hello, Ada
```
यह लिस्टों और डिक्शनरीज़ के लिए मायने रखता है। एक डिफ़ॉल्ट का मूल्यांकन **एक बार** होता है, जब फंक्शन परिभाषित होता है, इसलिए `def add(item, items=[])` उन हर कॉल में वही लिस्ट शेयर करता है जो `items` छोड़ देती हैं, और आइटम जमा होते जाते हैं। समाधान यह है कि डिफ़ॉल्ट `None` रखें और फंक्शन के अंदर एक नई लिस्ट बनाएं:
```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

---

डिक्शनरी से `[]` के साथ कोई मौजूद न होने वाली कुंजी पढ़ने पर `KeyError` उठता है। `get` मेथड सुरक्षित विकल्प है: जब कुंजी मौजूद होती है तो वह मान लौटाता है और न होने पर `None`:
```python
ages = {"Ada": 36}
print(ages.get("Ada"))    # 36
print(ages.get("Grace"))  # None
```
`get` एक दूसरा आर्ग्युमेंट स्वीकार करता है, जो कुंजी मौजूद न होने पर `None` के **बजाय** लौटाया जाने वाला मान है:
```python
print(ages.get("Grace", 0))  # 0
```
रोज़मर्रा के कोड में `None` इसी तरह सबसे अक्सर सामने आता है: एक लुकअप जिसे कुछ नहीं मिला।

---

जो फंक्शन कोई संख्या **या** `None` लौटाता है, उसे यह अपनी सिग्नेचर में बताना चाहिए। एक **type hint** एक एनोटेशन है जो अपेक्षित टाइप को दर्शाता है: पैरामीटर के लिए `name: str` और रिटर्न वैल्यू के लिए `-> int`। Python हिंट्स को फ़ोर्स नहीं करता, लेकिन एडिटर्स और पाठक उन पर भरोसा करते हैं:
```python
def parse_age(text: str) -> int | None:
    if text.isdigit():
        return int(text)
    return None
```
`int | None` का मतलब है "एक `int` या `None`"। `typing` मॉड्यूल की पुरानी वर्तनी `Optional[int]` बिल्कुल वही बात कहती है, और आप इसे मौजूदा कोड में अब भी मिलेगी।
जब भी आप सिग्नेचर में `| None` देखें, उसे उपयोग करने से पहले रिज़ल्ट की जाँच करना याद रखें।

---

जो फंक्शन `None` प्राप्त कर सकते हैं वे अक्सर एक **guard** के साथ शुरू होते हैं: एक `if` जो जल्दी लौट जाता है जब काम करने को कुछ नहीं होता। फंक्शन का बाकी हिस्सा तब मान सकता है कि मान मौजूद है, सब कुछ एक `else` के अंदर नेस्ट किए बिना:
```python
def shout(text):
    if text is None:
        return None
    return text.upper() + "!"
```
Guard पहले आते हैं, उसी क्रम में जिस क्रम में जाँचें होनी चाहिए: `text.split()` को कॉल करना संभव नहीं है इससे पहले कि आप जान लें कि `text`, `None` नहीं है।

---

`or` ऑपरेटर `True` या `False` लौटाता नहीं है: वह अपना **बायाँ** ऑपरेंड लौटाता है जब वह true हो, और अन्यथा अपना **दायाँ** ऑपरेंड। इससे फ़ॉलबैक देने का एक एक-लाइन का तरीका मिलता है:
```python
name = None
print(name or "anonymous")  # anonymous
name = "Ada"
print(name or "anonymous")  # Ada
```
बात यह है कि `or` truthiness देखता है, `None` नहीं: `0`, `""` और `[]` भी फ़ॉलबैक से बदल दिए जाते हैं। `x or fallback` का उपयोग केवल तब करें जब हर खाली मान को भी फ़ॉलबैक बनना चाहिए।

---

जब `0` या `""` को रखना हो और केवल `None` को बदलना हो, तो फ़ॉलबैक को साफ़ तौर पर लिखी गई एक `is None` जाँच चाहिए। कॉम्पैक्ट रूप **conditional expression** है, `a if condition else b`, जो कंडीशन true होने पर `a` का मूल्यांकन करता है और अन्यथा `b` का:
```python
timeout = 0
seconds = timeout if timeout is not None else 30
print(seconds)  # 0, not 30
```

---

एक लिस्ट में असली मानों के बगल में `None` हो सकता है, जैसे वे रीडिंग्स जो फेल हो गईं या वे जवाब जो छोड़ दिए गए। ज़्यादातर ऑपरेशन इसे स्वीकार नहीं करते: `sum([8, None])` एक `TypeError` उठाता है।
`None` मानों को एक list comprehension से फ़िल्टर करें जिसकी कंडीशन `is not None` हो:
```python
readings = [3, None, 5]
valid = [r for r in readings if r is not None]
print(valid)  # [3, 5]
```
इसकी जगह `if r` लिखने पर हर `0` भी छूट जाएगा, इसलिए जब शून्य एक मान्य रीडिंग हो तो साफ़ तौर पर लिखें।

---

लुकअप के बाद एक `None` जाँच आम तौर पर दो लाइनें लेती है: एक रिज़ल्ट स्टोर करने के लिए, एक उसे टेस्ट करने के लिए। **assignment expression** ऑपरेटर `:=`, जिसे *walrus* के नाम से जाना जाता है, एक एक्सप्रेशन के **अंदर** मान असाइन करता है, ताकि दोनों कदम `if` में समा जाएँ:
```python
ages = {"Ada": 36}
if (age := ages.get("Ada")) is not None:
    print(age + 1)  # 37
```
कोष्ठक ज़रूरी हैं: उनके बिना `:=` पूरी तुलना को असाइन करने की कोशिश करेगा। `if` के बाद `age` किसी भी दूसरे वेरिएबल की तरह उपलब्ध रहता है।

---

हर "not found" `None` के साथ रिपोर्ट नहीं होता। कुछ पुराने फंक्शन इसकी जगह एक **sentinel** मान लौटाते हैं, एक सामान्य मान जिसे विशेष मतलब दे दिया जाता है। स्ट्रिंग मेथड `find` एक सबस्ट्रिंग का इंडेक्स लौटाता है, या `-1` जब वह मौजूद न हो:
```python
print("banana".find("n"))  # 2
print("banana".find("x"))  # -1
```
`re` मॉड्यूल का फंक्शन `re.match(pattern, text)` जाँचता है कि क्या `text`, `pattern` से शुरू होता है, और एक match ऑब्जेक्ट लौटाता है, या `None` जब मैच न हो।
`None` अधिक सुरक्षित परंपरा है: `-1` एक मान्य इंडेक्स है, इसलिए `text[text.find("x")]` फेल होने की बजाय चुपचाप आखिरी कैरेक्टर लौटा देता है, जबकि `None` को इंडेक्स की तरह इस्तेमाल करने पर तुरंत एरर आ जाता है।

---

`None` को क्रम में नहीं रखा जा सकता: `None < 1` एक `TypeError` उठाता है, क्योंकि Python को नहीं पता होता कि "कुछ नहीं" किसी संख्या से छोटा है या बड़ा।
यह तब मायने रखता है जब `None` किसी सर्च के शुरुआती मान की तरह उपयोग किया जाए, जैसे "अब तक देखा गया सबसे अच्छा मान, यदि कोई हो"। हर तुलना को **पहले** रखी गई एक `is None` जाँच द्वारा सुरक्षित किया जाना चाहिए, ताकि `or` शॉर्ट-सर्किट करे और तुलना छोड़ दी जाए जब तुलना करने को कुछ न हो:
```python
if best is None or value > best:
    best = value
```
उल्टा लिखने पर, `value > best or best is None` पहले इटरेशन में `None` से तुलना करेगा और क्रैश हो जाएगा।
