# --description--

Un'extension di un **protocollo** è uno strumento diverso: aggiunge membri a ogni tipo che si conforma, presente e futuro. È così che dai a un requisito un'**implementazione predefinita**:
```swift
protocol Greeter {
    var name: String { get }
    func greet() -> String
}

extension Greeter {
    func greet() -> String {
        return "Hi, \(name)"
    }
}

struct Person: Greeter {
    var name: String
}

print(Person(name: "Ada").greet()) // Hi, Ada
```
`Person` non scrive mai `greet()` e si conforma comunque. Dentro l'extension del protocollo puoi usare ogni requisito del protocollo — qui `name` — perché qualsiasi tipo che si conforma ha la garanzia di averlo.

Esempio di utilizzo:
```swift
print(Fruits(items: ["fig", "plum"]).summary())
// prints 2 items
```

# --asserts--

Un cestino con `fig` e `plum` deve dare come riepilogo `2 items`

```swift
tryCatch(Fruits(items: ["fig", "plum"]).summary() == "2 items")
```

Un cestino vuoto deve dare come riepilogo `0 items`

```swift
tryCatch(Fruits(items: []).summary() == "0 items")
```

Un cestino con tre frutti deve dare come riepilogo `3 items`

```swift
tryCatch(Fruits(items: ["fig", "plum", "pear"]).summary() == "3 items")
```

Un altro tipo `Basket` che non scrive nessun metodo deve dare come riepilogo `1 items`

```swift

```

# --solutions--

```swift
protocol Basket {
    var items: [String] { get }
    func summary() -> String
}

extension Basket {
    func summary() -> String {
        return "\(items.count) items"
    }
}

struct Fruits: Basket {
    var items: [String]
}
```
