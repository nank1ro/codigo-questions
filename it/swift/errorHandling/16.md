# --description--

Tutto in questo capitolo risponde a una sola domanda: chi si occupa del fallimento?

Una funzione che lancia errori si rifiuta di rispondere. Nomina ciò che è andato storto — un caso di un enum `Error`, che porta con sé tutto ciò di cui il gestore avrà bisogno — e passa la decisione più in alto. Chi chiama sceglie quindi uno strumento: `do`/`catch` per reagire caso per caso, `try?` e `??` per ripiegare su un valore predefinito, `defer` per pulire in uscita in ogni caso.

Questa separazione è tutto il punto. La funzione che rileva il problema raramente sa cosa dovrebbe succedere dopo, e il codice che lo sa raramente vuole ripetere il controllo.

# --instructions--

Scrivi un validatore usando tutto quello di questo capitolo:
- dai a `FormError` un secondo caso `tooLong` contenente un `maximum` di tipo `Int`
- `validate` lancia `FormError.empty` quando il nome è vuoto, lancia `FormError.tooLong(maximum: 10)` quando è più lungo di 10 caratteri, e altrimenti restituisce il nome
- `safeName` restituisce il nome validato, oppure `"guest"` quando `validate` lancia un errore

Esempio di chiamata di funzione:
```swift
print(safeName(""))
// prints guest
```

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
