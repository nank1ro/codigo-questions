# --description--

Una volta che un mixin ha una clausola `on`, può fare **override** di un membro di quel tipo e chiamare **`super`** per raggiungere la versione sottostante nella catena:

```dart
class Logger {
  String log(String message) => message;
}

mixin Timestamped on Logger {
  @override
  String log(String message) => '[12:00] ${super.log(message)}';
}

class AppLogger extends Logger with Timestamped {}

void main() {
  print(AppLogger().log('started')); // [12:00] started
}
```

`super.log` non è il `log` del mixin stesso, è quello che sta sotto di esso, quindi non c'è ricorsione infinita. Impila più mixin di questo tipo con `with A, B` e ciascuno avvolge il precedente: la chiamata entra prima nell'**ultimo** mixin e scende fino alla superclasse.

# --instructions--

Dichiara una classe `Pipeline` con un metodo `run` che accetta una `String` `input` e la restituisce invariata.

Dichiara un mixin `Trimmed` su `Pipeline` che fa override di `run` passando a `super.run` l'input senza gli spazi iniziali e finali, e un mixin `Upper` su `Pipeline` che fa override di `run` restituendo il risultato di `super.run` in maiuscolo.

Dichiara una classe `TextPipeline` che estende `Pipeline` e utilizza `Trimmed` poi `Upper`, e una classe `TrimOnly` che estende `Pipeline` e utilizza solo `Trimmed`.

Esempio:
```dart
print(TextPipeline().run('  hi  ')); // HI
print(TrimOnly().run('  hi  '));     // hi
```

# --solutions--

```dart
class Pipeline {
  String run(String input) => input;
}

mixin Trimmed on Pipeline {
  @override
  String run(String input) => super.run(input.trim());
}

mixin Upper on Pipeline {
  @override
  String run(String input) => super.run(input).toUpperCase();
}

class TextPipeline extends Pipeline with Trimmed, Upper {}

class TrimOnly extends Pipeline with Trimmed {}
```
