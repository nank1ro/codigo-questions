# --description--

Con `gather`, le coroutine si alternano a ogni `await`. Una coroutine viene eseguita finché non attende qualcosa che non è ancora pronto, poi il loop passa a un'altra. Gli effetti collaterali come `print` avvengono quindi nell'ordine in cui le coroutine **riprendono**, non nell'ordine in cui sono state passate:
```python
import asyncio

async def step(name, delay):
    await asyncio.sleep(delay)
    print(name)
    return name

async def main():
    print(await asyncio.gather(step("a", 0.03), step("b", 0.01)))

asyncio.run(main())
```
Questo stampa `b`, poi `a`, poi `['a', 'b']`: `b` si risveglia per prima, ma la lista dei risultati mantiene l'ordine degli argomenti.

Cosa stampa questo codice?
```python
import asyncio

async def step(name, delay):
    await asyncio.sleep(delay)
    print(name)
    return name

async def main():
    names = await asyncio.gather(step("x", 0.03), step("y", 0.01), step("z", 0.02))
    print(names)

asyncio.run(main())
```

# --answers--

- `y`, `z`, `x`, poi `['x', 'y', 'z']`, perché ogni coroutine stampa quando la sua attesa termina ma `gather` mantiene l'ordine degli argomenti
- `x`, `y`, `z`, poi `['x', 'y', 'z']`, perché `gather` esegue le coroutine una dopo l'altra
- `y`, `z`, `x`, poi `['y', 'z', 'x']`, perché `gather` restituisce i risultati nell'ordine di completamento
- `x`, `y`, `z`, poi `['y', 'z', 'x']`, perché le stampe avvengono prima che qualsiasi attesa inizi
