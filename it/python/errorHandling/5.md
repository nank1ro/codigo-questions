# --description--

Scegliere il tipo più ristretto che copre il fallimento che ti aspetti è ciò che rende affidabile la gestione degli errori. Una funzione che legge del testo dovrebbe riprendersi da un testo sbagliato (`ValueError`) ma non deve nascondere di essere stata chiamata con il tipo di argomento sbagliato (`TypeError`) — quell'errore appartiene al chiamante, quindi lascialo passare.

# --instructions--

Scrivi una funzione `parse_age(text)` che restituisca `int(text)`, e restituisca `-1` quando `text` non è un numero intero valido. Cattura solo `ValueError`, in modo che `parse_age(None)` sollevi ancora `TypeError`

# --before-asserts--

```python
import unittest

class CodigoTests(unittest.TestCase):
```

# --asserts--

`parse_age("30")` deve restituire `30`

```python
    def test_1(self):
        self.assertEqual(parse_age("30"), 30, "--err-t1--")
```

`parse_age("old")` deve restituire `-1`

```python
    def test_2(self):
        self.assertEqual(parse_age("old"), -1, "--err-t2--")
```

`parse_age(None)` deve sollevare ancora `TypeError`

```python
    def test_3(self):
        with self.assertRaises(TypeError, msg="--err-t3--"):
            parse_age(None)
```

# --after-asserts--

```python
if __name__ == "__main__":
    unittest.main()
```

# --solutions--

```python
def parse_age(text):
    try:
        return int(text)
    except ValueError:
        return -1
```
