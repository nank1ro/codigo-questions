**주석(comment)**은 코드를 읽는 사람을 위해 소스 코드 안에 적어 두는 메모입니다. Python은 주석을 완전히 무시하므로, 주석은 프로그램의 동작을 절대 바꾸지 않습니다.

Python에 있는 유일한 주석은 **한 줄 주석**입니다: `#`으로 시작해서 줄의 끝까지 이어집니다.
```python
# Greets the user
print("Hello")
```
주석을 사용해 어떤 코드가 무슨 일을 하는지, 또는 왜 그렇게 작성했는지 설명하세요.

---

주석은 꼭 자기 줄을 가질 필요가 없습니다: 같은 줄에서 코드 뒤에 붙을 수 있습니다. 이것을 **인라인 주석**이라고 하며, 그 문장에 대한 짧은 메모를 남기기 좋은 자리입니다:
```python
retries = 3  # give up after three attempts
```
`#`부터 줄의 끝까지는 모두 무시되고, 그 앞의 코드는 평소처럼 실행됩니다.

Python의 스타일 가이드인 **PEP 8**은 여기에 약간의 공백을 요구합니다: 코드와 `#` 사이에는 **공백 두 칸**, `#` 뒤에는 **공백 한 칸**을 두세요. 자기 줄에 있는 주석에는 `#` 뒤의 공백만 필요합니다.

---

Python은 주석을 완전히 버리기 때문에, 주석을 추가하거나 삭제해도 프로그램의 동작은 절대 바뀌지 않습니다. 주석 처리되지 **않은** 코드만 실행됩니다.

덕분에 `#`은 코드 줄을 삭제하지 않고 끌 수 있는 빠른 방법이 됩니다. 이것을 **주석 처리(commenting out)**라고 합니다:
```python
total = 10
# total = total + 5
print(total)  # prints 10
```
두 번째 줄은 이제 주석이므로 `total`은 `10`으로 유지됩니다. `#`을 제거하면 그 줄이 다시 살아납니다.

주석 처리는 실험할 때 유용하지만, 나중에 정리하는 것을 잊지 마세요: 오랫동안 주석 처리된 채로 남아 있는 코드는 다음에 읽는 사람을 혼란스럽게 할 뿐입니다.

---

많은 언어에는 두 번째 종류의 주석, 여러 줄에 걸치는 **블록 주석**이 있습니다. 예를 들어 `/* ... */`처럼요. Python에는 이런 문법이 없습니다: `#`이 전부입니다.

설명이 여러 줄에 걸쳐야 한다면, 모든 줄 앞에 `#`을 붙이세요:
```python
# Prints the welcome banner.
# Called once when the app starts.
print("Welcome!")
```
같은 요령으로 여러 줄의 코드를 한 번에 주석 처리할 수 있습니다: 줄마다 `#`을 하나씩 붙이는 것이죠. 모든 에디터는 단축키 하나로 선택한 영역 전체에 `#`을 추가하거나 제거할 수 있으므로, 생각보다 비용이 들지 않습니다.

---

**삼중 따옴표 문자열**이 블록 주석인 것처럼 사용되는 것을 자주 보게 될 것입니다:
```python
"""
This looks like a comment,
but it is a string.
"""
print("done")
```
`"""`와 `"""` 사이의 문자열은 여러 줄에 걸칠 수 있고, 혼자 작성된 문자열은 유효한 문입니다: Python은 그 문자열을 만들고, 아무것도 하지 않고, 버립니다. 아무것도 출력되지 않으므로 결과는 주석처럼 보입니다.

하지만 주석이 아닙니다. 문자열 리터럴이므로 따옴표 규칙이 여전히 적용됩니다: 짝이 맞지 않는 따옴표나 그 안에 우연히 들어간 `"""`는 프로그램을 망가뜨립니다. 반면 `#` 주석 안에서는 무엇이든 쓸 수 있습니다. 또한 파일, 클래스 또는 함수의 첫 번째 문이 되면 우연히 docstring이 되어버릴 수도 있습니다. 그 외의 위치에서는 그저 아무 곳에도 가지 않습니다: CPython은 컴파일하는 동안 그 문 전체를 버립니다.

따라서 코드를 끄려면 `#`을 사용하세요. 삼중 따옴표 문자열에는 자기만의 역할이 있으며, 그 이야기는 다음 연습에서 시작됩니다.

---

문자열이 함수 안의 **첫 번째 문**이면, Python은 그것을 그 함수의 문서로 취급합니다. 이것을 **docstring**이라고 부릅니다:
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"
```
관례상 docstring은 한 줄에 들어가더라도 삼중 큰따옴표, `"""` 사이에 작성합니다. 나중에 따옴표를 바꾸지 않고도 길게 늘릴 수 있도록 하기 위해서입니다.

요약은 함수를 설명하듯 3인칭으로 작성하세요: "Returns...", "Adds...", "Checks...". docstring은 본문의 다른 어떤 문보다 앞에 와야 하며, 그렇지 않으면 그저 평범한 문자열에 불과합니다.

---

docstring은 버려지지 않습니다: Python은 그것을 함수의 `__doc__` 속성에 저장하므로, 프로그램이 실행되는 동안 자기 문서를 읽을 수 있습니다:
```python
def greet(name):
    """Returns the greeting for name."""
    return "Hi, " + name + "!"

print(greet.__doc__)  # Returns the greeting for name.
```
함수에 docstring이 없으면 `__doc__`은 `None`입니다. `help(greet)`가 출력하는 내용이자, 이름 위에 마우스를 올렸을 때 에디터가 보여 주는 내용입니다.

---

파일도 문서화할 수 있습니다. 어떤 import나 정의보다도 앞선 **파일의 맨 첫 번째 문**으로 작성된 문자열은 **모듈 docstring**입니다: 파일 전체가 무엇을 위한 것인지 말해 줍니다.
```python
"""Tools for working with rectangles."""

def area(width, height):
    """Returns the area of a rectangle."""
    return width * height
```
첫 번째 문만 해당됩니다. 주석은 그 위에 놓일 수 있지만, 그 사이에 실제 코드가 하나라도 들어가면 문자열은 다시 아무 쓸모없는 평범한 문자열로 돌아갑니다.

---

클래스도 같은 방식으로 동작합니다: 클래스 본문의 첫 번째 문으로 놓인 문자열은 그 클래스의 docstring이며, `__doc__`에 저장됩니다:
```python
class Point:
    """A point on a grid."""

    def __init__(self, x, y):
        self.x = x
        self.y = y

print(Point.__doc__)  # A point on a grid.
```
클래스 안의 각 메서드도 자기만의 docstring을 가질 수 있으며, `Point.__init__.__doc__`으로 읽을 수 있습니다. 따라서 docstring이 허용되는 세 곳은 모듈의 맨 위, 클래스의 맨 위, 함수의 맨 위입니다.

---

docstring과 `#` 주석은 비슷해 보이지만 서로 다른 질문에 답합니다.

**docstring**은 코드를 **사용하는** 사람을 위한 것입니다: 함수가 무엇을 하는지, 무엇을 기대하는지, 무엇을 돌려주는지요. docstring은 `__doc__`에 남아 있고, `help()`가 읽고, 에디터가 보여 주며, 문서화 도구가 수집합니다.

**주석**은 코드를 **읽는** 사람을 위한 것입니다: 이 줄이 왜 이렇게 작성되었는지, 이상한 숫자가 무슨 뜻인지, 어떤 버그를 우회하는 것인지요. 주석은 소스 파일에만 존재하며 프로그램이 실행되는 순간 사라집니다.

```python
def timeout():
    """Returns the number of seconds to wait for the server."""
    # the server drops idle connections after 35 seconds
    return 30
```
정리하면: 함수의 문서는 docstring에 들어가고, 구현에 대한 메모는 주석에 들어갑니다.

---

한 줄로는 부족할 때, docstring은 **PEP 257**에 기술된 고정된 레이아웃으로 발전합니다: 한 줄 요약, 빈 줄, 그다음 세부 내용, 그리고 마지막 `"""`은 자기 줄에 따로 둡니다.
```python
def to_seconds(minutes):
    """Returns the number of seconds in the given minutes.

    minutes is a whole number and is never negative.
    """
    return minutes * 60
```
빈 줄이 중요합니다: 도구는 첫 줄을 짧은 설명으로 따로 보여 주고, 나머지는 더 읽고 싶은 사람을 위해 남겨 둡니다.

---

docstring은 다른 모든 문보다 위인 **본문의 첫 번째 줄**이어야 합니다. `return` 뒤에 쓰인 문자열이나 본문의 다른 어디에 있든 문자열은 그저 문자열일 뿐입니다: `__doc__`은 `None`으로 남고, 어떤 도구도 그것을 보여 주지 않습니다.

---

일부 주석은 에디터가 이해하는 관례를 따릅니다. 가장 흔한 **마커**는 다음과 같습니다:
- `# TODO: ...`는 아직 작성해야 하는 것을 표시합니다
- `# FIXME: ...`는 잘못되었음이 알려져 수정이 필요한 코드를 표시합니다

```python
limit = 10
# TODO: read the limit from the settings
```
Python에게 이것들은 평범한 주석이지만, 에디터는 전용 패널에 모아 주므로 남은 작업을 쉽게 찾을 수 있습니다. `TODO`는 보통 실제 코드가 작성될 때까지 프로그램이 돌아가게 유지하는 자리 표시자 옆에 놓입니다.

작업을 끝내면 같은 변경에서 자리 표시자를 교체하고 마커를 삭제하세요. 그러면 주석이 코드의 상태에 대해 거짓말하는 일이 없습니다.

---

함수가 무엇을 하는지 설명하려고 함수 위에 놓인 주석은 잘못된 자리에 있는 것입니다. 그 역할은 docstring의 몫입니다: docstring은 함수에 붙어 있고 `help()`가 찾아 주며 에디터가 보여 주지만, `def` 위의 `#` 주석은 이들 모두에게 보이지 않습니다.

```python
# adds a and b
def add(a, b):
    return a + b
```
같은 문장을 한 줄 아래, 삼중 따옴표 사이로 옮기면 진짜 문서가 됩니다:
```python
def add(a, b):
    """Returns the sum of a and b."""
    return a + b
```

---

Python은 코드 안에서만 `#`을 찾으며, **문자열** 안에서는 찾지 않습니다. 따옴표 사이에서 `#`은 그저 평범한 문자입니다:
```python
print("black is #000000")  # a hex colour
```
첫 번째 `#`은 텍스트의 일부이고, 두 번째 것이 진짜 주석을 시작합니다. `#` 주석 안의 `"""`도 마찬가지입니다: 거기서는 그저 따옴표 문자 세 개일 뿐이며, 아무것도 시작하지 않습니다.

---

좋은 주석은 코드가 **무엇을** 하는지가 아니라 **왜** 그렇게 하는지를 설명합니다. 코드는 이미 무슨 일이 일어나는지 보여 줍니다. 그것을 말로 반복하면 소음이 더해질 뿐이고, 코드가 바뀌는 순간 낡아 버립니다:
```python
# set timeout to 30
timeout = 30
```
그 숫자 뒤에 숨은 이유가 바로 읽는 사람이 추측할 수 없는 부분입니다:
```python
# the server drops idle connections after 35 seconds, so stop earlier
timeout = 30
```
주석이 아래 줄을 그저 다시 말할 뿐이라면, 삭제하거나 이유로 바꾸세요. 최고의 주석은 코드가 말할 수 없는 것을 말하는 주석입니다.
