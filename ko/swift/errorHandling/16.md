# --description--

이 장의 모든 내용은 하나의 질문에 대한 답입니다. 누가 실패를 처리하는가?

오류를 던지는 함수는 그 답을 거부합니다. 무엇이 잘못됐는지 이름만 붙이고 — 핸들러가 필요로 할 모든 것을 담은 `Error` 열거형의 케이스로 — 결정을 위로 넘깁니다. 그러면 호출자가 도구를 고릅니다. 케이스별로 반응하려면 `do`/`catch`, 기본값으로 대신하려면 `try?`와 `??`, 어느 쪽이든 빠져나가면서 정리하려면 `defer`입니다.

바로 이 분리가 핵심입니다. 문제를 감지하는 함수는 다음에 무엇이 일어나야 하는지 거의 알지 못하고, 그것을 아는 코드는 그 확인을 반복하고 싶어 하지 않습니다.

# --instructions--

이 장에서 배운 모든 것을 사용해 검증 함수를 작성하세요:
- `FormError`에 `Int` 타입의 `maximum`을 담는 두 번째 케이스 `tooLong`을 추가하세요
- `validate`는 이름이 비어 있으면 `FormError.empty`를, 10자보다 길면 `FormError.tooLong(maximum: 10)`을 던지고, 그 외에는 이름을 반환합니다
- `safeName`은 검증된 이름을 반환하고, `validate`가 오류를 던지면 `"guest"`를 반환합니다

함수 호출 예시:
```swift
print(safeName(""))
// guest 를 출력합니다
```

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
