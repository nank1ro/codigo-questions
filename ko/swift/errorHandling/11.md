# --description--

함수가 오류를 던지면 `throw` 뒤의 모든 것이 건너뛰어집니다. 파일을 닫거나 잠금을 푸는 줄까지 포함해서 말이죠. `defer`가 그 문제를 해결합니다. 지금 블록을 등록해 두면 현재 스코프가 어떤 식으로 끝나든 그때 실행됩니다.
```swift
func load() throws {
    print("open")
    defer { print("close") }
    throw FileError.missing
}
```
이 호출은 `open`을 출력하고 그다음 `close`를 출력한 뒤에야 오류가 호출자에게 전달됩니다. 함수가 정상적으로 반환했더라도 `close`는 똑같이 출력되었을 것입니다. 바로 그것이 핵심입니다. 정리 코드를 준비 코드 바로 옆에 두고, 어느 출구로 나가는지 더는 신경 쓰지 마세요.

# --instructions--

`run`이 정상적으로 반환할 때와 오류를 던질 때 모두 일어나도록, `run` 안에 `log`에 `"cleanup"`을 추가하는 `defer` 블록을 넣으세요

# --seed--

```swift
enum TaskError: Error {
    case failed
}

func steps(_ shouldFail: Bool) -> [String] {
    var log: [String] = []
    func run() throws {
        log.append("start")
        
        if shouldFail {
            throw TaskError.failed
        }
        log.append("done")
    }
    do {
        try run()
    } catch {
        log.append("caught")
    }
    return log
}
```

# --asserts--

성공 경로에서 로그는 `start`, `done`, `cleanup`이어야 합니다

```swift
let _ok: [String] = steps(false)
tryCatch(_ok == ["start", "done", "cleanup"])
```

오류를 던지는 경로에서 로그는 `start`, `cleanup`, `caught`여야 합니다

```swift
let _bad: [String] = steps(true)
tryCatch(_bad == ["start", "cleanup", "caught"])
```

정리 코드는 두 경로 모두에서 실행되어야 합니다

```swift
tryCatch(steps(false).contains("cleanup") && steps(true).contains("cleanup"))
```

오류를 던지는 경로에서 정리 코드는 정확히 한 번만 실행되어야 합니다

```swift
let _once: [String] = steps(true)
tryCatch(_once.filter { $0 == "cleanup" }.count == 1)
```

```swift
enum TaskError: Error {
    case failed
}

func steps(_ shouldFail: Bool) -> [String] {
    var log: [String] = []
    func run() throws {
        log.append("start")
        defer { log.append("cleanup") }
        if shouldFail {
            throw TaskError.failed
        }
        log.append("done")
    }
    do {
        try run()
    } catch {
        log.append("caught")
    }
    return log
}
```
