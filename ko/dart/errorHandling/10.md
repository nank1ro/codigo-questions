# --description--

`Exception`은 인터페이스이므로 여러분의 클래스도 그것일 수 있습니다. 직접 만든 예외는 `on` 절이 고를 수 있는 이름을 실패에게 주고, 핸들러가 읽을 수 있는 필드를 줍니다:

```dart
class EmptyCartException implements Exception {
  final String message;

  EmptyCartException(this.message);

  @override
  String toString() => 'EmptyCartException: $message';
}

throw EmptyCartException('nothing to pay for');
```

세 가지를 갖추면 좋습니다: 클래스가 다른 실패들과 한데 속하게 해 주는 `implements Exception`, 세부 사항을 담는 `final` 필드, 그리고 처리되지 않은 예외 보고서를 읽을 수 있게 해 주는 재정의된 `toString()`. 그 재정의가 없으면 Dart는 클래스 이름만 출력하고 세부 사항은 사라집니다.

# --instructions--

`Exception`을 구현하는 클래스 `InvalidEmailException`을 정의하세요. 생성자가 설정하는 `final String` 필드 `message`와, `'InvalidEmailException: '` 뒤에 메시지를 붙여 반환하는 `toString()`을 갖습니다.

그다음 `String` 타입의 `email`을 받아 그것을 반환하지만, 이메일에 `'@'`가 없으면 `InvalidEmailException('missing @')`을 던지는 함수 `checkEmail`을 작성하세요.

예:
```dart
print(checkEmail('ada@dart.dev')); // ada@dart.dev
```

`checkEmail('ada@dart.dev')`는 이메일을 그대로 반환해야 합니다

  test('test1', () {

`checkEmail('nope')`은 `Exception`이기도 한 `InvalidEmailException`을 던져야 합니다

```dart
  test('test2', () {
    expect(() => checkEmail('nope'), throwsA(isA<InvalidEmailException>()), reason: '--err-t2--');
    expect(() => checkEmail('nope'), throwsA(isA<Exception>()), reason: '--err-t2--');
  });
```

던져진 객체는 메시지 `'missing @'`를 담고 `InvalidEmailException: missing @`로 출력되어야 합니다

```dart
  test('test3', () {
    try {
      checkEmail('nope');
      fail('--err-t3--');
    } on InvalidEmailException catch (e) {
      expect(e.message, 'missing @', reason: '--err-t3--');
      expect(e.toString(), 'InvalidEmailException: missing @', reason: '--err-t3--');
    }
  });
```

```dart
class InvalidEmailException implements Exception {
  final String message;

  InvalidEmailException(this.message);

  @override
  String toString() => 'InvalidEmailException: $message';
}

String checkEmail(String email) {
  if (!email.contains('@')) {
    throw InvalidEmailException('missing @');
  }
  return email;
}
```
