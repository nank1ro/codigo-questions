# --description--

믹스인은 메서드에만 국한되지 않습니다. **필드**도 선언할 수 있으며, 믹스인을 사용하는 모든 클래스의 모든 객체는 그 필드의 자신만의 복사본을 가집니다.

```dart
mixin Counter {
  int count = 0;

  void increment() {
    count++;
  }
}

class Clicker with Counter {}

void main() {
  final a = Clicker();
  final b = Clicker();
  a.increment();
  a.increment();
  print(a.count); // 2
  print(b.count); // 0, b has its own count
}
```

이것이 믹스인을 인터페이스 이상으로 만드는 점입니다. 믹스인은 데이터와 그 데이터를 다루는 코드를 모두 가져옵니다.

# --instructions--

`0`에서 시작하는 `int` 필드 `score`와, `int` 타입의 `points`를 받아 `score`에 더하는 메서드 `addPoints`를 가진 믹스인 `Scored`를 선언하세요.

`Scored`를 사용하고 자체 멤버는 아무것도 추가하지 않는 클래스 `Player`를 선언하세요.

예:
```dart
final p = Player();
p.addPoints(3);
print(p.score); // 3
```

# --asserts--

새 `Player`의 `score`는 `0`이어야 하고, `addPoints(3)`을 호출하면 `3`이 되어야 합니다

```dart
  test('test1', () {
    final p = Player();
    expect(p.score, 0, reason: '--err-t1--');
    p.addPoints(3);
    expect(p.score, 3, reason: '--err-t1--');
  });
```

`addPoints` 호출은 값이 누적되어야 합니다

```dart
  test('test2', () {
    final p = Player();
    p.addPoints(3);
    p.addPoints(4);
    p.addPoints(10);
    expect(p.score, 17, reason: '--err-t2--');
  });
```

각 `Player`는 자신만의 `score`를 가져야 하고, `Player`는 `Scored`이기도 해야 합니다

```dart
  test('test3', () {
    final a = Player();
    final b = Player();
    a.addPoints(5);
    expect(a.score, 5, reason: '--err-t3--');
    expect(b.score, 0, reason: '--err-t3--');
    expect(a, isA<Scored>(), reason: '--err-t3--');
  });
```
