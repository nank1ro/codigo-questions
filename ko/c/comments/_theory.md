**주석**은 컴파일러가 아니라 사람을 위한, 소스 코드 안의 텍스트입니다. 컴파일러는 프로그램을 빌드하기 전에 주석을 모두 버리므로, 주석을 사용해 코드의 용도를 설명하거나, 메모를 남기거나, 어떤 결정을 기록할 수 있습니다.

가장 흔한 종류는 **한 줄 주석**입니다: `//`부터 그 줄의 끝까지는 모두 무시됩니다.
```c
// Greet the user
printf("Hello\n");
```
프로그램이 실행될 때 첫 줄은 아무것도 하지 않으며, `printf`만 출력을 만듭니다.

---

컴파일러는 주석을 완전히 제거하므로, 주석을 추가하거나 삭제해도 프로그램의 동작은 절대 바뀌지 않습니다. 주석이 **아닌** 코드만 실행됩니다.

덕분에 `//`는 코드 줄을 삭제하지 않고 끄는 빠른 방법이 됩니다. 이를 **주석 처리**라고 합니다:
```c
int total = 10;
// total = total + 5;
printf("%d\n", total); // prints "10"
```
두 번째 줄은 이제 주석이므로 `total`은 `10`을 유지합니다. `//`를 제거하면 그 줄이 다시 살아납니다.

주석 처리는 실험할 때 유용하지만, 나중에 정리하는 것을 잊지 마세요: 오랫동안 주석 처리된 채로 남아 있는 코드는 다음에 읽는 사람을 혼란스럽게 만들 뿐입니다.

---

주석이 여러 줄에 걸칠 필요가 있을 때는 C의 **여러 줄 주석**(블록 주석이라고도 함)을 사용합니다: `/*`로 시작해서 `*/`로 끝나며, 줄바꿈을 포함해 그 사이의 모든 내용은 무시됩니다.
```c
/*
  Prints the welcome banner.
  Called once when the program starts.
*/
printf("Welcome!\n");
```
블록 주석은 짧게 한 줄에 머물 수도 있습니다: `/* like this */`.

줄의 끝에서 멈추는 `//`와 달리, `/*` 주석은 `*/`를 만나야만 끝납니다. 닫는 것을 잊으면 컴파일러는 뒤따르는 모든 코드를 주석의 일부로 취급합니다.

---

블록 주석은 **중첩되지 않습니다**. 컴파일러는 앞에 `/*`가 몇 개 있든 상관없이 가장 먼저 만난 `*/`에서 `/*` 주석을 끝냅니다:
```c
/* outer /* inner */ still code */
```
여기서 주석은 `inner` 바로 뒤에서 끝나므로, `still code */`는 코드로 컴파일되어 오류가 발생합니다.

이것은 이미 `/* */` 주석이 포함된 블록을 주석 처리하고 싶을 때 문제가 됩니다: 안쪽의 `*/`가 바깥쪽 주석을 너무 일찍 닫아 버리기 때문입니다. 이 경우에는 대신 각 줄 앞에 `//`를 붙이세요.

---

주석이 꼭 자기 줄을 가질 필요는 없습니다: 같은 줄에서 코드 뒤에 붙을 수도 있습니다. 이것을 **후행 주석**이라고 하며, 그 명령문에 대한 짧은 메모를 남기기 좋은 자리입니다:
```c
int retries = 3; // give up after three attempts
```
`//`와 `/* */` 모두 후행 주석으로 사용할 수 있지만, `/*`는 조심하세요: `*/`에서만 끝나므로 줄 끝에 닫히지 않은 `/*`는 뒤따르는 줄들까지 삼켜 버리고, 프로그램은 더 이상 컴파일되지 않습니다.

---

블록 주석의 흔한 용도는 **헤더 주석**입니다: 함수 바로 위에 놓이는 짧은 블록으로, 그 함수가 무엇을 하는지, 매개변수가 무엇을 뜻하는지, 무엇을 반환하는지 설명합니다.
```c
/*
 * Returns the number of seconds in the given minutes.
 * minutes: a whole number of minutes, never negative
 */
int to_seconds(int minutes) {
    return minutes * 60;
}
```
이제 `to_seconds`를 호출하는 사람은 본문 대신 헤더를 읽을 수 있습니다. 헤더는 함수 바로 옆에 두어 함께 업데이트되도록 하세요.

---

컴파일러는 모든 주석을 공백 하나로 바꿉니다. 즉, `/* */` 주석은 공백이 올 수 있는 어디에든 나타날 수 있으며, 명령문이나 표현식 한가운데에도 가능합니다:
```c
int area = width /* cm */ * height /* cm */;
```
이것은 피연산자나 호출의 인자에 레이블을 붙일 때 가끔 유용합니다. `//` 주석으로는 이렇게 할 수 없는데, 그 줄의 나머지 부분과 뒤따르는 코드까지 주석 처리해 버리기 때문입니다.

---

프로그래머는 아직 끝내지 않은 작업을 표시하기 위해 주석 시작 부분에 몇 가지 관용적인 키워드를 사용합니다:

- `TODO`는 아직 작성해야 하는 것을 표시합니다
- `FIXME`는 잘못되었음을 알고 있어 수정이 필요한 코드를 표시합니다

```c
// TODO: validate the input before using it
// FIXME: crashes when the list is empty
```
에디터와 도구는 이러한 표식을 목록으로 보여줄 수 있으므로 남아 있는 작업을 쉽게 찾을 수 있습니다. 작업이 끝나면 표식을 지우세요: 오래된 `TODO`는 오히려 오해를 부릅니다.

---

좋은 주석은 코드가 **무엇을** 하는지가 아니라 **왜** 그렇게 하는지를 설명합니다. 코드는 이미 무슨 일이 일어나는지 보여주므로, 그것을 말로 반복하면 잡음만 더해지고 코드가 바뀌는 순간 낡아 버립니다:
```c
// multiply price by 90 and divide by 100
return price * 90 / 100;
```
그 숫자 뒤에 있는 이유야말로 읽는 사람이 추측할 수 없는 것입니다:
```c
// launch discount: members get 10% off until the end of June
return price * 90 / 100;
```
주석이 아랫줄을 그대로 되풀이할 뿐이라면, 삭제하거나 이유로 바꾸세요.

---

정리하면: 짧은 메모와 후행 주석에는 `//`를, 더 긴 블록과 헤더 주석에는 `/* */`를 사용하고, 끝내지 못한 작업은 `TODO`나 `FIXME`로 표시하며, 주석 처리된 코드와 낡은 표식은 더 이상 필요 없어지면 제거합니다.
