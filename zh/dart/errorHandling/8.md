# --description--

有时处理程序并不是恢复的合适位置：你只想*留意*这次失败，然后让它继续传给真正能处理它的调用者。`rethrow` 关键字做的就是这件事，用在 `catch` 或 `on ... catch` 块中：

```dart
try {
  return int.parse(text);
} on FormatException {
  log.add('bad input: $text');
  rethrow;
}
```

`rethrow` 把**同一个**对象继续向外发送，所以调用者看到的是最初的失败。改成写 `throw e` 也能工作，但它会重新开始这段旅程，丢失失败最初发生的位置。

同一条语句中的 `finally` 块仍然会运行，即使是在失败向外传播的路径上。

# --instructions--

编写一个函数 `parseOrLog`，接受一个 `String` 类型的 `text` 和一个 `List<String>` 类型的 `log`，返回 `int.parse(text)`。

当文本不是整数时，把字符串 `'bad input: '` 加上该文本添加到 `log`，然后重新抛出（rethrow）这个 `FormatException`，让调用者仍然能看到它。

示例：
```dart
final log = <String>[];
print(parseOrLog('42', log)); // 42
```
