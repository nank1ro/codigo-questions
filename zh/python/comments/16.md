# --description--

好的注释解释代码**为什么**这样做，而不是它**做了什么**。代码本身已经展示了会发生什么；用文字重复一遍只会增加噪音，而且代码一改就会过时：
```python
# 将 timeout 设置为 30
timeout = 30
```
数字背后的原因才是读者猜不到的：
```python
# 服务器会在 35 秒后断开空闲连接，所以要提前停止
timeout = 30
```
如果一条注释只是复述它下面那一行，就删掉它，或者换成原因。最好的注释说的是代码本身说不出来的东西。
