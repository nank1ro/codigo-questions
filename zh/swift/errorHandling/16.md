# --description--

这一章的一切都在回答一个问题：谁来处理这个失败？

一个会抛出错误的函数拒绝回答这个问题。它只是说明出了什么问题——`Error` 枚举的一个成员，携带着处理程序将需要的一切——然后把决定权交给上层。调用方接着挑选一种工具：用 `do`/`catch` 逐个成员做出反应，用 `try?` 和 `??` 退回到一个默认值，用 `defer` 在退出时无论如何都完成清理。

这种分工正是关键所在。检测到问题的函数很少知道接下来该发生什么，而知道该怎么做的代码也很少想重复那个检查。

# --instructions--

运用本章学到的所有内容编写一个验证器：
- 给 `FormError` 添加第二个成员 `tooLong`，携带一个 `Int` 类型的 `maximum`
- `validate` 在名字为空时抛出 `FormError.empty`，在它超过 10 个字符时抛出 `FormError.tooLong(maximum: 10)`，否则返回该名字
- `safeName` 返回验证通过的名字，当 `validate` 抛出错误时返回 `"guest"`

函数调用示例：
```swift
print(safeName(""))
// 输出 guest
```

```swift
func _kind(_ name: String) -> String {
    do {
        return try validate(name)
    } catch FormError.empty {
        return "empty"
    } catch FormError.tooLong(let maximum) {
        return "max \(maximum)"
    } catch {
        return "other"
    }
}
```

# --solutions--

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
