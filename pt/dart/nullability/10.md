# --description--

A promoção de tipo **não** funciona em um **campo** de classe que pode ser alterado de fora, porque entre a verificação e o uso outro trecho de código (um getter sobrescrito em uma subclasse, outro método) poderia colocá-lo de volta como `null`:

```dart
class Box {
  int? value;

  int doubled() {
    if (value != null) {
      return value * 2; // error: 'value' can't be unconditionally accessed
    }
    return 0;
  }
}
```

A solução padrão é copiar o campo para uma **variável local**, que é promovida:

```dart
int doubled() {
  final v = value;
  if (v != null) {
    return v * 2;
  }
  return 0;
}
```

# --instructions--

Por que a primeira versão de `doubled` na descrição não compila?

# --answers--

- `value` é um campo, então a verificação de null não o promove: copie-o primeiro para uma variável local
- Valores `int?` não podem ser multiplicados, mesmo quando não são `null`
- Falta um ramo `else` na instrução `if`
- Campos de uma classe não podem ter um tipo nullable
