# --description--

Um mixin não se limita a métodos: ele também pode declarar **campos**, e todo objeto de toda classe que usa o mixin recebe sua própria cópia deles.

```dart
mixin Counter {
  int count = 0;

  void increment() {
    count++;
  }
}

class Clicker with Counter {}

void main() {
  final a = Clicker();
  final b = Clicker();
  a.increment();
  a.increment();
  print(a.count); // 2
  print(b.count); // 0, b has its own count
}
```

É isso que faz um mixin ser mais do que uma interface: ele traz tanto os dados quanto o código que trabalha sobre eles.

# --instructions--

Declare um mixin `Scored` com:
- um campo `score` do tipo `int` que começa em `0`
- um método `addPoints` que recebe um `int` `points` e o soma a `score`

Declare uma classe `Player` que usa `Scored` e não adiciona nada próprio.

Exemplo:
```dart
final p = Player();
p.addPoints(3);
print(p.score); // 3
```

# --asserts--

Um novo `Player` deve ter um `score` de `0`, e `addPoints(3)` deve levá-lo a `3`

```dart
  test('test1', () {
    final p = Player();
    expect(p.score, 0, reason: '--err-t1--');
    p.addPoints(3);
    expect(p.score, 3, reason: '--err-t1--');
  });
```

As chamadas a `addPoints` devem se acumular

```dart
  test('test2', () {
    final p = Player();
    p.addPoints(3);
    p.addPoints(4);
    p.addPoints(10);
    expect(p.score, 17, reason: '--err-t2--');
  });
```

Cada `Player` deve ter seu próprio `score`, e um `Player` deve ser um `Scored`

```dart
  test('test3', () {
    final a = Player();
    final b = Player();
    a.addPoints(5);
    expect(a.score, 5, reason: '--err-t3--');
    expect(b.score, 0, reason: '--err-t3--');
    expect(a, isA<Scored>(), reason: '--err-t3--');
  });
```
