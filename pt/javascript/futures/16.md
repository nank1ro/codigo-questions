# --description--

Juntando as últimas peças temos uma pequena ferramenta usada em quase toda aplicação real: um prazo. Construa uma promise que é rejeitada após `ms` milissegundos, faça uma corrida entre ela e o trabalho real, e a que se estabelecer primeiro decide o resultado:
```javascript
const timer = new Promise((resolve, reject) => {
  setTimeout(() => reject(new Error("timeout")), ms);
});
return Promise.race([work, timer]);
```
Retornar uma promise de uma função `async` é válido: a promise que a função devolve a acompanha, então quem chama aguarda o valor final e não uma promise de uma promise.

# --asserts--

Uma promise que já está cumprida deve dar o seu valor.

```javascript
(async () => {
  tryCatch((await withTimeout(Promise.resolve("ok"), 50)) === "ok");
})().catch(() => tryCatch(false));
```

Uma promise que é rejeitada antes do prazo deve manter o seu próprio erro.

```javascript
(async () => {
  const failing = Promise.reject(new Error("broken"));
  let message = "";
  await withTimeout(failing, 60).catch((error) => { message = error.message; });
  tryCatch(message === "broken");
})().catch(() => tryCatch(false));
```

Uma promise rápida o suficiente deve dar o seu valor, não uma promise.

```javascript
(async () => {
  const quick = new Promise((resolve) => setTimeout(() => resolve(7), 10));
  tryCatch((await withTimeout(quick, 120)) === 7);
})().catch(() => tryCatch(false));
```

Uma promise lenta demais deve ser rejeitada com a mensagem `"timeout"`.

```javascript
(async () => {
  const slow = new Promise((resolve) => setTimeout(() => resolve("late"), 150));
  let message = "";
  await withTimeout(slow, 20).catch((error) => { message = error.message; });
  tryCatch(message === "timeout");
})().catch(() => tryCatch(false));
```
