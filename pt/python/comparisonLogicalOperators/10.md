# --description--

`==` compara **valores**; `is` compara **identidade**, ou seja, se ambos os nomes se referem exatamente ao mesmo objeto. Duas listas iguais construídas separadamente são `==` mas não `is`:
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` serve para singletons como `None`, `True` e `False`: escreva `value is None` ou `value is not None`, nunca `value == None`, porque uma classe pode definir `==` para retornar qualquer coisa. Usar `is` com números ou strings não é confiável e Python avisa sobre isso.

Escreva uma função `is_missing(value)` que retorne `True` apenas quando `value` for `None`, e `False` para qualquer outro valor, incluindo os falsos como `0`, `""` e `[]`

# --asserts--

`is_missing(None)` deve retornar `True`

```python
    def test_1(self):
        self.assertIs(is_missing(None), True, "--err-t1--")
```

Valores falsos não são `None`

```python
    def test_2(self):
        self.assertIs(is_missing(0), False, "--err-t2--")
        self.assertIs(is_missing(""), False, "--err-t2--")
        self.assertIs(is_missing([]), False, "--err-t2--")
        self.assertIs(is_missing(False), False, "--err-t2--")
```

Um objeto cujo `==` afirma ser igual a tudo continua não sendo `None`, então a verificação deve usar identidade

```python
    def test_3(self):
        class Anything:
            def __eq__(self, other):
                return True
        self.assertIs(is_missing(Anything()), False, "--err-t3--")
```
