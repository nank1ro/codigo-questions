# --description--

Tudo neste capítulo responde a uma única pergunta: quem lida com a falha?

Uma função que lança erros se recusa a responder isso. Ela nomeia o que deu errado — um caso de um enum `Error`, carregando tudo o que quem trata vai precisar — e passa a decisão para cima. Quem chama então escolhe uma ferramenta: `do`/`catch` para reagir caso a caso, `try?` e `??` para recorrer a um valor padrão, `defer` para limpar na saída de qualquer forma.

Essa divisão é o ponto principal. A função que detecta o problema raramente sabe o que deve acontecer em seguida, e o código que sabe raramente quer repetir a verificação.

# --instructions--

Escreva um validador usando tudo deste capítulo:
- dê a `FormError` um segundo caso `tooLong` carregando um `maximum` do tipo `Int`
- `validate` lança `FormError.empty` quando o nome está vazio, lança `FormError.tooLong(maximum: 10)` quando ele tem mais de 10 caracteres e, caso contrário, retorna o nome
- `safeName` retorna o nome validado, ou `"guest"` quando `validate` lança um erro

Exemplo de chamada da função:
```swift
print(safeName(""))
// imprime guest
```

func _kind(_ name: String) -> String {
    do {
        return try validate(name)
    } catch FormError.empty {
        return "empty"
    } catch FormError.tooLong(let maximum) {
        return "max \(maximum)"
    } catch {
        return "other"
    }
}

```swift
enum FormError: Error {
    case empty
    case tooLong(maximum: Int)
}

func validate(_ name: String) throws -> String {
    guard !name.isEmpty else {
        throw FormError.empty
    }
    guard name.count <= 10 else {
        throw FormError.tooLong(maximum: 10)
    }
    return name
}

func safeName(_ name: String) -> String {
    return (try? validate(name)) ?? "guest"
}
```
