# --description--

The generated `equals()` makes `==` a **structural** comparison: two instances are equal when every property of the primary constructor is equal. The `===` operator is different, it asks whether both names point to the **very same object** in memory.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, same data
println(a === b) // false, two different objects
println(a === a) // true
```

Because `hashCode()` is generated together with `equals()`, data class instances also behave correctly inside a `Set` or as `Map` keys: duplicates collapse.

```kotlin
println(setOf(a, b).size) // 1
```

A regular class generates none of this, so for it `==` falls back to identity.

# --asserts--

Two users built with the same data must have the same data

```kotlin
    tryCatch(sameData(User(1, "Ann"), User(1, "Ann")))
```

Two users built with different data must not have the same data

```kotlin
    tryCatch(!sameData(User(1, "Ann"), User(2, "Ann")))
```

Two separately built users must not be the same instance

```kotlin
    tryCatch(!sameInstance(User(1, "Ann"), User(1, "Ann")))
```

The same user compared with itself must be the same instance

```kotlin
    val user = User(3, "Bo")
    tryCatch(sameInstance(user, user))
```

`User` must generate `hashCode()`, so a set of two equal users holds one element


```kotlin
data class User(val id: Int, val name: String)

fun sameData(a: User, b: User): Boolean {
    return a == b
}

fun sameInstance(a: User, b: User): Boolean {
    return a === b
}
```
