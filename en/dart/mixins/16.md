# --description--

Stacked mixins are how small, independent rules are combined into one class. Each mixin overrides the same member, does its own part, and calls `super` to hand the work on. Because the call enters the **last** mixin first, the order of the `with` list decides which rule runs before which:

```dart
class Account {
  int balance = 0;

  void deposit(int amount) {
    balance += amount;
  }
}

mixin Doubled on Account {
  @override
  void deposit(int amount) {
    super.deposit(amount * 2);
  }
}
```

`class A extends Account with Doubled {}` doubles every deposit. Add a second mixin after `Doubled` and it gets the deposit first, before `Doubled` ever sees it.

# --instructions--

The class `Account` is already written: it has an `int` field `balance` starting at `0` and a method `deposit` that adds its `int` argument to `balance`.

Declare a mixin `Audited` on `Account` with a `List<String>` field `log` starting empty, overriding `deposit` so that it first adds the string `'deposit '` followed by the amount to `log`, then calls `super.deposit`.

Declare a mixin `Limited` on `Account` overriding `deposit` so that an amount greater than `100` is ignored, and any other amount is passed on to `super.deposit`.

Declare a class `SafeAccount` that extends `Account` and uses both mixins, so that a rejected deposit never reaches the log.

Example:
```dart
final account = SafeAccount();
account.deposit(30);
account.deposit(500);
print(account.balance); // 30
print(account.log);     // [deposit 30]
```

# --solutions--

```dart
mixin Audited on Account {
  final List<String> log = [];

  @override
  void deposit(int amount) {
    log.add('deposit $amount');
    super.deposit(amount);
  }
}

mixin Limited on Account {
  @override
  void deposit(int amount) {
    if (amount > 100) return;
    super.deposit(amount);
  }
}

class SafeAccount extends Account with Audited, Limited {}
```
