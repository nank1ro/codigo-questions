# --description--

Once a mixin has an `on` clause, it may **override** a member of that type and call **`super`** to reach the version underneath it in the chain:

```dart
class Logger {
  String log(String message) => message;
}

mixin Timestamped on Logger {
  @override
  String log(String message) => '[12:00] ${super.log(message)}';
}

class AppLogger extends Logger with Timestamped {}

void main() {
  print(AppLogger().log('started')); // [12:00] started
}
```

`super.log` is not the mixin's own `log`, it is the one below it, so there is no infinite recursion. Stack several such mixins with `with A, B` and each one wraps the previous: the call enters the **last** mixin first and travels down to the superclass.

# --instructions--

Declare a class `Pipeline` with a method `run` that takes a `String` `input` and returns it unchanged.

Declare a mixin `Trimmed` on `Pipeline` that overrides `run` by passing the trimmed input to `super.run`, and a mixin `Upper` on `Pipeline` that overrides `run` by returning the result of `super.run` in uppercase.

Declare a class `TextPipeline` that extends `Pipeline` and uses `Trimmed` then `Upper`, and a class `TrimOnly` that extends `Pipeline` and uses only `Trimmed`.

Example:
```dart
print(TextPipeline().run('  hi  ')); // HI
print(TrimOnly().run('  hi  '));     // hi
```

# --solutions--

```dart
class Pipeline {
  String run(String input) => input;
}

mixin Trimmed on Pipeline {
  @override
  String run(String input) => super.run(input.trim());
}

mixin Upper on Pipeline {
  @override
  String run(String input) => super.run(input).toUpperCase();
}

class TextPipeline extends Pipeline with Trimmed, Upper {}

class TrimOnly extends Pipeline with Trimmed {}
```
