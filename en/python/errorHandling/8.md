# --description--

`except:` with no type after it is a **bare except**. It matches everything, including exceptions that have nothing to do with the operation you were guarding, so the rule is simple: always name the types you can actually recover from.

# --instructions--

Why should this code name a specific exception type instead of using a bare `except:`?
```python
try:
    total = int(amout)
except:
    total = 0
```

# --answers--

- Because the bare `except:` also catches unrelated failures, such as the `NameError` caused by the misspelled `amout`, so a real bug silently becomes `total = 0`
- Because a bare `except:` is slower, as Python has to compare the exception against every built-in class
- Because a bare `except:` only works at module level and raises a `SyntaxError` inside a function
- Because a bare `except:` catches nothing, so the exception is raised again as soon as the block ends
