# --description--

Choosing the narrowest type that covers the failure you expect is what makes error handling trustworthy. A function that reads text should recover from bad text (`ValueError`) but must not hide being called with the wrong kind of argument (`TypeError`) — that error belongs to the caller, so let it through.

# --instructions--

Write a function `parse_age(text)` that returns `int(text)`, and returns `-1` when `text` is not a valid whole number. Catch only `ValueError`, so that `parse_age(None)` still raises `TypeError`

# --before-asserts--

```python
import unittest

class CodigoTests(unittest.TestCase):
```

# --asserts--

`parse_age("30")` must return `30`

```python
    def test_1(self):
        self.assertEqual(parse_age("30"), 30, "--err-t1--")
```

`parse_age("old")` must return `-1`

```python
    def test_2(self):
        self.assertEqual(parse_age("old"), -1, "--err-t2--")
```

`parse_age(None)` must still raise `TypeError`

```python
    def test_3(self):
        with self.assertRaises(TypeError, msg="--err-t3--"):
            parse_age(None)
```

# --after-asserts--

```python
if __name__ == "__main__":
```

# --solutions--

```python
def parse_age(text):
    try:
        return int(text)
    except ValueError:
        return -1
```
