# --description--

`==` compares **values**; `is` compares **identity**, that is, whether both names refer to the very same object. Two equal lists built separately are `==` but not `is`:
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` is meant for singletons such as `None`, `True` and `False`: write `value is None` or `value is not None`, never `value == None`, because a class can define `==` to return anything. Using `is` with numbers or strings is unreliable and Python warns about it.

# --instructions--

Write a function `is_missing(value)` that returns `True` only when `value` is `None`, and `False` for any other value, including falsy ones such as `0`, `""` and `[]`

`is_missing(None)` must return `True`

```python
    def test_1(self):
        self.assertIs(is_missing(None), True, "--err-t1--")
```

Falsy values are not `None`

```python
    def test_2(self):
        self.assertIs(is_missing(0), False, "--err-t2--")
        self.assertIs(is_missing(""), False, "--err-t2--")
        self.assertIs(is_missing([]), False, "--err-t2--")
        self.assertIs(is_missing(False), False, "--err-t2--")
```

An object whose `==` claims to equal everything is still not `None`, so the check must use identity

```python
    def test_3(self):
        class Anything:
            def __eq__(self, other):
                return True
        self.assertIs(is_missing(Anything()), False, "--err-t3--")
```
