# --description--

Un mixin no se limita a los métodos: también puede declarar **campos**, y cada objeto de cada clase que use el mixin obtiene su propia copia de ellos.

```dart
mixin Counter {
  int count = 0;

  void increment() {
    count++;
  }
}

class Clicker with Counter {}

void main() {
  final a = Clicker();
  final b = Clicker();
  a.increment();
  a.increment();
  print(a.count); // 2
  print(b.count); // 0, b has its own count
}
```

Esto es lo que hace que un mixin sea más que una interfaz: aporta tanto los datos como el código que trabaja sobre ellos.

# --instructions--

Declara un mixin `Scored` con:
- un campo `int` `score` que empiece en `0`
- un método `addPoints` que reciba un `int` `points` y lo sume a `score`

Declara una clase `Player` que use `Scored` y no añada nada propio.

Ejemplo:
```dart
final p = Player();
p.addPoints(3);
print(p.score); // 3
```

# --asserts--

Un `Player` nuevo debería tener un `score` de `0`, y `addPoints(3)` debería llevarlo a `3`

```dart
  test('test1', () {
    final p = Player();
    expect(p.score, 0, reason: '--err-t1--');
    p.addPoints(3);
    expect(p.score, 3, reason: '--err-t1--');
  });
```

Las llamadas a `addPoints` deberían acumularse

```dart
  test('test2', () {
    final p = Player();
    p.addPoints(3);
    p.addPoints(4);
    p.addPoints(10);
    expect(p.score, 17, reason: '--err-t2--');
  });
```

Cada `Player` debería tener su propio `score`, y un `Player` debería ser un `Scored`

```dart
  test('test3', () {
    final a = Player();
    final b = Player();
    a.addPoints(5);
    expect(a.score, 5, reason: '--err-t3--');
    expect(b.score, 0, reason: '--err-t3--');
    expect(a, isA<Scored>(), reason: '--err-t3--');
  });
```
