# --description--

La promoción de tipos **no** funciona sobre un **campo** de una clase que puede cambiarse desde fuera, porque entre la comprobación y el uso otro fragmento de código (un getter sobreescrito en una subclase, otro método) podría devolverlo a `null`:

```dart
class Box {
  int? value;

  int doubled() {
    if (value != null) {
      return value * 2; // error: 'value' can't be unconditionally accessed
    }
    return 0;
  }
}
```

La solución estándar es copiar el campo en una **variable local**, que sí se promociona:

```dart
int doubled() {
  final v = value;
  if (v != null) {
    return v * 2;
  }
  return 0;
}
```

# --instructions--

¿Por qué no compila la primera versión de `doubled` de la descripción?

# --answers--

- `value` es un campo, por lo que la comprobación de null no lo promociona: cópialo primero en una variable local
- los valores `int?` no se pueden multiplicar, ni siquiera cuando no son `null`
- A la sentencia `if` le falta una rama `else`
- Los campos de una clase no pueden tener un tipo nullable
