# --description--

Elegir el tipo más estrecho que cubre el fallo que esperas es lo que hace confiable el manejo de errores. Una función que lee texto debería recuperarse de un texto inválido (`ValueError`) pero no debe ocultar que se llamó con el tipo de argumento equivocado (`TypeError`) — ese error le corresponde al llamador, así que déjalo pasar.

# --instructions--

Escribe una función `parse_age(text)` que devuelva `int(text)`, y devuelva `-1` cuando `text` no sea un número entero válido. Captura solo `ValueError`, de modo que `parse_age(None)` siga lanzando `TypeError`

# --before-asserts--

```python
import unittest

class CodigoTests(unittest.TestCase):
```

# --asserts--

`parse_age("30")` debe devolver `30`

```python
    def test_1(self):
        self.assertEqual(parse_age("30"), 30, "--err-t1--")
```

`parse_age("old")` debe devolver `-1`

```python
    def test_2(self):
        self.assertEqual(parse_age("old"), -1, "--err-t2--")
```

`parse_age(None)` debe seguir lanzando `TypeError`

```python
    def test_3(self):
        with self.assertRaises(TypeError, msg="--err-t3--"):
            parse_age(None)
```

# --solutions--

```python
def parse_age(text):
    try:
        return int(text)
    except ValueError:
        return -1
```
