# --description--

`except:` sin ningún tipo detrás es un **except desnudo**. Coincide con todo, incluidas excepciones que no tienen nada que ver con la operación que estabas protegiendo, así que la regla es simple: nombra siempre los tipos de los que realmente puedes recuperarte.

# --instructions--

¿Por qué este código debería nombrar un tipo de excepción concreto en lugar de usar un `except:` desnudo?
```python
try:
    total = int(amout)
except:
    total = 0
```

# --answers--

- Porque el `except:` desnudo también captura fallos no relacionados, como el `NameError` causado por `amout` mal escrito, de modo que un error real se convierte silenciosamente en `total = 0`
- Porque un `except:` desnudo es más lento, ya que Python tiene que comparar la excepción con todas las clases integradas
- Porque un `except:` desnudo solo funciona a nivel de módulo y lanza un `SyntaxError` dentro de una función
- Porque un `except:` desnudo no captura nada, así que la excepción se vuelve a lanzar en cuanto termina el bloque
