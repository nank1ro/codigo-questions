# --description--

`==` compara **valores**; `is` compara la **identidad**, es decir, si ambos nombres se refieren exactamente al mismo objeto. Dos listas iguales construidas por separado son `==` pero no `is`:
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` está pensado para singletons como `None`, `True` y `False`: escribe `value is None` o `value is not None`, nunca `value == None`, porque una clase puede definir `==` para devolver cualquier cosa. Usar `is` con números o cadenas no es fiable y Python lo advierte.

# --asserts--

`is_missing(None)` debe devolver `True`

```python
    def test_1(self):
        self.assertIs(is_missing(None), True, "--err-t1--")
```

Los valores falsos no son `None`

```python
    def test_2(self):
        self.assertIs(is_missing(0), False, "--err-t2--")
        self.assertIs(is_missing(""), False, "--err-t2--")
        self.assertIs(is_missing([]), False, "--err-t2--")
        self.assertIs(is_missing(False), False, "--err-t2--")
```

Un objeto cuyo `==` afirma ser igual a todo sigue sin ser `None`, así que la comprobación debe usar la identidad

```python
    def test_3(self):
        class Anything:
            def __eq__(self, other):
                return True
        self.assertIs(is_missing(Anything()), False, "--err-t3--")
```
