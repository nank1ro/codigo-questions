# --description--

Una extensión de un **protocolo** es una herramienta distinta: añade miembros a todo tipo que conforme, presente y futuro. Así es como le das a un requisito una **implementación por defecto**:
```swift
protocol Greeter {
    var name: String { get }
    func greet() -> String
}

extension Greeter {
    func greet() -> String {
        return "Hi, \(name)"
    }
}

struct Person: Greeter {
    var name: String
}

print(Person(name: "Ada").greet()) // Hi, Ada
```
`Person` nunca escribe `greet()` y aun así conforma. Dentro de la extensión del protocolo puedes usar cualquier requisito del protocolo —aquí `name`— porque cualquier tipo que conforme tiene garantizado tenerlo.

# --instructions--

Añade una extensión de `Basket` que le dé a `summary()` una implementación por defecto que devuelva el número de elementos seguido de ` items`, de modo que `Fruits` conforme sin escribir el método

Ejemplo de uso:
```swift
print(Fruits(items: ["fig", "plum"]).summary())
// imprime 2 items
```

```swift
tryCatch(Fruits(items: ["fig", "plum"]).summary() == "2 items")
```

An empty basket must summarise as `0 items`

```swift
tryCatch(Fruits(items: []).summary() == "0 items")
```

A basket with three fruits must summarise as `3 items`

```swift
tryCatch(Fruits(items: ["fig", "plum", "pear"]).summary() == "3 items")
```

Another `Basket` type that writes no method must summarise as `1 items`


# --solutions--

```swift
protocol Basket {
    var items: [String] { get }
    func summary() -> String
}

extension Basket {
    func summary() -> String {
        return "\(items.count) items"
    }
}

struct Fruits: Basket {
    var items: [String]
}
```
