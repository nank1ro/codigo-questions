# --description--

Todo lo visto hasta ahora pertenece a una sola sintaxis, así que las piezas se combinan con libertad: un patrón de objeto puede anidar otro patrón de objeto, que puede contener una clave renombrada con un valor por defecto, junto a un patrón de array que termina en un elemento rest. Una línea describe entonces toda la forma que espera una función:
```javascript
function head({ title, tags: [main, ...extra] }) {
    return `${title} [${main}] +${extra.length}`;
}
console.log(head({ title: "Post", tags: ["js", "web", "dev"] }));
// prints Post [js] +2
```
Mantenlo legible: un patrón que ya no cabe en un par de líneas suele ser señal de que la función está pidiendo demasiado.

# --asserts--

Tres elementos deben dejar dos atrás.

```javascript
tryCatch(report({ id: 7, customer: { name: "Ada" }, items: ["pen", "book", "lamp"] }) === "#7 Ada: pen +2");
```

Un solo elemento no debe dejar ninguno atrás.

```javascript
tryCatch(report({ id: 42, customer: { name: "Bob" }, items: ["mug"] }) === "#42 Bob: mug +0");
```

Un cliente sin nombre debe convertirse en `guest`.

```javascript
tryCatch(report({ id: 1, customer: {}, items: ["hat", "map"] }) === "#1 guest: hat +1");
```

Un nombre explícitamente `undefined` también debe convertirse en `guest`.

```javascript
tryCatch(report({ id: 9, customer: { name: undefined }, items: ["x"] }) === "#9 guest: x +0");
```

Cuatro elementos deben dejar tres atrás.

```javascript
tryCatch(report({ id: 3, customer: { name: "Cy" }, items: ["a", "b", "c", "d"] }) === "#3 Cy: a +3");
```

# --solutions--

```javascript
function report(order) {
  const { id, customer: { name = "guest" }, items: [first, ...rest] } = order;
  return `#${id} ${name}: ${first} +${rest.length}`;
}
```
