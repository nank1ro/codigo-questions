# --description--

Unir las últimas piezas da como resultado una pequeña herramienta que se usa en casi toda aplicación real: un plazo límite. Construye una promesa que se rechace después de `ms` milisegundos, hazla competir contra el trabajo real, y la que se asiente primero decide el desenlace:
```javascript
const timer = new Promise((resolve, reject) => {
  setTimeout(() => reject(new Error("timeout")), ms);
});
return Promise.race([work, timer]);
```
Devolver una promesa desde una función `async` está bien: la promesa que la función entrega sigue a esa promesa, así que quien llama espera el valor final y no una promesa de una promesa.

# --asserts--

Una promesa que ya está cumplida debe dar su valor.

```javascript
(async () => {
  tryCatch((await withTimeout(Promise.resolve("ok"), 50)) === "ok");
})().catch(() => tryCatch(false));
```

Una promesa que se rechaza antes del plazo límite debe conservar su propio error.

```javascript
(async () => {
  const failing = Promise.reject(new Error("broken"));
  let message = "";
  await withTimeout(failing, 60).catch((error) => { message = error.message; });
  tryCatch(message === "broken");
})().catch(() => tryCatch(false));
```

Una promesa que es lo bastante rápida debe dar su valor, no una promesa.

```javascript
(async () => {
  const quick = new Promise((resolve) => setTimeout(() => resolve(7), 10));
  tryCatch((await withTimeout(quick, 120)) === 7);
})().catch(() => tryCatch(false));
```

Una promesa que es demasiado lenta debe rechazarse con el mensaje `"timeout"`.

```javascript
(async () => {
  const slow = new Promise((resolve) => setTimeout(() => resolve("late"), 150));
  let message = "";
  await withTimeout(slow, 20).catch((error) => { message = error.message; });
  tryCatch(message === "timeout");
})().catch(() => tryCatch(false));
```
