# --description--

Das generierte `equals()` macht `==` zu einem **strukturellen** Vergleich: Zwei Instanzen sind gleich, wenn jede Eigenschaft des Primärkonstruktors gleich ist. Der Operator `===` ist anders: Er fragt, ob beide Namen auf **dasselbe Objekt** im Speicher zeigen.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, same data
println(a === b) // false, two different objects
println(a === a) // true
```

Da `hashCode()` zusammen mit `equals()` generiert wird, verhalten sich data-class-Instanzen auch in einem `Set` oder als `Map`-Schlüssel korrekt: Duplikate verschmelzen.

```kotlin
println(setOf(a, b).size) // 1
```

Eine normale Klasse generiert nichts davon, daher fällt `==` bei ihr auf Identität zurück.

# --asserts--

Zwei mit denselben Daten erstellte Benutzer müssen dieselben Daten haben

```kotlin
    tryCatch(sameData(User(1, "Ann"), User(1, "Ann")))
```

Zwei mit unterschiedlichen Daten erstellte Benutzer dürfen nicht dieselben Daten haben

```kotlin
    tryCatch(!sameData(User(1, "Ann"), User(2, "Ann")))
```

Zwei separat erstellte Benutzer dürfen nicht dieselbe Instanz sein

```kotlin
    tryCatch(!sameInstance(User(1, "Ann"), User(1, "Ann")))
```

Derselbe Benutzer, mit sich selbst verglichen, muss dieselbe Instanz sein

```kotlin
    val user = User(3, "Bo")
    tryCatch(sameInstance(user, user))
```

`User` muss `hashCode()` generieren, sodass eine Menge aus zwei gleichen Benutzern ein Element enthält

```kotlin
    tryCatch(setOf(User(4, "Cy"), User(4, "Cy")).size == 1)
```

data class User(val id: Int, val name: String)

fun sameData(a: User, b: User): Boolean {
    return a == b
}

fun sameInstance(a: User, b: User): Boolean {
    return a === b
}
