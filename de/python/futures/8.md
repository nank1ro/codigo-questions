# --description--

Mit `gather` kommen Coroutinen bei jedem `await` abwechselnd zum Zug. Eine Coroutine läuft, bis sie auf etwas awaitet, das noch nicht bereit ist, dann schaltet die Loop zu einer anderen um. Nebeneffekte wie `print` passieren daher in der Reihenfolge, in der die Coroutinen **fortgesetzt** werden, nicht in der Reihenfolge, in der sie übergeben wurden:
```python
import asyncio

async def step(name, delay):
    await asyncio.sleep(delay)
    print(name)
    return name

async def main():
    print(await asyncio.gather(step("a", 0.03), step("b", 0.01)))

asyncio.run(main())
```
Das gibt `b` aus, dann `a`, dann `['a', 'b']`: `b` wacht zuerst auf, aber die Ergebnisliste behält die Argumentreihenfolge bei.

# --instructions--

Welche Ausgabe hat der folgende Code?
```python
import asyncio

async def step(name, delay):
    await asyncio.sleep(delay)
    print(name)
    return name

async def main():
    names = await asyncio.gather(step("x", 0.03), step("y", 0.01), step("z", 0.02))
    print(names)

asyncio.run(main())
```

# --answers--

- `y`, `z`, `x`, dann `['x', 'y', 'z']`, weil jede Coroutine ausgibt, wenn ihr sleep endet, aber `gather` die Reihenfolge der Argumente beibehält
- `x`, `y`, `z`, dann `['x', 'y', 'z']`, weil `gather` die Coroutinen nacheinander ausführt
- `y`, `z`, `x`, dann `['y', 'z', 'x']`, weil `gather` die Ergebnisse in der Reihenfolge ihrer Fertigstellung zurückgibt
- `x`, `y`, `z`, dann `['y', 'z', 'x']`, weil die Ausgaben erfolgen, bevor irgendein sleep beginnt
