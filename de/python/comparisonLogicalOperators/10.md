# --description--

`==` vergleicht **Werte**; `is` vergleicht **Identität**, das heißt, ob beide Namen auf dasselbe Objekt verweisen. Zwei gleiche, separat erzeugte Listen sind `==`, aber nicht `is`:
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` ist für Singletons wie `None`, `True` und `False` gedacht: Schreibe `value is None` oder `value is not None`, niemals `value == None`, weil eine Klasse `==` definieren kann, um Beliebiges zurückzugeben. `is` mit Zahlen oder Zeichenketten zu verwenden ist unzuverlässig, und Python warnt davor.

# --asserts--

`is_missing(None)` muss `True` zurückgeben

```python
    def test_1(self):
        self.assertIs(is_missing(None), True, "--err-t1--")
```

Falsy-Werte sind nicht `None`

```python
    def test_2(self):
        self.assertIs(is_missing(0), False, "--err-t2--")
        self.assertIs(is_missing(""), False, "--err-t2--")
        self.assertIs(is_missing([]), False, "--err-t2--")
        self.assertIs(is_missing(False), False, "--err-t2--")
```

Ein Objekt, dessen `==` behauptet, mit allem gleich zu sein, ist trotzdem nicht `None`, daher muss die Prüfung die Identität verwenden

```python
    def test_3(self):
        class Anything:
            def __eq__(self, other):
                return True
        self.assertIs(is_missing(Anything()), False, "--err-t3--")
```
