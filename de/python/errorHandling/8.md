# --description--

`except:` ohne Typ dahinter ist ein **nacktes except** (bare except). Es passt auf alles, auch auf Ausnahmen, die mit der Operation, die du absichern wolltest, nichts zu tun haben. Die Regel ist also einfach: Nenne immer die Typen, von denen du dich wirklich erholen kannst.

# --instructions--

Warum sollte dieser Code einen bestimmten Ausnahmetyp nennen, statt ein nacktes `except:` zu verwenden?
```python
try:
    total = int(amout)
except:
    total = 0
```

# --answers--

- Weil das nackte `except:` auch zusammenhangslose Fehler abfängt, etwa den durch den verschriebenen `amout` verursachten `NameError`, sodass ein echter Fehler still zu `total = 0` wird
- Weil ein nacktes `except:` langsamer ist, weil Python die Ausnahme mit jeder eingebauten Klasse vergleichen muss
- Weil ein nacktes `except:` nur auf Modulebene funktioniert und innerhalb einer Funktion einen `SyntaxError` auslöst
- Weil ein nacktes `except:` nichts abfängt, sodass die Ausnahme erneut ausgelöst wird, sobald der Block endet
