# --description--

Den schmalsten Typ zu wählen, der den erwarteten Fehler abdeckt, macht Fehlerbehandlung vertrauenswürdig. Eine Funktion, die Text liest, sollte sich von schlechtem Text erholen (`ValueError`), darf aber nicht verbergen, dass sie mit der falschen Art von Argument aufgerufen wurde (`TypeError`) — dieser Fehler gehört zum Aufrufer, also lass ihn durch.

# --instructions--

Schreibe eine Funktion `parse_age(text)`, die `int(text)` zurückgibt und `-1` zurückgibt, wenn `text` keine gültige ganze Zahl ist. Fange nur `ValueError` ab, sodass `parse_age(None)` weiterhin einen `TypeError` auslöst

# --before-asserts--

```python
import unittest

class CodigoTests(unittest.TestCase):
```

# --asserts--

`parse_age("30")` muss `30` zurückgeben

```python
    def test_1(self):
        self.assertEqual(parse_age("30"), 30, "--err-t1--")
```

`parse_age("old")` muss `-1` zurückgeben

```python
    def test_2(self):
        self.assertEqual(parse_age("old"), -1, "--err-t2--")
```

`parse_age(None)` muss weiterhin einen `TypeError` auslösen

```python
    def test_3(self):
        with self.assertRaises(TypeError, msg="--err-t3--"):
            parse_age(None)
```

if __name__ == "__main__":

# --solutions--

```python
def parse_age(text):
    try:
        return int(text)
    except ValueError:
        return -1
```
