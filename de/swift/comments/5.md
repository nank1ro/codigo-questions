# --description--

Anders als `//`, das am Ende der Zeile stoppt, stoppt ein `/*`-Kommentar erst beim `*/`. Vergisst du ihn zu schließen, behandelt den Compiler den gesamten folgenden Code als Teil des Kommentars und meldet einen Fehler:
```swift
let width = 10 /* in centimetres
print(width) // still inside the comment: error, the comment is never closed
```
Sowohl `//` als auch `/* */` funktionieren als nachstehende Kommentare, aber bei `/*` musst du immer sicherstellen, dass das `*/` vorhanden ist.

# --instructions--

`twice` kompiliert nicht, weil der nachstehende Kommentar in der ersten Zeile nie geschlossen wird und dadurch das `return` verschluckt. Schließe den Kommentar am Ende derselben Zeile

# --asserts--

Der Kommentar muss auf derselben Zeile geschlossen werden

```json
{
  "regex": "/\\* twice the input \\*/",
  "modifiers": ["m"],
  "shouldMatch": true
}
```

`twice(4)` muss `8` zurückgeben

```swift
tryCatch(twice(4) == 8)
```

`twice(-3)` muss `-6` zurückgeben

```swift
tryCatch(twice(-3) == -6)
```

`twice(0)` muss `0` zurückgeben

```swift
tryCatch(twice(0) == 0)
```
