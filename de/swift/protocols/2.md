# --description--

Ein Protokoll kann auch **Methoden** verlangen. Du schreibst die Signatur — Name, Parameter und Rückgabetyp — und machst dort Schluss, ganz ohne Rumpf:
```swift
protocol Greeter {
    func greet() -> String
}
```
Ein konformer Typ muss eine Methode mit genau dieser Signatur deklarieren und liefert den Rumpf:
```swift
struct Robot: Greeter {
    func greet() -> String {
        return "BEEP"
    }
}

print(Robot().greet()) // BEEP
```
Weicht irgendetwas ab — der Name, ein Parametertyp, der Rückgabetyp —, implementiert der Typ das Protokoll nicht konform, und der Compiler sagt dir, welche Anforderung fehlt.

# --instructions--

Sorge dafür, dass `Friendly` `Greeter` konform implementiert, indem du die geforderte Methode `greet()` hinzufügst, die den Namen zwischen `Hello, ` und `!` zurückgibt

Beispiel einer Verwendung:
```swift
print(Friendly(name: "Ada").greet())
// gibt Hello, Ada! aus
```

    return g.greet()

# --asserts--

`Friendly(name: "Ada")` muss mit `Hello, Ada!` grüßen

```swift
tryCatch(_asGreeter(Friendly(name: "Ada")) == "Hello, Ada!")
```

`Friendly(name: "Bo")` muss mit `Hello, Bo!` grüßen

```swift
tryCatch(_asGreeter(Friendly(name: "Bo")) == "Hello, Bo!")
```

Ein leerer Name muss mit `Hello, !` grüßen

```swift
tryCatch(_asGreeter(Friendly(name: "")) == "Hello, !")
```
