# --description--

Das letzte Teilstück ist das absichtliche Werfen eines `Error`. Eine Funktion, die dokumentiert, was sie akzeptiert, sollte alles andere laut ablehnen, und `ArgumentError` ist das Objekt dafür:

```dart
int setVolume(int level) {
  if (level < 0 || level > 100) {
    throw ArgumentError('level must be between 0 and 100');
  }
  return level;
}
```

Die Nachricht ist als `e.message` erreichbar, und `toString()` gibt `Invalid argument(s): ` gefolgt von ihr aus.

Das widerspricht nicht der Regel von zuvor. Einen `ArgumentError` zu werfen ist richtig, einen abzufangen nicht: Er sagt dem Autor des *Aufrufers*, dass der Aufruf selbst falsch ist, und die Lösung ist eine Prüfung vor dem Aufruf, kein Handler darum herum.

# --instructions--

Schreibe eine Funktion `checkAge`, die einen `int` `age` entgegennimmt und ihn zurückgibt, aber `ArgumentError('age must be between 0 and 120')` wirft, wenn das Alter unter `0` oder über `120` liegt.

Beispiel:
```dart
print(checkAge(30)); // 30
```

```dart
  test('test1', () {
    expect(checkAge(30), 30, reason: '--err-t1--');
    expect(checkAge(0), 0, reason: '--err-t1--');
    expect(checkAge(120), 120, reason: '--err-t1--');
  });
```

`checkAge(-1)` und `checkAge(121)` sollten einen `ArgumentError` werfen

```dart
  test('test2', () {
    expect(() => checkAge(-1), throwsArgumentError, reason: '--err-t2--');
    expect(() => checkAge(121), throwsArgumentError, reason: '--err-t2--');
  });
```

```dart
  test('test3', () {
    try {
      checkAge(200);
      fail('--err-t3--');

      expect(e.message, 'age must be between 0 and 120', reason: '--err-t3--');
    }
  });
```
