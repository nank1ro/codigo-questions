# --description--

Gdy funkcja zgłasza błąd, wszystko po `throw` jest pomijane — także linia, która miała zamknąć plik albo zwolnić blokadę. `defer` rozwiązuje to: rejestruje blok od razu i wykonuje go, gdy bieżący zasięg się kończy — niezależnie od tego, jak się kończy.
```swift
func load() throws {
    print("open")
    defer { print("close") }
    throw FileError.missing
}
```
Wywołanie wypisuje `open`, potem `close`, i dopiero potem błąd wędruje dalej do wywołującego. Gdyby funkcja zwróciła się normalnie, `close` również by się wypisał — o to chodzi. Umieść sprzątanie tuż obok przygotowania i przestań się martwić, którą drogą wyjdzie kod.

# --seed--

```swift
enum TaskError: Error {
    case failed
}

func steps(_ shouldFail: Bool) -> [String] {
    var log: [String] = []
    func run() throws {
        log.append("start")
        
        if shouldFail {
            throw TaskError.failed
        }
        log.append("done")
    }
    do {
        try run()
    } catch {
        log.append("caught")
    }
    return log
}
```

# --asserts--

na ścieżce sukcesu log musi być `start`, `done`, `cleanup`

```swift
let _ok: [String] = steps(false)
tryCatch(_ok == ["start", "done", "cleanup"])
```

na ścieżce zgłoszenia błędu log musi być `start`, `cleanup`, `caught`

```swift
let _bad: [String] = steps(true)
tryCatch(_bad == ["start", "cleanup", "caught"])
```

sprzątanie musi wykonać się na obu ścieżkach

```swift
tryCatch(steps(false).contains("cleanup") && steps(true).contains("cleanup"))
```

sprzątanie musi wykonać się dokładnie raz na ścieżce zgłoszenia błędu

```swift
let _once: [String] = steps(true)
tryCatch(_once.filter { $0 == "cleanup" }.count == 1)
```
