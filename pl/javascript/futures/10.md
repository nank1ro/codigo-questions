# --description--

Częstym użyciem `try` / `catch` wokół `await` jest zastąpienie niepowodzenia rozsądną wartością domyślną, tak aby wywołujący nigdy nie musiał zajmować się błędem:
```javascript
async function sizeOf(path) {
  try {
    return await measure(path);
  } catch (error) {
    return 0;
  }
}
```
Zachowaj `await` przed `measure(path)`, nawet jeśli wartość jest zwracana od razu. Bez niego obietnica opuszcza funkcję, nigdy nie przechodząc przez blok `try`, a odrzucenie wymknęłoby się `catch`.

# --asserts--

`await safeParse("12")` musi dawać `12`.

```javascript
(async () => {
  tryCatch((await safeParse("12")) === 12);
})().catch(() => tryCatch(false));
```

`await safeParse("-7.5")` musi dawać `-7.5`.

```javascript
(async () => {
  tryCatch((await safeParse("-7.5")) === -7.5);
})().catch(() => tryCatch(false));
```

`await safeParse("abc")` musi dawać `-1`.

```javascript
(async () => {
  tryCatch((await safeParse("abc")) === -1);
})().catch(() => tryCatch(false));
```

`safeParse("oops")` musi być spełniona, nigdy odrzucona.

```javascript
(async () => {
  let ok = false;
  await safeParse("oops").then(() => { ok = true; }, () => { ok = false; });
  tryCatch(ok);
})().catch(() => tryCatch(false));
```

```javascript
function parseLater(text) {
  return new Promise((resolve, reject) => {
    const value = Number(text);
    if (Number.isNaN(value)) {
      reject(new Error(`not a number: ${text}`));
    } else {
      resolve(value);
    }
  });
}

async function safeParse(text) {
  try {
    return await parseLater(text);
  } catch (error) {
    return -1;
  }
}
```
