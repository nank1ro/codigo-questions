# --description--

Nie ograniczasz się do klas generycznych dostarczanych z Dartem: możesz deklarować własne. **Parametr typu** zapisuje się w nawiasach kątowych po nazwie klasy, a od tej chwili jest to zwykły typ wewnątrz jej ciała:

```dart
class Box<T> {
  final T value;

  Box(this.value);

  T unwrap() => value;
}
```

`T` to jedynie nazwa zastępcza. Jest uzupełniana w momencie tworzenia `Box`, jawnie albo dzięki inferencji:

```dart
final a = Box<int>(7);   // Box<int>
final b = Box('fig');    // Box<String>, inferred from the argument
print(a.value + 1);      // 8, the compiler knows value is an int
```

Litera nie ma znaczenia: `T` to konwencja oznaczająca „typ” i nic więcej.

# --instructions--

Zadeklaruj generyczną klasę `Box` z jednym parametrem typu `T`, polem `final` `value` typu `T` ustawianym przez konstruktor oraz getterem `label`, który zwraca tekst `Box of ` i następującą po nim wartość.

Przykład:
```dart
final box = Box<int>(7);
print(box.value); // 7
print(box.label); // Box of 7
```

# --asserts--

`Box<int>(7)` powinno mieć `value` równe `7` i `label` równe `'Box of 7'`

```dart
  test('test1', () {
    final box = Box<int>(7);
    expect(box.value, 7, reason: '--err-t1--');
    expect(box.label, 'Box of 7', reason: '--err-t1--');
  });
```

`Box` powinno działać z dowolnym typem, więc `Box<String>('fig')` też powinno być `Box<String>`

```dart
  test('test2', () {
    final box = Box<String>('fig');
    expect(box.value, 'fig', reason: '--err-t2--');
    expect(box.label, 'Box of fig', reason: '--err-t2--');
    expect(box, isA<Box<String>>(), reason: '--err-t2--');
  });
```

Argument typu powinien być wywnioskowany z argumentu konstruktora

```dart
  test('test3', () {
    expect(Box(true), isA<Box<bool>>(), reason: '--err-t3--');
    expect(Box(true).label, 'Box of true', reason: '--err-t3--');
  });
```
