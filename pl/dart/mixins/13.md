# --description--

Gdy mixin ma klauzulę `on`, może **nadpisać** składową tego typu i wywołać **`super`**, aby sięgnąć wersji znajdującej się pod nim w łańcuchu:

```dart
class Logger {
  String log(String message) => message;
}

mixin Timestamped on Logger {
  @override
  String log(String message) => '[12:00] ${super.log(message)}';
}

class AppLogger extends Logger with Timestamped {}

void main() {
  print(AppLogger().log('started')); // [12:00] started
}
```

`super.log` to nie własne `log` mixinu, tylko wersja znajdująca się pod nim, więc nie ma nieskończonej rekurencji. Ułóż kilka takich mixinów przez `with A, B`, a każdy opakuje poprzedni: wywołanie wchodzi najpierw do **ostatniego** mixinu i wędruje w dół do nadklasy.

# --instructions--

Zadeklaruj klasę `Pipeline` z metodą `run`, która przyjmuje `String` `input` i zwraca go bez zmian.

Zadeklaruj mixin `Trimmed` na `Pipeline`, który nadpisuje `run`, przekazując przycięty input do `super.run`, oraz mixin `Upper` na `Pipeline`, który nadpisuje `run`, zwracając wynik `super.run` wielkimi literami.

Zadeklaruj klasę `TextPipeline`, która dziedziczy po `Pipeline` i używa najpierw `Trimmed`, a potem `Upper`, oraz klasę `TrimOnly`, która dziedziczy po `Pipeline` i używa tylko `Trimmed`.

Przykład:
```dart
print(TextPipeline().run('  hi  ')); // HI
print(TrimOnly().run('  hi  '));     // hi
```

# --solutions--

```dart
class Pipeline {
  String run(String input) => input;
}

mixin Trimmed on Pipeline {
  @override
  String run(String input) => super.run(input.trim());
}

mixin Upper on Pipeline {
  @override
  String run(String input) => super.run(input).toUpperCase();
}

class TextPipeline extends Pipeline with Trimmed, Upper {}

class TrimOnly extends Pipeline with Trimmed {}
```
