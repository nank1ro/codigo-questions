# --description--

Ostatnim elementem jest rzucanie `Error` celowo. Funkcja, która dokumentuje, co przyjmuje, powinna głośno odrzucać wszystko inne, a `ArgumentError` jest do tego odpowiednim obiektem:

```dart
int setVolume(int level) {
  if (level < 0 || level > 100) {
    throw ArgumentError('level must be between 0 and 100');
  }
  return level;
}
```

Komunikat jest dostępny jako `e.message`, a `toString()` wypisuje `Invalid argument(s): ` wraz z nim.

To nie przeczy zasadzie sprzed chwili. Rzucenie `ArgumentError` jest słuszne, łapanie go już nie: mówi autorowi *wywołującego*, że samo wywołanie jest złe, a poprawką jest sprawdzenie przed wywołaniem, a nie procedura obsługi wokół niego.

# --asserts--

`checkAge(30)` powinno zwrócić `30`, a oba końce zakresu powinny być akceptowane

```dart
  test('test1', () {
    expect(checkAge(30), 30, reason: '--err-t1--');
    expect(checkAge(0), 0, reason: '--err-t1--');
    expect(checkAge(120), 120, reason: '--err-t1--');
  });
```

`checkAge(-1)` i `checkAge(121)` powinny rzucić `ArgumentError`

```dart
  test('test2', () {
    expect(() => checkAge(-1), throwsArgumentError, reason: '--err-t2--');
    expect(() => checkAge(121), throwsArgumentError, reason: '--err-t2--');
  });
```

Rzucony błąd powinien nieść komunikat `'age must be between 0 and 120'`

```dart
  test('test3', () {
    try {
      checkAge(200);
      fail('--err-t3--');
    } on ArgumentError catch (e) {
      expect(e.message, 'age must be between 0 and 120', reason: '--err-t3--');
    }
  });
```
