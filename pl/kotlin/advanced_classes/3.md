# --description--

Wygenerowane `equals()` sprawia, że `==` jest porównaniem **strukturalnym**: dwie instancje są równe, gdy każda właściwość konstruktora głównego jest równa. Operator `===` działa inaczej, pyta, czy obie nazwy wskazują **dokładnie ten sam obiekt** w pamięci.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, te same dane
println(a === b) // false, dwa różne obiekty
println(a === a) // true
```

Ponieważ `hashCode()` jest generowane razem z `equals()`, instancje data class zachowują się poprawnie także wewnątrz `Set` lub jako klucze `Map`: duplikaty się scalają.

```kotlin
println(setOf(a, b).size) // 1
```

Zwykła klasa nie generuje nic z tego, więc dla niej `==` sprowadza się do tożsamości.

# --asserts--

Two users built with the same data must have the same data

```kotlin
    tryCatch(sameData(User(1, "Ann"), User(1, "Ann")))
```

Two users built with different data must not have the same data

```kotlin
    tryCatch(!sameData(User(1, "Ann"), User(2, "Ann")))
```

Two separately built users must not be the same instance

```kotlin
    tryCatch(!sameInstance(User(1, "Ann"), User(1, "Ann")))
```

The same user compared with itself must be the same instance

```kotlin
    val user = User(3, "Bo")
    tryCatch(sameInstance(user, user))
```

`User` must generate `hashCode()`, so a set of two equal users holds one element

```kotlin
    tryCatch(setOf(User(4, "Cy"), User(4, "Cy")).size == 1)
```

data class User(val id: Int, val name: String)

fun sameData(a: User, b: User): Boolean {
    return a == b
}

fun sameInstance(a: User, b: User): Boolean {
    return a === b
}
