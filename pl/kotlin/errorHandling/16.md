# --description--

To, gdzie umieścisz `try`, decyduje, ile pracy niszczy pojedyncza zła wartość. Owiń nią **całą pętlę**, a pierwsza awaria porzuci resztę partii; owiń nią **ciało**, a straci się tylko ten jeden element:

```kotlin
var total = 0
for (value in listOf("3", "x", "5")) {
    try {
        total += value.toInt()
    } catch (e: NumberFormatException) {
        // pomiń tę wartość
    }
}
println(total) // 8
```
Świetnie łączy się to z walidującą funkcją, która zgłasza wyjątek: funkcja ustala jedną regułę i odrzuca wszystko, co ją łamie, a pętla decyduje, że odrzucenie kosztuje tylko jeden element.

# --instructions--

Napisz dwie funkcje.

`validate(text: String): Int` musi zwrócić liczbę zawartą w `text`, albo zgłosić `IllegalArgumentException` z komunikatem `not a number: ` zakończonym tym tekstem.

`sumValid(values: List<String>): Int` musi zsumować wartości akceptowane przez `validate`, pomijając te, na których `validate` zgłasza wyjątek.

Przykład wywołania funkcji:
```kotlin
println(sumValid(listOf("1", "x", "3")))
// wypisuje 4
```

```kotlin
fun validate(text: String): Int {
    val n = text.toIntOrNull()
    if (n == null) throw IllegalArgumentException("not a number: $text")
    return n
}

fun sumValid(values: List<String>): Int {
    var total = 0
    for (value in values) {
        try {
            total += validate(value)
        } catch (e: IllegalArgumentException) {
            // skip this one
        }
    }
    return total
}
```
