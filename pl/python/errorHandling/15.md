# --description--

Czasem program obsługi powinien zareagować na awarię, nie biorąc za nią odpowiedzialności: zapisać ją, policzyć, coś zamknąć — a potem pozwolić zająć się nią wywołującemu. Samo `raise` wewnątrz bloku `except` **ponownie zgłasza** obsługiwany wyjątek, z nienaruszonym pierwotnym typem, komunikatem i tracebackiem:
```python
try:
    value = int(text)
except ValueError:
    print("could not read the value")
    raise
```
Napisanie zamiast tego `raise ValueError(...)` utworzyłoby nowy wyjątek i wyrzuciło pierwotny traceback, czyli dokładnie tę informację, której potrzebujesz przy debugowaniu.

```python
def load(text):
    try:
        return int(text)
    except ValueError:
        print(f"could not read {text}")
        raise
print(load("5"))
try:
    load("abc")
except ValueError:
    print("handled by the caller")
```
