# --description--

`==` porównuje **wartości**; `is` porównuje **tożsamość**, czyli to, czy obie nazwy odnoszą się do dokładnie tego samego obiektu. Dwie równe listy zbudowane osobno są `==`, ale nie `is`:
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` jest przeznaczone dla singletonów takich jak `None`, `True` i `False`: pisz `value is None` lub `value is not None`, nigdy `value == None`, ponieważ klasa może zdefiniować `==` tak, by zwracało cokolwiek. Używanie `is` z liczbami lub łańcuchami jest zawodne i Python przed tym ostrzega.

# --asserts--

`is_missing(None)` musi zwrócić `True`

```python
    def test_1(self):
        self.assertIs(is_missing(None), True, "--err-t1--")
```

Wartości fałszywe nie są `None`

```python
    def test_2(self):
        self.assertIs(is_missing(0), False, "--err-t2--")
        self.assertIs(is_missing(""), False, "--err-t2--")
        self.assertIs(is_missing([]), False, "--err-t2--")
        self.assertIs(is_missing(False), False, "--err-t2--")
```

Obiekt, którego `==` twierdzi, że jest równy wszystkiemu, nadal nie jest `None`, więc sprawdzenie musi używać tożsamości

```python
    def test_3(self):
        class Anything:
            def __eq__(self, other):
                return True
        self.assertIs(is_missing(Anything()), False, "--err-t3--")
```
