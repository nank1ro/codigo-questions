# --description--

Un `except:` sans type après lui est un **bare except** (« except nu »). Il correspond à tout, y compris aux exceptions qui n'ont rien à voir avec l'opération que vous protégiez, donc la règle est simple : nommez toujours les types dont vous pouvez réellement vous remettre.

# --instructions--

Pourquoi ce code devrait-il nommer un type d'exception spécifique au lieu d'utiliser un `except:` nu ?
```python
try:
    total = int(amout)
except:
    total = 0
```

# --answers--

- Parce que le `except:` nu intercepte aussi les défaillances sans rapport, comme la `NameError` causée par le `amout` mal orthographié, de sorte qu'un vrai bug devient silencieusement `total = 0`
- Parce qu'un `except:` nu est plus lent, car Python doit comparer l'exception à chaque classe intégrée
- Parce qu'un `except:` nu ne fonctionne qu'au niveau du module et lève une `SyntaxError` dans une fonction
- Parce qu'un `except:` nu n'intercepte rien, donc l'exception est levée à nouveau dès que le bloc se termine
