# --description--

`==` compare les **valeurs** ; `is` compare l'**identité**, c'est-à-dire si les deux noms désignent exactement le même objet. Deux listes égales construites séparément sont `==` mais pas `is` :
```python
a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)  # True False True
```
`is` est destiné aux singletons comme `None`, `True` et `False` : écrivez `value is None` ou `value is not None`, jamais `value == None`, car une classe peut définir `==` pour renvoyer n'importe quoi. Utiliser `is` avec des nombres ou des chaînes n'est pas fiable et Python vous en avertit.

# --instructions--

Écrivez une fonction `is_missing(value)` qui renvoie `True` uniquement lorsque `value` vaut `None`, et `False` pour toute autre valeur, y compris les valeurs fausses comme `0`, `""` et `[]`

# --asserts--

`is_missing(None)` doit renvoyer `True`

```python
    def test_1(self):
        self.assertIs(is_missing(None), True, "--err-t1--")
```

Les valeurs fausses ne sont pas `None`

```python
    def test_2(self):
        self.assertIs(is_missing(0), False, "--err-t2--")
        self.assertIs(is_missing(""), False, "--err-t2--")
        self.assertIs(is_missing([]), False, "--err-t2--")
        self.assertIs(is_missing(False), False, "--err-t2--")
```

Un objet dont le `==` prétend être égal à tout n'est toujours pas `None`, la vérification doit donc utiliser l'identité

```python
    def test_3(self):
        class Anything:
            def __eq__(self, other):
                return True
        self.assertIs(is_missing(Anything()), False, "--err-t3--")
```
