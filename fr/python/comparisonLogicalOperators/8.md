# --description--

`and` et `or` ne renvoient pas toujours `True` ou `False` : ils renvoient l'un de leurs **opérandes**. `a and b` renvoie `a` s'il est faux, sinon `b` ; `a or b` renvoie `a` s'il est vrai, sinon `b` :
```python
print(0 and "x")       # 0
print(3 and "x")       # x
print("" or "none")    # none
print("hi" or "none")  # hi
```
Le résultat est vrai ou faux exactement quand l'expression entière l'est, c'est pourquoi `if a and b:` fonctionne malgré tout. Un usage courant est la valeur par défaut : `name = user_input or "guest"`.

# --instructions--

Qu'affiche ce code ?
```python
print(0 or 5, 3 and 0, "x" and "y")
```

# --answers--

- `5 0 y`, car `or` renvoie le premier opérande vrai et `and` le premier faux, ou le dernier opérande lorsqu'il n'y en a aucun
- `True False True`, car les opérateurs logiques produisent toujours un booléen
- `0 3 x`, car `and` et `or` renvoient toujours leur premier opérande
- `5 3 y`, car les deux opérateurs renvoient l'opérande vrai
