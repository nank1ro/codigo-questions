# --description--

Le `equals()` généré fait de `==` une comparaison **structurelle** : deux instances sont égales quand chaque propriété du constructeur principal est égale. L'opérateur `===` est différent, il demande si les deux noms pointent vers le **même objet** en mémoire.

```kotlin
data class User(val id: Int, val name: String)

val a = User(1, "Ann")
val b = User(1, "Ann")
println(a == b)  // true, same data
println(a === b) // false, two different objects
println(a === a) // true
```

Comme `hashCode()` est généré avec `equals()`, les instances d'une data class se comportent aussi correctement dans un `Set` ou comme clés d'un `Map` : les doublons fusionnent.

```kotlin
println(setOf(a, b).size) // 1
```

Une classe régulière ne génère rien de tout cela, donc pour elle `==` retombe sur l'identité.

# --asserts--

Deux utilisateurs construits avec les mêmes données doivent avoir les mêmes données

```kotlin
    tryCatch(sameData(User(1, "Ann"), User(1, "Ann")))
```

Deux utilisateurs construits avec des données différentes ne doivent pas avoir les mêmes données

```kotlin
    tryCatch(!sameData(User(1, "Ann"), User(2, "Ann")))
```

Deux utilisateurs construits séparément ne doivent pas être la même instance

```kotlin
    tryCatch(!sameInstance(User(1, "Ann"), User(1, "Ann")))
```

Le même utilisateur comparé à lui-même doit être la même instance

```kotlin
    val user = User(3, "Bo")
    tryCatch(sameInstance(user, user))
```

`User` doit générer `hashCode()`, ainsi un ensemble de deux utilisateurs égaux contient un élément

```kotlin
    tryCatch(setOf(User(4, "Cy"), User(4, "Cy")).size == 1)
```

data class User(val id: Int, val name: String)

fun sameData(a: User, b: User): Boolean {
    return a == b
}

fun sameInstance(a: User, b: User): Boolean {
    return a === b
