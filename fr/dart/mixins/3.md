# --description--

Un mixin ne se limite pas aux méthodes : il peut aussi déclarer des **champs**, et chaque objet de chaque classe utilisant le mixin obtient sa propre copie de ces champs.

```dart
mixin Counter {
  int count = 0;

  void increment() {
    count++;
  }
}

class Clicker with Counter {}

void main() {
  final a = Clicker();
  final b = Clicker();
  a.increment();
  a.increment();
  print(a.count); // 2
  print(b.count); // 0, b has its own count
}
```

C'est ce qui fait d'un mixin plus qu'une interface : il apporte à la fois les données et le code qui les manipule.

# --instructions--

Déclarez un mixin `Scored` avec :
- un champ `int` `score` qui commence à `0`
- une méthode `addPoints` qui prend un `int` `points` et l'ajoute à `score`

Déclarez une classe `Player` qui utilise `Scored` et n'ajoute rien en propre.

Exemple :
```dart
final p = Player();
p.addPoints(3);
print(p.score); // 3
```

Un nouveau `Player` doit avoir un `score` de `0`, et `addPoints(3)` doit l'amener à `3`

```dart
  test('test1', () {
    final p = Player();
    expect(p.score, 0, reason: '--err-t1--');

    expect(p.score, 3, reason: '--err-t1--');
  });
```

Les appels à `addPoints` doivent s'additionner

```dart
  test('test2', () {
    final p = Player();
    p.addPoints(3);
    p.addPoints(4);
    p.addPoints(10);
    expect(p.score, 17, reason: '--err-t2--');
  });
```

Chaque `Player` doit avoir son propre `score`, et un `Player` doit être un `Scored`

```dart
  test('test3', () {

    final b = Player();

    expect(a.score, 5, reason: '--err-t3--');

    expect(a, isA<Scored>(), reason: '--err-t3--');
```
