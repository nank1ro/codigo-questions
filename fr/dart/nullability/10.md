# --description--

La promotion de type ne fonctionne **pas** sur un **champ** de classe qui peut être modifié de l'extérieur, car entre la vérification et l'utilisation, un autre morceau de code (un getter redéfini dans une sous-classe, une autre méthode) pourrait le remettre à `null` :

```dart
class Box {
  int? value;

  int doubled() {
    if (value != null) {
      return value * 2; // error: 'value' can't be unconditionally accessed
    }
    return 0;
  }
}
```

La correction standard consiste à copier le champ dans une **variable locale**, qui est bien promue :

```dart
int doubled() {
  final v = value;
  if (v != null) {
    return v * 2;
  }
  return 0;
}
```

# --instructions--

Pourquoi la première version de `doubled` dans la description ne compile-t-elle pas ?

# --answers--

- `value` est un champ, donc la vérification de nullité ne le promeut pas : copiez-le d'abord dans une variable locale
- les valeurs `int?` ne peuvent pas être multipliées, même quand elles ne sont pas `null`
- L'instruction `if` n'a pas de branche `else`
- Les champs d'une classe ne peuvent pas avoir un type nullable
